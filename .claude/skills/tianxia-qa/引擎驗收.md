# 引擎驗收：瀏覽器湊不出來的，用腳本跑 Game

這些情況實機很難湊，或要等很久：滿級、頭目戰、切磋、決戰軍餉、低機率掉落、求援傳聞、開關關著的對照、跨季。
做法是寫一次性腳本，用真實內容跑 `Game`。規矩：腳本放 scratchpad、不進 repo，`TIANXIA_DB` 指到 scratchpad，印中文前先包 UTF-8；
暫時的 `content/profiles/*.json` 用完就刪；結論寫進試玩回饋時註明「程式跑的」。

## 1. 起手式（暫存資料庫加 Game.new）
```python
import io, os, sys, tempfile, random
sys.path.insert(0, os.getcwd())                      # 在 repo 根目錄跑
sys.stdout = io.TextIOWrapper(sys.stdout.buffer, encoding="utf-8", errors="replace")
from pathlib import Path
from tianxia.content import load_content
from tianxia.engine import Game
from tianxia.sqlite_world import open_world
c = load_content(Path("content"), "season21")       # "weekend"；None＝14 天
w = open_world(Path(tempfile.mkdtemp()) / "t.db")
admin = Game.new(c, "管測", rng=random.Random(1), world=w)
assert w.open_season(c, 1000.0)                     # 先 Game.new 再開季，順序反了會回 False
admin.sync(1000.0); admin._settle_season_start()   # 開季那一刻：第一批懸賞、軍令
T = [1100.0]                                        # 世界秒自己給，每個動作前 sync 往前推
```
- 管理者的 `admin_*` 要名號在 `TIANXIA_ADMINS`。
- **擋模型**：`Game.new` 會照設定建 Ollama client。腳本一開頭先寫 `from tianxia import ollama_client; ollama_client.OllamaClient.from_config = classmethod(lambda cls, cfg: None)`。
- **照現實天的季**（season21、week7）：
  - `open_season(c, now)` 的 now 要給現實的 epoch，錨點 `cal_offset` 照它蓋；之後一路 `g.sync(現實 epoch)`。
  - 開季用 `admin.admin_open_season(now)`，開季那一刻的大事、軍令、懸賞會一起結算。
  - 「第 N 天 HH:MM」的世界秒是 `(N−1)×DAY + 時刻 − season.cal_offset`。
- **一路同步到季末時，決戰要另外推**：玩家的 `sync` 只補算季，不推決戰。每一步另外叫一次 `Game.for_world(c, w).world_tick(real)`（伺服器的排程就是這一個）。沒叫的話，集結開了一直卡著，後面那一場決戰被跳過，時間軸看起來像壞了。
- 開關要在開季**之前**改。`precise_actions` 這類是開季時蓋章的；要模擬「上線前開的舊季」，開季後改 `g.state.world.precise_actions = False`。
- 改開關的寫法：`c.config.x = c.config.x.model_copy(update={...})`。
- **密鹽是空的**：`seal.ensure_salt` 只有 `server.main`、`run_bots.main` 叫，腳本開的世界密鹽是空字串，碎片的藏處、撿不撿到每一局都一樣。要換種子就在開季前 `w.mutate(lambda st: setattr(st.seal, "salt", "qa1"))`（2026-10-21 換 80 個密鹽看九塊中立地的分布）。

## 2. 把角色調到指定陣營、等級、地點
```python

    g = Game.new(c, name, rng=random.Random(sum(map(ord, name))), world=w); g.client = None
    T[0] += 5; g.sync(T[0]); p = g.state.player
    p.location = {"guan": "changshe", "huang": "huangjin_camp", "haoqiang": "haozu_fort"}[faction]

    g.choose("faction:confirm")
    p.location = loc; p.member.level = level; p.member.exp = 0       # 等級在 member，不是 p.level
    p.stamina = float(c.config.stamina_max); p.tutorial_step = len(c.tutorial.steps)
    return g
```
- **調強**：`rules.learn_skill(g.state, c, "xingwu_qiang")`、`p.member.wugong_id = "xingwu_qiang"`、`p.art_quality[id] = "絕學"`、兩門十成、
  `p.stats["str"] = p.stats["con"] = 15`；補滿 `p.member.neili = None; p.member.injury = 0.0`。
- **差幾點升級**：`p.member.exp = team.level_cost(c.config, lv) - 10`。
- **直接改 `p.location`**：不觸發抵達的事（護送交差、路上小事）。要觸發，就挪到隔壁再真的走一段疾行（`/api/travel` 帶 `mode: "dash"`）。
- **同伴**：`p.team = [cid]`，經驗看 `w.get_companion(cid)`。
- **世界狀態**：季用 `w.mutate_season(fn)`，全服用 `w.mutate(fn)`，都包在 `w.db.transaction()` 裡。人物聲威是 `ws.figures[fid].prestige`，打到 0 會退場，別設太低。
- **伺服器上的角色**：用 `CharacterStore(open_database(path))` 的 `load`／`save` 包交易。先讓角色登入同步過一次再改（換季重設會蓋掉）；
  略過序章會把人放回起點，先略過再挪。
- **事件**：`g.state.pending_event = "<事件 id>"`，之後選單上就是 `choice:N`。

## 4. 照種子挑擲得中的名號（稀有掉落、挑戰四階）
這些都是自己的亂數，固定寫成「名號｜戰報流水號」，所以可以先算再建角色。動手前先拿現在的程式碼核對種子字串。
```python
hit = lambda seed, p: random.Random(seed).random() < p
# 出陣稀有：f"出陣稀有|{季數}|{名號}|{流水號}|寶物"（另有 |良駒、|破境丹），機率在 Config.sortie
# 挑戰四階：f"四階|{季數}|{名號}|{流水號}|挑戰|{fid}"，機率是 Config.four_tiers.challenge_chance
```
- **流水號**：`g.state.battle_seq + 1`，每季從 1 起。每一場仗都佔一號：練功、出陣攻、挑戰，平手和輸也算。守、巡哨不佔。
- **挑名號**：拿一串名號跑 1～10 號，挑命中排得好的，再用 `scripts/set_password.py <帳號> --character <名號>` 建角色。
- **號碼被平手吃掉了**：重算命中表，用練功墊場把號碼推到命中的那一號。
- **上限**：一季的上限記在 `sortie_treasures`、`sortie_horses`、`tier4_wins`、`tier4_challenge_drops`。

## 5. 決戰怎麼打完
1. 開戰：`/api/do/start_showdown {"id": "changshe_fire"}`（`Game.admin_start_showdown`）。管理者的「定結果」只給沒在打的決戰，定了沒有參戰者，不發東西。
2. 加入：參戰的人站在決戰的大區，選 `battle:join:<陣營>`；散人與豪強選 `battle:enlist:<guan|huang>`。
3. 收集結：把 `state.active_battle.muster_deadline_real` 改成 `time.time() - 1`（`w.mutate`）。下一次請求就收集結。
4. 打回合：每個在場的人選一個 `battle:act:*`，最後一個送出時結算。
5. 有人不出手：把 `state.active_battle.round.opened_real` 改成 `time.time() - 100000`，下一次請求逾時代選、結算。
6. 打完：軍餉、四階、戰報都在每個人**下一次同步**才發，所以要用那個帳號登入。「下線回來補」就是這樣驗的。

天命之爭、保底收場湊不出來，照單元測試。

## 6. 欄位速查
- 出陣每日次數：`PlayerState.sorties_today`、`sortie_day`。看現實時間，管理者快轉沒用，要直接改成 0。
- 閉門不見：`PlayerState.snubbed_until[fid]`，刪掉那一筆就能再挑戰。
- 回體丹：`pills_today`、`pill_day`。
- 銀兩在 `p.stats["silver"]`。
- 醫館用銀兩買破境丹：`g._silver_act("buy_legend")`，鈕看 `g._silver_options()`。`Game.buy_legend` 是用心得換的那一條，名字容易拿錯。
- 天命之爭的排程：這一季用 `admin_seal_mandate("now")`；換季那一條路用 `"next"`，再 `admin_end_season`、`admin_next_season`。之後看 `season.schedule["tianming"]`。
- 序章：`tutorial_step = len(c.tutorial.steps)`，或 `/api/do/skip_tutorial`。
- 軍令只在週一發；要驗某一種軍令的記功，自己掛一道：`Order(id=..., template="siege", faction="guan", week=orders.period_of(g.state, c), front="yingru", quota=6, text="QA")`
  用 `w.mutate_season(lambda s: s.orders.append(o))`（包在 `w.db.transaction()` 裡），再 `g.sync`；卡上那一行是 `atlas.order_how(g.state, c, o)`，
  假人往哪走看 `orders.win_counts`／`targets`。卡上寫的地點要真的打一場確認記得到（記功看的是 `orders._counts`，不是卡上的清單）。
- **攻城記功（`orders._counts`）只看戰線與對手陣營，不看地點**：運糧隊（敵方陣營的隊伍）在不在 `siege_places` 的地方被打贏，只要在同一條線，同一天掛著的攻城令照樣 +1（領地爭奪複驗，FB-534）。要驗「只算截糧」「只算攻城」這類說法，兩道令一起掛、看回傳訊息有幾行軍令。`orders.targets` 把守城令算成整條戰線的全部地點，單看攻城用 `orders.siege_places`。
- **決戰收場直接寫戰線**（不必打完一場決戰）：`a._apply_outcome_trends_and_flags(season, SimpleNamespace(outcome_trend_delta={"nanyang": -30}, outcome_world_flags=[]))`，`season` 用 `a.state.world`。

## 7. 兩份程式碼對照比較（開關關著一字不變、舊季照舊）
```bash
SP=<scratchpad>; mkdir -p "$SP/base" && git archive <base commit> tianxia content | tar -x -C "$SP/base"
python -I cmp.py "$SP/base" "$SP/out_base.txt"; python -I cmp.py "$(pwd)" "$SP/out_branch.txt"; diff "$SP/out_base.txt" "$SP/out_branch.txt"
```
`cmp.py` 開頭：`root = sys.argv[1]; sys.path.insert(0, root); os.chdir(root)`。
- 一定要加 `-I`，不然會 import 到另一份。
- base 用這一批開分支的那一點，不是 main。
- 只印穩定的字：戰報、選單、`reward_text`、`howto_text()`、`forge_secrets.active(...)`。新加的欄位先拿掉再比。
- 舊的 Config 沒有新欄位，改之前先 `if "x" in type(cfg).model_fields`。
- 差異只有 id（流水號）這類玩家看不到的，回報時照實寫。
- **逐行歸類差異不要拿整行丟 `difflib`**：SVG 一行十幾萬字，`SequenceMatcher` 跑了十分鐘還沒完（2026-10-21）。先在 `>`、`,`、`。` 之後切成小段（`re.split(r"(?<=[>,。；])", line)`），對小段的清單做 `SequenceMatcher`，再把每一段 `replace`／`insert` 照內容歸類（多一條路、多一顆鈕、描寫、路程），剩下的「其他」逐條看。
- **整個畫面一次比**：腳本裡 `import server`，`server.main_view(g)` 每一個鍵各印一行（`json.dumps(..., sort_keys=True)`，`HH:MM` 換掉），
  再加 `g.map_state()`、`g.map_base()`、`g.map_legend()`、`g.world_map_svg("situation")`、`g.howto_text()`、`howto.war_help(g.state, c)`；
  照現實天的季開季用固定的 epoch，兩份就一個位元組都一樣（領地爭奪第一批三種季各約 570 行、90 萬位元組）。
- **出陣只在戰線地點**（開關關著、地盤照拔河時）：`scenario.territory.lines` 的官軍大營、汝南荒野、南陽郊野、淯水河畔、白馬津、下曲陽、拒馬河畔、燕山腳，
  加上自家的大本營；潁川郊野、嵩山深處這類沒有出陣鈕，對照腳本只走那些地方等於什麼都沒比到。先印一次鈕，確認真的出陣了。
- **夾值、邊界的修正兩頭都驗，而且基準要真的超出牆**（領地爭奪複驗）：南陽中立 3 塊加淯水河畔給黃巾，基準 108.33；冀州官軍拿 4 塊中立加涿郡、集市小鎮、樓桑里，基準 −37.5。同一支腳本在修前、修後的複本各跑一次，每一步印（值，基準，偏移）逐行對照：往牆推、往回推、基準在牆內的一般推、再還一塊回去。只驗一頭會漏掉另一頭同樣的毛病（修前往 0 推一下偏移從 +5 變 +37.5）。

## 8. 假人：帶假時鐘的 BotRunner
```python
from tianxia.bot_runner import BotRunner
from tianxia.characters import open_characters        # 簽名以程式為準
db = Path(tempfile.mkdtemp()) / "t.db"; w = open_world(db)
now = [1_800_000_000.0]
runner = BotRunner(c, world=w, characters=open_characters(db), rng=random.Random(1), clock=lambda: now[0])
assert w.open_season(c, now[0])        # 籌備、休季、暫停中 tick() 什麼都不做
for _ in range(200):
    now[0] += c.config.bot_tick_seconds
    report = runner.tick()             # TickReport：這一輪誰動了
```
- 假人 `client=None`：不叫模型、不寫自由文字，所以放手一搏、隨口應對、取名驗不到。
- 整季跑請用 `scripts/sim_server_bots.py`，量表照派工才跑。
- 任何輸出都不能透露誰是假人。
- **驗「假人不去做某件事」**：`bot_policy.take_turn(game, BotProfile(personality="普通", seed=3, faction=side, season_number=1), rng)` 一個地點一個**新角色**、各跑 50 輪，用 `mock.patch.object(g, "choose", wraps=g.choose)` 數 `act:train` 按了幾次，修前修後各跑一次。不要數 `sorties_today`（巡哨也扣次數），也不要一個人連測好幾個地點（前面打輸的內傷讓假人 `_crippled`、不出陣不挑戰，後面的 0 全是假的）。
- **數假人「在某種地方按了幾次」要在 `choose` 的包裝裡量按下去那一刻人在哪**（`g.choose = spy`，spy 裡讀 `g.state.player.location` 與 `conquest.push_problem(...)`，再呼叫原本的 choose）：以出發點分類會算錯，假人會先走一段再出陣（2026-10-21：從推不動的地方出發、按在推得動的地方；反過來亦然）。整段 `BotRunner` 的版本用 `Game._sortie = spy`（只記 `p.bot is not None` 的人），留著開季的截糧軍令跑假時鐘，才碰得到「軍令把假人拉去推不動的地方」。

## 9. 領地爭奪的攻城戰（單方攻中立地、三方混戰、轉回單方）
- **流程全走 `Game`**：每個動作前先 `g.sync(現實時刻)`（同伺服器從資料庫重讀）→ 投票 `g.conquest_vote(地點 id, 當天第幾分鐘)` → 22:00 之後 `Game.for_world(c, w).world_tick(t)` 結算、排出時程表 → 開集結時各人 `g.sync` → `battle:join:<guan|huang>` 加入（再 `battle:escort:none…` 略過隨行同伴）→ 公告的開打時刻之後（例如 20:00:30）再 `world_tick` 一次，戰場才進到 `active`。攻城戰在 `w.get_sieges()`（不是 `get_battle()`，那一個是時刻表決戰）；改它用 `w.mutate_siege(record_id, fn)`，收場後 `w.ended_battle(record_id)`。
- **三種局面怎麼湊**：只有一軍投票＝單方攻中立地（守將站另一軍的 id，池 1500）；兩軍投同一塊同一刻＝三方混戰（守將站 `guard` 那一格，池 30×到場人數）；兩軍都投、只有一軍有人加入＝開打那一刻轉回單方（裁決 23）。**散人助守要選對鈕**：三方混戰與轉回單方選 `battle:enlist:guard`；單方攻中立地選 `battle:enlist:<守將那一軍的 id>`。轉回單方那一組如果助守的散人選成 `battle:enlist:huang`，會被算成黃巾到場，仍是三方混戰，池也變成 30×人數（自己踩過一次）。
- **放手一搏直接送分數**（跳過模型）：`tag = next(o.tag for o in bi.options_for(b, d, 出手的人) if o.free_text)`，`bi.submit_action(b, 出手的人, tag, 文字, 100)`（包在 `w.mutate_siege` 裡），其餘的人再各自 `g.choose("battle:act:…")`，最後一個送出時結算。守將是 `next(x for x in b.commanders if x.fid.startswith("squad:"))`，比出手前後的 `neili`；`bi.find_commander`／`find_target`／`target_line` 也可以對同一張單子直接問，三個一起印最清楚。決戰的人物上陣是 `w.get_battle()`／`w.mutate_battle`，開法 `admin.admin_start_showdown("changshe_fire", t)`。
- **「誰看得到什麼」的對照法**：每個站位（攻方、助守、另一軍旁觀、依附兩軍的豪強、散人旁觀、晚到的）各印 `g.scene_text()` 與 `json.dumps(server.main_view(g))`，在集結、開打、打了兩個回合之後各一次，grep 要找的字；兩份複本的輸出 `diff`，只該差預期的那幾行，並且數出差了幾行、分別是誰。

## 10. 翻地與爭搶（輿圖第三版第 1 批）
- **推一下只有 2／100**（名目量 1 × `progress_scale` 2，同一邊人多再 ÷√n、集火再乘）：要推滿先 `admin_conquest_progress(地點, 陣營, 99.5)` 再真的出陣一次；99 不一定推得滿。管理者定進度不記帳（`Bar.pushers`）也不設警報（`BlockFight.alarm`）：驗分紅要先真的出陣推幾下（或 `conquest.push(world, c, 地點, 陣營, 名號, 量, "attack")`），驗守城功要用 `conquest.push` 推過五成，再讓管理者往下定、守的人拉到零。
