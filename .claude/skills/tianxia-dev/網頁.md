## 網頁測試（`tests/webharness.py`）

- 沒有前端框架：測試把 app.js 的函式切出來交給 node 跑，看吐出來的 HTML。沒有 node 就略過：`pytestmark = pytest.mark.skipif(webharness.NODE is None, …)`。
- DRIVER 是一段 JS 字串，拿得到這幾個：
  - `fn("名字")`：抓 `\n  function 名字(` 到下一個 `\n  }\n`；一行寫完的 function 只抓那一行。
  - `konst("名字")`：**只抓一行寫完的** `const 名字 = …;`。多行的箭頭函式、多行的物件抓不到，會丟「app.js 裡找不到 const X」——要被切的 helper 一律寫成 `function`。
  - `wholeApp([...])`：整支 app.js 放進假瀏覽器，交出要測的名字（店面測試走這條，`test_shop2_web.DRIVER`、`test_dadian_shop._shop_run`），新加的函式自動在。
  - `busyKit()`：切 `busy` 一律用它，不單切 busy。`finish(值)` 印結果。
- **新 helper 被既有函式呼叫時，每一個切了那個函式的 DRIVER 都要補上它**（例：`checkinPeek` 進了 `peekParts`，`tests/test_peek_row.py` 的清單也要加，不然那一檔幾十條一起 ReferenceError）。改前先 grep 函式名在 tests 裡被誰切。
- 餵的資料：大部分手寫 `m`（`/api/main` 那一份的形狀）最清楚；另外至少一條用真的 `game.status_data()`／`server.main_view(game)`，伺服器那邊改了形狀才抓得到。
- 兩條只讀原文的守門測試，改網頁的批常常不小心弄紅（商城第二批就是，QA 只跑點名的檔沒看到，`test_for` 才抓到）：
  - `style.css` **第一個** `@media (min-width: 641px)` 以前都算手機那一半（`test_bounty_tags.py` 照它切）：新的電腦寬規則放在「電腦上的店面」那一段（FB-225）後面，不要在檔案前半另開一個 641px 的 media。
  - app.js 裡寫死的 `data-glow="…"` 都要在 `models.GLOW_KEYS`（多半是加進 `REVEAL_KEYS`）登記（`test_content.py::test_every_glow_key_the_page_draws_is_one_the_content_may_name`）。
- CSS 沒辦法在 node 裡排版：測試讀 `style.css` 的字、斷言那一條規則（前例 `test_dadian_shop.py` 的 FB-411、`test_checkin_web.py` 的 FB-437），真正的幾何到瀏覽器裡量（下一節）。
- 跑：`scripts/test_for.py --base origin/feature/<名字>`，或直接給改到的測試檔；`TIANXIA_DB` 設到 repo 外、`PYTHONIOENCODING=utf-8`。

## 手機寬度：375、360、320

- 375×812 是主要的：按完一個動作不用捲就看得到「剛剛」、場景與整排行動。360 是常見的 Android，320 是最窄的；`style.css` 有 `≤340px`（小標的箭頭收掉）、`≤359px`、`≥641px`（電腦上照中間 640 那一欄，FB-225）幾段。
- `resize_window` 設寬高，量用 `javascript_tool`，不要只看截圖：
  - 一排有沒有折行：每一顆 `getBoundingClientRect().top` 一樣。
  - 字有沒有被切：`el.scrollWidth > el.clientWidth`。只多出不到半 px 時兩個整數一樣大、瀏覽器照樣收「…」：程式裡要判斷（量了才加 class）就量 Range（`selectNodeContents(el)` 的 `getBoundingClientRect().right` 對 `el` 的 right；收了「…」Range 照樣是整段的寬），同 `fitBars`。
  - 不折行的小段有沒有被拆：`span.getClientRects().length === 1`。
  - 有沒有橫向捲軸：`document.documentElement.scrollWidth === innerWidth`。
  - 偽元素（朱印這類 `::after`）：`getComputedStyle(el, "::after")` 的 top／right／width 換算回矩形，再跟字的矩形比有沒有重疊。
- 放不下時先想「怎麼排」：照「＋」拆兩行（簽到第 6 天 `ckGift`，FB-436）、四顆時收內距與間距（`.peek-row:has(> .peek-chip:nth-child(4))`）、朱印移到角上；**字一個不改**、不靠縮到看不清的字級（店面字級最低 12px）。
- 量完 `resize_window` 回 `desktop`。
- **狀態列裡「量了才變」的東西放進 `fitBars`**（體力氣血兩個字 FB-198、所在那一行折不折 FB-493）：它在 render 的 `renderPage` 之前與之後各叫一次、`renderTop`、resize、字型載入完也叫。會讓狀態列變高的要在 `renderPage` 之前量好，不然第一屏（`fitFirstScreen`）照舊的高度收、行動列被推下去沒人管；`--top-h` 也要排在它後面寫。
- 狀態列名號底下那一行（`.where`：📍 地名　時刻）最長的：地名是潁川郡（陽翟）（起點、醫館）；時刻 week7／週末「第 12 週・週日 HH:MM」（約 221px），season21 只到第 3 週（約 214，375 寬元寶四位數剛好一行、五位數就折），不帶設定檔（14 天、第一季規則關著）「第 N 天 HH:MM／共 14 天」（約 232，最長）。week7 也是寫「第 N 週」（12 週），不是「第 N 天」。
- 320×700 本來就放不進行動列（閒著、師父的框在的時候，FB-493 之前也是）；第一屏只照 375×812 驗。
- 拆成幾個行內 `<span>` 不改版面，但每一段的寬照 LayoutUnit（1/64 px）進位，整行可能挪 0.02px：手機兩倍像素逐像素一樣，電腦一倍像素那一行有十幾個反鋸齒像素不同（看不出來）。說「一個像素都不變」時照實寫。

## 詞中間斷行：不折行的小段

中文會在任何兩個字之間斷，「九／折」「您／挑」「最／多打點到 40」就是這樣來的。做法是把字切成一段一段的 `<span class="nb">`（行內區塊、不折行），段與段之間才換行：

- `nbChunks`／`nbHtml`（FB-132）：切在「・；、，＋→」後面與「（」前面，一段超過 `NB_MAX` 16 字就不包。鐵匠鋪、馬市的長標籤用它。
- `dealHtml`（FB-297）：價錢後面的折扣原因，「稱號・N折」連同緊貼的「（」與後面的「，」「）」一起包；只包字不包括號的話，Chrome 會在括號跟小段之間斷，一行收在「（」上。
- `.btn` 是不換行的橫向 flex：鈕裡的字與小段要先**整段包在一個 span 裡**，不然每一段各成一個 flex 項目、排成一列、把鈕撐出畫面（FB-297 複驗沒過的那一次）。
- `ledgerText`（FB-411，打點帳簿）切在「，・；／：」後面、不切「→」（「情誼 0 → 5」是一件事）；`sayHtml`（FB-433，掮客那一句）切在「，。：；！？」後面，緊跟著的「」』」併進前一段，不讓收引號落單。
- 價錢與名額這種兩件事中間用「・」接（FB-410），讓它只在「・」後面斷。
- 新地方要用就挑最接近的那一個，切法不同就照同樣寫法另寫一個，不要改 `nbChunks` 本身（很多地方共用）。

## 店面那一層與輪詢

- 店面（鐵匠鋪、馬市、懸賞榜、打點、酒肆、擂台）是蓋在整個畫面上的 `.shop-layer`（z-index 41；武學譜那本書 42）。`shopHtml` 是共用的框（招牌、掌櫃那一句、出店），底下照 `shop.shop` 畫各店；捲的內容一律包 `.shop-col`（電腦上照中間那一欄）。
- class 不要撞既有的通用名：實機撞過 `.held`、`.bar`、`.week`、`.day`；新東西加前綴（`held-row`、`abil`、`ck-day`）。
- 前端每 10 秒打 `/api/main`：分頁在背景不打、上一次沒回來不打、**內容沒變不重畫**。手指按在畫面上時不重畫，放開才補（不然按下去那一顆被換掉、click 落空）。
- 店開著時輪詢只重畫店面那一層（`refreshPage` 最前面問 `shopPolled`）：捲到哪裡放回去、換頁才回頂上、**不淡入**（淡入每 10 秒重播一次、底下跟著閃）。店開了、收了、換了一間（比 `main.shop.shop`）才從頭來。
- 江湖頁上的小動作原地換掉那一塊（例 `peekTap` 換 `#peek` 的 outerHTML），不重畫整頁：重畫會讓「剛剛」的浮現動畫再播一次。
- 送出動作一律走 `busy()`／`doMain(op, body)`：按下去那一顆 `.sending`，伺服器那邊在 `server.MAIN_ACTIONS` 加一條；點擊在 app.js 底下那一大串 `case "…":` 裡加。
- **回應沒收到、照同一個編號再送的動作**（商城的購買，FB-491）：伺服器要分得出「這一次成了」「這個編號早就成了」「沒成」三種（`bought`／`already`），早就成了的照成了的樣子講（綠的），不要回成被拒的紅字。網頁手上留著的舊編號，在之後抓到的資料變了（指紋：餘額、手上的數量、到期日）時丟掉，不然確認框照新資料算「再買一件」、送出去的卻是舊的那一筆；還留著舊編號時確認框寫明「上一筆再送一次」。實機重現：在頁面裡把 `window.fetch` 包一層，等真的回應回來之後丟 `TypeError`（伺服器做了、頁面沒收到）。
- **表單那一行（`.form-msg`）沒帶 `ok` 就是紅字**（`var(--bad)`、600 粗）：做成了的結果要帶 `ok`（`formMsg(form, text, true)`，或自己畫時加 class），不然管理者分不出成了沒有（FB-492）。照狀態重畫的表單要把「這一句是成了的」記在 `S` 裡，跟那一句一起畫。
- 修練頁到輿圖那一段的 JS 不用單字母變數 `x`：`tests/test_server.py` 會把那個變數讀的欄位都當 `menxia_view` 的欄位查。

## 序章與初入江湖的藏與亮

- `shown(key)` 同時看序章（`m.prologue`，草廬裡）與初入江湖（`m.onboard`，出了草廬那四步）的 `reveal`。`m.onboard` 的 reveal 是到這一步為止寫過的鍵的聯集，**不會有 `all`**：用 `shown()` 藏的東西要等初入江湖整段走完才出現。
- 「出師後就有」的東西（例：商城的兩個入口，FB-490）只看 `pro()`（`mallShown`）；要在初入江湖的某一步才亮，就把鍵寫進那一步的 `reveal`（`REVEAL_KEYS` 要收那個鍵，`content.validate` 擋拼錯的）。
- 測試照正式內容的每一步算一次（`server.main_view` 看 `prologue`／`onboard`），不要只拿手寫的 `reveal: ["all"]` 測：教學步驟改了也抓得到。

## 深色模式與動態

- 顏色一律用 `style.css` `:root` 的變數（`--paper`、`--card`、`--card-2`、`--ink`、`--ink-2`、`--line`、`--accent`、`--gold`、屬性色 `--gang`／`--rou`／`--kuai`／`--man`、`--radius`、`--serif`／`--sans`），深色那一份已經寫好；不要寫死色碼。草圖用的 `--j-*` 換成這些。
- 驗：`resize_window` 帶 `colorScheme: "dark"` 重新載入看一次。懸賞榜的告示與紙固定是淺色的紙，是刻意的。
- 動畫、爐火、震動、淡出都要照 `prefers-reduced-motion` 關掉。

## 瀏覽器窗格（`mcp__Claude_Browser__*`）的坑

- 伺服器用 PowerShell `Start-Process` 開（`python -u server.py --port <埠>`，`TIANXIA_DB` 指到暫存檔、`TIANXIA_PROFILE` 照要驗的季），記 PID，驗完 `taskkill /PID <PID> /T /F`。不要用 Bash 背景跑。
- **每個 session 用自己的 `<名字>.localhost:<埠>`**：127.0.0.1 與 localhost 的登入 cookie 跟別的 QA session 共用，會被互相登出。伺服器重開＝重新登入。
- 測試帳號用暫存腳本建（存角色走 `CharacterStore.save`、包在 `db.transaction()` 裡），密碼寫進 scratchpad 的檔，只在 localhost 用、不要在回覆裡寫出來。要特定狀態（例：簽過哪幾天、開季在幾天前）也用暫存腳本改存檔，不要在畫面上硬點。
- 窗格沒顯示或還沒畫好時，`computer` 的點擊、打字會失敗或打不進去（「not on screen」）、截圖逾時：登入欄位改用 `find` 找 ref 再 `form_input` 填；按鈕可以 `javascript_tool` 裡 `el.click()`；讀字用 `get_page_text`／`read_page`。`Viewport: 0x0` 先 `resize_window` 一次。
- `javascript_tool` 裡 `location.reload()` 會把那一段截斷、回傳值丟掉：重新載入另外一次呼叫，下一次再量。
- 截圖是兩倍像素（360 寬回 720 寬的圖），`zoom` 的座標照截圖說的座標框。
- 375 寬時 `scale` 不給（1）的截圖曾經只拍到左上那一塊（2026-10-20 商城第三批）：要存檔的截圖給 `scale: 0.95`。設定抽屜這類有淡入的，打開之後 `wait` 1 秒再拍，不然拍到半透明疊在江湖頁上。
- 窗格是好幾個子代理共用的：「Browser pane is currently hidden」時截圖逾時，隔幾秒重試就好；不要 `tabs_select` 搶別人的分頁。
- **登入不要把密碼讀進對話**：auto mode 會擋讀 `local/*_password.txt`（Credential Materialization）。打 API 的腳本自己讀那個檔；瀏覽器要登入就在 `javascript_tool` 裡用 `crypto.getRandomValues` 產一組只活在瀏覽器裡的密碼，`/api/register` → `/api/character {name, gender}` → `/api/do/skip_tutorial`（略過序章，底部分頁、商城入口跟出師一樣全亮）。
- 量完把 viewport 設回 `desktop`、配色設回 `light`。
