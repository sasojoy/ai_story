## 網頁測試（`tests/kit/webharness.py`）

- 沒有前端框架：測試把 app.js 的函式切出來交給 node 跑，看吐出來的 HTML。沒有 node 就略過：`pytestmark = pytest.mark.skipif(webharness.NODE is None, …)`。
- DRIVER 是一段 JS 字串，拿得到這幾個：
  - `fn("名字")`：抓 `\n  function 名字(` 到下一個 `\n  }\n`；一行寫完的 function 只抓那一行。
  - `konst("名字")`：**只抓一行寫完的** `const 名字 = …;`。多行的箭頭函式、多行的物件抓不到，會丟「app.js 裡找不到 const X」——要被切的 helper 一律寫成 `function`。本來就是多行的常數（例：見聞的籤 `NEWS`）在 DRIVER 裡照原文切：`src.match(/\n  const NEWS = \[[\s\S]*?\n  \];/)[0]`（`tests/web/test_conquest_web.py`）。
  - `wholeApp([...])`：整支 app.js 放進假瀏覽器，交出要測的名字（店面測試走這條，`test_shop2_web.DRIVER`、`test_dadian_shop._shop_run`），新加的函式自動在。
  - `busyKit()`：切 `busy` 一律用它，不單切 busy。`finish(值)` 印結果。
- **新 helper 被既有函式呼叫時，每一個切了那個函式的 DRIVER 都要補上它**（例：`checkinPeek` 進了 `peekParts`，`tests/test_peek_row.py` 的清單也要加，不然那一檔幾十條一起 ReferenceError）。改前先 grep 函式名在 tests 裡被誰切。
- 餵的資料：大部分手寫 `m`（`/api/main` 那一份的形狀）最清楚；另外至少一條用真的 `game.status_data()`／`server.main_view(game)`，伺服器那邊改了形狀才抓得到。
- 兩條只讀原文的守門測試，改網頁的批常常不小心弄紅（商城第二批就是，QA 只跑點名的檔沒看到，`test_for` 才抓到）：
  - `style.css` **第一個** `@media (min-width: 641px)` 以前都算手機那一半（`test_bounty_tags.py` 照它切）：新的電腦寬規則放在「電腦上的店面」那一段（FB-225）後面，不要在檔案前半另開一個 641px 的 media。
  - app.js 裡寫死的 `data-glow="…"` 都要在 `models.GLOW_KEYS`（多半是加進 `REVEAL_KEYS`）登記（`test_content.py::test_every_glow_key_the_page_draws_is_one_the_content_may_name`）。
- CSS 沒辦法在 node 裡排版：測試讀 `style.css` 的字、斷言那一條規則（前例 `test_dadian_shop.py` 的 FB-411、`test_checkin_web.py` 的 FB-437），真正的幾何到瀏覽器裡量（下一節）。
- 跑：`scripts/test_for.py --base origin/feature/<名字>`，或直接給改到的測試檔；`TIANXIA_DB` 設到 repo 外、`PYTHONIOENCODING=utf-8`。
- **`wholeApp` 的 app.js 跑在 node 的 `vm` context 裡**（2026-10-21 FB-648）：裡面每一次讀全域（`Math`、`Infinity`、`Object`）都要穿過那一層，熱迴圈慢五十倍上下（區圖名字框一次擺法在 vm 裡 40～200ms，瀏覽器裡快得多）。會被大量呼叫的小函式（`regionLabels` 的 `inter`）不要碰 `Math`，用 `a < b ? a : b`；量時間別拿 vm 的數字當瀏覽器的。
  在 DRIVER 裡掛除錯資料用 `S.__xxx`（腳本用 `H.S.__xxx` 讀）：`globalThis` 在 vm 裡跟腳本那一邊不是同一個。
  `webharness.run(DRIVER, {..., "app": 別的 app.js 路徑})` 可以拿改過的一份跑（變體、修前那一版）；那一份沒有 `NAMES` 裡的名字時 `wholeApp` 整支 ReferenceError，DRIVER 先 `.replace(', "那個名字"', '')`。
- **擺字的東西，讓框的大小不看會變的局面**（FB-648 第二段乙，2026-10-22）：局面只改框裡畫什麼（進度條收在框裡、冷卻不寫字），擺法就只看幾何，局面一變名字不跳；

- **「擠不下」這種綜合判斷抽成純函式、一個條件一個合成的例子測**（`regionCrowded`、`test_fb648_what_counts_as_crowded`）：真實內容裡壓到的局面幾乎都連帶壓到小圖，
  拿掉「名字框兩兩相交」「鄰區出口」那幾條，整套掃描照樣綠（變異檢查抓不到）。判斷照真的幾何：第二輪當牆用的近似形狀（`R_RING` 五塊）拿來判「壓到了沒」會在 1、2px² 誤判，把擺得好好的縮掉。

- **擺字（名字框、大區名）的避讓不能只量開季那一刻**（FB-648）：框會跟著局面變大（翻地的進度條、冷卻那一行），你站的那一處多朱圈與旗。量的時候在 JS 裡把疊層複製一份、改 `tug`／`cool`／`here`／`journey`，一區一區、你站每一處 × 一塊一塊翻／全部翻，一支 node 跑完幾千種（scratchpad 的 `map4fix/sweep2.py`、`fullsweep.py`，三、四秒一區）；比較兩版看「改了的畫面是不是原本就壓」（`samelayout2.py`）。

## 手機寬度：375、360、320

- 375×812 是主要的：按完一個動作不用捲就看得到「剛剛」、場景與整排行動。360 是常見的 Android，320 是最窄的；`style.css` 有 `≤340px`（小標的箭頭收掉）、`≤359px`、`≥641px`（電腦上照中間 640 那一欄，FB-225）幾段。
- `resize_window` 設寬高，量用 `javascript_tool`，不要只看截圖：
  - 一排有沒有折行：每一顆 `getBoundingClientRect().top` 一樣。
  - 字有沒有被切：`el.scrollWidth > el.clientWidth`。只多出不到半 px 時兩個整數一樣大、瀏覽器照樣收「…」：程式裡要判斷（量了才加 class）就量 Range（`selectNodeContents(el)` 的 `getBoundingClientRect().right` 對 `el` 的 right；收了「…」Range 照樣是整段的寬），同 `fitBars`。
  - 不折行的小段有沒有被拆：`span.getClientRects().length === 1`。
  - 有沒有橫向捲軸：`document.documentElement.scrollWidth === innerWidth`。
  - 偽元素（朱印這類 `::after`）：`getComputedStyle(el, "::after")` 的 top／right／width 換算回矩形，再跟字的矩形比有沒有重疊。
- 放不下時先想「怎麼排」：照「＋」拆兩行（簽到第 6 天 `ckGift`，FB-436）、四顆時收內距與間距（`.peek-row:has(> .peek-chip:nth-child(4))`）、朱印移到角上；**字一個不改**、不靠縮到看不清的字級（店面字級最低 12px）。
- 量完 `resize_window` 回 `desktop`。
- **狀態列裡「量了才變」的東西放進 `fitBars`**（體力氣血兩個字 FB-198、所在那一行折不折 FB-493）：它在 render 的 `renderPage` 之前與之後各叫一次、`renderTop`、resize、字型載入完也叫。會讓狀態列變高的要在 `renderPage` 之前量好，不然第一屏（`fitFirstScreen`）照舊的高度收、行動列被推下去沒人管；`--top-h` 也要排在它後面寫。
- 狀態列名號底下那一行（`.where`：📍 地名　時刻）最長的：地名是潁川郡（陽翟）（起點、醫館）；時刻 week7／週末「第 12 週・週日 HH:MM」（約 221px），season21 只到第 3 週（約 214，375 寬元寶四位數剛好一行、五位數就折），不帶設定檔（14 天、第一季規則關著）「第 N 天 HH:MM／共 14 天」（約 232，最長）。week7 也是寫「第 N 週」（12 週），不是「第 N 天」。
- 320×700 本來就放不進行動列（閒著、師父的框在的時候，FB-493 之前也是）；第一屏只照 375×812 驗。
- **行動列格子的名字差 1 px 折行時，收字距、不改字**（FB-671，2026-10-22）：格子名字 `.act-ink b` 字距 0.5 px 是每個字後面都加（四個字 2 px），360 寬格子內寬 52.8 px、「出陣・守」54 px 就折成兩行、整排長高 21.5 px。帶「・」的名字 `inkName` 已經包成 `.nb`，所以規則寫 `.act-ink b .nb { letter-spacing: 0 }`：只動那幾個名字，其他名字（探索、練功、交友、移動、遊歷）一個像素都不變，也不必 `:has`、不改標記（`tests/web/test_jianghu_page_web.py` 鎖著 `<b><span class="nb">出陣・</span><span class="nb">守</span></b>` 的原文）。量一排格子的名字：`.nb` 的 `getBoundingClientRect().top` 去重算行數（拿 `Range.getClientRects()` 數 top 會把行內區塊與文字節點各算一個，一行也數成兩行）；格子高度是最直接的指標（一行 96.4、折行 117.9）。
- 拆成幾個行內 `<span>` 不改版面，但每一段的寬照 LayoutUnit（1/64 px）進位，整行可能挪 0.02px：手機兩倍像素逐像素一樣，電腦一倍像素那一行有十幾個反鋸齒像素不同（看不出來）。說「一個像素都不變」時照實寫。
- **展開的卡要整張捲到底部分頁列上方：不要靠 `scrollIntoView({ block: "nearest" })` 加 CSS 的 `scroll-margin-bottom`**（FB-663，2026-10-21）。卡本身整個還在視窗裡、只是落在 fixed 的分頁列底下時，`nearest` 認為「已經看得到」不捲，`scroll-margin` 不算數（卡底 797、分頁列頂 756、`scrollY` 一直 0）；卡超出視窗時才會捲、而且捲到 margin 算進去的位置。要保證離分頁列多遠就自己量：卡的 `getBoundingClientRect().bottom`、`.tabs` 的 top（含底部安全區，不要寫死 64）、`#top`（sticky 狀態列）的 bottom，再 `window.scrollBy`（`revealShift`／`revealMoveCard`）。node 測試用假 document／window 餵幾組位置，在瀏覽器裡量最終的位置。
- **瀏覽器窗格藏著時 `behavior: "smooth"` 的捲動不會動**（點了之後 `scrollY` 停在 0，可是 `behavior: "auto"` 會捲）：要量「點了之後捲到哪」用無頭 Chromium＋CDP（下面「對比圖要存成 PNG 檔」那一節；無頭的會捲）。要讓「卡底落在視窗裡、分頁列底下」可重現（版面差幾十 px 就變成不同的毛病），在頁面裡把 `#page` 的 `style.marginTop` 設成負值往上挪，再點。
- **灰格小字：五格時最多四個字、四格時六個字**（FB-670 起一類一顆的季行動列五格：探索、練功、出陣、交友、移動）。量到的格寬：375 寬 61.8 px（扣 2 px 內距與 1 px 框，字能用 56 px）、320 寬 50.8 px（45 px）；四格時 78.8／65 px。10 px 的字一個漢字 10 px，「今日 5 次」40.03 px、「名望還差 42」約 54 px（320 寬會被切）。原因比這長的，格子寫短的（`SOCIAL_NO_ONE_SUB`「沒有人」、`TALKED_OUT_SUB`「已談滿」、`FAME_GAP_SUB`「名望不夠」、`SORTIE_LONG_SUB`「未投靠」「不在爭奪」、練功的「城外才有」「這裡沒有」「頭目不在」；要看伺服器才知道的分別〔城鎮與否〕由伺服器在鈕的 `Option.note` 帶那個字，網頁照寫），整句放行動列底下那一行——伺服器那一行本來就寫了整句的（散人不能出陣、不在爭奪之列）就讓它寫；沒寫的用 `actionBar` 的 `noted` 第三項（整句）蓋過伺服器給的 `action_notes`（FB-664；伺服器那一句說的是按得下去的時候）。新加灰格原因時，測試逐一驗小字寬（漢字 1、英數與空白 0.5：`tests/web/test_jianghu_page_web.py::test_every_grey_cell_says_at_most_four_characters` 照三種季、十幾個地點與身分跑），量有沒有被切用 Range 對格子的矩形（上面的「Range」那一條）。
- **格子上的名字（13 px 粗體、字距 0.5）也會放不下**：「出陣・守」54 px、「出陣・攪局」67.5 px，五格時前者 320 寬、後者 375 寬就折兩行，瀏覽器會斷在「攪／局」中間。`inkName` 照「・」切成 `.nb` 小段，只在「・」後面換行（那一排跟著高 21 px；375×812 行動列底還在分頁列上面）。量 `<b>` 折了幾行**不能用 `getClientRects().length`**：flex 裡的 `<b>` 是區塊，永遠回 1；用高度 ÷ 行高，或 Range 的寬（折了之後 Range 寬是最長那一行）。開季時沒有攪局的地方，量的時候在頁面裡把那一格的 `<b>` 換成 `inkName("出陣・攪局")` 吐的標記（只量、不改程式）。
- **行動列多一格**：`ACT_CELLS` 加一筆（`key`、`ids`、`name`、`none`、`icon`），選單上沒有那個選項時不畫的（同調息）在 `(d.key === "rest" || …) && !o` 那一行加；序章與初入江湖照 `shown("act:<key>")`，鍵要加進 `models.REVEAL_KEYS`（教學內容沒寫它就整段序章與初入江湖都不畫，`m.onboard` 的 reveal 沒有 `all`）。底下那一行的句子放伺服器（`Game.action_notes` 加一個鍵、跟鈕同一個判斷），網頁只照它畫（FB-670 的 `Game._practice_line`）。

## 詞中間斷行：不折行的小段

中文會在任何兩個字之間斷，「九／折」「您／挑」「最／多打點到 40」就是這樣來的。做法是把字切成一段一段的 `<span class="nb">`（行內區塊、不折行），段與段之間才換行：

- `nbChunks`／`nbHtml`（FB-132）：切在「・；、，＋→」後面與「（」前面，一段超過 `NB_MAX` 16 字就不包。鐵匠鋪、馬市的長標籤用它。
- `dealHtml`（FB-297）：價錢後面的折扣原因，「稱號・N折」連同緊貼的「（」與後面的「，」「）」一起包；只包字不包括號的話，Chrome 會在括號跟小段之間斷，一行收在「（」上。
- `.btn` 是不換行的橫向 flex：鈕裡的字與小段要先**整段包在一個 span 裡**，不然每一段各成一個 flex 項目、排成一列、把鈕撐出畫面（FB-297 複驗沒過的那一次）。
- `ledgerText`（FB-411，打點帳簿）切在「，・；／：」後面、不切「→」（「情誼 0 → 5」是一件事）；`sayHtml`（FB-433，掮客那一句）切在「，。：；！？」後面，緊跟著的「」』」併進前一段，不讓收引號落單。
- 價錢與名額這種兩件事中間用「・」接（FB-410），讓它只在「・」後面斷。
- 新地方要用就挑最接近的那一個，切法不同就照同樣寫法另寫一個，不要改 `nbChunks` 本身（很多地方共用）。

## 不准寫進 `web/` 的字（FB-673）

`web/` 底下每一個檔都隨 `/static/…` 送到每個玩家的瀏覽器（連註解都是），伺服器假人的設計是「任何地方都不能透露有假人」。`app.js`、`style.css`、`index.html`、`zhuan.css` 的**註解與字串**都不准出現「假人」「機器人」「bot」（不分大小寫）；要交代「這個選項 id 不能動，因為模擬腳本認它」之類，寫「選單與模擬腳本不受影響」「每個角色都在同一份名單裡」這種中性的字，細節放 docs 或 Python 端。`tests/bots/test_server_bots.py` 掃 `web/` 全部文字檔，只放行 CSS／DOM 的 `bottom`（`getBoundingClientRect().bottom`、`padding-bottom`）與 `both`（`animation-fill-mode: both`、`clear: both`）；掃描器自己有測試證明抓得到 `isBot`、`robot`、`bother`。新加註解前想一下有沒有寫到這幾個字（QA 在練功入口那一批抓到過：`ACT_CELLS` 的註解寫了「假人、整季機器人不受影響」）。

## 店面那一層與輪詢

- 店面（鐵匠鋪、馬市、懸賞榜、打點、酒肆、擂台）是蓋在整個畫面上的 `.shop-layer`（z-index 41；武學譜那本書 42）。`shopHtml` 是共用的框（招牌、掌櫃那一句、出店），底下照 `shop.shop` 畫各店；捲的內容一律包 `.shop-col`（電腦上照中間那一欄）。
- **不是伺服器開的店、只是網頁自己的一層**（玉璽碎片第 2 批選目標那一層，2026-10-21）：照樣用 `.shop-layer` 的框（`shop-bar`／`shop-line`／`shop-body`＞`shop-col`／`shop-row`／`shop-page`），加自己的修飾 class（`.shop-seal`），開合記在 `S`（`S.sealAct`），`render()` 裡跟 `shopHtml` 同一個位置畫；`refreshPage` 最前面看資料變了沒、只換那一層的 `outerHTML`（捲到哪裡放回去）。自己寫的字級放檔尾自己一段、一律 em（同酒肆），就不必在店面那一段補電腦寬 ×1.3 的雙胞胎（`tests/core/test_desktop_type.py` 只掃店面那一段）；電腦寬那一欄的底色照 `.shop-layer.shop-tavern` 那一條補一條。開、收、送出都整個重畫時，底下的頁面記 `window.scrollY`、畫完放回去。
- class 不要撞既有的通用名：實機撞過 `.held`、`.bar`、`.week`、`.day`；新東西加前綴（`held-row`、`abil`、`ck-day`）。
- 前端每 10 秒打 `/api/main`：分頁在背景不打、上一次沒回來不打、**內容沒變不重畫**。手指按在畫面上時不重畫，放開才補（不然按下去那一顆被換掉、click 落空）。
- 店開著時輪詢只重畫店面那一層（`refreshPage` 最前面問 `shopPolled`）：捲到哪裡放回去、換頁才回頂上、**不淡入**（淡入每 10 秒重播一次、底下跟著閃）。店開了、收了、換了一間（比 `main.shop.shop`）才從頭來。
- 江湖頁上的小動作原地換掉那一塊（例 `peekTap` 換 `#peek` 的 outerHTML），不重畫整頁：重畫會讓「剛剛」的浮現動畫再播一次。
- 送出動作一律走 `busy()`／`doMain(op, body)`：按下去那一顆 `.sending`，伺服器那邊在 `server.MAIN_ACTIONS` 加一條；點擊在 app.js 底下那一大串 `case "…":` 裡加。
- **回應沒收到、照同一個編號再送的動作**（商城的購買，FB-491）：伺服器要分得出「這一次成了」「這個編號早就成了」「沒成」三種（`bought`／`already`），早就成了的照成了的樣子講（綠的），不要回成被拒的紅字。網頁手上留著的舊編號，在之後抓到的資料變了（指紋：餘額、手上的數量、到期日）時丟掉，不然確認框照新資料算「再買一件」、送出去的卻是舊的那一筆；還留著舊編號時確認框寫明「上一筆再送一次」。實機重現：在頁面裡把 `window.fetch` 包一層，等真的回應回來之後丟 `TypeError`（伺服器做了、頁面沒收到）。
- **表單那一行（`.form-msg`）沒帶 `ok` 就是紅字**（`var(--bad)`、600 粗）：做成了的結果要帶 `ok`（`formMsg(form, text, true)`，或自己畫時加 class），不然管理者分不出成了沒有（FB-492）。照狀態重畫的表單要把「這一句是成了的」記在 `S` 裡，跟那一句一起畫。
- 修練頁到輿圖那一段的 JS 不用單字母變數 `x`：`tests/server/test_server.py` 會把那個變數讀的欄位都當 `menxia_view` 的欄位查。

## 瀏覽器窗格（`mcp__Claude_Browser__*`）的坑

- 伺服器用 PowerShell `Start-Process` 開（`python -u server.py --port <埠>`，`TIANXIA_DB` 指到暫存檔、`TIANXIA_PROFILE` 照要驗的季），記 PID，驗完 `taskkill /PID <PID> /T /F`。不要用 Bash 背景跑。
- 實機的擺法（2026-10-20 第二輪）：伺服器從 `git archive HEAD` 解到 scratchpad 的複本開（複本的 `content/config.json` 加 `"ollama_url": "http://127.0.0.1:9"`，打不到 11434）；帳號用複本的 `scripts/set_password.py <帳號> --character <名號> --db <暫存檔> --local-dir <scratchpad>`（密碼在那個資料夾）；管理者用 `TIANXIA_ADMINS`。要「開季幾天之後」的狀態（第 7 天、季末往後排），在腳本裡 `admin_open_season(過去那一刻)`、`sync(現在)` 補算，再改 `schedule` 或帳（`store.mutate`）；伺服器開著也能這樣改，下一次請求就讀到。
- **每個 session 用自己的 `<名字>.localhost:<埠>`**：127.0.0.1 與 localhost 的登入 cookie 跟別的 QA session 共用，會被互相登出。伺服器重開＝重新登入。
- 測試帳號用暫存腳本建（存角色走 `CharacterStore.save`、包在 `db.transaction()` 裡），密碼寫進 scratchpad 的檔，只在 localhost 用、不要在回覆裡寫出來。要特定狀態（例：簽過哪幾天、開季在幾天前）也用暫存腳本改存檔，不要在畫面上硬點。
- 窗格沒顯示或還沒畫好時，`computer` 的點擊、打字會失敗或打不進去（「not on screen」）、截圖逾時：登入欄位改用 `find` 找 ref 再 `form_input` 填；按鈕可以 `javascript_tool` 裡 `el.click()`；讀字用 `get_page_text`／`read_page`。`Viewport: 0x0` 先 `resize_window` 一次。
- `javascript_tool` 裡 `location.reload()` 會把那一段截斷、回傳值丟掉：重新載入另外一次呼叫，下一次再量。
- 截圖是兩倍像素（360 寬回 720 寬的圖），`zoom` 的座標照截圖說的座標框。
- **只量一段 CSS 的幾何，不必開遊戲伺服器擺局面**（FB-576，2026-10-21）：把那一段畫面照 `app.js` 吐出來的標記手寫成一頁靜態 HTML（連 `<link rel="stylesheet" href="style.css">`），跟 `web/style.css` 的複本放進 scratchpad 的一個資料夾，`Start-Process python -m http.server <埠> --bind 127.0.0.1 --directory <資料夾>`（記 PID），`preview_start` 開 `http://<名字>.localhost:<埠>/<頁>.html`，`resize_window` 375／360／320 各量一次 `getBoundingClientRect`。改了樣式表重抄一份，頁面裡換 `link.href = 'style.css?v=' + Date.now()` 等 `onload` 再量（不必 reload）。窗格的 `file://` 分頁 `javascript_tool`、`resize_window` 都動不了（「This tab shows a local file」），一定要走 http。修前先量出 QA 報的數字（FB-576 是 −2px）再改。
- 375 寬時 `scale` 不給（1）的截圖曾經只拍到左上那一塊（2026-10-20 商城第三批）：要存檔的截圖給 `scale: 0.95`。設定抽屜這類有淡入的，打開之後 `wait` 1 秒再拍，不然拍到半透明疊在江湖頁上。
- 窗格是好幾個子代理共用的：「Browser pane is currently hidden」時截圖逾時，隔幾秒重試就好；不要 `tabs_select` 搶別人的分頁。
- **登入不要把密碼讀進對話**：auto mode 會擋讀 `local/*_password.txt`（Credential Materialization）。打 API 的腳本自己讀那個檔；瀏覽器要登入就在 `javascript_tool` 裡用 `crypto.getRandomValues` 產一組只活在瀏覽器裡的密碼，`/api/register` → `/api/character {name, gender}` → `/api/do/skip_tutorial`（略過序章，底部分頁、商城入口跟出師一樣全亮）。
- **viewport 會被清掉**：窗格寬度一變（或一輪結束），`resize_window` 設的 375×812 就沒了，截圖回 `800x600`、畫面擠成一團（2026-10-20）。截圖結果寫的大小不是你設的，就再 `resize_window` 一次重截。
- **窗格藏著時轉場停在半路**（`tabs_context` 說 hidden）：玩家卡、設定頁截出來是半透明疊在頁面上。截圖前在那個分頁用 `javascript_tool` 插一段 `*,*::before,*::after{transition:none!important;animation:none!important}` 的 style（只動那一頁的畫面，不改程式），截完重新載入就沒了。問句那一層插了之後，第一張截圖可能還沒畫，再截一次。
- **管理者的問句**（`adminAsk` 那一層）：點 `#admin-zone [data-op="…"]` 會從底下浮一層 `.ask-layer`，設定頁那一張紙同時在滑，馬上截會疊成兩層，等一秒再截；看完按「取消」（`.ask-layer button`），不要真的送出不打算做的事。
- **輿圖選一個地點**：地圖上的記號照 pointer 事件選，`dispatchEvent(click)` 選不到。改走「找地點」：`[data-act="map-search"]` → `#mbody input` 設值、送 `input` 事件 → `[data-act="map-pick"][data-id="<地點>"]`。抽屜拉高按 `#mgrab`，會捲的是 `#mbody`。
- 量完把 viewport 設回 `desktop`、配色設回 `light`。

## 對比圖要存成 PNG 檔（領地爭奪第一批，2026-10-20）

瀏覽器窗格的截圖只回給你看、存不成檔。要放進 `…-草圖/` 的真實截圖這樣拍（不碰共用的窗格）：
