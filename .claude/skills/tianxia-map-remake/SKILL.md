# 輿圖簡化與天下重製：開發手冊

**設計稿**：`docs/superpowers/specs/2026-10-20-輿圖簡化-design.md`（先整份讀完，第一章是企劃者的原話、第七章是設計 session 替他定的、第八章是還沒定的）。草圖與產生器在 `docs/superpowers/specs/2026-10-20-輿圖簡化-草圖/`（README 寫每一張是哪一輪、企劃者挑了什麼）。

## 不准再談的（企劃者定了）

- 輿圖只有**兩張不自由縮放的圖**：天下圖（形勢、前線、寶、你）、區圖（一州的地點）。不加濾鏡那一排、不加小牌子、不加 ⚔、不加圖例框、不加捏合縮放。「塗層」只有一顆、只在區圖。
- 天下三圈：外圈出生州（官軍西、黃巾東，沿外環直接相連）、內圈中原四郡（開季中立、高級資源）、核心藏玉璽。**畫出來不是正圓**——不規則州郡與山水。
- 區圖的記號：墨筆小圖、印章框（框色＝誰的）、朱印「寶」、名字底下的悟字、朱圈與旗、「→ 鄰州」；底是現在的設色山水、線收掉。
- 出生點用選的（細節等 PM）。
- **投靠點只在外圈**（官軍洛陽、南陽；黃巾冀州、青州）；長社、黃巾別部營寨改成中原的高級資源地，盧植營、南陽黃巾營搬進中原當前哨舊址（設計稿 3.1）。
- **玉璽碎片**：所有開季中立的區塊都可能、核心機率最高；「璽」印是「最可能」不是「只在這裡」（設計稿 3.1）。
- **地圖跟著劇本、程式不寫死陣營**（企劃者更正：「所有季共用一張輿圖。錯的，不共用～只有設計的理念是通用的」）：通用的是畫法（三圈、兩層、一張卡、塗層）；地點、州、連線、每一州屬哪一圈、誰的出生州、幾方陣營、每一方的顏色都從劇本讀（`scenario.json`／`map.json`／`locations.json`）。程式裡不准出現寫死的「兩方」「西半邊官軍／東半邊黃巾」「藍黃灰」：天下圖的地面一方一色、任兩方相接就是前線，區圖的印章框同一套——之後的劇本可能三～四方，外圈切成三、四塊出生州也要畫得出來（設計稿 3.6、驗收那一條）。這一季的內容照兩方版本做。
- **同一個劇本裡規則開關不同的季也用新畫法**（領地爭奪關著、地盤關著、14 天只有黃巾聲勢）：照設計稿 4.6 畫，不留舊輿圖給這些季。這不是「所有季共用一張地圖」。

這些要改，先停下來回報 PM，不要自己折衷。

## 分批與檔案

照設計稿第十章。一批一個工作樹、從派工指定的分支開（多半是 `origin/dev/conquest-1` 或它合進去之後的功能分支；開工前 `git fetch origin +refs/heads/<分支>:refs/remotes/origin/<分支>`，這份 clone 的 `git fetch origin` 不會更新 `origin/dev/*`）。

1. **內容：新天下**（純內容）——`content/locations.json`（地點、座標、連線、標籤、`region`）、`content/scenario.json` 的 `regions`、`territory.blocks`（外圈 `guan`／`huang`、內圈與核心 `neutral`）、`territory.lines` 先照 PM 定的線改；新地點（青州、東郡、陳留、鹿台）先放佔位名與最少的敵人、素材、意境（`content.validate` 要過：每種素材拿得到、連通、名字過濾）；序章與出生點**先不動**。驗收：`tests/test_real_content.py`（含 slow）過、每個中立區塊官軍與黃巾各有一條路從自家領地走得到（寫一條測試守住）。名單先排一版列給 PM 對（設計稿 3.3）。
2. **輿圖：天下圖**——`tianxia/mapdata.py`（天下圖要的資料：每州的地點歸屬、寶、你）、`tianxia/mapview.py`／`mapart.py`（州郡輪廓照新座標、山水淡襯）、`web/app.js` 的輿圖段（`pageMap`、`marksParts`、`mapCtl`、抽屜）、`web/style.css`。地面分法「離哪個地點最近」，正式畫法自己定（Voronoi 或暈色），紅線＝官巾相接。版圖變化（`timelineHtml`）搬到天下圖上播。
3. **輿圖：區圖與卡**——固定取景、記號照設計稿 4.2、抽屜那張卡照 4.3、塗層濾鏡、拿掉 4.4 那一表的東西（`MAP_CHIPS`、`insightButton`、`mapBadges`、⚔、前線鋸齒、`NEUTRAL_INK` 虛線、看大局 `MAP_FAR`、`hudHtml`）。`tests/test_conquest_mapview.py` 的中立地虛線那幾條改掉；新寫網頁測試（webharness）：375 寬每個地名框不互相壓到、卡上找得到軍令／懸賞／勝算／路程／劇情、塗層開關只差那一層。
4. **出生點與序章**——等 PM 派，不要先做。
5. **領地爭奪接縫**——大勢值的線（PM 定）、攻城公告與投票在新輿圖上的位置（Task 13 的對比圖以設計稿第六章為底重出）。

每一批開工先核對設計稿對不對得上現行程式（計畫可能是照舊版寫的），差異寫進自己的計畫；前提不在了就停下來回報。

## 拍圖給企劃者看

畫面的決定一律 2～3 張**真實畫面**對比圖給企劃者挑（企劃者 10/15 的規矩）：做法在 `.claude/skills/tianxia-dev/網頁.md`「對比圖要存成 PNG 檔」那一節（無頭 Chromium＋DevTools Protocol、375×812 兩倍像素、登入在頁面裡 fetch）。草圖資料夾的 `shot.js`（登入版）、`shot2.js`（靜態頁）可以直接拿來用；並排圖用 PIL（字型 `C:\Windows\Fonts\msjh.ttc`）。預覽伺服器照 PM 給的埠與 `<名字>.localhost`，`TIANXIA_DB` 指 scratchpad 的暫存檔、`ollama_url` 指沒人聽的埠；領地爭奪的開關只在預覽行程裡打開（`serve.py` 的做法）。

## 回報

照 `tianxia-dev` 的格式回報 PM：做了什麼、跑了哪些測試（貼結果）、對比圖在哪、哪些是自己定的、哪些要 PM 或企劃者決定。拿掉的東西（4.4）一樣一樣寫明「資訊搬去哪裡」，不要只寫「拿掉」。
