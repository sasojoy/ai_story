## 模組

**門面與程式**
- `tianxia/`：純 Python 規則引擎，**不得 import 任何網頁框架**（fastapi 等）。`engine.Game` 是唯一對外門面。**例外**（PM 2026-10-31）：功能包的 `tianxia/features/<包>/routes.py` 可以 import fastapi，只在殼掛路由時延後 import（包的 `__init__.py` 在 `routes()`、`admin_tools()` 裡面才 `from . import routes`）；引擎、`run_bots.py`、假人不碰。守門：`tests/core/test_feature_boundaries.py` 的 `test_only_package_routes_import_a_web_framework_and_only_when_the_shell_mounts_them`（照原始碼：`tianxia/` 底下只有包的 `routes.py` import fastapi／starlette／uvicorn、沒有模組在載入時就 import `routes`，幾毫秒）與 `test_the_engine_the_bot_program_and_the_bots_load_no_web_framework`（slow，約 3 秒：乾淨的子行程 import `tianxia.engine`、`tianxia.bot`、`bot_policy`、`bot_runner`、`run_bots` 之後 `sys.modules` 裡沒有這三個）。
- `content/`：所有遊戲內容（JSON），載入時由 `tianxia/content.py::validate` 交叉檢查（id、連通、素材拿不拿得到、退路字表組出的每個名字都過得了命名過濾、獎勵不能給或扣博聞、隨口應對的獎勵不能高過檢定選項……）。`content/gear.json` 是寶物表、名駒、名將贈禮（裝備三；沒有這個檔就沒有寶物的來源）。`content/profiles/<名字>.json` 是設定覆寫檔，由環境變數 `TIANXIA_PROFILE` 選（`weekend`：第一季規則開、季長 2.5 天、人數上限 20〔Joy 2026-10-14 為二十人試玩從 2 調上來〕、30 級以後的加陡 `late_exp_step` 0.12），只能寫 `Config` 有的欄位。`season21`（正式季第 1 批）：21 天的季（`season21`、第一季規則開、`season_weeks` 3、`season_days` 21、人數上限 20、豪強分屬兩軍），見「第一季濃縮版」的「21 天季」；只有寫了 `season21` 的設定檔可以改 `season_weeks`（`tests/core/test_content.py` 守門：`season21` 的章加季長釘住它）。
- `server.py`：網頁伺服器（FastAPI），只負責登入、行動鎖、鎖外的模型呼叫與把畫面要的東西整理成 JSON；引擎的 Markdown 在這裡轉成 HTML（原始 HTML 一律跳脫）。鎖內模型呼叫的全服斷路器也在這裡（見「模型呼叫」）。
- `web/`：手機優先的單頁網頁（`index.html`／`style.css`／`app.js`，沒有建置步驟、不靠外部函式庫，見「介面」）。
- `run_bots.py`：伺服器假人程式的入口，每隔 `bot_tick_seconds` 呼叫一次 `BotRunner.tick()`，跟 `server.py` 同時開著、開同一個資料庫與同一份設定。
**存檔與全服狀態**
- `tianxia/database.py`：SQLite（預設 `saves/tianxia.db`，環境變數 `TIANXIA_DB` 可改；線上版與開發版各用各的）：連線、資料表、交易。一個動作＝一筆交易（`BEGIN IMMEDIATE`，出錯整個撤回），同一個執行緒可以巢狀（交易可以巢狀；`WorldStateStore.mutate` 不行，內層寫的會被外層蓋掉，直接丟 `RuntimeError`）。結構版本記在 `PRAGMA user_version`（目前第 8 版：第 4 版加 `gear_recipes`，全服兵器配方；第 5 版加 `biographies`，玩家傳；第 6 版加 `mall_purchases`、`mall_ledger`、`mall_entitlements`，商城，見 [商城](商城.md)；第 7 版加 `action_counts`、`action_firsts`，真人量表，見下面 `playlog`；第 8 版拿掉從來沒人讀寫的見聞紀錄 `rumor_heard`〔審查 S-12〕）；改結構時新增一組句子、接進 `SCHEMA`、`MIGRATIONS[舊版]` 指向它、`SCHEMA_VERSION` 加一，舊檔打開時在同一筆交易裡一版一版就地升級（中途出錯整個撤回、檔還是舊版；沒有遷移路徑就丟 `RuntimeError`）。**改結構前先跟 PM 對版本號。**
- `tianxia/world_state.py`：全服狀態的資料模型與存取介面 `WorldStateStore`（Protocol）；實作是 `tianxia/sqlite_world.py::SqliteWorldStore`（`open_world()`）。小的整份覆寫，會長大的（傳聞、江湖史、全服登記的武學、配方、兵器配方、改過的名字、合併出來的意境、第一個練成絕學的人、投靠名冊、決戰回合）一筆一筆加、照季分；換季不刪資料，江湖史跨季保留——**例外是傳聞與決戰回合紀錄**（審查 S-12，企劃者 Joy「上上季的資料存在另一個封存區備用」）：`next_season` 換到第 N 季時，第 N−2 季與更早的 `rumors`、`battle_rounds` 搬進資料庫旁邊的 `<檔名>-archive.sqlite`（`tianxia/log_archive.py`：主檔的寫入交易裡讀出 → 另一條連線寫進封存檔、COMMIT → 主檔一個 savepoint 刪掉；封存檔寫不進去、刪不掉都只是這一次不搬，換季照常，下一次換季再搬；同一個流水號 INSERT OR REPLACE，重搬不重複），搬了就照易名帖那樣作廢傳聞快取（`_forget_logs`）。封存檔遊戲裡沒有畫面讀它；決戰本身（`battles`）、江湖史、戰記（`-tale.sqlite`）不搬。武學、改過的名字、意境、兵器配方共用一個名字空間（`sqlite_world._name_taken`）；登記都是鎖內原子（`claim_recipe`、`claim_insight_recipe`、`claim_weapon_recipe`、`link_recipe`、`link_insight_recipe`、`rename_skill`、`claim_master`，隱藏配方的首位發現者與神器原品主人 `claim_gear_find`、神器定名 `name_divine`、仿品數 `add_copy`）；`fused_arts`／`merged_insights` 是合到舊的找候選用的；`divine_records` 讀神器譜（`gear_recipes` 裡「鑄|」開頭的列，跨季）；名將本命兵器的歸屬（`WorldState.signature_arms`：人物 id → `SignatureClaim`〔拿的人、送或奪〕，小的整份覆寫，隨季存進 `seasons` 表）由 `signature_records()` 跨季讀（唯讀快照，一次 `json_extract`，沒有新資料表、結構版本不動），給神器譜的本命兵器那幾行（`signature_arms.book_rows`）；玉璽碎片的全服登記 `SharedWorldState.seal`（正本，跨季、不分季）與還沒收場的奪璽單挑 `seal_duels`（全服、不在季裡，寫一律 `world.mutate`、只加傳聞與江湖史，`_save_season` 蓋不到），唯讀的 `seal_state()`、`seal_duel_open()`。**存進資料庫的模型要讓上一版程式讀得進來**（FB-695，退回舊程式用）：這些模型沒設 `extra`，pydantic 預設略過不認得的欄位，所以加欄位沒事；可是往舊程式也有的 `Literal` 加一個值（例：碎片登記 `SealEvent.kind` 加 `use`），新程式一寫進去，舊程式讀到整列就 `ValidationError`、伺服器與假人程式都起不來。新的種類另開一欄（`SealRegistry.uses`），空的時候用模型自己的 `model_serializer(mode="wrap")` 把那個鍵拿掉、不寫進 JSON（`SealRegistry._drop_empty_uses`、`BattleInstance._drop_empty_front_note`；關著、沒用過的存檔一個位元組都不變）——**不用 `Field(exclude_if=…)`**：那是 Pydantic 2.11 才有的，`requirements.txt` 寫 `pydantic>=2.6`，舊版當多餘的參數略過、空的照樣寫出來，讀檔時用 before 驗證器把舊資料搬過去。
- `tianxia/characters.py`：角色存檔（`CharacterStore`、`open_characters()`），一個角色一列，**不含賽季**（`GameState.world` 只在記憶體）；名號比對不分大小寫。`PlayerState.seen_real`（自己上線的現實秒）只在那個人自己的請求裡寫（伺服器的 `act`／`act_look` 叫 `Game.mark_seen`、假人程式自己那一輪），`Game.sync` 不寫——管理者的 `_admin_target`、`_kin`、`_load_kin` 都碰不到；奪璽單挑的 `last_seen` 也只有 `own_request` 的 Game 記，假人永遠不在場。
- `tianxia/accounts.py`：帳號與密碼（`accounts`、`logins` 表），見「原則」的登入那條。
- `tianxia/playlog.py`：真人量表（減法季批 0，設計稿第十章；資料庫第 7 版）：每個帳號（`characters.name_key`）每一天（回體丹換日的那一天）上線了沒、按了哪幾顆（`action_counts.buttons`，`button_of` 歸類：`act:`、`explore:` 留兩段，其他留第一段），第一次寫隨口應對（`/api/answer`）、第一次跟人物說話（交友、求見、對話選項、自己說）、第一次看輿圖的「全區」（`whole_area`，表先留好，輿圖四層那一批接上）是哪一天（`action_firsts`，一季只記第一次）。表名照整合設計 11.4 的 `action_counts`。**只有伺服器記**：`server.act`／`act_look` 進鎖同步之後記上線（`_play_seen`），`/api/choose`（被擋下來、不在選單上的不算）、`/api/travel`、`/api/answer`、`/api/say` 做成之後另開一筆小交易記一次（`_play_did`）；假人不記。**不露給玩家**（沒有 API、不進 `main_view`）；主機端 `scripts/play_metrics.py`（唯讀）印一季的總數：第 3、7 天留存（判準【預設】五成、四成）、第幾天不再上線、每顆鈕的佔比、三種第一次的中位數、第 2 天以前寫過隨口應對的幾成（判準五成）；設計寫的「管理者頁一張表」還沒做（批 0 先給主機端腳本）；**只印總數不印名號**（表上只有真人，列名號等於從缺席看出誰是假人）。
- **手機通知**（減法季批 9，整合設計第十章「回來的理由」）：`tianxia/notices.py` 純函式認五種事（來信、約戰〔`DUEL_SOURCES` 留給批 3b 登記〕、決戰集結、被截殺〔江湖紀錄「遭某某截殺」〕、被〈天下形勢〉最新一篇提到），每一件一個穩定的 key；`server_push.py` 下半段是 Web Push（RFC 8291 加密、RFC 8292 VAPID 簽名，只用 `cryptography`；對過 RFC 8291 附錄 A 的範例）與訂閱的小檔 `PushStore`（資料庫旁邊的 `<db>-push.sqlite`，認帳號不認名號，不進資料庫結構）；`server.notice_round` 是看守的一輪（`Config.web_push`：`watch_seconds` 30、`quiet_seconds` 120 之內同步過不跳、一人一輪最多 `per_round` 3 則），跳過的 key 記在記憶體 `NOTICE_SENT`（重開後第一輪只記下）。**09:00 來信**：`letters.mail_day`（減法季子開關 `morning_mail`、`mail_hour` 9，時區同回體丹）取代遊戲日當「一天一封」的日子；開了通知的人由看守在 9 點替他送（`Game.morning_mail`：只做同步裡書信那一格，不補算體力、不算上線）。網頁：設定頁「手機通知」、第一次來信時在信的小卡底下問一次（`pushAskHtml`，問過記在 localStorage `tianxia-push-asked`），`web/sw.js`（`/sw.js`）跳通知、`web/manifest.webmanifest`（iPhone 加到主畫面才收得到）。**加入主畫面的圖示**（Joy 2026-10-26）：iPhone 不吃 manifest 的 SVG，`index.html` 有 `apple-touch-icon`（`web/icon-180.png`，滿版、iOS 自己切圓角）與 `apple-mobile-web-app-title`；manifest 的 icons 是 `icon-192.png`、`icon-512.png`（跟 `icon.svg` 同一個圓角）與 `icon-512-maskable.png`（滿版、字在中間 80% 的安全圈）；四張都由 `scripts/make_icons.py` 從 icon.svg 的樣子出（Noto Serif CJK TC Bold，字型檔不進版控），改圖就改那支再出一次。**「怎麼收到手機通知」**（Joy 2026-10-26：一顆鈕點開獨立的一步步說明，不跟玩法說明混）：設定頁手機通知開關底下 `push-how`，`S.pushHow` 時設定抽屜整頁換成 `pushHowHtml`（`web/app.js`）：頂上一句照此刻的狀況（還在 iPhone 瀏覽器裡、已從主畫面開、被擋了、已開），照 `pushDevice()` 把 iPhone／Android／電腦那一段攤開、其他收摺疊，開得了時給「現在就開通知」（同 `push-yes`）；`tests/web/test_push_how_web.py`。主機端怎麼驗見 `beta-主機端操作.md` 的「手機通知」。
**規則核心**
- `tianxia/models.py`：內容的資料模型（`Config` 的每個數字與它的理由都寫在欄位註解裡）。`tianxia/state.py`：執行期狀態（玩家、門下、世界）；裝備是 `Equipment`（四欄，`slot`），舊名 `Weapon` 是別名；`Journey.pace` 是出發那一刻的步調（坐騎）；寶物欄 `PlayerState.treasure`、寄放 `held_gear`，全服的名將贈禮名單、名將本命兵器的歸屬與這一季的天機在 `WorldState.general_gifts`／`signature_arms`／`tianji`；本命兵器用 `Equipment.signature`（人物 id）標記，這一季打贏名將本人的次數記在 `PlayerState.figure_wins`。
- **減法季的開關**（減法季批 0，企劃者 2026-10-24；設計稿第十章）：`Config.jianfa`（`JianfaRules.enabled`，暫名）加開季時蓋的章 `WorldState.jianfa_on`（`world_state.stamp_season`），讀的時候一律走 `rules.jianfa(content, world)`（設定開著＋這一季有章；主機關掉時一律關）。`content/profiles/season21.json`、`week7.json` 打開，週末設定與不帶設定都關著（關著一個字都不變）；正在跑的季照它開季時的章。減法季的**規則**改動全掛它（兩邊共用這個欄位名），**畫面**的改動不掛。子開關照整合設計第十二章（`explore_one`、`drill_gates`、`sortie_duel`、`four_wins`、`free_text_outcomes`、`marks_visible`、`stances`、`errands`、`week_unlock`、`rewrite_narration`，預設全開）：各批問 `rules.jianfa(content, world, "<子開關>")`，主機可以單獨關掉一批。各批的數字之後加在 `JianfaRules`。
- **出陣約戰的存檔**（減法季批 3b）：約戰本身在 `SharedWorldState.sorties`（world 那一列的 JSON，空的時候不寫鍵；`sqlite_world.sortie_duels()` 只讀那一格；換季清掉、暫停繼續時窗往後挪）。`PlayerState.answer_day`、`answers_today`、`sortie_cooldown_until`、`answer_cooldown_until`、`duty_day`、`duties_today` 都在 `state.QUIET_DEFAULTS`。戰報是 `kind="sortie"`＋`label="約戰"`（不往 `BattleRecord.kind` 的 Literal 加值：舊程式讀不進新存檔，FB-695）。推送指紋還沒算 `sorties`（`server_push` 是雲端側的檔，`tests/server/test_server.py` 列在 `NOT_IN_THE_FINGERPRINT`、理由寫著交雲端）。資料庫結構不動（第 7 版）。
- **三陣營四勝利的存檔**（減法季批 3c）：`PlayerState.ledgers`、`lean_changed`、`season_title`、`step_day`、`step_skip` 都在 `state.QUIET_DEFAULTS`（空的、0 的時候不寫進存檔，`_drop_quiet_defaults`）；`WorldState.final_tiers`（名號 → `TierResult`）空的時候不寫（併進 `_drop_empty_marks_fired`；`tests/server/test_server.py` 的推送指紋表列在 `NOT_IN_THE_FINGERPRINT`）。季末論功與 `tier_hint` 讀 `CharacterStore.books(season)`（SQL 只挑名號、陣營、ally、contrib、ledgers，不讀整份存檔）；換季讀上一季那一列走 `WorldStateStore.past_season(number)`（不含傳聞與江湖史）。資料庫結構不動（第 7 版）。
- `tianxia/rules.py`：條件、效果（`apply_effect`）、事件檢定（`check_outlook`）、大勢推動（`change_trend`）、第一季的亂局與割據（`chaos_fronts`、`geju_per_day`、`chaos_note`）、戰況變化換成一句話（`front_chip`、`humanize`）、求見門檻（`audience_bar`、`can_meet`）。
