## 模組

**散人、懸賞與截殺**（每季都有，只看劇本有沒有陣營；`docs/superpowers/specs/2026-10-10-懸賞榜每季都有-design.md`）
- `tianxia/ranger.py`：遊俠名號（散人的成長階梯）：`active`＝散人＋劇本有陣營（不看第一季開關）；記帳（`note_gain`、`add_deeds`）、階與名號、各階的好處（求見、經驗、招募、懸賞加成）、狀態列與人物卡的資料（`status`）。
- `tianxia/bounties.py`：懸賞榜：開關（`active`＝`Config.bounties.enabled`＋劇本有陣營＋這一季還沒收）；週初自動掛單（`issue`：第一季掛在 `WEEK_HOOKS`，規則關著的季由 `tick` 掛；兩道擋——只掛這一週、`WorldState.bounty_week` 掛過了不再掛；期限錨在 `calendar.week_start(週次＋auto_weeks)`；同一地點不重複、只挑已開放的地點〔`_opened`〕）、看得到的（`visible`：懸賞榜的張數與第二層都照它）、期限與名額的寫法（`due_text`〔到季末寫「到季末」〕、`due_line`；店面告示上短的 `due_short`〔第一季寫最後還有效的那一週：週一 00:00 到期寫「到第 N−1 週・剩 N」，不在週一 00:00 到期寫「期限 第 N 週・剩 N」；7 天濃縮季（`week7_on`）每一張都寫第幾天——00:00 到期「到第 N−1 天・剩 N」、其餘「期限 第 N 天・剩 N」，追剿、復仇、系統與玩家掛的通緝這幾種沒有 `b.day` 的也一樣，不看 `b.day`（FB-506）；規則關著「期限 第N天・剩 N」；到季末「到季末・剩 N」；FB-196〕；`to_season_end`〔期限寫「到季末」的：到期在名義季末 `calendar.nominal_end` 或之後——照現實天的季（21 天、7 天）是扣了開季偏移的季曆終點，其他季是季長 × DAY；管理者往後排的季末不算（FB-500）〕、`past_due`〔所有看期限的地方問這一個：季收了一律算過，寫「到季末」的撐到季真的收了；休季沒有榜，`active` 在季收了之後是假〕）、誰接得了（`can_take`；換陣營之後還接不接得了是 `stranded`，投靠、叛投那一下拿掉名字的是 `drop_stranded`）、揭下與放棄、四種交差的掛鉤（`on_win`／`on_explore`／`on_arrive`／`on_raid_win`）、被搶先、過期、換陣營或季收了補一句（`deliver_lapses`）、通緝與押金退回（`post`、`post_problem`〔目標還在新手期不能通緝〕、`deliver_refunds`）；截殺關著（`Config.raid.enabled`）時通緝不算（`open_bounties` 濾掉）。玩家卡的「通緝」鈕在 `tianxia/wanted.py`（截殺關著不畫；輸入框下限 `CardButton.amount_min`＝`post_min`）。求藝與求兵（`GIVE_KINDS`；劇本的每個陣營每週初各掛一張，不用揭、在懸賞榜上直接交）：合不合用（`fit_problem`〔只看東西〕、`fitting`〔合用的、最不值錢的先〕、`give_problem`〔再加懸賞榜看得到、還在榜上〕）、交出與獎勵（`give`，求藝的擲骰 `gift_rolls`）、懸賞榜第三層（`hand_in_options`；第二層的字 `pick_label`、`stuck_label`）、整季機器人與假人共用的挑法（`give_choice`）；懸賞卡（`status(state, content, world)`）在手上揭了的後面多列交得出的求藝求兵（`have`）。收起懸賞榜一律走 `close_board`；`has_prize` 是「還掛著重賞」的唯一判法（`reward_text` 與店面告示共用）。
- `tianxia/raid.py`：截殺掛上玩家卡；規則在 `Game.raid_shown`／`raid_refusal`／`raid_targets`／`raid`／`_raid_spoils`（`Config.raid.enabled` 是主機的緊急開關；新手期照 `roster.raid_newbie` 從各自加入的那一刻算；打贏的貢獻只在第一季記）。

## 第一季濃縮版（`rules.season_one` 開著時才有）

- **切磋**（玩家互動第二層，企劃者 2026-10-08；`tianxia/spar.py` 登記進玩家卡 `social.ACTIONS`，規則在 `Game.spar_invite`／`answer_invite`／`_spar`）：同一地點的人發邀請（`WorldState.invites`，`tianxia/invites.py`，`invite_ttl_seconds` 600 秒逾時），對方答應才打；收到的邀請也進閒著的選單（`invite:yes|no|cancel:<id>`，假人照它答，`bot_policy._answer_invite`）。本人對本人單次判定（不帶同伴部下，從發邀請的一方算、另一方照鏡像），休季（這一季收了）卡上不畫切磋、論武（FB-169，同截殺 FB-163）。不扣氣血、不掉銀兩，雙方各花一次遊歷的體力、各一份戰報（`kind="spar"`），經驗與心得照 `Config.spar`，同一對人每個遊戲日最多 `per_pair_day` 場（`WorldState.spar_tally`；滿了那一句寫換日的那一刻、不寫「今天」，切磋、贈物、論武三本帳同一個寫法 `social.pair_full`，FB-117）。答應了卻打不成（他忙、體力不夠、走了），邀請作廢、發邀請的人江湖紀錄補一句（`Game._tell_sender`，結伴、論武也是）；答應的一方那一則紀錄照樣寫結果那一句（`Draft.keep`）；兩邊各寫各自拿到的經驗與心得、各連自己的戰報，不寫「（每人）」（FB-244）。動到別人時 `Game.touched` 記名號，`server._tell_tabs` 一起叫醒他們的分頁。
- **玩家之間的互動**（企劃者 2026-10-08；`tianxia/social.py`）：場景底下「此地還有」列 `presence_seconds`（600）現實秒內同步過、不在路上也不在序章的人（真人假人一樣），點名字開玩家卡；卡上的鈕是登記表 `social.ACTIONS`（打招呼、贈物、結伴同行、切磋）。**贈物**（銀兩、素材、回體丹）不必對方同意，兩邊江湖紀錄各一則。**打招呼**（抱拳、請教、挑釁、敬酒，`social.GESTURES`）與**結伴同行**走跟切磋同一套邀請（`invites.py`，kind `greet`／`travel`），收到的列在閒著的選單（`invite:<回應>:<id>`）與場景底下（`Game.calls_here`），他的玩家卡上也換成回禮、「答應結伴同行／婉拒同行」（`Game.answer_on_card`，跟場景那一顆同一則紀錄；FB-117）；打招呼只有固定的回禮、沒有自由文字。場景底下最多畫兩份（舊的在前），其餘收成「還有 N 份邀請 ▾」、點了攤開（`openCalls` 記下那時的那幾份，那幾份還在就一直攤著，FB-241）；第一屏還放不下時 FB-107 的收法多一步（6b），從最後一份往前收進那一行；決戰輪到你出招時「此地還有」與邀請那幾行挪到三招後面自己一張卡（FB-117）。玩家卡開著時跟著輪詢重抓（`refreshPeer`，變了才換、手指按著等放開、確認框與數量欄開著不換）。結伴同行答應之後記在跟著的人身上（`PlayerState.tagalong`，帶頭的人照它從資料庫查，`CharacterStore.tagging`）：帶頭的人出發、改道、喊停時跟著的人照抄那一趟（`Game._lead`，體力各付各的，跟不上就散），跟著的人路上只能「分道揚鑣」（`act:part`），路上小事的收穫兩人都有（`_share_road`），到終點就散；答應了 `party_wait_seconds` 沒動身也散。假人照人的步調回打招呼與結伴（`bot_policy.answer_call`：先等一段、有回有拒有不理），答應了結伴就在原地等。
- **論武**（玩家互動第二層；`tianxia/discuss.py` 登記進玩家卡，規則在 `Game.discuss_*`、`_discuss`）：同一地點的兩個人各出一樣（武學或全服意境，私有意境不行）合成一樣新的，兩人都拿到；走 fusion 的三種合成，對方那一樣用 `fusion.Partner` 借進來（不必是你的、不佔持有），價錢各付一半（`fusion.half_price`，進位）；血統、持有上限、「已經有了」照舊兩邊各自擋，一邊合不成整爐不開。答應的一方開爐：首創取名照三段式（`social.CardAction.request` → `Game.peer_request` A 段、`server.prepare_peer` 鎖外取名、`peer_act` 的 `params["proposed"]` C 段，網頁等的時候一句論武的等候話；A 段先問 C 段一定會擋的〔`discuss_invite_problem`、`discuss_item_problem`〕，成不了就不開單、不叫模型，直接回同一句拒絕，FB-245），發邀請的一方接著照配方合出同一門。答應要挑自己出哪一樣，所以在他的玩家卡上答：場景底下那一列是「挑一樣答應」（`social.calls` 帶 `peer`，網頁打開他的卡、捲到答應那一格，不送伺服器；選單上那一顆照舊是灰的，「此地還能做」裡同一顆也打開卡）；卡上的下拉清單每一樣先驗兩邊合不合得成（`Game.discuss_item_problem`），合不成的灰掉、寫兩三個字的原因，預設第一樣合得成的，一樣都不成或這一張邀請本身成不了（`discuss_invite_problem`）只畫一顆灰的「答應論武」寫為什麼；挑的那一樣不行時邀請留著換一樣再答，真的作廢才收掉、發邀請的人補一句（FB-117）。首創兩人共有：`creator` 是開爐的人、`co_creator` 是另一個、`creator_shown` 寫「甲、乙」（首創的傳聞、秘方那一句寫兩個人）；發邀請的那一方那一句寫「你與某某一起首創的」（`fusion.CO_FIRST`，只在對方剛在同一次論武裡首創時〔`Partner.fresh`〕；之後再合寫「是你與某某首創的」，FB-243）；對方那邊合不成照他那兩三個字寫成從你這邊看的話（`engine.THEIR_SIDE`）；首創名望回饋兩人各補（`Echo.co_paid`）。假人照同一張卡上按得下去的那幾樣挑。假人答論武走同一條路，首創取名開 `bot_policy.DiscussJob` 交給 `bot_runner`（取不到名字不答）。
