# 商城

元寶錢包、帳本、商品表、購買與發貨、月卡、封測發放、管理者工具（企劃者 2026-10-20 核准的設計 `docs/superpowers/specs/2026-10-20-商城架構-design.md`；計畫 `docs/superpowers/plans/2026-10-20-商城架構.md`，三批）。
改到這一塊的程式或內容之前先讀這一份；跟程式對不上時以程式為準。第一批（引擎、API、主機端腳本）在 `feature/shop`；第二批是畫面（企劃者 2026-10-20 從對比圖挑了入口乙＋丙、那一層子，見下面「畫面」）。

## 模組

- `tianxia/mall.py`：規則與字句。開關 `on`（`Config.mall.enabled`）、允許的效果表 `EFFECTS`（第一版只有 `pills` 回體丹 N 顆〔消耗品〕、`card_days` 月卡 N 天）、商品哪裡寫錯 `item_problems`（`content.check_mall` 叫）、上架 `on_sale`、限購 `limit_problem`、買不了的原因 `buy_problem`、購買 `buy`、發貨 `_deliver`、月卡往後接 `card_span`、封測發放 `grant_beta`、月卡加上限 `card_bonus`、畫面資料 `view`／`records`／`card_view`、管理者 `adjust`（補發、扣回）與 `refund`。日數照回體丹那一套（台灣 00:00 換日）：`date_day`（`YYYY-MM-DD` → 日數）、`day_text`（「10/25」）、`real_text`（現實時間「10/25 21:40」，購買紀錄用；不是季曆的時刻，不走 `calendar.point_text`）。不讀時鐘、不碰 `Game.rng`。
- `tianxia/wallet.py`：資料庫那一側（第 6 版的三張表）。`Wallet(db)`：`balance`、`ledger`、`post`（編號重複回 False、扣到負的丟 `ValueError`，都什麼都不寫）、`add_purchase`、`purchase`／`purchase_by_ref`／`purchases`、`count`（不算退了的）、`mark_refunded`、`card`／`set_card`、`character_name`、`export`。每個寫的方法自己開 `db.transaction()`，呼叫端開著就併進去。
- `content/mall.json`：商品（joy 寫，`MallItem`）。現在三件是 PM 佔位（`draft` 寫「待 joy」）。
- 引擎：`Game._wallet`（商城關著是 None，什麼都不讀不寫）、`_mall_owner`、`_mall_grant`（`own_turn_checks` 叫）、`pill_cap`（月卡）、`mall_buy`、`mall_view`、`mall_records`、`admin_mall_reissue`／`admin_mall_revoke`／`admin_mall_refund`／`admin_mall_ledger`。
- 伺服器：`GET /api/mall`、`GET /api/mall/records`（`act_look`）、`POST /api/mall/buy {item, ref}`（`act`，回 `{message, bought, mall, main}`：`bought` 是買成的商品 id〔不成是 None，`Game.mall_bought` 在鎖裡讀〕、`main` 是江湖畫面〔狀態列當場換〕）、`POST /api/admin/mall {name}`、`/api/do/mall_reissue|mall_revoke|mall_refund`（`server.MALL_ADMIN_ACTIONS`）。開關關著全部 404。江湖畫面（`main_view`）開著時多一個 `mall`＝`Game.mall_entry()`（`{balance}`，只讀帳的加總、不排商品），關著沒有這個鍵。
- 畫面資料（第二批加的）：`mall.view` 每件多 `gives`（允許表的鍵 → 數量）與 `card_to`（今天買的話月卡用到哪一天，含；不是月卡是 None）；`Game.mall_view` 多 `pills`（名字、手上幾顆、今天還能服幾顆〔不限是 None〕、一天上限〔含月卡；0 是不限〕、一顆回多少、月卡多幾顆）與 `grant`（封測發了多少）；`mall.records` 的帳每一列多 `item`（連著一筆購買的寫商品名，其餘 None）與 `refunded`。
- `scripts/mall_ledger.py [--db] [--out]`：主機端把全部的帳匯出成 CSV（utf-8-sig），stderr 印筆數、錢包數、發出與花掉的合計、有沒有負的餘額。只讀。

## 規則速查

- **開關** `Config.mall.enabled`：模型預設關、測試內容明寫關、正式內容與 `week7` 開。關著時不發元寶、不讀不寫三張表（月卡不加上限）、API 都 404，其餘一個字都不變。設定覆寫檔是淺合併：覆寫檔寫 `mall` 就要整個寫（`week7` 寫 `{"enabled": true, "beta_grant": 5000}`）。
- **錢包的主人**是角色名號的 casefold（`characters.name_key`，同 `characters.key`、真人的 `accounts.character_key`）。真人的帳號與角色一對一、綁了不換；假人沒有帳號（`bot_runner` 只建角色）也有錢包，管理者查帳時真人假人長得一樣。換季角色重來，`characters` 那一列留著，錢包跟著跨季。【開發，PM 待確認；另一條是掛 `accounts.id`、假人沒有錢包】
- **餘額＝帳的加總**（不另存）；餘額不能是負的。每一筆帶不重複的編號：封測發放 `grant:beta:<主人>`、購買 `buy:<主人>:<網頁的編號>`、退款 `refund:<購買 id>`、管理者 `admin:<伺服器的編號>`。原因：`grant` 封測發放、`buy` 購買、`refund` 退款、`reissue` 補發、`revoke` 扣回、`topup` 儲值（留給之後的金流，表的 CHECK 已經收）。
- **封測發放** `Config.mall.beta_grant`（預設 0、`week7` 5000【預設】）：本人那一輪（`Game.own_turn_checks`：伺服器的 `mark_seen`、假人程式自己那一輪）錢包還沒發過就發，寫一則「商城」江湖紀錄；暫停中照發。之後再開新的一季、換一份設定都不會再發。沒建角色的帳號要等建了角色、第一次進來才發。
- **購買**（`mall.buy`，一筆交易）：查重（同一個編號回「這一筆已經買好了」，不扣不發）→ 上架（季的清單、日期含頭尾；沒上架回「沒有這件商品」，不露之後要賣什麼）→ 限購（每天照台灣日、每季照季數、每個帳號照全部；數的是沒退的購買）→ 餘額 → 寫購買紀錄 → 扣元寶 → 發貨（先寫月卡、最後才把回體丹加進 `PlayerState.stamina_pills`）。伺服器在行動鎖裡做，出錯整筆撤回。一次買一件。籌備中、休季、序章裡都能買；賽季時鐘暫停中照其他動作擋。成了寫一則「商城」紀錄（變化寫「元寶 -N」與拿到的東西）。
- **月卡**：每天回體丹上限 +`Config.mall.card_pill_bonus`（1；平常 2→3、新手期 5→6；不限照舊不限），加在 `Game.pill_cap` 這一個地方（`pills_left_today`、服滿那一句、狀態列跟著變）。存在 `mall_entitlements`（`kind='card'`、`key='pill_cap'`、開始日～到期日不含）。買的那一天算第一天（台灣 23:59 買也算）；還沒到期再買從到期日往後接、開始日不動，過期了從今天起算。
- **管理者**（`Game.is_admin`；帳跟季無關，籌備中、休季、暫停中都做得了）：補發、扣回（原因必填；扣回不能扣到負的）、退一筆購買（元寶全退；回體丹收回手上還有的、用掉的不追；月卡扣回那一張的天數，那一張屬於已經過期的舊卡就不動；一筆只能退一次）、查帳（名號或帳號都找得到；帳多寫編號與經手的管理者，玩家自己看的不寫）。每一筆寫進帳（誰、何時、為什麼），管理者自己的江湖紀錄記一則「商城」〔管理者〕。設定頁的表單見「畫面」。
- **假人**不買東西（設計 4.8，這一版沒有外觀，別人看不到誰買了什麼）；任何畫面與回話不寫誰是假人。
- **外觀、通行證**：種類留著（`MallItem.kind`、`mall_entitlements.kind`），允許表裡沒有它們的效果，這一版寫不出商品、不做顯示。

## 畫面（第二批，`web/app.js` 的「商城」那一段、`web/style.css`）

企劃者 2026-10-20 從對比圖（https://claude.ai/artifact/QZPqsGyvLvbStND9bh7aBK）挑的：入口乙＋丙、那一層子。錢一律寫「元寶」，不寫儲值、付款。店名「萬寶閣」、掌櫃的話、貨架與紀錄底下那一句、管理者區的字都是佔位，待 joy 潤。

- **入口**（`main.mall` 有才畫；商城關著一個字都不變）：乙＝齒輪左邊一顆錠子鈕寫元寶餘額（`mallBtnHtml`、`.mall-btn`、`ingotSvg`）；名號那一欄跟著窄（375 寬 214px），長名號照舊收成「…」。丙＝底部第六格「寶／商城」（`tabsHtml` 照格數排成六欄，`.tab-mall`；375 寬一格 63px、320 寬 53px）。兩個都打開商城那一層、不換頁（出店回到原本那一頁）。**序章裡**兩個都跟還沒開放的分頁一樣藏著：`shown("tab:mall")`，reveal 裡沒有這個鍵（`REVEAL_KEYS` 不動），亮齊（all，出師那一步）才出來；初入江湖照它（reveal 已經有 all）。
- **那一層**：沿用店面的框（`shopHtml` 的 `shop: "mall"`；`mallShop` 交給它招牌、掌櫃那一句、餘額），紫檀底 `.shop-layer.shop-mall`。伺服器沒有「人在店裡」：開不開只在網頁（`S.mallOpen`；`openMall` 抓 `/api/mall`、`closeMall` 收起並整個重畫；`forgetMall` 在登入、登出時清掉），出店是 `mall-close`。底下兩頁（`S.mallTab`）：
  - **貨架**（`mallShelfHtml`）：上面兩張小卡（手上幾顆丹、今天還能服幾顆；月卡到哪天或「還沒開」、一天最多服幾顆），底下照種類分（照 `content/mall.json` 的順序）：消耗品一格一件三欄（`mallTileHtml`，比 360 窄改兩欄），月卡一張寬卡（`mallCardHtml`）；格子寫名字、價錢、限購（`nbHtml` 不在詞中間斷）。封測有發時最底下一句發了多少、正式開服清空。買不了的畫淡（`.off`）、照樣點得到：點了掌櫃那一句換成原因（`S.mallSay`，`.said.no`；元寶不夠、限購、下架照伺服器的 `why`），不問。
  - **購買確認**（`mallAsk`）：貼在下緣的紙（同管理者的 `.ask`，跟著深淺色），寫花多少、元寶「現在 → 買完」、回體丹「現在 → 買完」、月卡「還沒開或到哪天 → 到哪天」（還沒有月卡時多寫一天最多服幾顆 → 幾顆），底下商品的說明一行、限購一行；「再想想／買下（價錢）」。編號在問的那一刻產（`mallRef`，16 個英數字）；上一次同一件送出去沒拿到回應（逾時、斷線，`S.mallPending`）就用回那一個，伺服器照編號回「已經買好了」、不扣兩次。
  - **買**（`mallBuy`，走 `busy`）：回來的 `mall` 換掉貨架、`main` 換掉狀態列（錠子鈕的餘額、丹鈕當場換），掌櫃那一句換成伺服器回的那一句（`bought` 有值 `.said.ok`、沒有 `.said.no`）。
  - **紀錄**（`mallLogHtml`）：每次切過去重抓 `/api/mall/records`；元寶餘額、一筆一列（連著購買的寫商品名、退了的掛「已退」；右邊增減與那一筆之後的餘額；底下時間・原因・說明）。
  - 輪詢：那一層開著時不畫被蓋住的頁面，`main.mall.balance` 變了（管理者補發、別的分頁買了）才重抓這一頁；`main.mall` 不見了（主機關掉開關）就收起。
  - 電腦寬照店面「遊戲那一欄 640px」（FB-225：底色列在 `@media (min-width: 641px)` 那一條），字級 ×1.3（FB-305：每一條寫了字級的規則在電腦寬那一段有一條同一個選擇器的，`tests/test_desktop_type.py`；選擇器一律從 `.shop-layer.shop-mall` 起），購買確認那張紙另有一段 ×1.3。
- **設定頁的管理者區**（`mallAdminHtml`，商城開著才畫，不靠 `/api/admin` 那一份）：名號或帳號＋「查帳」（`#ad-mall-form` → `/api/admin/mall`，查到的畫在底下 `mallBookHtml`：餘額與月卡、購買〔沒退的一筆一顆「退這一筆」〕、帳〔原因、經手的管理者〕）；元寶數與原因（必填）＋「補發」「扣回」。每一顆先問一次（`mallAdminAsk` → `ask`），沒填名號、元寶不是正整數、沒寫原因就在查帳那一行講、不問；補發、扣回的編號在問的那一刻產。送出（`mallAdminDo`）之後結果寫在查帳那一行、抽屜不關、重查一次那個人的帳；成了原因欄清掉（被拒的那一句都包在括號裡）。

## 資料庫（第 6 版）

- `mall_purchases`：`id, owner, ref UNIQUE, item, price, time, day, season, data（發了什麼，退的時候照它收回）, refunded`。
- `mall_ledger`：`id, owner, time, delta, reason（六種）, ref UNIQUE, purchase_id, admin, note`。
- `mall_entitlements`：`owner, kind（card／pass／look）, key, start_day, end_day, data`，主鍵 `(owner, kind, key)`。
- 舊檔打開時在同一筆交易裡從第 5 版升上來（`MIGRATIONS[5]`）；部署前先備份。正式開服整份資料庫換新，這三張表一起清。
