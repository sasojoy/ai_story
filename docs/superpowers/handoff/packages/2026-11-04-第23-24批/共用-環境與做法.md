# 共用：環境與做法

兩批都照這一份做。下面的 `python` 都是裝好 `requirements-dev.txt` 的那一個，`$PKG` 是這個工作包的路徑（`docs/superpowers/handoff/packages/2026-11-04-第23-24批`）。

## 一、環境

```bash
git clone https://github.com/sasojoy/ai_story.git
cd ai_story
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements-dev.txt    # 別的系統是 .venv/bin/python
```

- 主機用的版本：Python 3.14.3、Node 22。網頁測試要 node。
- 驗收的截圖要 Chromium 與 Pillow：`npx playwright install chromium`、`pip install pillow`。工具預設找 Windows 上 playwright 的 chromium-1208，別的情況設 `QA_CHROME` 指到執行檔。
- Windows：工作樹是 CRLF、git 裡存 LF。用腳本改檔要先把 `\r\n` 轉成 `\n` 再比對、寫回時轉回去。提交前用 `git ls-files --eol <檔>` 確認是 `i/lf`。

**工作樹分開**：工作包在 `develop` 上，開發分支裡沒有。

```bash
git worktree add ../pkg origin/develop          # 這一份放著讀工作包、跑 tools/
git worktree add ../work origin/dev/sense-1b    # 這一份做事（照工作單的分支）
```

工作樹要有自己的 venv，或都用同一個 python 的絕對路徑。

**主機上那份 clone 有個坑**：`git fetch origin <分支>` 不更新 `origin/*`。你的 clone 如果也這樣，就寫 `git fetch origin +refs/heads/X:refs/remotes/origin/X`。

- 總表 `docs/superpowers/plans/2026-10-31-全部拆包-總表.md` 你那一批那一列、第六節。

計畫與 README 跟程式對不上時，以程式為準。

## 三、不能碰的

- **行為不准變**：這兩批不加玩家看得到的字，不改數字，不改回應的鍵順序。
- **不改資料庫結構**（develop 第 9 版）。
- **不碰 `web/`、輿圖、鐵匠鋪、戰記（`tale.py`、server 的 `TALES` 與 `narrate_*`）、別的包的行為。**
- **不改**技能檔、`CLAUDE.md`、手冊、批次表、總表：只有 PM 改，要改的列給企劃者。
- **任何畫面、輸出都不能透露誰是假人。** `web/` 底下的檔連註解都不准寫假人、機器人、bot。
- **模型**：跑測試、開伺服器都不打真的模型。網址指到 `127.0.0.1:9`，絕不打 11434。
- **線上**：不碰 `main`、線上資料庫、`https://tianxiadashi.com`、Tunnel。
- **測試**：pytest 一律 `-n 4`，同一台同時最多兩份。`TIANXIA_DB` 指到 repo 外的暫存檔，不然會開到 `saves/tianxia.db`。
- **包的規矩**：包只 import 核心、共用規則層與標了「過渡」的舊模組，不能 import 別的包；`Game` 上的委派只有一行；測試不改斷言，只改路徑與 import（例外要寫明）。
- **same_behavior 新開的軌**一律用原創的人物名，不用金庸、古龍等作品的名字。
- **暫存**：解出來的 base、比對輸出一次約 1.5 GB，跑完就刪。

## 四、前後對照（same_behavior）

```bash
mkdir ../base && git archive <base 的 SHA> | tar -x -C ../base    # 要整個程式根目錄，不能只挑 tianxia

# 在 head 的工作樹裡跑：
python scripts/same_behavior.py compare --base ../base --head . --tmp ../sb --jobs 4
python scripts/same_behavior.py explore-compare --base ../base --head . --tmp ../sb2
python scripts/same_behavior.py selftest --base ../base --tmp ../sb3 --tracks <軌>
```

- `compare` 不給 `--tracks` 就是所有軌；`--profiles` 不給就是五種設定。比「整段」與「base 前半＋head 後半」，加假人。最後一行要是 **全部一樣**。主機約 15 分鐘，`explore-compare` 約 3 分鐘。
- `selftest` 確認比對本身穩：同一份跑兩次一樣、前半＋後半＝整段、改一個字抓得到。
- 不要用 `python -I`，它會連 `PYTHONHASHSEED` 一起忽略。
- 要單獨看一軌：`--tracks sense --profiles season21,week7`。

**改了情境（`same_behavior.py`）之後，那一軌的雜湊會變**：新舊都用新腳本重跑，再把新雜湊記進計畫。**只改文件、說明字**的話，之前的比對照樣有效，不用重跑。

## 五、審查與修正

**審查**要找一個沒有參與開發的人或新的 AI session，只讀不改。每個鏡頭一位，都要帶證據（指令與輸出），分 blocker（合了會壞、行為變了、違反規矩）、should、nit，沒有就回空的，不要湊。

1. **行為不變的證明誠不誠實**：讀這一批加的情境，每一個都真的走到了嗎（看回應與資料庫裡有沒有那幾句、那幾筆，不是被擋在前面）？半舊半新的切點是不是在這一包「寫到一半」的那一刻？假人碰不碰得到這一包的選項？**自己重跑一次**：開兩份工作樹（base 與 head），season21 與 week7 各比一次所有軌，再做一個單點突變看 compare 抓不抓得到。
2. **照不照手冊、批次表、總表**：包只 import 核心、共用規則層與標了過渡的舊模組（數一數，跟開發報的對）；委派都是一行；別名是同一個模組物件；這一批加的是不是集中在自己那一段；第 11 批有掛鉤的位置接了掛鉤、沒有新增 `GAME_DIRECT`；前綴與 `bots.py`；歸屬照總表附錄甲、丙；README；有沒有碰到第三節不准碰的。**只有 2 個鏡頭的批，這一位兼下面第 3 項。**
3. **回歸與測試**：跑包的測試（含 slow，記時間）與相關的 slow（`-m "slow or not slow" -n 4`）；在包裡改壞一個搬過去的方法，看哪些測試紅、`test_for` 挑不挑得到；monkeypatch 敏感的路照舊有效；改包任一檔 `test_for` 挑到幾條（300 以內）；有沒有測試被改了斷言。

**修正**：

- 每修一條一個 commit，修一條推一次。
- 先寫會紅的測試（或讓 same_behavior 先抓到）再修。
- 屬實才修，不屬實的寫明理由與證據；nit 能順手就修。
- 修完重跑 same_behavior（所有軌、五種）與相關測試。

## 六、驗收（QA）

**一律先凍住局面再比。** 兩台真伺服器（HEAD 一台、BASE 一台）用真的 HTTP 打同一串步驟，每個回應的狀態碼與內容逐位元組比，收場後資料庫逐表比。

工具在 `$PKG/tools/qa/`（第 12 批的版本）：

| 檔 | 用途 |
|---|---|
| `serve.py` | 外殼：凍住時鐘與亂數、不開排程、模型指到死埠、`/__qa/*` 擺局面。`/__qa/peek` 讀的欄位換成你這一批的。 |
| `drive.py` | 驅動：`python drive.py <season21\|week7> <hb\|hh\|mh> [snap]`。**`flow()` 是第 12 批的步驟，要換成你這一批的**（工作單列了要走哪些）。 |
| `dbcmp.py` | 兩份資料庫逐表比。 |
| `crossrun.py` | 同一份 HEAD 分開跑兩次的回應逐檔比。 |
| `mkmut.py` | 做 MUT：HEAD 改一個字，看比對有沒有牙。字換成你這一批的。 |
| `shots.py`、`shots.mjs` | 無頭 Chromium 截圖並排。場景換成你這一批的。 |
| `resp.py`、`cleanup.py` | 看存下來的回應、收暫存。 |

```bash
export QA_DIR=<repo 外的暫存資料夾>      # 底下放 HEAD、BASE 兩份工作樹（MUT 另外抄）
export QA_PORTS=<HEAD 埠>,<BASE 埠>      # 工作單有寫
export QA_HOST=<你這一批的名字>           # 瀏覽器用 <名字>.localhost
git worktree add --detach $QA_DIR/HEAD <head 的 SHA>
git worktree add --detach $QA_DIR/BASE <base 的 SHA>
```

**順序**：

1. `hh`（同一份跑兩台）：要 0 處不同，證明凍得住。凍不住，後面比了也沒有意義。
2. `hb`（HEAD 對 BASE）：這才是驗收。
3. `mh`（改一個字的 MUT 對 HEAD）：要抓得到不同，證明比對有牙。
4. 拿 `hh` 與 `hb` 兩次的 HEAD 回應用 `crossrun.py` 比，是便宜的第二道穩定性證明。

**差異要分清楚是雜訊還是程式**。常見的雜訊與該固定的，`tianxia-qa`「純搬的批」那一節有清單（玉璽密鹽、種子帶時刻、旁白背景執行緒、`server._monotonic`、`BOARDS_CACHE`、`world_step`、`<db>-archive.sqlite` 也要比；流程最後有換季的話，季中要留資料庫快照）。外殼已經做了大部分。

**兩種驗收**：

- **逐位元組比**（第 23 批）：回應與資料庫一樣之後，拍 375×812 淺色三張並排當 sanity。
- **完整實機 QA**（第 24 批）：除了上面，並排截圖 375 淺、375 深、1280，逐像素比，主控台 0 錯誤，網路沒有 4xx、5xx。做法細節看 `tianxia-qa`。

**有問題**寫進 `docs/superpowers/feedback/試玩回饋.md`（用工作單給的號段），報告與挑過的圖推到 `qa/<批名>`。**沒問題**就在 PR 寫「沒有問題」與數字。順帶看到、新舊都一樣的問題不算退版，列在 PR 裡給企劃者看。

## 七、開 PR

**分支**：照工作單繼續用 `dev/sense-1`、`dev/arts-1`。如果你的環境只能推 `claude/<名字>`（雲端 session），就從它們開一條 `claude/` 分支，PR 一樣開到 `develop`。PR 由 Joy 在 GitHub 合。

**合之前**：把最新的 `develop` 合進來，衝突照「兩邊的行都留」解：

- 共用登記檔（邊界測試、`services.py`、`registry.py`、`FEATURES`、`same_behavior.py`、`aliases()`）各包的段都留、照順序接。
- `engine.py` 的 import：兩邊拿掉的都拿掉、兩邊加的都留。
- **git 自己合好的也要逐檔看**：有些衝突 git 不會報，但邊界測試會紅。
- 導覽的過渡處數照合好之後 `python tests/core/test_feature_boundaries.py` 重印的寫。

**閘門**（全部對合好的那一筆跑）：

```bash
# 四種設定各載一次內容（none 就是不帶）
python $PKG/tools/gate/load_profile.py <樹> season21      # 還有 week7、weekend、none

# 四種設定各起一次伺服器，GET / 要 200，關掉之後確認埠空了（不帶設定的就不設 TIANXIA_PROFILE）
TIANXIA_PROFILE=season21 TIANXIA_DB=<暫存>/a.db python -u $PKG/tools/gate/boot_server.py <樹> <埠>

# 不含 slow 的整套
TIANXIA_DB=<暫存>/t.db python -m pytest -q -n 4

# 相關的 slow：包的 tests/、包的 README「另外要跑」列的檔、tests/bots/
TIANXIA_DB=<暫存>/s.db python -m pytest -q -n 4 -m "slow or not slow" <上面那些>

# same_behavior 對最新的 develop：base 是 develop，所有軌加 explore-compare，全部一樣
```

**develop 動了**：只多了 `docs/`、`.claude/` 的提交，再合一次、確認沒撞就好，不必重跑。動到程式就再合一次、重跑不含 slow 的整套與 same_behavior。

## 八、被打斷、要問人

**做到一半要停**：把沒提交的改動提交成一筆 WIP，推到 `dev/<x>b` 或 `dev/<x>c`（不要直接推回 `dev/<x>`），訊息寫清楚做到哪、哪些沒跑過。接手的人從那裡開工作分支，做完快轉推回 `dev/<x>`。

**要先問企劃者**：要改資料庫結構、要改玩家看得到的字或數字、行為必須改才做得下去、要動第三節不准碰的東西。其他的自己判斷，寫進計畫的「交 PM 定的」，不要停下來等。

**開工先查雲端的線**：`git ls-remote origin 'refs/heads/claude/*'`，看最近兩天有提交、還沒合進 `develop` 的，有沒有改到你這一批的方法或模組。動到了就先問。打包時沒合的 `admin-gallery`（形象包與 `web/`）、`sleepy-shannon-glqkoc`（只有文件）都沒碰這兩批。

**機器是別人的**：跑完伺服器與測試都收乾淨。主機也是企劃者的遊戲電腦，企劃者說暫停就要全停。
