## 學到的

- 包名 arts 跟共用規則層的 tianxia/arts.py 同名，會讓 test_feature_boundaries 的「共用規則層的模組不是包」那條斷言紅；new_feature.py 本來就不准這種撞名。包裡要拿共用層那一個，一律寫 `from tianxia import arts as arts_mod`，因為 `from . import arts` 在包裡指到包自己。
- 舊模組搬進包、改成別名之後，tests 裡用 `glob('tianxia/*.py')` 掃原始碼的（例 test_seal_acts 的頒詔呼叫端），以及 test_test_for 拿那個模組當例子的（T-02 的 ascend→cultivation），都會紅。開工時先 grep 這兩種。
- 改成一行委派之後，test_for 照「內文寫到方法名」挑測試；方法名是常見字（practice、cultivate、allocate、art_rows）時，挑到的條數會比搬之前多好幾倍。
- same_behavior 有兩種寫法會讓路徑看起來有走到、其實沒走到，用單點突變才量得出來：追風步的舊品質要角色手上真的有那一門，因為讀檔時不在手上的品質本來就照「手上有的」清掉；配點那一句的「此刻全隊」要威力夠大，一級的人配一點不會出現那一段。
- 破境丹衝關的「敗」、絕學契機的「成」、練成的「受傷」：在記憶體裡把機率擺成 1% 或必中（兩份程式同一套，做完擺回來）是穩的作法，不必靠種子碰運氣。
- /api/main 回的是 main_view 本身：境界卡在頂層的 milestone（WIP 寫成 .get('main') 讀不到）；破境卡在 status.ascension。
- BotRunner 不帶 client 時，假人的絕學定名一次都不走（named 0）。要比對假人那一段，照 run_bots 帶一個叫不動的 client。
- develop 在這一批開工之後合了第 22 批（151d9fc7）：allocate_stat 的 note_action 改成 self._note_action，_graduate_pass 搬進了引導包。後合的人要照這兩處改，細節寫在計畫第五節「合併時要對上的」。
