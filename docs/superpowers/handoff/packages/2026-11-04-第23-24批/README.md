1. 讀 [共用-環境與做法.md](共用-環境與做法.md)，把環境裝好。

3. 碰到工作單沒寫到的，看共用第八節。

**這個工作包在 `develop` 上，不在 `dev/*` 分支裡。** 開一份 `develop` 的工作樹放著讀、跑工具（共用第一節有指令），程式在另一份工作樹做。

## 交付的定義

一批算做完，要全部打勾：

- [ ] 審查員的發現都處理了：屬實的修了，不屬實的寫明理由。
- [ ] 驗收過了：HEAD 跟 BASE 一樣，或差異都有解釋、開了單。
- [ ] 分支合了最新的 `develop`，閘門全綠（共用第七節）。
- [ ] 計畫裡寫了第五節（量到的數字）、第六節（審查與修正）、第七節（合併紀錄）。格式看 `develop` 上的 `docs/superpowers/plans/2026-11-01-新手引導包-第1批.md`。
- [ ] PR 開到 `develop`，說明照共用第七節的範本。
- [ ] 把「要 PM 改的文件」與還沒定的題目列給企劃者。

## 詞彙

| 詞 | 意思 |
|---|---|
| 批 | 拆包的一個工作單位。全部 68 批，路線在 `docs/superpowers/plans/2026-10-31-全部拆包-總表.md`。 |
| 包 | `tianxia/features/<包>/`，一個功能一包。舊模組名留成指到包裡的別名。 |
