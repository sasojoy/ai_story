## 七、PM 的做法與坑（這台機器）

**分支與推送**
- 這份 clone 的 `git fetch origin` 不更新 `dev/*`、`feature/*`、`qa/*`、`talk/*`：要明確 fetch（`git fetch origin +refs/heads/X:refs/remotes/origin/X`），推完用 `git ls-remote` 確認。
- PM 不能寫別的工作樹的檔：用 scratchpad 的暫存工作樹（這個 PM 對話用的是 `scratchpad/pmhost`，detached；用之前先明確 fetch、`checkout --detach origin/develop`；唯讀調查另開 `scratchpad/splitwt`、補跑 main 的整套用 `scratchpad/mainchk`），改完 `git push origin HEAD:develop`。
- 改交接用 scratchpad 裡的 .py 腳本：
  - 保留 CRLF。
  - 每一處 assert 只換一次。
  - assert 沒有 `\x07`、`\t`。
  - 跟 `git add`／`commit`／`push` 用 `&&` 串。

**雲端 session**
- 雲端開 PR 到 develop、由 Joy 在 GitHub 合（企劃者 10/31：照現況）；PR 說明寫改了哪一包、跑了哪些測試、退版風險。PM 靠每天 03:30 的整套事後驗，紅了開單交回。規矩寫在 CLAUDE.md（10/31 晚加）。
- 雲端不能回訊息給 PM，協作靠分支與企劃者轉話。
- 只有企劃者轉來的才算派給雲端的工。

**子代理**
- Agent 工具，`model: sonnet`、`isolation: worktree`、背景跑。
- 派工單寫明：要讀哪幾塊導覽、範圍、跑哪幾個測試、FB 號段、埠、`<名字>.localhost`、scratchpad 子資料夾。
- 換帳號時子代理全部停，照 `tianxia-flow`「換帳號、對話斷掉」那一段接回來。

**本機看畫面**
- `set_password.py` 建帳號，用 `TIANXIA_ADMINS`、`TIANXIA_PROFILE`、暫存 DB。
- 用 `-u` 分離啟動伺服器，在瀏覽器窗格登入 `<名字>.localhost:<埠>`。
