2. **包名先查同名**：`tianxia/<包>.py` 存在而且這一批不搬它，就換名。前例：`cultivation`（不用 `arts`）、`figure_acts`（不用 `figures`）、`military`（不用 `orders`）。
3. **開工**：在 `docs/superpowers/pm-workflows/paused-1104/make_more.py` 加這一批（批的 dict 可以蓋掉預設：核心批寫 `reviewers=3, dev_model=None, all_tracks=True`、`prev_plan`、`parallel`，第 25 批是範例），把 `feature/<x>` 開或快轉到主幹那一筆，再跑：
   `python docs/superpowers/pm-workflows/paused-1104/make_more.py <批號> <SHA> <scratchpad>`，把產生的 `b<批號>.js` 交給 Workflow（`scriptPath`）。
4. **工作流程會做的**（`split-batch.js`）：開發三段（計畫與 Task 1、Task 2～4、Task 5，每段新的子代理）、審查（純搬兩位，核心批與拿掉批三位，只讀不跑）、修正一輪（nit 不修）、動到 `web/` 才有實機驗收。純搬批的開發與修正用 Sonnet（`dev_model`），審查用 Opus。
5. **合併**：看結果 `python docs/superpowers/pm-workflows/tools/show_fix.py <run_id>`，把「交 PM 定的」定下來。寫成 JSON，`python docs/superpowers/pm-workflows/make_merge.py <args.json> <merge-b<批號>.js>`，交給 Workflow。**一次合一批**。閘門只驗合起來才會壞的（三種設定起得來、邊界、契約、煙霧、未定義名稱掃描），撞到程式才多跑撞到的檔與那一軌。
6. **合完**：拿掉開發工作樹（`git worktree remove`，三段加修正共四個）與本地分支（`git branch -D dev/<x>*`），改這一份、`CLAUDE.md` 的包清單。
7. **全面檢查**（一天一次，或合了幾批之後）：`python docs/superpowers/pm-workflows/trunk_daily.py`，用 Bash 背景跑，約 25 分鐘、不花額度。所有軌對 `.local/trunk_daily/verified.txt` 那一筆比，加整套含 slow。紅了從那段期間合的批裡找。每天 03:30 的排程只跑 develop，不驗主幹。
8. **撞額度或 session 斷掉**：子代理停在半路。看工作樹 `git status`，把沒提交的收成一筆推到 `dev/<x>b`，拿掉工作樹，在 ARGS 的 `body` 開頭寫接手說明（前例 `paused-1104/make_next.py` 的第 13 批）。同一個 session 可以用 `resumeFromRunId` 接，換 session 不行。
