## 設計稿沒定、我先選了的畫面（第九節「留給開發的」）——請企劃者挑

每一組甲是做進程式的，乙、丙是在真的頁面上注入樣式或搬節點的原型（程式碼沒改；`tools/compare.mjs` 裡就是注入的那幾段）。

1. **爐火那一行放哪**（`C/對比-爐火那一行.jpg`）：**甲 爐子底下一行**（我選的：設計稿說「火旁一行」，看火候跟這一爐的機率是同一件事，放在爐子與開爐鈕之間；代價是開爐鈕往下推 30px，375×812 素材格照舊在第一屏）／乙 換掉頂上鐵匠那一句（不多佔一行，可是鐵匠那一句本來會換成修淬、熬的結果，兩件事搶同一格）／丙 火上一枚小籤（最省地方，可是「今天看過了」「還差 N 兩」這種長原因放不下）。
2. **灰格點了之後的小單**（`A/對比-灰格小單.jpg`）：**甲 在那一排底下展開**（我選的：設計稿【提案】的寫法，熬完素材格當場變、看得到哪一格變了）／乙 從畫面底下浮一張（同確認框，蓋住素材格，熬完看不到格子變了）。
3. **裝備庫一列的折法**（`C/對比-裝備庫一列.jpg`）：**甲 名字一行、四顆鈕一整行**（我選的：375 寬一顆 81px，小字兩行放得下；320 寬 68px 也沒切字）／乙 名字在左、四顆 2×2 在右（一列更矮，可是名字那一欄只剩一半寬、那一行數字折成三四行）／丙 一行四顆不帶小字（最矮，可是看不到修、淬煉要多少錢、為什麼灰）。
4. **收藏冊的格子**（`E/對比-收藏冊.jpg`）：**甲 寫名字的方格，375 寬一排四格、電腦五格**（我選的：六個字的定名一行放得下）／乙 圓形的印（一排五枚，像蓋章，可是四字以上的名字要縮得很小）／丙 一件一行（最清楚，可是 21 行要捲很久）。
