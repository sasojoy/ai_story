## 零、一句話

探索事件加三種新玩法：**隨口應對**（自己打一句話應對，LLM 只評成功率，系統擲骰）、**地方痕跡**（大家在一個地點做的選擇會累積，改變之後的人抽到什麼）、**合力事件**（一件事要很多人各出一份力，湊滿了全服都看得到結果）。數值一律由規則決定。

---

## 一、現況

| | 現在 | 問題 |
|---|---|---|
| 事件選項 | 全部是手寫的固定選項 | 玩家的創意沒有出口；LLM 只在人物對話與決戰出現 |
| 別人的痕跡 | 只有 `Effect.rumor` 會寫一則傳聞 | 你在潁水河畔救了流民，下一個人來看到的河畔還是一模一樣 |
| 全服狀態 | 事件條件可以看大勢（`trend_min/max`）和世界旗標 | 能用，但內容幾乎沒用到；而且只有「全服大勢」這一個尺度，沒有「這個地點」的尺度 |
| 多人協作 | 只有全服決戰 | 決戰一季幾次，平常的探索是純單機 |

## 二、玩法 A：隨口應對（LLM）

### 2.1 玩起來

有些事件多一個選項「自己想辦法……」。按下去出現 20 字的輸入框，玩家寫自己要怎麼做，例如酒樓鬥毆時寫「把酒罈砸在地上大喊官兵來了」。

系統把事件情境和這句話交給 LLM，LLM 只回一個 0～100 的成功率。系統拿這個機率擲骰：成功套用手寫的 `effect`，失敗套用 `fail_effect`。最後 LLM 可以把結果潤色成一兩句敘事，但不能改數值。

這跟決戰的放手一搏是同一套：`SuccessRateJudgment`、`DEFAULT_FREE_TEXT_SUCCESS_RATE = 40`、在鎖外評估。

### 2.2 規則 【預設】

- **只有標了的事件才有**：事件加一個 `free_text` 欄位（提示文字、相關屬性、effect、fail_effect）。不是每則都開；先開在每個地點的一兩則事件上。
- **屬性仍然有用**：LLM 的成功率再按相關屬性修正，每點比 5 高 +4%，比 5 低 −4%。最後夾在 **5%～85%**，所以再會寫也不會穩贏，也不會因為寫得爛就必敗。
- **獎勵不能比手寫選項高**：`free_text` 的 effect 不得超過同一則事件裡最好的那個檢定選項。這個玩法賣的是好玩，不是更划算。內容檢查會擋。
- **防灌水**：LLM 的提示詞寫明「只判斷這個行動在情境裡合不合理」。玩家寫「我必定成功」這種話照樣被評成低機率。上限 85% 也是保險。
- **等待**：本機模型評估實測要 27～83 秒（煉製取名的量測）。比照人物對話的做法：先拿鎖準備、在鎖外呼叫 LLM、再拿鎖確認狀態沒變才套用（`app.prepare_dialogue` 那一套）。介面上按鈕先變成「思量中……」。
- **LLM 連不上**：用保底的 40%，再加屬性修正。遊戲照常能玩。
- **假人不用**：假人不選這個選項，跟決戰一樣。

### 2.3 為什麼值得做

這是本作「LLM 文字遊戲」最直接的賣點：玩家的奇招真的會改變結果的機率。決戰已經證明這套分工可行，而且不違反「數值由規則決定」。

## 三、玩法 B：地方痕跡（多人同服）

### 3.1 玩起來

每個地點記幾個「痕跡」計數，全服共用、每季清空。事件選項可以加痕跡，事件也可以要求痕跡夠多才會出現。

例子：

- **潁水河畔**：選「幫流民搭棚」的人多了（`yingshui:棚屋` ≥ 10），之後的人會抽到新事件「河畔新村」：流民開始種地，有人想拜師、有人想報恩。選「趕走流民」的人多了，則會出現「流民成匪」。
- **潁川書院**：有人在壁上題了一首反詩（選項加痕跡），之後的人抽到「壁上題詩」：可以附和（再加一筆）、塗掉、或抄去報官。附和的人多了，書院會被官府查封一陣子。
- **白馬津**：大家在渡口幫忙還是勒索，決定之後擺渡人對你的價錢與態度。

畫面上用模糊數量呈現：「這一帶已有十來個人幫過流民」。**不列名字**，所以也看不出誰是假人（伺服器假人設計的硬規定）。值得一提的痕跡變化照現有的地方傳聞發出去。

### 3.2 規則 【預設】

- `Effect.marks: {"<地點>:<痕跡>": 數量}`；`Condition.marks_min / marks_max`。痕跡存在全服共用的賽季狀態（`WorldStateStore`），寫入包在行動鎖裡。
- 一個人對同一個痕跡一天只算一次，免得一個人就能刷出整條變化。
- 門檻照伺服器人數換算，比照伏筆文件 2.8 的三檔換算（開發期的小伺服器門檻低）。
- 痕跡每季清空，跟配方、自創武學名字一起換季。

### 3.3 為什麼值得做

這是同服感最便宜的做法：不必同時在線，也不必湊隊，你只要回到一個地點就看得出別人來過。內容上也只要多寫「痕跡夠了之後」的事件，跟現在寫事件的方式一樣。

## 四、玩法 C：合力事件（多人協作）

### 4.1 玩起來

某些地點會出現需要眾人出力的事，例如「修孟津渡的浮橋」「替新野湊出徵糧」「把廣宗城外的壕溝填平」。抽到的人可以出一份力：花體力或素材，或者過一個檢定。全服進度湊滿之後：

- 觸發一個世界效果，例如浮橋修好之後孟津到河內的路變短、或解開一則新事件；
- 每個出過力的人都拿到一份獎勵；
- 寫一則地方傳聞，人數多時寫進江湖史（「孟津浮橋，由六十七位義士合力修成」）。

### 4.2 規則 【預設】

- 新的內容種類 `projects`（合力事件）：地點、目標量、出力的方式、完成效果、時限（沒在時限內湊滿就作罷，也發一則傳聞）。
- 有陣營的合力事件只算同陣營出的力，這等於地方級的「集體密謀型」機緣（世界觀推進 4.3）。
- 跟軍令、大勢任務的分工：軍令推大勢線，合力事件只改**地方**（路、事件、價錢），不直接推大勢，免得跟陣營推進重複。
- 假人可以出力（只走 `Game` 的公開行動），讓開發期的小伺服器也湊得滿。

### 4.3 為什麼排在最後

它要新的內容種類、新的狀態、新的畫面，工作量最大，而且跟軍令、軍備物資的設計有重疊，要先跟那兩份對齊。

## 五、待企劃者決定

1. **先做哪個？** 建議先做 **A 隨口應對** 和 **B 地方痕跡**：A 是 LLM 賣點最直接的展示，B 是同服感最便宜的做法，兩個都能沿用現有的事件格式。C 留到軍令做完再談。
2. **隨口應對要開多少？** 建議每個地點先開 1 則，看試玩反應再增加。全部開會讓 LLM 的等待時間變成常態。
3. **地方痕跡要不要讓人看到數量？** 建議用模糊數量（「十來個人」），不列名字。
4. **成功率上下限 5%～85% 和屬性修正 ±4%/點** 可以嗎？

## 六、要動的程式（給「遊戲架構與介面」和「LLM 整合」）

| 內容檢查：free_text 獎勵不超過同事件最好的選項、痕跡名稱有人寫有人讀 | `content.py::validate` | 架構與介面 |
| 事件內容（free_text 事件、痕跡事件） | `content/events/` | 劇情與世界觀 |

## 七、現在不改引擎就能做到的

事件條件本來就能看全服大勢（`trend_min/max`）和世界旗標。這次補內容時已經加了 5 則（`content/events/trend.json`）：黃巾聲勢 ≥40 時陽翟閉城、涿郡鄉勇南下，≥50 時白馬津爭渡，官道被切斷後的送軍書，聲勢 ≤15 時南陽流民返鄉。全服大家一起把大勢推到哪裡，探索就會看到不同的事。
