# 《天下大勢》交鋒統一：檢定、戰鬥與戰報 — 設計

> 來源：第一階段 1a 試玩回饋（「檢定與戰鬥兩套規則」「各種戰鬥呈現不一樣」「戰報看不出是哪一場」）。
> 這是四個子題中的第 ① 項；② 同伴入戲、③ 資質的意義、④ 整體畫面整理各自另有設計。

## 一、要解決的問題

1. **同樣是「出手」，規則卻有兩套**：劇情選項中有 16 個是擲本人屬性的檢定，另外 9 個是三人全自動戰鬥；同伴、武學在檢定裡完全派不上用場。
2. **戰鬥呈現不一致**：歷練、劇情戰、關卡戰的訊息寫法和獎懲各不相同；劇情戰打平時事件直接結束、什麼都不發生，等於多一條不用打贏的後路。
3. **戰報看不出是哪一場**：戰報分頁只留最近一場，沒有時間、地點、對手，也沒有歷史。
4. **打之前看不到對手**：選項一按就開打，沒有「先配好陣容再出手」的 SLG 準備感。

## 二、交鋒分三類

每個會分勝負的劇情選項，都屬於下面其中一類：

| 類別 | 用在 | 怎麼判定 | 選項上怎麼寫 |
|---|---|---|---|
| **動手** | 打鬥、硬闖、搶奪 | 三對三全自動戰鬥（與歷練同一套引擎） | 「拔劍闖進去（對手：水寇・有把握）」 |
| **辦事** | 跟蹤、打聽、救人、勸架、挖掘等對外的事 | 隊伍檢定：自動派出該項屬性最高的隊員 | 「悄悄救人（小墨出手）」 |
| **修行** | 服藥、聽禪、領悟、請教、偷學等本人的機緣 | 本人檢定：只看本人屬性 | 「坐下靜聽（本人）」 |

### 2.1 檢定
- 內容格式：`Check` 新增 `by`，值為 `"team"`（預設）或 `"self"`。
- 標為 `self` 的 6 個選項：`herb`「當場服下」、`temple_zen`「坐下靜聽」、`teahouse`「上台和說書先生對幾句」、`train_insight`「靜下心來細想」、`monk_jinshan`「請教調息之法」、`waterfall`「躲在石後偷學」。其餘 10 個維持 `team`。
- **誰出手**：`team` 檢定取出戰隊伍中，該屬性目前數值（含等級成長）最高的人；同分時依隊伍順序（本人最先）。`self` 檢定一律是本人。
- **成功率公式不變**：50% ＋（出手者屬性 − 難度）× 10%，限制在 5%～95%。
- **不顯示成功率**：選項只寫由誰出手（「（小墨出手）」「（本人）」），不寫百分比。
- 結果前加一行說明誰出手、成敗，例如「（小墨出手——成功）」；後面接原本的劇情文字。同伴怎麼在劇情文字裡出場屬於第 ② 項。

### 2.2 戰前情報
- 凡是會開打的選項（事件的動手選項、歷練）都在按鈕上顯示對手與勝算：
  - 事件：「拔劍闖進去（對手：水寇・有把握）」。
  - 歷練：「歷練（體力 10・可能遇到：地痞無賴 穩勝、劫道山賊 穩勝）」。
- **勝算**：以目前隊伍、配置與目前內力，模擬 40 場，依勝率分五段：

  | 勝率 | 勝算 |
  |---|---|
  | ≥ 90% | 穩勝 |
  | ≥ 65% | 有把握 |
  | ≥ 35% | 五五波 |
  | ≥ 10% | 凶險 |
  | < 10% | 必敗 |

  平手不算勝。
- 模擬使用固定亂數種子，同樣的情況每次畫面顯示相同的勝算，不會跳動。結果依「隊伍、配置、成數、等級、內力、對手」快取，每次重畫的額外耗時要低到察覺不出來。
- 在門下調整配置後回到江湖，勝算會依新陣容重算。

### 2.3 結果一致
| 情況 | 歷練 | 劇情戰 |
|---|---|---|
| 勝 | 對手獎勵（經驗、心得、銀兩）＋歷練原有的屬性機會與大勢變化 | 對手獎勵＋該選項的劇情結果 |
| 敗 | 失落一成銀兩 | 走失敗分支 |
| 平 | 無獎懲 | **算沒打贏，走失敗分支** |

## 三、戰鬥呈現

### 3.1 戰鬥紀錄
每場戰鬥（歷練、劇情戰）都存成一筆紀錄，包含：
- 流水號、遊戲時間、地點、類型（歷練／劇情）
- 我方與敵方陣容（名字、等級）
- 結果（勝／平／敗）、回合數、結束原因
- 關鍵時刻（最多 3 則）
- 獲得與損失（經驗、心得、銀兩、劇情結果摘要）
- 完整逐回合戰報
- 我方每人表現：造成傷害、控制命中次數

存檔保留最近 20 場，最新的在前。舊存檔沒有這筆資料，就從空的歷史開始；1a 的存檔照常讀取，不需要備份。

### 3.2 關鍵時刻
由戰鬥引擎回傳結構化的戰鬥事件，不從戰報文字反推。依序挑選最多 3 則：
1. 施展絕招
2. 控制命中（點穴／卸兵／封脈）
3. 有人倒下，含隊長倒下

每則寫成一句，例如「第4回合　小墨【亂針】封住劫道山賊的經脈」。
`battle.py` 仍然只處理數字、不 import 內容模型。

### 3.3 場景裡的戰鬥卡片
某次行動發生戰鬥時，場景裡出現一張卡片，下一次行動後消失。內容：
- 標題「⚔ 地點・對陣 對手們」，下方是時間與類型
- 結果、回合數，以及隊長是否無恙
- 關鍵時刻
- 獲得與損失
- 「看完整戰報」按鈕：切到右欄「戰報」分頁，並選好這一場

紀錄只留一行摘要，例如「⚔ 揚州城郊：擊退劫道山賊（4 回合）」，不再附「（戰報見「戰報」分頁）」。

### 3.4 戰報分頁
- 上方是歷史列表，最新在前，每列寫「勝／平／敗　第N天 HH:MM　地點　vs 對手　N 回合」。
- 點選後在下方顯示這一場的完整內容：陣容、逐回合戰報、結果、我方表現。
- 預設選最新一場。

## 四、不在這次範圍
- 劇情文字裡寫出同伴的動作、本人與同伴的成長規則對等：第 ② 項。
- 資質的用途與呈現：第 ③ 項。這次的「我方表現」只提供數據。
- 左右兩欄的整體重排：第 ④ 項。這次只在現有位置放入戰鬥卡片與戰報列表。
- 戰鬥規則、數值、平衡：不改。

## 五、測試
- 規則引擎：
  - 出手者挑選，含同分與 `self`
  - 選項文字（出手者、對手與勝算）
  - 勝算分段，以及固定種子下的穩定性
  - 三種結果在歷練與劇情戰的處理，含劇情戰平手走失敗分支
  - 戰鬥紀錄的建立與 20 場上限
  - 關鍵時刻的挑選順序與數量
  - 存檔來回，以及 1a 舊存檔照常讀取
- 內容：6 個 `self` 檢定已標註；驗證 `by` 只能是 `team` 或 `self`。
- 介面：
  - 戰鬥後場景出現卡片、下一次行動後消失
  - 戰報列表與選取
  - 「看完整戰報」切換分頁並選好該場
  - 輸出數量與順序一致
- 真實內容：機器人跑完整季不出錯。
