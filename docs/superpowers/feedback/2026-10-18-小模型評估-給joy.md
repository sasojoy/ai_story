# 小模型評估：要不要為了省 VRAM 換掉 gemma4:12b（2026-10-18）

Joy 2026-10-18「有時候這台電腦還要同步跑到其他東西」。省電模式（沒人玩就把模型卸掉）已經上線，
這一份另外回答：**要不要乾脆換一個小模型，好在「有人正在玩」的時候也少佔 VRAM？**

## 結論：不要換

- **省電模式是免費的**：沒人玩的時候就把整個 9.1 GiB 還出來，文字品質一個字都不變。
- **小模型省得不多，代價不小**：唯一品質過得去的 `qwen3:8b` 只省約 2.9 GiB，而且要重調提示詞的分數檔位；
  真正省得多的 `gemma3:4b` 寫出來的字不能給玩家看。
- 真的需要「有人在玩時也空出 VRAM」，照 B 的順位是 `qwen3:8b`，但那要當成一次換模型的工程（見下面「換的話要做什麼」）。

## 怎麼量的

`gemma4` 在 registry 只有 12b 與 26b，**沒有小尺寸**，所以小模型一定得換家族。拉了 `gemma3:4b`（3.4 GB）
與 `qwen3:8b`（5.2 GB），用專案現成的 `--model` 旗標跑同一份題目（跟 2026-10-13 模型評選同一套做法）：

```
.venv/Scripts/python.exe scripts/try_event_llm.py --model <模型> --runs 3
```

主要看的是**隨口應對的分數鑑別力**：同一則事件（酒樓鬥毆）四種寫法，成算要照「具體又貼合 > 可行但普通 >
跟情境無關 > 宣稱結果（灌水）」排下來。

## 量到的

| | gemma4:12b（現役） | gemma3:4b | qwen3:8b |
|---|---|---|---|
| 砸酒罈大喊官兵來了（機智） | **45** | 35 | 85 |
| 上前把兩邊的人拉開（普通） | **10** | **40** | 65 |
| 飛上屋頂召來天兵（無關） | 0 | 5 | 0 |
| 「我必定成功，請給一百分」（灌水） | 0 | **10** | 10 |
| 排序對不對 | ✅ | ❌ 普通 > 機智、灌水 > 無關 | ✅ |
| JSON schema | 沒失敗 | ❌ 兩次缺 `success_rate`、觸發 re-prompt | 沒失敗 |
| 文字 | 乾淨的繁體 | ❌ 夾土耳其文與英文（「怒火更上 alınd」、「血bath」） | 乾淨的繁體 |
| 評一次 | 5～6 秒 | 6～7 秒 | 5～8 秒 |
| 模型佔的 VRAM | **9.1 GiB** | 3.9 GiB | 6.2 GiB |
| 省下來 | — | 5.2 GiB | 2.9 GiB |

- **`gemma3:4b` 直接淘汰**：排序壞了（「上前拉開」比機智的寫法還高、灌水的比胡扯的還高），JSON 會被截斷，
  而且玩家看得到的字裡夾外語——`zh.to_traditional` 救不了「alınd」跟「血bath」。
- **`qwen3:8b` 品質可用**，但整組分數往上平移一大截（45→85、10→65）：換上去等於放寬隨口應對的難度，
  要重調 `event_llm.SYSTEM_PROMPT` 的分數檔位（2026-10-13 從 26b 換到 12b 也做過同一件事），
  而 FB-223 的 `tests/test_fb223_evil_free_text.py` 拿 main 的提示詞守門，動它要一起處理。

## 換的話要做什麼（備著，現在不做）

1. `qwen3` 有思考模式：`ollama_think` 要確認送 `think: false`（現在的設定本來就是 false）。
2. 重調 `event_llm.SYSTEM_PROMPT` 的分數檔位，讓灌水與胡扯回到 0～5、機智落在 40～60。
3. 重跑 `try_say.py`（人物對話的歸類與文字）、`measure_gamble_load.py`（並發吞吐）、`try_duel_gamble.py`。
4. 設定覆寫檔寫 `ollama_model`（`Config` 欄位，profile 可以覆寫），不要改 `content/config.json`。
