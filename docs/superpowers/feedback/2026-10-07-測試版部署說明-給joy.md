# 測試版部署說明（給 joy，2026-10-07）

- 對象：joy（部署測試版的人）。PM 轉交。
- 這一版：四條分支都進 main 之後的 main——chain-on-main、stamina-refill（測試期一鍵補滿體力）、stamina-balance（體力平衡，GitHub PR #33）、rulings-1（企劃者對晉升與第 3、4 階的裁決，這一份說明跟著它進來）。四條都上 main 之後，QA 會在部署之前照驗收清單走一遍。
- 比較的基準：joy 上一次部署的是 **playtest-2026-10-04b（commit `774d657a`，資料庫第 1 版）**。下面寫的「變了什麼」都是從那一版算起，資料庫是**從第 1 版升到第 3 版**。
- 怎麼開伺服器、給網址、備份、換季的細節在 [beta-主機端操作.md](beta-主機端操作.md)；這份只寫這一次要留意的。

## 先說結論（PM 的四點）

1. **建議開新的資料庫、從零開一季。** 舊的資料庫也能用：新程式打開時會一版一版就地升級（第 1 版 → 第 2 版 → 第 3 版），可以留著。可是舊角色會停在舊規則留下的樣子，例如舊角色會被當成已經走完序章，新角色才有的那一段他們碰不到。要讓大家照這一版的樣子玩，請開新的。
2. **如果在 `774d657a` 之後還部署過別的版本**，請在 #pm 說是哪一個 commit，我們把中間的差異補上。
3. **部署完請回報部署的 commit**（`git log -1` 的那一串），PM 會打 `playtest-<日期>` 的 tag 記下這次試玩的基礎。
4. **只打開週末設定裡的「測試期一鍵補滿體力」**。伺服器自己的排程、模型佇列、伺服器推送三樣都維持關（預設就是關的，設定檔不要加它們的鍵）。

## 一、從上一次部署到這一版，變了什麼

只列玩家碰得到的大項（中間合了 joy 的 PR #18～#33，與我們這邊的幾十個計畫）：

- **武學與成長**：屬性五項（臂力、身法、根骨、悟性、博聞）只靠升級配點；意境（探索悟、善惡名到了悟）；三種合成（武學＋意境、意境＋意境、武學＋武學），配方全服共享、首創者取名；修練衝品質、絕學定名；功法庫的持有上限、熔煉、改練。
- **悟意境**：探索時偶爾「有所感」，照看到的畫面悟一個私有的意境（全服記每一處的首悟，寫進江湖史）。
- **新手引導**：草廬序章（師父帶著走完第一段）、投靠之後的入伍段、「碰到才說」的提示（一次一條）。
- **傳聞分層**：見聞頁分成天下大事、陣營軍情、地方傳聞、個人線索四層。
- **第一季正式版**：叛投；第 2 階行動與機緣；拼圖、推理、集體密謀；第 3、4 階的晉升（官軍、黃巾、豪強各自的晉升奇遇）；第 4 階的席次每週一照上一週的貢獻輪替；第 3、4 階的行動（黃巾煽動起事、豪強修築塢堡、在任的豪強趁亂占據郡縣）。
- **體力**：回體丹（PR #32）；測試期一鍵補滿體力（stamina-refill）；體力平衡（PR #33）：上限 250、探索與遊歷 6、交友 3，事件失敗另扣的體力減半、寫在選項上，新手期體力回復 ×3。
- **企劃者裁決（rulings-1）**：
  - 第 3、4 階行動推的那條線今天已經推滿（每人每曆日的上限）時，按鈕灰掉、寫「今天這條線已經推滿」，不再白花體力。
  - 召見一發出來（或往下一段、換人換了地點），去召見地點的那一條路就摸清，疾行到得了；樓桑里、下曲陽在地圖上沒摸清時也畫出名字。
  - 晉升卡住、沒有人能引見時說一句（一次）。
  - 求見大人物的門檻：第 4 階只有這一週在任的才算第 4 階。
  - 何進那一關的「給他。」銀兩不夠 50 兩時不出現。
  - 叛投之後，聽過的機緣線索留著（舊陣營的機緣做不了）。
  - 有檢定的行動照事件選項的寫法寫出屬性與心裡話。
  - 劇情戰打輸另扣的體力減半，寫在開打的選項上（「輸了多耗體力 N」）。

## 二、資料庫：第 1 版升到第 3 版

- **第 2 版**加了四張表（武學與成長）：改過的名字（`skill_aliases`）、合併出來的意境（`insights`、`insight_recipes`）、第一個練成絕學的人（`masters`）。
- **第 3 版**加了一張表（悟意境）：每一處的首悟（`insight_firsts`）。
- 只加表、不改舊表。舊檔打開時，在同一筆交易裡一版一版升上來；中途出錯整個撤回，檔還是第 1 版。
- **升上去之後，舊版程式就打不開了**（會說「資料庫結構是第 3 版，這版程式只認得第 1 版」）。所以要用舊的資料庫，**先備份**（`beta-主機端操作.md`「怎麼備份資料庫」，或伺服器關著的時候直接複製那個 `.db` 檔）。
- 角色存檔是 JSON，這中間新加的欄位都有預設值，舊角色讀得進來。rulings-1 沒有動結構（新加的「說過沒有人能引見」記號存在角色的 JSON 裡）。

## 三、設定

### 週末設定（`content/profiles/weekend.json`）

兩個程式啟動前都設 `$env:TIANXIA_PROFILE = "weekend"`。它一次換掉四個值：

| 鍵 | 值 | 意思 |
|---|---|---|
| `season_one` | `true` | 第一季濃縮版的規則開 |
| `season_days` | `2.5` | 一季 2.5 天（12 週，一週約 5 小時） |
| `server_max_players` | `2` | 陣營規模、軍令額度照 2 人算 |
| `beta_free_refill` | `true` | 測試期一鍵補滿體力：狀態列體力條上那顆鈕寫「補滿」，按一下補到滿、不花丹 |

啟動時「資料庫：…」下面會印：

`設定：weekend（第一季濃縮版規則開啟、季長 2.5 天、人數上限 2）　測試期一鍵補滿體力：開`

最後那句就是補滿開著的記號。測試期結束時從 `weekend.json` 拿掉 `beta_free_refill`，這句就不再印。

### 四條分支新加的設定欄位

都有預設值，**不用另外設**；正式的數字已經寫在 `content/config.json` 或 `weekend.json` 裡。

| 分支 | 欄位 | 預設 | 這一版用的值 |
|---|---|---|---|
| chain-on-main | `rank3_contrib`、`rank4_contrib` | 900、1800 | 同預設（升第 3、4 階要的本季貢獻） |
| stamina-refill | `beta_free_refill` | `false` | `weekend.json` 打開 |
| stamina-refill | `beta_free_refill_label` | 「補滿」 | 同預設（鈕上的字） |
| stamina-balance（PR #33） | `event_fail_stamina_scale` | 1 | `config.json` 0.5（事件失敗、劇情戰打輸另扣的體力減半） |
| stamina-balance（PR #33） | `newbie_stamina_days`、`newbie_stamina_multiplier` | 18、1 | `config.json` 的倍數是 3（新手期 18 個季曆天體力回復 ×3；週末季約 13 小時） |
| stamina-balance（PR #33） | `newbie_days`（舊欄位，改了預設） | 3 → 18 | 新手期氣血回復加倍的天數，跟體力同一段 |
| rulings-1 | （沒有新欄位） | | |

PR #33 另外改了 `config.json` 的幾個數字：`stamina_max` 150 → 250、`stamina_pill_restore` 150、`action_cost` 探索 6、遊歷 6、交友 3。

## 四、怎麼開

伺服器要的套件跟 `774d657a` 一樣（`requirements.txt` 沒變；`requirements-dev.txt` 是新的，只有跑測試才要）。本機 AI 一樣是 Ollama 的 `gemma4:26b`，要開著。

**視窗一：伺服器**（資料庫的路徑換成你的；開新的就寫一個還不存在的檔名）

```powershell
cd <專案資料夾>
$env:TIANXIA_DB = "<資料庫檔>"
$env:TIANXIA_PROFILE = "weekend"
.venv\Scripts\python.exe -u server.py --port 7861 --share
```

**視窗二：假人**——照 PM 10/6 的決定，這次試玩**先不開**假人。之後要開時，另開一個視窗、設**同一個**資料庫與設定：

```powershell
cd <專案資料夾>
$env:TIANXIA_DB = "<資料庫檔>"
$env:TIANXIA_PROFILE = "weekend"
.venv\Scripts\python.exe -u run_bots.py
```

- `-u` 一定要加：輸出導到檔案時沒有它，log 會一直是空的。
- 兩個程式啟動時都印「資料庫：…」與「設定：…」，兩邊要一樣。
- `--share` 要先裝好 cloudflared（`beta-主機端操作.md`「第一次要先做的」）。網址大約 7 秒後印在「公開網址：…」那一行。停的時候用 `taskkill /PID <PID> /T /F` 關整棵，不然 cloudflared 會留著。

**開新的資料庫時**：

1. 第一次開，賽季停在「籌備中」。先替管理者建角色（`Rayal` 在 `content/config.json` 的 `admins` 裡）：
   `.venv\Scripts\python.exe scripts\set_password.py Rayal --character Rayal --db <資料庫檔>`（密碼寫到 `.local/`，不印在畫面上）。
2. 用 `Rayal` 登入，右上角 ⚙ → 管理者工具 →「開季」。
3. 同一個抽屜往下是「時刻表」：長社火攻、宛城之戰、廣宗決戰、季末四件，不改就照預設（第 6、9、11 週中與第 12 週末，開季後 60 小時收季）；要改照 `beta-主機端操作.md`「換成第一季濃縮版的那一天」第 4 步。

**照用舊的資料庫時**：先備份；打開之後它就是第 3 版。舊的那一季要收掉、開一季新的，照 `beta-主機端操作.md`「換成第一季濃縮版的那一天」第 2～5 步（收季 → 帶週末設定重開 → 開啟下一季 → 大家重新登入）。帳號和江湖史留著，角色照換季的規矩重來。

## 五、玩起來要留意的

- 體力的數字都變了（上限 250、探索與遊歷 6）。一個人推同一條戰線，一個曆日只推得動 10 點（每人每曆日的上限沒變）：第 3、4 階的行動一天大概兩次就會灰掉，隔一個曆日（週末季約 43 分鐘）再來。
- 召見一發出來就會在輿圖上摸清那一條路；有人回報「召見的地方去不了」請記下是哪個陣營、從哪裡出發。
- 劇情戰打輸另扣的體力減半了；「改成扣別的（氣血、銀兩、名望）」是內容那一邊的事，列在 [待 joy 潤的句子](../specs/2026-10-06-第一季正式版-待joy潤的句子.md) 第八節，之後再做。
