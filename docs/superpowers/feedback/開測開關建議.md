# 開測前：週末設定要打開哪些開關（建議表）

Infra 2026-10-06 寫給 PM，PM 拿去問企劃者。照 main `a5fe9aa` 的程式寫：排程、推送、LLM 佇列、備份都已在 main；帳號（LINE／Google）與壓測 Task 3～4 擱著。

**前提**：這一輪是跟 joy 測，在線的真人兩三個。試玩伺服器用週末設定（`content/profiles/weekend.json`，現在是 `{"season_one": true, "season_days": 2.5, "server_max_players": 2}`），對外照舊用 `server.py --share` 的 trycloudflare 網址，登入照舊用帳號密碼。

**每一個開關都可以單獨關回去**：改設定檔、重開伺服器就好，資料不用動。伺服器啟動時會各印一行「排程：…」「模型佇列：…」「推送：…」，一眼看得出開了哪些。

## 建議表

| 開關 | 建議 | 理由 | 風險與怎麼退 |
|---|---|---|---|
| `season_one`、`season_days: 2.5`、`server_max_players: 2` | **照現在的週末設定** | 第一季濃縮版的規則、2.5 天一季、需求量照兩人換算，都是這一輪要測的東西 | 已經測過好幾輪，不動 |
| `world_tick_seconds`（伺服器自己的排程） | **開，10** | 2.5 天的季會跨好幾個晚上。人少、假人又不開（10/4 定的）時，沒有人開著網頁，世界就不會動：<br>・時刻表的大事要等下一個人上線才一次補算；<br>・排定的決戰在沒人時會被跳過，照前線起點直接判結果（T8 的 I-1）；<br>・**大家睡醒才發現長社已經打完了**。<br>開了之後，大事準時發生；決戰到點就開集結，白天有人時才打得到 | 每 10 秒拿一次行動鎖，兩三個人時負擔可以忽略。某一下出錯會印「排程這一下出錯」，下一輪照跑。退回：改成 0 重開 |
| `push_events`（伺服器推送） | **開**，前提是 QA 驗過「經過 trycloudflare 收得到」那一步（推送計畫 Task 4 第 6 項）；**沒驗過就先關** | 決戰一回合結算、另一個分頁做了動作，幾秒內就更新，不用等 10 秒；平常每 60 秒才輪詢一次。兩三個人時負擔本來就不大，好處在「看得到即時的變化」 | 推送一斷，前端自己退回每 10 秒輪詢，玩家不會卡住。唯一沒把握的是 trycloudflare 中間會不會把串流攔住，所以要先驗。退回：改成 false 重開 |
| `llm_queue_slots`（LLM 佇列） | **開，1**（一張顯卡） | 只有一張顯卡，兩三個人同時對話或開爐時，本來就會在 Ollama 那邊排隊。開了佇列多三件事：<br>・同一個人連按兩下或開兩個分頁，不會叫兩次模型；<br>・排超過 20 秒直接用退路，不會拖到 trycloudflare 約 100 秒切斷；<br>・按鈕上看得到「前面還有幾件」 | 兩三個人時很少排到隊。最壞的情況是有人排了 20 秒拿到退路（對話那一輪取消、不扣體力；開爐用字表取名）。退回：改成 0 重開 |
| `llm_queue_bot_cap: 1`、`llm_queue_wait_seconds: 20` | **照預設** | 假人不開時用不到上限；20 秒加上模型自己的預算，整段仍在 100 秒以內 | — |
| `push_watch_seconds: 5`、`push_world_min_seconds: 10` | **照預設** | 世界變了最慢 5 秒內發現，兩次通知至少隔 10 秒，最壞跟輪詢一樣 | — |
| 模型的時間預算（`dialogue_budget_seconds`、`naming_budget_seconds`、`big_fight_budget_seconds`，都是 60；鎖內 `in_lock_model_timeout` 15） | **照預設** | 都已經是照 trycloudflare 約 100 秒切斷訂的 | — |
| `ollama_keep_alive: "12h"`（`content/config.json`） | **照現在** | 大模型冷啟動第一次要 32 秒，會超過遊戲的時限。開測前先叫一次模型讓它常駐（例如管理者自己先跟人物說一句話） | 不叫一次的話，第一個玩家的第一句話會走退路 |

## 設定檔怎麼改

照上面的建議，`content/profiles/weekend.json` 改成下面這樣。推送那一行要等 QA 驗過才加：

```json
{
  "season_one": true,
  "season_days": 2.5,
  "server_max_players": 2,
  "world_tick_seconds": 10,
  "llm_queue_slots": 1,
  "push_events": true
}
```

這是內容檔，企劃者點頭之後由專職開發或 PM commit，換上試玩伺服器時照主機文件「換成第一季濃縮版的那一天」的步驟重開。

## 開測前要先做、先驗的

1. **備份**：
   - 換程式、改設定之前，先手動備份一次（主機文件「怎麼備份資料庫」）；
   - 企劃者自己貼好每日備份的排程。
2. **重開後看啟動訊息**，四行都要對：
   - `設定：weekend（…）`
   - `排程：每 10 秒…`
   - `模型佇列：同時 1 件…`
   - `推送：開…`（或是 `推送：關…`，看第 3 項的結果）
3. **推送經過 trycloudflare**：
   - 手機打開公開網址，另一個分頁做一個動作，看手機在 1～2 秒內跟著刷新；
   - 不行就把 `push_events` 拿掉重開，其他照開。
4. **排程**：關掉所有網頁等一陣子再打開，季曆時間有往前走、到了的大事已經在本週大事卡上。
5. **模型常駐**：管理者先跟人物說一句話，確認不是退路（不是「那一輪對話取消」）。
