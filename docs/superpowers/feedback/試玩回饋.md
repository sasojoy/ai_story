# 試玩回饋清單

由 QA session 維護：收企劃者試玩的回饋、自動測試與模擬發現的問題，重現後整理給 PM。

第一次 beta 換上伺服器前，要照 [beta 驗收清單](beta-驗收清單.md) 在本機跑一遍。

- **分類**：錯誤／平衡／設計問題／內容（文字、事件）／體驗（介面、流程）
  - 企劃者試玩時說「這個要改」「這個要再想」的，一律標「設計問題」，並附相關設計段落（PM 會把流程圖上那一項改成討論中）。
- **嚴重度**：阻擋試玩／嚴重／一般／小
  - 會擋住第一次 beta（企劃者和朋友從零開季、用 gradio.live＋帳號密碼來玩）的，嚴重度後面另外加「**beta 前要修**」。
- **狀態**：新／已回報 PM／已分派給某 session／已修好待複測／✅ 已驗證／不處理
  - 「✅ 已驗證」＝ QA 照原本的重現步驟複測通過（PM 會把對應功能改成已完成）。
- **第一次 beta 改用新網頁**（企劃者 2026-10-03 決定，分支 `claude/project-thread-w2myt7`，不再用 Gradio）。第 2 輪仍在 Gradio（`1640c1e`）上收回饋；畫面類的問題（煉製、門下、按鈕、版面）另外註明「**新網頁也要驗**」，新網頁接上主線後要在新畫面上再確認一次。
- 原型階段**先不驗效能、卡頓、穩定性**（企劃者 2026-10-03）；企劃者自己碰到的卡頓照常記錄，但除非卡到不能玩，嚴重度不往上拉。

## 細節

### FB-001 操練之後接到「苦戰之後」的戰後事件

- **在哪裡**：歷練遇到自己陣營的隊伍、改成操練時（例如黃巾陣營在潁川郊外遇到黃巾散兵）。
- **看到什麼**：
  ```
  你與黃巾散兵一同操軍擺陣，軍心為之一振。
  心得 +12
  【拆招頓悟】
  一番苦戰之後，方才對手的一招在你腦海中反覆浮現。
  ```
- **預期**：操練不打架，不該接「苦戰」「打鬥剛歇」的戰後事件。或者這兩個事件改成只在真的打過之後才會觸發。
- **原因**：`tianxia/engine.py::_train()` 不管 `_squad_encounter()` 走的是開打還是操練（`_drill()`），打完都會以 `train_event_chance`（`content/config.json` 為 0.3）的機率抽 `actions: ["train"]` 的事件。符合條件的兩個事件 `train_insight`、`train_onlooker`（`content/events/general.json`），文字都是戰後的情境。
- **為什麼測試沒抓到**：`tests/conftest.py` 的 `game` fixture 把 `train_event_chance` 設成 0。
- **重現**：用真實 `content/`，把 `train_event_chance` 設成 1、玩家設成黃巾、站在有黃巾隊伍的地點按「歷練」。20 個 seed 全部重現（20/20）。可以直接放進 `tests/test_engine.py` 的失敗測試：
  ```python
  def test_a_drill_is_not_followed_by_a_post_fight_event(content):
      """操練不是打架，不該接『一番苦戰之後』這類戰後事件。"""
      from tianxia.engine import Game
      _training_factions(content)
      content.squads["thug"].faction = "huang"
      content.config.train_event_chance = 1.0
      game = Game.new(content, "沈浪", rng=random.Random(0))
      game.state.player.faction = "huang"
      game.choose("move:lake")
      msgs = game.choose("act:train")
      assert any("操軍擺陣" in m for m in msgs)
      assert game.state.pending_event is None
  ```
  QA 在 `802bb1e` 實跑過，這個測試會失敗：`AssertionError: assert 'chain_a' is None`。fixture 內容裡湖邊的 `chain_a` 就是 `actions: ["train"]` 的事件，操練之後被抽中。
- **相關設計**：`docs/superpowers/specs/2026-10-02-第一季黃巾之亂-design.md` 第 209 行「歷練看陣營」：操練的定義是不打。
- **建議歸屬**：開發 session（小改：`_train()` 遇到操練就不抽戰後事件，或給操練另寫一組事件）。
- **處理**：地圖擴充開發修在 `f91531a`，改成操練不抽戰後事件、真的打過才抽，並把上面那段測試加進 `tests/test_engine.py`。主線 `49a9763` 上 986 個測試全過。
- **QA 程式層面確認**（2026-10-03，主線 `49a9763`，真實內容、`train_event_chance` 設成 1）：
  - 黃巾在潁川郊外操練 20 次，接到戰後事件 0 次（修之前 20 次）。
  - 散人在同一地點真的開打 20 次，20 次都接到戰後事件，真打的情況沒被改壞。
  - 還沒在試玩伺服器上看過畫面，所以不標「已驗證」。等伺服器換版後，到有自己陣營隊伍的地點歷練幾次，確認操練後不再跳出「拆招頓悟」「錦衣少年」。

### FB-002 「經驗（每人）」實際上只有本人拿到，同伴永遠第 1 級

- **在哪裡**：歷練打贏或操練之後的戰報、江湖紀錄。
- **看到什麼**：紀錄寫「經驗 +15（每人）」。
- **實際**：全程式只有兩處呼叫 `team.add_exp()`：`tianxia/engine.py:991`（操練）和 `:1031`（打贏），傳進去的都是 `p.member`（玩家本人）。同伴的 `CompanionProgress.level`／`exp`（`tianxia/world_state.py:72-73`）沒有任何地方會增加。
- **影響**：等級決定氣血上限（300＋20×等級，見 `2026-09-30-氣血門戶名冊-design.md`），所以同伴的氣血上限永遠停在第 1 級。A1 方案上線之後，戰鬥會扣氣血、累積內傷，同伴會越打越虛。
- **要企劃者決定的**：同伴該不該跟著拿經驗、升級？
  - 該：這是錯誤，同伴要一起加經驗。
  - 不該：「（每人）」是 3v3 時代留下的字，要拿掉。
- **重現**：讀程式即可確認（上面兩個呼叫點）。也可以帶一個同伴歷練幾場，到門下頁看同伴的等級。
- **建議歸屬**：開發 session（等企劃者回答上面的問題再修）。
- **企劃者決定**（2026-10-03，PM 轉達）：同伴也要跟著拿經驗、升級。交給地圖擴充開發，進第一次 beta。
- **複測方式**：帶一個同伴歷練或操練幾場，到門下看同伴的等級和經驗有沒有增加、升級時氣血上限有沒有跟著長。

### FB-003 決戰逾時一律代選官軍的「穩守」（已知、已排修）

- **來源**：PM 審程式時發現，2026-10-03 通知 QA。不必重現。
- **位置**：`tianxia/engine.py:709-711`。逾時代選的 tag 是 `min(definition.action_tags, key=neili_damage)`，只挑一個，不分陣營。`battle_instance.fill_timed_out_actions()` 再把這個 tag 套給所有還沒出手的人。
- **影響**：黃巾那邊沒出手的人，會替官軍推 +2 戰局。企劃者這一輪打到決戰、覺得黃巾莫名吃虧，原因就是這個。
- **嚴重度為什麼標嚴重**：決戰是一季的重頭戲。多人同時在線時，逾時沒出手很常見，這個錯會有系統地偏向官軍一邊。
- **處理**：地圖擴充開發修在 `8342d54`（跟「決戰要人在大區」同一個 commit）。逾時時改成每個人代選**自己陣營**最保守的固定選項（`battle_instance.safest_option_tag()`），官軍選 `guan_safe`、黃巾選 `huang_safe`。這一幕沒有他能選的固定選項時，才退回全表最溫和的那個。主線 `1de6a1a`。
- **QA 程式層面確認**（2026-10-03，主線 `1de6a1a`）：用真實 `content/battles.json` 的黃巾決戰，官軍、黃巾各一人都不出手，連跑 12 回合逾時。每回合都代選 `甲: guan_safe`、`乙: huang_safe`，戰局一直停在 50 沒動（修之前全員代選同一招，會一直往官軍推）。還沒在伺服器上看過畫面，所以不標「已驗證」。
- **複測方式**（修好之後）：開一場有陣營的決戰，讓黃巾那邊有人不出手、等回合逾時，確認代選的行動是黃巾自己的保守選項，戰局不會往官軍推。

### FB-004 真人可以取大勢人物的名號

- **在哪裡**：註冊後「取一個名號」那一步。
- **現況**：`app.py::name_taken()`（主線 `b76d8b6`，約 629 行）只擋三種名號：已有存檔的、綁在帳號上的、管理者的。所以真人可以取「曹操」「張角」「劉備」。
- **對照**：
  - 假人取名會避開趙雲、周瑜等 105 個名人，以及遊戲裡人物的名字（裁決第 7 條、`specs/2026-10-02-伺服器假人-design.md` 第 59 行）。
  - 對真人，設計文件沒有寫要不要擋。
- **影響**：beta 時朋友取「曹操」，江湖紀錄會寫「曹操升到第 2 級！」，跟譙縣那位大勢人物曹操混在一起，求見、傳聞、戰報都容易看錯。
- **要企劃者決定的**：
  - 要擋：沿用假人那份名人加人物名單，訊息也用「這個名號已有人使用。」，才不會透露名單。這要在 beta 前改好。
  - 不擋：當成玩家的自由，記為不處理。
- **建議歸屬**：開發 session（決定要擋的話，是小改）。
- **企劃者決定**（2026-10-03，PM 轉達）：擋掉。真人不能取大勢人物和名人的名號，回「這個名號已有人使用。」。交給 Infra，進第一次 beta。
- **複測方式**：註冊新帳號，名號依序試「曹操」「張角」「趙雲」，都要回「這個名號已有人使用。」，跟名號被真人用掉時一字不差。再試一個普通的名號，要能建立角色。

### FB-005 煉製不能把同一樣素材放兩次

- **企劃者的話**：「我剛剛試著丟同一個材料煉製~但介面看起來沒有辦法重複丟入」
- **在哪裡**：門下頁的「煉製」，素材複選選單。
- **原因**：`app.py` 的素材選單是 `gr.Dropdown(multiselect=True, max_choices=2)`，每種素材只是一個選項（「精鐵砂（凡品・屬剛）×2」），複選不能選同一個值兩次。
- **設計怎麼寫**：`specs/2026-10-01-無限煉製-design.md`
  - §5.1：「一次煉製吃**兩樣素材**（可以同種）……配方空間 ＝ C(12+1, 2) × 2 ＝ 156」
  - §8：「選兩樣（可選同一樣兩次）」
- **規則引擎本身沒問題**：`craft.can_craft()` 用 `material_ids.count(mid)` 檢查數量。QA 在伺服器那一版（`1640c1e`）用 `Game.craft(["gang_1", "gang_1"], "武學")` 實跑，成功煉出一門武學，背包的精鐵砂 ×2 扣成 0。
- **影響**：
  - 配方空間 156 個裡，同種的 24 個（12 種 × 內功／武學）在畫面上永遠煉不到。
  - 素材少的時候，手上常常只有同一種湊得出兩個，結果什麼都煉不了。
- **建議歸屬**：開發 session（改選單：例如兩個各自單選的欄位「第一樣」「第二樣」，或讓數量 ≥2 的素材在選單裡出現兩次）。主線上 sasojoy 改過的煉製頁仍是同一個選單，要一起改。
- **新網頁也要驗**（2026-10-03）：beta 改用新網頁之後，QA 讀了分支 `claude/project-thread-w2myt7` 的 `web/app.js`。新的煉製分頁把素材做成卡片，同一種可以點兩次，點到剩 0 張就停用，看起來已經解決。Infra 接上主線後，在新畫面上照上面的重現步驟複測。

### FB-006 煉出來的功法沒有地方看說明

- **企劃者的話**：「煉製【沉柳纏勁】煉製【鐵柳纏勁】 在哪個介面可以看到技能的說明??」
- **現況**（伺服器 `1640c1e`，主線 `1456968` 一樣）：
  - 模型寫的那句說明（`MartialArt.note`，例如沉柳纏勁是「招式如垂柳般綿密且沉重難測」）**只在煉成的那一刻**出現在門下頁的結果訊息裡。
  - 江湖紀錄只記一行「煉製【沉柳纏勁】」，不含說明。
