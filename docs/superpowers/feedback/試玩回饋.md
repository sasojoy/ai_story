# 試玩回饋清單

由 QA session 維護：收企劃者試玩的回饋、自動測試與模擬發現的問題，重現後整理給 PM。

- **分類**：錯誤／平衡／設計問題／內容（文字、事件）／體驗（介面、流程）
  - 企劃者試玩時說「這個要改」「這個要再想」的，一律標「設計問題」，並附相關設計段落（PM 會把流程圖上那一項改成討論中）。
- **嚴重度**：阻擋試玩／嚴重／一般／小
- **狀態**：新／已回報 PM／已分派給某 session／已修好待複測／✅ 已驗證／不處理
  - 「✅ 已驗證」＝ QA 照原本的重現步驟複測通過（PM 會把對應功能改成已完成）。
- 原型階段**先不驗效能、卡頓、穩定性**（企劃者 2026-10-03）；企劃者自己碰到的卡頓照常記錄，但除非卡到不能玩，嚴重度不往上拉。

## 細節

### FB-001 操練之後接到「苦戰之後」的戰後事件

- **在哪裡**：歷練遇到自己陣營的隊伍、改成操練時（例如黃巾陣營在潁川郊外遇到黃巾散兵）。
- **看到什麼**：
  ```
  你與黃巾散兵一同操軍擺陣，軍心為之一振。
  心得 +12
  【拆招頓悟】
  一番苦戰之後，方才對手的一招在你腦海中反覆浮現。
  ```
- **預期**：操練不打架，不該接「苦戰」「打鬥剛歇」的戰後事件。或者這兩個事件改成只在真的打過之後才會觸發。
- **原因**：`tianxia/engine.py::_train()` 不管 `_squad_encounter()` 走的是開打還是操練（`_drill()`），打完都會以 `train_event_chance`（`content/config.json` 為 0.3）的機率抽 `actions: ["train"]` 的事件。符合條件的兩個事件 `train_insight`、`train_onlooker`（`content/events/general.json`），文字都是戰後的情境。
- **為什麼測試沒抓到**：`tests/conftest.py` 的 `game` fixture 把 `train_event_chance` 設成 0。
- **重現**：用真實 `content/`，把 `train_event_chance` 設成 1、玩家設成黃巾、站在有黃巾隊伍的地點按「歷練」。20 個 seed 全部重現（20/20）。可以直接放進 `tests/test_engine.py` 的失敗測試：
  ```python
  def test_a_drill_is_not_followed_by_a_post_fight_event(content):
      """操練不是打架，不該接『一番苦戰之後』這類戰後事件。"""
      from tianxia.engine import Game
      _training_factions(content)
      content.squads["thug"].faction = "huang"
      content.config.train_event_chance = 1.0
      game = Game.new(content, "沈浪", rng=random.Random(0))
      game.state.player.faction = "huang"
      game.choose("move:lake")
      msgs = game.choose("act:train")
      assert any("操軍擺陣" in m for m in msgs)
      assert game.state.pending_event is None
  ```
  QA 在 `802bb1e` 實跑過，這個測試會失敗：`AssertionError: assert 'chain_a' is None`。fixture 內容裡湖邊的 `chain_a` 就是 `actions: ["train"]` 的事件，操練之後被抽中。
- **相關設計**：`docs/superpowers/specs/2026-10-02-第一季黃巾之亂-design.md` 第 209 行「歷練看陣營」：操練的定義是不打。
- **建議歸屬**：開發 session（小改：`_train()` 遇到操練就不抽戰後事件，或給操練另寫一組事件）。

### FB-002 「經驗（每人）」實際上只有本人拿到，同伴永遠第 1 級

- **在哪裡**：歷練打贏或操練之後的戰報、江湖紀錄。
- **看到什麼**：紀錄寫「經驗 +15（每人）」。
- **實際**：全程式只有兩處呼叫 `team.add_exp()`：`tianxia/engine.py:991`（操練）和 `:1031`（打贏），傳進去的都是 `p.member`（玩家本人）。同伴的 `CompanionProgress.level`／`exp`（`tianxia/world_state.py:72-73`）沒有任何地方會增加。
- **影響**：等級決定氣血上限（300＋20×等級，見 `2026-09-30-氣血門戶名冊-design.md`），所以同伴的氣血上限永遠停在第 1 級。A1 方案上線之後，戰鬥會扣氣血、累積內傷，同伴會越打越虛。
- **要企劃者決定的**：同伴該不該跟著拿經驗、升級？
  - 該：這是錯誤，同伴要一起加經驗。
  - 不該：「（每人）」是 3v3 時代留下的字，要拿掉。
- **重現**：讀程式即可確認（上面兩個呼叫點）。也可以帶一個同伴歷練幾場，到門下頁看同伴的等級。
- **建議歸屬**：開發 session（等企劃者回答上面的問題再修）。

### FB-003 決戰逾時一律代選官軍的「穩守」（已知、已排修）

- **來源**：PM 審程式時發現，2026-10-03 通知 QA。不必重現。
- **位置**：`tianxia/engine.py:709-711`。逾時代選的 tag 是 `min(definition.action_tags, key=neili_damage)`，只挑一個，不分陣營。`battle_instance.fill_timed_out_actions()` 再把這個 tag 套給所有還沒出手的人。
- **影響**：黃巾那邊沒出手的人，會替官軍推 +2 戰局。企劃者這一輪打到決戰、覺得黃巾莫名吃虧，原因就是這個。
- **嚴重度為什麼標嚴重**：決戰是一季的重頭戲。多人同時在線時，逾時沒出手很常見，這個錯會有系統地偏向官軍一邊。
- **複測方式**（修好之後）：開一場有陣營的決戰，讓黃巾那邊有人不出手、等回合逾時，確認代選的行動是黃巾自己的保守選項，戰局不會往官軍推。
