## 先講結論（四件事）

1. **一定要在休季換。** 季還在跑的時候換新程式，季曆和時刻表會整個算錯（FB-520）。
2. **換之前先手動備份。** 這一份是唯一回得去的路。
3. **資料庫會從第 5 版升到第 6 版，升了就回不去。** 舊程式（main）打開第 6 版的檔會直接停下來；要退回只能還原第 2 步的備份。
4. **要部署的版本：`develop` 的 `b1150372`**（整套測試 9659 條全過；之後 develop 上只有文件的 commit，程式一樣）。

## 這一次換了什麼

- **程式**：develop，比線上的 `main`（`96939b1d`）多了：正式季十批、同伴、找素材分支、武學隨地理、商城、7 天濃縮季。套件（`requirements.txt`）沒變、`run_bots.py` 沒變，不用重裝。
- **設定**：一樣是 `TIANXIA_PROFILE=week7`（看守的 `start_*.cmd` 已經帶著，不用改），但 **week7 的內容換了**：
  - 舊的 week7 是「週末式」（一季 12 週壓進 7 天）；新的是**照現實天**：畫面寫「第 N 天 HH:MM」，三場大決戰在**第 2、4、7 天 20:00**，每天的軍令、懸賞、簽到。
  - 打開商城：每個角色第一次進來發 **5000 元寶**（假人也發，但假人不買東西）。
- **資料庫**：新程式第一次打開就自動升到第 6 版（多三張商城的表）。

## 步驟

以下指令都在線上主機的 PowerShell 打。程式資料夾是 `C:\Users\User\Documents\ai_story-tianxia`，資料庫是它底下的 `saves\tianxia.db`（看守的 `start_*.cmd` 就是用這一份）。備份、還原、對帳的腳本沒給 `--db` 時讀環境變數 `TIANXIA_DB`、沒設就是 `saves\tianxia.db`，所以**這個視窗不要設 `TIANXIA_DB`**（`echo $env:TIANXIA_DB` 要是空的）。

0. **暫停看守**（不然五分鐘內會把你停掉的東西開回來）：

   ```powershell
   New-Item C:\Users\User\tianxia-ops\PAUSED -ItemType File
   ```

1. **確認是休季**：用管理者帳號登入 → ⚙ → 管理者工具，要寫「休季中」。
   - 這一季還在跑：先「⚠ 立刻收季」→「確定收季」（用現在的舊程式收）。
   - 看到伺服器印 `⚠ 正在跑的這一季是用另一種季曆開的……` 那一行，就是季還在跑：先停下來，照最後一節「出事怎麼回去」。

2. **停伺服器與假人**（監控頁與隧道可以不停）：

   ```powershell
   Get-CimInstance Win32_Process -Filter "Name='python.exe'" | Where-Object CommandLine -match 'server\.py|run_bots\.py' | ForEach-Object { taskkill /PID $_.ProcessId /T /F }
   ```

   停完再跑一次同一行的前半段（拿掉 `| ForEach-Object …`），確認沒有東西了。

3. **手動備份**（舊程式還在的時候做）：

   ```powershell
   cd C:\Users\User\Documents\ai_story-tianxia
   .venv\Scripts\python.exe scripts\backup_db.py --dest <你平常放手動備份的資料夾>
   ```

   要印「已備份：…（**結構第 5 版**、帳號 N、角色 N、季 N、江湖史 N）」。把檔名記下來、旁邊寫「7 天季上線前」。手動備份不會被自動刪。

4. **換程式**：

   ```powershell
   cd C:\Users\User\Documents\ai_story-tianxia
   git status
   git fetch origin
   git checkout --detach b1150372
   git log -1 --oneline
   ```

   - `git status` 只能看到 `saves\` 這類沒進版控的東西；如果有改過的程式檔（例如你在這台改過的設定），**先不要換**，跟 PM 說一聲。
   - `git log -1` 要印 `b1150372 Merge the 7-day compressed test season into develop …`。

5. **開服務**：刪掉暫停檔、叫看守馬上跑一次（它用 `start_server.cmd`／`start_bots.cmd`，已經帶 `week7`）：

   ```powershell
   Remove-Item C:\Users\User\tianxia-ops\PAUSED
   Start-ScheduledTask -TaskName tianxia-watchdog
   ```

   等一兩分鐘，看伺服器與假人的 log（`start_*.cmd` 導出去的那兩個 `*_out.log`）：
   - 兩邊都要印「資料庫：…saves\tianxia.db」與「設定：week7（第一季濃縮版規則開啟、季長 7 天、人數上限 20）」，而且**一樣**。
   - **不能有 `⚠ 正在跑的這一季是用另一種季曆開的……` 那一行**（休季時不會印）。
   - 確認資料庫升好了（唯讀，伺服器開著也可以跑）：

     ```powershell
     .venv\Scripts\python.exe -c "import sqlite3; print(sqlite3.connect(r'file:C:\Users\User\Documents\ai_story-tianxia\saves\tianxia.db?mode=ro', uri=True).execute('PRAGMA user_version').fetchone())"
     ```

     印 `(6,)` 就是升好了。預演時角色、帳號、陣營、等級、銀兩、江湖紀錄、戰報、上一季的江湖史都在。

6. **開下一季**：管理者帳號登入 → ⚙ → 管理者工具 →「⚠ 開啟下一季」→ 確定。
   - **建議週一早上開**（PM 建議）：開季那一天就是第 1 天（照台灣 00:00 算，不管幾點開），所以早上開第 1 天才完整；週一開的話，三場大決戰落在**週二、週四、週日的 20:00**，最後一場剛好在週日晚上。
   - 第 1 天 00:00、12:00 的大事如果開季時已經過了，會當場補結算，正常。
   - 時刻表照天自己排，不必手排三場決戰。

7. **自己登入看一眼**：
   - 狀態列名號底下寫「📍 地名　第 1 天 HH:MM」（不是「第 N 週・週X」）。
   - 右上角錠子鈕寫 5000，江湖紀錄有一則「商城」；點錠子鈕或底部「寶／商城」打開萬寶閣。

## 元寶與對帳

- **自動發**：每個角色自己第一次進來的那一下發 5000，寫一則「商城」紀錄；之後不再發。休季、籌備中也發。假人輪到它的那一輪也發（假人不買），所以對帳的「發出」會比真人數多，正常。
- **補發、扣回、退一筆**：管理者 → ⚙ → 管理者工具 → 商城那一組（查帳 → 補發／扣回要寫原因；某一筆買錯按「退這一筆」）。每一筆都記進帳、寫誰經手。
- **對帳**（唯讀，不會改資料庫，伺服器開著也可以跑）：

  ```powershell
  cd C:\Users\User\Documents\ai_story-tianxia
  .venv\Scripts\python.exe scripts\mall_ledger.py --db saves\tianxia.db --out <備份資料夾>\mall-YYYYMMDD.csv
  ```

  要對得上：**發出 − 花掉 ＝ 餘額合計**；「負的餘額」要是「沒有」。升級之前跑只會印「這份資料庫還是第 5 版（還沒升級），沒有商城的帳」，不會把它升級。一定要給 `--out`。

## 出事怎麼回去

- **只換回舊程式不行**：資料庫已經是第 6 版，舊程式一開就停（不會讀壞，只是開不起來）。
- **要回到上線前**：
  1. 先建 `PAUSED`，照第 2 步停伺服器與假人。
  2. 還原第 3 步的備份：`.venv\Scripts\python.exe scripts\restore_db.py <第 3 步的備份檔>`（資料庫照預設的 `saves\tianxia.db`）。要印「已還原：…（結構第 5 版、…）」；原本的第 6 版檔會改名留著（`tianxia.db.pre-restore-…`）。
  3. 程式換回 main：`git checkout main`（`96939b1d`）。
  4. 刪 `PAUSED`、`Start-ScheduledTask -TaskName tianxia-watchdog`。上線之後的進度（新的一季、元寶的帳）都會沒有。
- **只是商城出問題**：把 `content\profiles\week7.json` 裡 `"mall": {"enabled": true, "beta_grant": 5000}` 的 `true` 改成 `false`，伺服器與假人重開。商城入口與 API 不見、不再發元寶，其餘照跑；帳都留著，改回 `true` 就回來。（這條預演沒驗過。）
- **季已經在新程式底下開了，才發現時刻表或季曆不對**：先「⏸ 暫停賽季時鐘」，再找 PM。

## 預演沒驗到的

- 線上那一份資料庫的大小與升級要多久（預演的檔只有幾百 KB，升級是瞬間）。
- `run_bots.py` 與伺服器同時第一次開舊檔時誰先升級（兩個都會等寫入權，照理不會撞）。
- 商城的緊急開關、固定網域、隧道、看守、省電模式。
