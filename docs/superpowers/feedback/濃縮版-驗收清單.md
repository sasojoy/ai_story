# 第一季濃縮版驗收清單

第一季濃縮版要讓企劃者和 joy 用一個週末（約 60 小時），從開季玩到季末結局。

- 版本目標：[2026-10-04-第一季濃縮版-版本目標.md](../specs/2026-10-04-第一季濃縮版-版本目標.md)，以下簡稱「版本目標」。
- 實作計畫：[2026-10-04-第一季濃縮版.md](../plans/2026-10-04-第一季濃縮版.md)（main `90f9a41`），以下簡稱「計畫」。
- 寫這份清單時對照的是 main `b7c4047`，也包括：
  - 戰鬥系統的三場大戲（第五節、附錄 A）；
  - S1 的[濃縮版內容表](../specs/2026-10-04-第一季陣營內容-濃縮版內容表.md)第一節（大勢人物）；
  - 江湖頁的水墨行動列（PR #10，取代輪盤）。

這份清單照計畫的 T0～T11 分節，每節寫實機怎麼驗：玩家看得到什麼、管理者要做什麼、怎麼快轉季曆。最後一節對照版本目標第四節的 6 條，做整季驗收。

## 怎麼用這份清單

- **什麼時候驗**：開發每做完一個任務、併進 main，PM 通知要驗哪一節。
  - QA 驗那一節，並跑全套測試。
  - 結果寫在那一節最後的「結果」；問題記進 [試玩回饋.md](試玩回饋.md)（FB-xxx）。
  - 整批回報 PM，加一行「狀態變動」。
- **在哪驗**：本機 `127.0.0.1:7890`。
  - 不用 localhost，免得 cookie 混在一起。
  - `TIANXIA_DB` 指到 scratchpad 的暫存檔。
  - 不碰 7861（企劃者的試玩伺服器）、7870（Infra）、7880（PM）。
- **不開伺服器假人**（企劃者 2026-10-04 定）：實機測試只用 QA 自己的幾個帳號，跟週末兩個真人的情況一樣。假人只用在 T11 的整季模擬與整季驗收第 1 條。
- **換季重來，不開新資料庫**（企劃者定，T0）：週末的試玩伺服器沿用現在的資料庫，管理者收掉 beta 這一季、開下一季。T0 那一節要把這條升級路演練一次。
- **怎麼記**：
  - 過了打勾 `[x]`。
  - 沒過的寫上 FB 編號，例如 `[ ] … → FB-033`。
- **標記**：
  - 「**可調狀態**」：可以先用腳本改自己暫存資料庫裡的狀態再驗，省時間，例如把貢獻改成 290。沒標的項目要照正常玩法走到。
  - 「**RF n**」：計畫「Review Focus」的第 n 條。
  - 「**手機**」：要在 375×812 的畫面上看。
  - 「**記下**」：計畫沒定答案，照實記下畫面怎麼呈現，看不懂的記成體驗回饋。
- **不驗**：
  - 效能、卡頓、穩定性（企劃者 2026-10-03）。
  - 版本目標「這一版不做」的東西。
  - 「有時間就加」的項目（第 3 階、機密軍令、玉璽、董卓擁兵自重、軍備）做進來時再補一節。
- **測試當天**：企劃者和 joy 試玩時，回報照版本目標第一節的五個問題整理，記進試玩回饋.md，來源寫「企劃者試玩」或「joy 試玩」。

**怎麼快轉**：

- **設定頁的管理者區**：「時間快轉 +1／+8／+24 小時」（現在就有，全服一起快轉）。
  - +1 小時是 1.4 曆日，+8 小時是 1.6 週，+24 小時是 4.8 週。
  - API 是 `POST /api/do/fast_forward`，`{"hours": n}`，n 只能是整數。
- **T10 做完以後**：用「跳到下一件大事」，停在下一件大事的時間；決戰停在集結開始。
- **要停在某個曆時**（例如夜裡）：先快轉到那一週，再看狀態列的季曆時鐘，等真實時間（夜裡每 43 分鐘來一次）。也可以用 QA 腳本在自己的暫存資料庫上用 `Game.advance(秒數)` 細推。
- 快轉推的是世界時鐘：體力跟著回，人物跟著推，割據跟著漲，跟真的過了那麼久一樣。
- **快轉不推決戰的集結與回合**：決戰看真實時間（T0 實測：快轉 1 小時後，集結還剩 29 分 59 秒）。要看開打中的決戰，得等真實的 30 分鐘集結。
