# Discord 客服官：做法與設定

客服自動受理第 218 批（設計 `docs/superpowers/specs/2026-11-09-客服自動受理-design.md` 6.3、第七、十一節；企劃者 2026-11-10「照計畫繼續」）。寫法照 `中間bot-設定.md`。

## 做法：第二個專職的 Claude session

- 玩家在遊戲的客服頁送單 → 橋（`scripts/support_bridge.py`）唯讀看旁檔，把單貼到 `#客服`、在 `bridge.log` 記一行 → 客服官（終端機裡另一個 `claude --channels` session，工作夾 `C:\Ray\tianxia-support\`）的 Monitor 盯 `bridge.log` 醒來，先 `./cli.sh queue`，一張一張照 FAQ 回。
- 客服官動遊戲**只透過** `cli.sh`（Git Bash 跑，直接叫 `scripts/support_cli.py`；鎖定模式：金鑰檔、伺服器網址、截圖夾只照 `cli.sh` 設的環境變數）；它看不到 token。同一個資料夾的 `cli.cmd` 做一樣的事，給人在 cmd、PowerShell 用，**不進客服官的白名單**：Git Bash 叫 `.cmd` 時參數不加引號就交給 cmd，`./cli.cmd queue "R&D"` 的 `&` 會被 cmd 當成下一個指令（第 218 批實跑過，批次檔裡擋不到）。
- 工作夾的檔從範本來：`docs/support/session/` 六個（`CLAUDE.md`、`.claude/settings.local.json`、`cli.sh`、`cli.cmd`、`start.cmd`、`stop.cmd`），用 `scripts/support_session_init.py C:\Ray\tianxia-support` 抄過去（已經在的不蓋）；答題的三樣（`knowledge\FAQ.md`、`patch_notes.json`、`howto.md`）用 `scripts/support_knowledge.py C:\Ray\tianxia-support` 匯出，改版後重跑。
- 跟聯絡官是**兩個 bot**：客服官用自己的 `DISCORD_STATE_DIR`（`%USERPROFILE%\.claude\channels\discord-support`，`start.cmd` 設好了），有自己的 token 與 `access.json`，只在 `#客服` 一個頻道；聯絡官的 `access.json` 不加 `#客服`。

## 安全規矩（一定要守）

- **絕對不要用 `--dangerously-skip-permissions` 開客服官。** 單上的字、截圖都是外部輸入；白名單外的動作跳許可、沒人按就停住，那是設計。
- 權限白名單（`settings.local.json`）只有四條：Discord 外掛的 `reply`、`Bash(./cli.sh *)`、Read 工作夾底下的檔、Monitor 盯 `bridge.log`。沒有下載附件（截圖從遊戲經 `./cli.sh ticket` 存進 `inbox\`）、沒有改檔、沒有寫檔。另外 Claude Code 本來就放行工作夾裡的唯讀指令（`ls`、`cat`、`tail` 工作夾裡的檔），工作夾外的一律跳許可（第 218 批實跑：`cat ../local/support.json` 被擋）——所以 **`.local/support.json` 不能放在工作夾裡**。
- token 與 webhook 只在 `.local/support.json`（不進版控）；不要貼給任何 Claude、不寫進任何文件或 commit。
- `#客服` 是私密頻道，只有企劃者、Joy、兩個 bot；不開給玩家。

## 企劃者要自己做的五樣（Claude 不能代做：建 bot、處理 token、授權、建帳號都要本人）

1. **建第二個 bot**：[Discord Developer Portal](https://discord.com/developers/applications) → New Application（例：「天下大勢客服官」）→ **Bot** → **Reset Token** 複製下來（先存在自己那裡，不貼給任何 Claude）→ **Privileged Gateway Intents** 打開 **Message Content Intent** → **OAuth2 → URL Generator** 勾 `bot`，權限同聯絡官（View Channels、Send Messages、Send Messages in Threads、Read Message History、Attach Files、Add Reactions）→ 打開網址加進伺服器。
2. **建 `#客服`**（私密，只有你、Joy、兩個 bot）→ 頻道設定 › 整合 › Webhook → 新增、複製 **webhook 網址**。開發者模式下右鍵複製 `#客服` 的頻道 ID、你與 Joy 的使用者 ID。
3. **開客服官、設 token 與白名單**：先照下面「開起來」把工作夾準備好、`start.cmd` 的 `TIANXIA_DB` 填好，雙擊 `start.cmd`（它會設 `DISCORD_STATE_DIR`）。在開起來的那個終端機**你自己**輸入：
   - `/discord:configure <客服官的 bot token>`
   - `/discord:access policy allowlist`
   - `/discord:access group add <#客服 的頻道 ID> --allow <你的 ID>,<Joy 的 ID>`
4. **客服官的遊戲帳號**：`scripts/set_password.py <帳號> --character <名號>`，再寫進 `Config.support.bot_account`（第 216 批）。
5. **`.local/support.json`**（repo 根的 `.local/`，跟 `server.py` 同一份 clone）：自己產一個 32 字以上的亂數 token，填 webhook 與兩個 Discord ID。格式：

   ```json
   {
     "bot_token": "<填：32 字以上的亂數>",
     "discord_webhook": "<填：#客服 的 webhook 網址>",
     "server_url": "<填：例 http://127.0.0.1:7861>",
     "mention": ["<填：你的 Discord ID>", "<填：Joy 的 Discord ID>"]
   }
   ```

   `discord_webhook` 可以先不填（橋只記 `bridge.log`、不貼 Discord）；`bot_token` 不填等於客服官關著（客服官的路一律 404）。

## 開起來

1. 工作夾：`.venv/Scripts/python.exe scripts/support_session_init.py C:\Ray\tianxia-support`（要指別的伺服器加 `--url`，金鑰檔不在 repo 的 `.local/` 加 `--config`）。
2. 填工作夾裡的 `<填>`：`CLAUDE.md` 的 `#客服` 頻道 ID、你與 Joy 的 ID（「要管理者時」那兩個 `<@…>` 也是）；`start.cmd` 的 `TIANXIA_DB`（要跟線上的 `server.py` 同一個資料庫：橋讀它旁邊的客服旁檔；沒填 `start.cmd` 會停下來說）。
3. 知識：`.venv/Scripts/python.exe scripts/support_knowledge.py C:\Ray\tianxia-support`（改版、改 FAQ 之後重跑）。
4. 雙擊 `start.cmd`：橋在背景跑（PID 在 `bridge.pid`，輸出在 `bridge-out.log`、`bridge-err.log`、`bridge.log`），然後開客服官的 session。第一次照上面第 3 樣設 token 與白名單。
5. 停：關掉客服官的終端機，再雙擊 `stop.cmd`（`taskkill /PID <bridge.pid> /T /F`）。

工作夾路徑不能有空白（`start.cmd` 用 `Start-Process` 帶參數）。開著才收得到：終端機不關、電腦不睡；每張單走企劃者的訂閱額度，每週到 85% 照規矩暫停（關掉客服官 session，單還在、人照舊在客服頁回）。

## 還不確定、要實測的

- Discord 那一半的排練（`docs/support/排練.md` 後半）：真的 bot、真的 `#客服`，看整條線走完一次許可都沒跳。
