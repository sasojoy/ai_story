## 二、改法（第二段照這個順序；每一步量完才走下一步）

1. **拍法：視窗拍完再量一次，跟第一張之前不一樣就整個視窗重拍**（`driver.mjs` `shoot()` 的 for 迴圈裡）：
   - 把「flip（sameWindow）→ setView → stable → fixGutter → LAYOUT → SCROLLER → 第一張 → 捲動的 `__sN` → 捲回 → stable」包成一段，
     段尾再 `ev(LAYOUT)`；`sw` 或 `cw` 跟段頭的不一樣，就把這個視窗已推進 `facts.shots` 的檔、`facts.vol` 的鍵拿掉，重跑一段，**最多重拍 2 次**。
     `hashes[f]` 跟檔會被同名覆寫，不用另清。重拍後段頭的 `facts.layout[v]` 換成新的。
   - 第二次還不一樣：`facts.moved = (facts.moved || []).concat(v[0])`，`facts.layoutEnd[v[0]]` 記段尾那一次；log 寫一行 `id v "gutter moved while shooting"`。
   - 只在 1280（`fixGutter` 也只在 1280）？**全部視窗都做**最保守：量一次 LAYOUT 不到 10ms；手機寬 `scrollbar_flip` 本來就不算，`moved` 照記。
2. **判法（拍法之後還有 `moved` 才用到；也照寫，舊報告沒有新欄位照舊）**：`compare.py` 1280 那一輪：
   - 第一張（`<id>__<v>.png`）照舊用 `layout[v].sw`；`__sN` 與那個視窗的樣式列（傾印在捲完之後）用 `layoutEnd[v].sw`（沒有就用 `layout`）。
   - 兩邊**同一個時點**的 `sw` 差 15、非手機寬、`dom_same`、`noise.used_only(props, flip=True)`、不 `unstable` 時才歸 `gutter`；其他照舊。
   - `noise.py` 只加說明（`gutter` 那一行補「第一張與捲動後各自的時點」），`scrollbar_flip`、`pixel_class` 的簽名不動，`compare.py` 傳對的 `sw` 進去。
3. **不准做的**（派工單）：放寬 aa、列景名白名單、把 DOM 有差或非 used 值的差收進來、讓「兩邊溝一樣、畫面真的移 15px」變綠。
4. **可以試、要量才收的**（跟 1、2 獨立）：卡住的溝能不能在 `fixGutter` 裡救回來（例：捲整頁 1px 再捲回 0、再量），
   救得回來就從 039 起不再卡、也就沒有翻面；但會改掉 039～094 兩邊每一張 1280 的拍法（自己對自己照樣一樣），三趟比 `GUTTER` 景數、`gutter` 列數再決定；
   救不回來就不收、寫進回報。
