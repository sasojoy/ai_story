## 一、規則（核心）

`tianxia/core/identity_base.py`（第七節第一列，核心新檔）：
- `admin_session_ok(db, content, token, now) -> bool`：`not on(content)` 回真（**identity 關著管理者行為位元組一樣**，不走 `staff_session_ok` 關著那一支〔看 `SessionStore.created_at` 六小時〕，那一支會讓關著時登入超過 6 小時的管理者掉權限）；開著時等於 `staff_session_ok` 開著那一支（`session_auth` 的 `method == "password"`、`now - last_checked <= staff_hours*3600`）。放在 `staff_session_ok` 下面。

## 九、順序與坑

1. 核心（`identity_base` 兩支＋`accounts.check_password`）→ 殼 `api_do`、`main_view`、`_game`、`_start_session` → admin 包 → identity 包 → 註冊與改密碼 → `set_password.py` → README。每做完一段推一次。
2. `SESSION_TOKEN` 在 `_game` 設；identity 的 async 路由用 `run_in_threadpool` 叫 `_game` 的，ContextVar 在同一個執行緒的複製 context 裡，`main_view` 讀得到；`_start_session` 跟 `_entry` 要在同一個同步函式裡叫才看得到（dev 逐條確認驗證碼、第三方、密碼三種登入的回應）。
3. `admin_session_ok` 先問 `is_admin()`（不是管理者不碰旁檔）；關著不讀任何檔（`on` 先看 `enabled`）。
4. 不夠的回話一律跟不是管理者逐字一樣；不寫「請重新驗證」這種新句（要的話第 208 批之後另開，見 leftovers）。
5. 名單上的帳號名比的是 `admins`（名號）：管理者的登入名跟名號不同的，註冊時判不到、改密碼時照角色判得到。
