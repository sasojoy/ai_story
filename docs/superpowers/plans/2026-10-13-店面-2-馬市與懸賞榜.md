## Review Focus

1. **懸賞榜的第三層（替一張求藝、求兵挑東西）**：選單上只有那一張的交出鈕與「回到懸賞榜」（`bounty:unpick`），沒有 `bounty:back`、`bounty:take`。店面要照樣畫得出來（`_shop_live` 認 `bounty:unpick`），放大的紙收起、放大別張、出店之前先送 `bounty:unpick`，不然按下去會被 `Game.choose` 擋成「榜上的情形變了」。→ Task 3 `test_the_third_layer_is_still_the_board_shop`、Task 5 `test_closing_the_hand_in_list_unpicks_first`、`test_leaving_from_the_third_layer_goes_back_to_the_board_first`。
2. **兩次輪詢之間換了一間店**（出了鐵匠鋪、走進馬市）：有沒有店都是「有」，`setMain` 與 `shopPolled` 要比 `main.shop.shop`，鐵匠鋪那幾個欄位（停在哪一頁、爐裡的東西、出爐卡）清掉、整個重畫。→ Task 4 `test_moving_from_the_smithy_to_the_market_starts_the_market_fresh`。
3. **被拿走了的告示**（名額被別人交滿、過期、自己交了）：木板上不再畫，放大的那一張跟著收；看得到的都沒了寫 `bounties.BOARD_EMPTY`。自己交出之後那一張蓋「交差」朱印再淡出（減少動態效果的人不跑淡出）。→ Task 3 `test_an_emptied_board_says_so`、Task 5 `test_a_hand_in_stamps_the_note_done`。
4. **懸賞榜不露出誰是假人**：通緝的告示寫被通緝的人與掛單的陣營，不寫掛單的人（同現在的選單）。→ Task 3 `test_a_wanted_note_never_names_who_posted_it`。
5. **開關關著跟上線前一字不差**：馬市與懸賞榜的選單（id 與字）、`main_view` 沒有 `shop`。→ Task 2 `test_the_switch_off_leaves_the_old_market_menu`、Task 3 `test_the_switch_off_leaves_the_old_board_menu`。

## 跟設計寫的時候不一樣的地方（照程式，寫成裁決）

- **馬市的「換上」送 `market:wield:<id>`**，不走設計 6.3 的 `/api/menxia/wield`：6.3 改走修練頁是因為鐵匠鋪的選單最多只列 8 顆換上；馬市的選單本來就替裝備庫裡每一匹各列一顆（`Game._market_options`），走現在的選項 id 就夠，紀錄也照舊是馬市那一則。做錯的代價：網頁一行，改成 `shopMx("wield", …)`。
- **交出求藝、求兵分兩下**：放大的紙上「交出…」送 `bounty:pick:<id>`（伺服器打開第三層），回來的 `board_view` 帶 `picked` 與 `hand_in`（照 `bounties.hand_in_options` 的每一顆），每件照選單上的 `confirm` 先問一次再送 `bounty:give:…`（網頁的 `choose` 本來就照選項的 `confirm` 問）。設計 4 寫「放大的紙底下展開合用的東西」，沒寫要先開第三層；不開的話 `bounty:give` 不在眼前的選單上、送了會被擋。做錯的代價：無（行為照設計，多一次請求）。
- **放棄的問句問在網頁那一層**（`shop-ask`，字是 `board_view` 給的 `DROP_ASK`）：選單上的 `bounty:drop` 沒有 `confirm`，加上去就改了開關關著時的選單。
- **手上那一排**：揭著的每張一格，還能揭的話後面一格空的寫「還能揭 N 張」（草圖的畫法），不是 `max_taken` 格都畫出來。超過 `max_taken`（截殺關了又開，FB-155）照實全列。
- **「交差」朱印**在網頁那一層判斷：送了 `bounty:give:<懸賞>:…`、回來的木板上沒有那一張了才蓋。不另開伺服器的欄位。
- **掌櫃的情況**（設計 1.4 只舉例）：馬市 `enter`、`buy`、`feed`、`wield`、`short_silver`、`rack_full`、`refused`；懸賞榜 `enter`、`take`、`drop`、`pick`、`give`、`held_full`、`refused`。灰掉的鈕在 `Game.choose` 的選單那一關就擋下，所以 `short_silver`、`held_full`、`refused` 多半只在兩個分頁搶的時候出現。
- **揭不了、交不出的告示畫淡一點**（草圖的通緝那一張）；點得開、放大的紙上寫原因。
- **小的整理**（不改行為）：`mounts.abilities`（四項本事的數字，修練頁那一列與馬廄共用）、`bounties.has_prize`（`reward_text` 與告示上的「另有重賞」共用）、`bounties.UNPICK_ID`、`bounties.NOT_HELD`、`mounts.close_market`、`bounties.close_board`（凡是收起馬市、懸賞榜的地方都走這兩個，一起清掉掌櫃那一句，同第一批的 `equipment.close_smith`）。

    def _shop_open(self) -> str | None:
        """哪一間店開著（店面獨立介面設計 1.1；同 options() 的先後：懸賞榜、鐵匠鋪、馬市）。那個地方已經不開門了（同步之前）是 None；
        鐵匠鋪的一步一步單子還開著（開關關著時開的、舊存檔）也是 None，照舊畫那一串按鈕（店面上的鈕在單子那一步不在選單上）。"""
        s, c = self.state, self.content
        p = s.player
        if p.picking_bounty:
            return "board" if bounties.board_here(s, c) else None
        if p.picking_smith:
            return "smith" if p.smith_draft is None and equipment.smith_open(s, c) else None
        if p.picking_market:
            return "market" if mounts.market_here(s, c) else None
        return None

    def _shop_live(self, option_ids=None, shop: str = "smith") -> bool:
        """這間店那一串此刻真的是眼前的選單（店面與直接開爐都問它）：選單上有這間店的離開鈕（shopview.BACKS：鐵匠鋪 smith:back、
        馬市 market:back、懸賞榜 bounty:back 或第三層的 bounty:unpick），而且前面沒有決戰、奪璽單挑的鈕。決戰開打、休季時選單換成三招
        或「休季中」，店裡那一串根本不在上面（picking_* 卻還是真的）：這時給店面，出店會被拒絕、人就困在店裡（第一批終審 Critical 1）。
        集結時決戰的鈕排在店裡那一串前面：照舊畫那一串，加入、趕到的鈕不被蓋住。option_ids 是現在的選單（main_view 已經讀過就傳進來）；
        沒給就讀一次（不推進戰鬥）。"""
        ids = [o.id for o in self.options(odds=False, tick=False)] if option_ids is None else list(option_ids)
        return any(back in ids for back in shopview.BACKS[shop]) and not any(i.startswith(("battle:", "seal:")) for i in ids)

    def shop_view(self, option_ids=None) -> dict | None:
        """店面（店面獨立介面設計 6.1）：開關開著、有一間店開著（_shop_open）、那間店那一串是眼前的選單（_shop_live）才有；
        照哪一間店給 shopview 的 smith_view、market_view 或 board_view。"""
        s, c = self.state, self.content
        if not c.config.shop_screens:
            return None
        shop = self._shop_open()
        if shop is None or not self._shop_live(option_ids, shop):
            return None
        view = {"smith": shopview.smith_view, "market": shopview.market_view, "board": shopview.board_view}[shop]
        return view(s, c, self.world)

REFUSALS = ("short_silver", "rack_full", "held_full", "refused")


def _mark(state: GameState) -> str:
    """被拒那一下的狀態指紋：銀兩、背包、身上與裝備庫每一件的 id 與磨損、淬煉。"""
    p = state.player
    gear = [(e.id, e.edge, e.tempers) for e in (p.weapon, p.armor, p.mount, p.treasure, *p.rack) if e is not None]
    raw = json.dumps([p.stats.get("silver", 0), sorted(p.materials.items()), gear], ensure_ascii=False)
    return hashlib.sha256(raw.encode()).hexdigest()[:16]


def hold_for(state: GameState, content: Content, key: str, problem: str | None) -> str:
    """這一下的那一句要撐到什麼時候（PlayerState.shop_hold）：錢不夠（「還差 N 兩」）記要的銀兩、裝備庫滿了記 rack、手上揭滿了記 held，
    其餘被拒的記狀態指紋；做成了的是空字串。"""
    if key == "short_silver":
        digits = re.search(r"\d+", problem or "")
        if digits:
            return f"silver:{state.player.stats.get('silver', 0) + int(digits.group())}"
    if key == "rack_full":
        return "rack"
    if key == "held_full":
        return "held"
    return f"same:{_mark(state)}" if key in REFUSALS else ""


def still_holds(state: GameState, content: Content, hold: str) -> bool:
    """被拒的原因還成立嗎（hold_for 記的）：沒記的（舊存檔、做成了的情況）算成立。"""
    p = state.player
    kind, _, arg = hold.partition(":")
    if kind == "silver":
        return p.stats.get("silver", 0) < int(arg)
    if kind == "rack":
        return len(p.rack) >= content.config.weapons.rack_cap
    if kind == "held":
        return len(bounties.mine(state, content)) >= content.config.bounties.max_taken
    if kind == "same":
        return _mark(state) == arg
    return True
