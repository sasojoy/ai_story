**Goal:** 玩家在遊戲裡送的客服單（可附截圖）自動貼到 Discord `#客服`，一個專職的 Claude session（客服官）用本機工具讀單、看圖、看帳號卡，答得了的回（標明自動回覆）、缺資訊的追問、要管理者動手的點名企劃者與 Joy；玩家按「找真人」就轉人；已回覆的單 3 天沒再回自動結。

**Architecture:** 遊戲那一側只在 `tianxia/features/support/` 包裡加截圖、客服官的 token 身分、自動回覆標示、「找真人」旗標、明確的 `sweep` 路由（第 215、216 批）；伺服器不碰 Discord、不接模型。主機那一側兩支獨立腳本：橋 `scripts/support_bridge.py` 唯讀旁檔、貼 webhook、印一行鬧鐘；手 `scripts/support_cli.py` 用 token 打 `/api/support/*`（第 217 批）。客服官是第二個 Discord bot 的 Claude session，權限白名單寫死，只透過 CLI 動遊戲（第 218 批）。

**Tech Stack:** Python 3 標準庫＋`requests`（橋與 CLI）、FastAPI 路由（包裡）、sqlite3 旁檔（`CREATE TABLE IF NOT EXISTS`，不 `ALTER`）、`web/support.js`＋`web/support.css`（殼不動）、Discord webhook（multipart）、Claude Code 的 Discord 外掛（`DISCORD_STATE_DIR` 第二個 bot）。不加 Pillow、不加任何圖片函式庫。

**Spec:** `docs/superpowers/specs/2026-11-09-客服自動受理-design.md`（第 1 版；企劃者 11/10「照計畫繼續」）。這一份只寫做法與介面；為什麼、不做什麼看設計稿。**設計稿跟這一份對不上時照這一份**（這一份照程式寫，下面「對不上的」那一段列了哪幾處）。

## Review Focus

設計沒明寫、但玩家或主機會碰到的，各由一條測試釘在負責的那一批：

1. **上傳的內文比 `Content-Length` 說的大、或根本沒有 `Content-Length`、或是故意送 50 MB**（手機瀏覽器分段送；已登入的人灌記憶體）：伺服器**串流累計**（`async for chunk in request.stream()`），累到超過 `file_bytes_max` 就停止讀、拒絕、檔不落地；`Content-Length` 說超過的提早拒、說不超過的不信。→ 第 215 批 `test_file_too_big_is_refused_by_real_size`、`test_oversized_upload_stops_reading_early`。
2. **檔頭是 PNG、內容不是圖**（改副檔名的任何東西）：照檔頭存成 `.png`、照檔頭回 `image/png`，瀏覽器在 `nosniff` 下畫不出來就是破圖，不會執行；伺服器不驗整張圖。→ 第 215 批 `test_kind_is_by_magic_bytes_only`。
3. **同一個請求同時帶 cookie 與 `Authorization: Bearer`**：在 `/api/support/*` 以 Bearer 為準（對得上就是客服官、對不上 404，不退回 cookie）；在其他路由 Bearer 當不存在。→ 第 216 批 `test_bearer_wins_on_support_and_is_ignored_elsewhere`。
4. **自動結單跟玩家再回一句撞在同一秒**：`store.sweep` 在 `BEGIN IMMEDIATE` 裡重讀狀態與最後一則再結，玩家的回覆先進去就不結。→ 第 216 批 `test_sweep_rechecks_inside_the_write_lock`。
5. **橋讀旁檔時伺服器正在寫**（WAL、`database is locked`）或 **Discord 回 429／5xx／逾時**：這一輪跳過、進度不前進、下一輪再來；連續 10 輪失敗印一行警告、不停；4xx 裡 400、401、403、404（webhook 壞了或被刪）印警告**並前進**（不然永遠卡在同一則）。→ 第 217 批 `test_bridge_retries_without_advancing_state`、`test_bridge_skips_a_dead_webhook_reply`。
6. **單內文裡寫 `@everyone`、`<@某人>`、`<@&角色>`**：貼到 `#客服` 不能真的點名——webhook 的 `payload_json` 一律帶 `allowed_mentions`（一般事件 `{"parse": []}`，`HUMAN` 事件 `{"parse": [], "users": [兩個 ID]}`）。→ 第 217 批 `test_bridge_payload_never_lets_the_player_mention_anyone`。
