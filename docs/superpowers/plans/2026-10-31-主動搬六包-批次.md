## 二、每一批都照這些做（PM 定；含挑錯的人的修正）

**身體搬進包、接縫留在原位。**
- 搬：方法本體與整個模組進包；舊模組名留 `sys.modules` 別名（同一個模組物件，monkeypatch 照樣有效）。
- 留在原位叫 Game 的一行委派：選單、`sync`／`advance`／`world_tick`、行動列那一格、`choose` 前段、`/api/main` 的鍵（鍵的順序算行為，這一輪不用 `status` 掛鉤）、server 的 `/api/do`。每一處記進 `GAME_DIRECT`／`GAME_DELEGATE_CALLERS` 並寫理由，每批記下還剩幾處，第 11 批一次收。
- 掛鉤只用在位置不影響結果的地方：互斥前綴的 `choose`、換季照帶的欄位、`check_content`、清失效參照、`enabled`、`player_fields`。
- **假人**（挑錯的人 must-fix 1）：一包一拿到選項前綴，`bot_policy.score` 就先問那一包（`features_core.bot_pick`）。**那一批要同時把 `bot_policy.score` 裡那個前綴的那一段搬進包的 `bots.py`**（照宴客），不然原位那段變死碼、假人不再按那幾顆。`bot.py`、`bot_runner` 其餘照舊叫委派與舊名。
- **核心不准 import 包**（must-fix 2）：核心模組在模組層 import 要搬的舊模組時（例：`content.py` import `explore_one`、`arena_crowd`、`sortie`），那一批把那幾個內容檢查改成包的 `check_content`、常數搬進核心或包；`content.py` 的 `sortie.on` 改讀 `territory.on`。
- `services.py` 分四段：共用服務、查詢服務（例：決戰包經 Game 委派回答「我在哪一場」）、過渡（別的功能還沒搬的方法，標主人）、寄放（Game 上的暫時旗標）。調查漏列的照挑錯的人補（第 1 批 `_duel_option`、`duel_on`；第 4 批 `_sortie_host`、三選一那五個、`_gate_scale`、`_drop_scale`）。
- 測試換掉 Game 方法的（`setattr(game, "_outing_plan")`、`Game._explore_weights`、`Game.sorties_left`、`_battle_status`、`_apply_battle_outcome`）：包裡叫那些方法一律經 `ctx.<名>`，列進服務清單，不改測試。
- 契約測試的 `_dirty` 補 float、str、`Optional[子模型]`（第 2 批先踩到；改核心測試，算例外）。
- 測試只搬整檔；混在別人檔裡的這一輪不拆，數字記進交接。改斷言字的例外照第 1 階（路徑字串：`test_explain2`、`test_schema_required`）。
