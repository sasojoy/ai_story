```python
def add_team_exp(state: GameState, content: Content, world: WorldStateStore, amount: int) -> list[str]:
    """本隊每個人（本人與帶著出戰的同伴）各得 amount 經驗，照同一套 add_exp 規則升級；回傳升級訊息，
    本人在前、同伴照隊伍順序（試玩回饋 FB-002：戰報一直寫「經驗 +N（每人）」，以前只有本人真的拿到）。

    同伴的等級與經驗存在全服共用的 CompanionProgress（world.update_companion 當場寫回共用世界，
    跟著那一筆交易存檔），所以換頁、重新登入都還在；換季時跟其他同伴進度一起清空。氣血上限
    （neili_cap：基礎＋每級加成）由等級算出來，升級就跟著變高（氣血設計 A1：等級只買氣血上限）；
    目前氣血不變，不順便回血。"""
    msgs = add_exp(content, state.player.member, amount, state.player.name)
    for companion_id in state.player.team:
        name = content.characters[companion_id].name
        levels: list[str] = []
        world.update_companion(companion_id, lambda progress: levels.extend(add_exp(content, progress, amount, name)))
        msgs += levels
    return msgs
```

### Task 3: 主畫面「走法」切換（步行／趕路／疾行）

Spec for this task: above the option buttons a three-way toggle 步行／趕路／疾行 (default 步行). The `move:` buttons use the chosen mode: labels show that mode's time and stamina (like the map page's travel buttons); an unaffordable mode disables the button with the reason; the number of buttons doesn't change; after a page refresh the toggle is back to 步行 (UI state only, never in saves); the map page's three travel buttons stay as they are.

**How the mode reaches `options()`/`choose()` (decided here):**
- The mode is an attribute on the `Game` object, `Game.move_mode` (default `"walk"`), set by `Game.set_move_mode(mode)`. It is not a `GameState` field, so it is never saved. The app keeps one `Game` per browser session in `gr.State`; a page refresh logs in again and builds a new `Game` (`open_game` → `Game(CONTENT, state)`) while the radio component resets to its default — both are back to 步行 without any extra render output.
- `options()` builds each move with `_move_option()`: walk keeps the id `move:<地點>` (bots, `conftest.walk_to`, `bot_policy._toward_faction` and every existing test keep working); hurry/dash use `move:<地點>:hurry` / `move:<地點>:dash`. `choose()` is untouched: it still accepts only ids on the current menu, so a stale button from another mode is refused with 「（此刻無法這麼做。）」.
- Bots never call `set_move_mode`, so their menus are byte-for-byte the same as today; walking is free and always enabled, exactly as before, so `bot.play_season`'s "no enabled option → advance time" signal is unaffected.
- App wiring: `render(game)` already calls `game.options()`, so the timer, every action and the toggle itself all render with the session's mode. `ids_state` carries the mode-specific ids into `make_option_handler`; move ids never match `may_generate_dialogue`, so they keep the one-lock path; `visible_options` trims by count only and the count doesn't change.
