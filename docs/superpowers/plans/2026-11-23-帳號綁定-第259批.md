## 二、改法（只動 `routes.py`）

- 在 `need_recent` 旁邊（181 行前後，同一個工廠閉包裡）加一個小函式，例名 `mark_reauth(token, by, now) -> bool`：
  先 `record_reauth`；回 True 就回 True。回 False（沒有那一列）→ `identity_base.record_session(token, by, now)` 補一列，
  再 `record_reauth(token, by, now)` 回它的結果。旁註寫理由：剛用 `by` 這一種證明過是本人，等於這一刻用它登入；identity 打開之前能開 session 的只有密碼登入（含註冊）。
- 三處換成它，**位置與先後不動**：608 行（`by="password"`；回的字照舊，回傳值照舊不拿來分支——補完一定是 True，保守起見不加新的失敗句）；
  234 行（`by=provider`，`owner != account.id or` 照舊在前短路）；523 行（`by=channel`，subject 不對照舊先短路，不會替別人的碼補列）。
- 密碼那一條補的 `method` 是 `password`；第三方、驗證碼補的是**那一種**（`line`／`google`／`phone`／`email`），所以 `staff_session_ok`、`admin_session_ok` 對它們照舊是假。
- `record_session` 的「蓋過並清 verified」只在已有那一列時才有作用；這裡只在 UPDATE 沒打到時才叫，緊接著再 UPDATE，所以不會清掉誰的重驗。
  同一個 token 同時有人 INSERT 的競態：token 只有 `_start_session` 發（新的亂數），已存在的 token 不會再被記一次，不用處理。
- 不改：`identity_base.py`、`server.py`、`accounts.py`、`binding.py`、`store.py`、別的包；`admin_session_ok`／`staff_session_ok` 查不到回假；
  `/api/identity/session` 的 `relogin`；任何回給玩家的字。沒有新字。資料庫第 9 版、旁檔表結構不動。
- 沒有搬方法、沒有委派、不接掛鉤、核心直接碰包 0 處、沒有選項前綴（choose／bot_policy／bot.py／bot_runner 都不碰）、沒有被 patch 的名字。

## 三、想清楚的（寫進包 README 第 259 批那一節）

- **權限**：補列只在密碼（或綁定的那一種）剛驗對之後。拿著別人 cookie 而不知道密碼的人過不了 `authenticate`（錯了照舊算一次猜錯，不補列）；
  知道密碼的人本來就能 `/api/login` 開一個有那一列的新 session。第三方、驗證碼的重驗要那一種本來就綁在這個帳號、subject 對得上才補。沒有誰多拿到權限。
- **旁檔不見**（被刪、搬機漏帶）：所有 session 都沒有那一列，現在全體綁定、解綁、設密碼都被擋到重新登入；補了之後重驗一次就能繼續，跟「剛用那一種登入」同義。
  **要 PM 看一眼的一點**：旁檔不見時，原本用驗證碼或第三方登入的 session 打密碼重驗，會補成 `method=password` → 管理者、客服權限回來。
  手冊第十五節第 204 批認定（「用驗證碼進來事後補打密碼也不給，設計 4.4 最保守的讀法」）在這個邊角對不上；權限上不多（知道密碼就能直接密碼登入）。
  identity 關→開這條主路徑上，那些 session 確實是密碼登入，跟設計 4.4「這次 session 是密碼登入、6 小時內驗過」一致，所以不停。
- **補完之後讀到的**（`at = verified = now`，`method = verified_by = by`）：
  - `binding.recent` → `last_checked = now` → recent_seconds 內為真（跟已有列重驗一樣）。
  - `binding.checked_by` → `verified_by` = `by`（跟已有列重驗一樣：已有列時也是看 `verified_by`）。
  - `not_by_new` → 看 `by` 那一種是不是新綁：用新綁的手機重驗補的列，checked_by 是 `phone`，照舊擋「新綁的不能拿來解綁別的、設密碼」；密碼那一條 checked_by 是 `password`，跟已有列一樣。這一條不會因為補列而失效。
  - `staff_session_ok`／`admin_session_ok`（開著）：密碼補的 → 真（staff_hours 內）；第三方、驗證碼補的 → 假（method 不是 password）。
  - `me_info.recent` → recent_seconds 倒數，同上。
