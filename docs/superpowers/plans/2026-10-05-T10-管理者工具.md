# T10 管理者工具 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 管理者在設定頁能看到整張時刻表、排三場大戲與季末的真實時間、一鍵「跳到下一件大事」，出事時能救場（定戰況、定結果、清鎖定、取消決戰）；宛城在第 3 週結算前不出現在開戰選單；換版當天的順序有一條測試從頭走到尾。

**Architecture:** 引擎（`tianxia/engine.py`）加六個 `admin_*`，全部走既有的 `_admin_refusal`，改共用賽季的照 `admin_fire` 的寫法（改 `self.state.world`、`_save_season`、`_deliver_big_events`）；時間換算與時刻表狀態放在 `tianxia/timetable.py` 的小函式。伺服器（`server.py`）只加 `ADMIN_ACTIONS` 與 `admin_choices()["timetable"]`；網頁（`web/app.js`）的管理者區加「時刻表」與「救場」兩塊，每個按鈕照既有的 `adminAsk` 先問一次。

**Tech Stack:** Python 3.14、pydantic、FastAPI、原生 JavaScript、pytest。

**Spec:**
- 總計畫 `docs/superpowers/plans/2026-10-04-第一季濃縮版.md` 的 T10 一節（介面、換版當天的順序、測試名）與「T10 要接的介面」。
- 版本目標第二節（排時間、跳到下一件大事）、第四節第 5 條（救場）。
- PM 加的（2026-10-05）：管理者開戰選單裡，宛城在第 3 週結算前不列。

**基準：** 本分支在 T5 之後（6362dcd）；開工前接上最新 main。

## Global Constraints

- 開關：一律 `rules.season_one(content, world)`。開關關著（beta 那一季）時沒有時刻表：時刻表、跳到下一件、定結果、清鎖定在 beta 一律拒絕（「這一季沒有時刻表。」），設定頁不畫那兩塊；定戰況照舊能用（beta 有大勢線）；取消決戰 beta 也能用（beta 有門檻決戰）。既有的開戰、觸發、推動、快轉、開季收季照舊。
- 每個新動作：不是管理者 → 「（只有管理者能……。）」；賽季不在進行 → 「（賽季沒有在進行，無法觸發。）」（`_admin_refusal`）。
- 引擎不讀電腦時鐘：現實時間一律由呼叫端傳 `now`（伺服器傳 `time.time()`）。
- 現實時間 ↔ 世界秒：`world_seconds = world.time + (at_real − now) × config.time_scale`；反過來 `at_real = now + (when − world.time) / time_scale`。呼叫前伺服器已經同步到 `now`（`server.act` 進鎖先 `sync`）。
- `mutate`／`mutate_season` 不能巢狀：引擎改 `self.state.world` 再 `_save_season()`，開戰走既有的 `start_pending_battle`。
- 數字只由規則引擎定；公告與江湖史只用時刻表內容裡的句子（定結果走 `timetable.resolve`），新寫的只有管理者自己的江湖紀錄與一句取消決戰的公告（列給 S1 看）。
- 每個任務做完全套都要過；畫面的東西 375×812 看過；`node --check web/app.js`。

## Review Focus

1. **一次跨過好幾件**：跳到下一件只跳到最早那一件（同一刻的幾件一起結算），決戰停在集結開始、直接開集結，不會被跳過也不會開兩場（Task 1 `test_jump_next_resolves_one_event_and_opens_showdown_muster`）。
2. **排定的時間不在曆時交界上**：管理者排 20:07，季的事每曆時跑一次——集結要在 20:07 之後第一個曆時交界開，不能卡住；跳到下一件時也一樣要跳過那個交界（Task 1 `test_schedule_off_the_hour_still_opens`）。
3. **救場的順序**：決戰正在打時定那件的結果要拒絕（先取消決戰）；取消之後那件不會自己再開（`showdowns_opened` 還在），由管理者定結果收尾（Task 1 `test_cancel_then_resolve_showdown`）。
4. **開關關著**：beta 那一季呼叫時刻表類的動作一律拒絕、不改任何東西（Task 1 `test_switch_off_timetable_admin_refused`）。
5. **換版當天**：照總計畫的表走一次，舊季在開關打開後什麼都沒補算，新季第 1 週只結算一次，排好的長社在排定時間開集結，兩個角色都是新角色（Task 3 `test_cutover_sequence`）。

### Task 1：引擎的管理者動作

**Interfaces（Produces）：**
- `timetable.SCHEDULABLE(content) -> list[str]`：可排的項目，照時刻表順序：三場決戰的 id，最後是 `"finale"`。
- `timetable.status_rows(state, content) -> list[dict]`：每一件一列：`id`、`week`、`title`、`kind`、`when`（世界秒）、`state`（`"done"`＝已結算、`"running"`＝決戰開過集結還沒收場、`"due"`＝時間到了還沒結算、`"later"`＝還沒到）、`result`（已結算的結果鍵，含版本）、`schedulable`（決戰與季末，而且還沒結算、沒開過）。
- `timetable.result_keys(state, content, event) -> list[str]`：不含版本的結果鍵（有版本的只列這一季那一版的）；季末沒有。
- `Game.admin_schedule(item: str, at_real: float, now: float) -> list[str]`。拒絕：不是可排的項目；已經結算或開過集結；換算後不在未來（`<= world.time`）；跟前後的可排項目順序不對（要嚴格在前一項之後、後一項之前，已結算的不算）。成功寫 `schedule[item]`，回一句「已把長社之戰排在第 6 週週四 20:00（季曆）。」
- `Game.admin_jump_next(now: float) -> list[str]`：決戰正在集結或開打時拒絕（「決戰還沒收場，先等它打完或取消。」）；沒有下一件就說沒有。否則推進到下一件的時間，取整到下一個曆時交界（`_to_next_cal_hour`），走 `self.advance(seconds)`（會結算、會開集結）。
- `Game.admin_set_trend(trend_id: str, value: int) -> list[str]`：照 `admin_push_trend` 的檢查（看得到、推得動，衍生線拒絕），把那條線推到 `value`（夾在 0～100），推過門檻照常觸發。
- `Game.admin_resolve_event(event_id: str, key: str) -> list[str]`：只有第一季；不是時刻表大事、季末、已經結算、決戰正在打（先取消）、鍵不在 `result_keys` 都拒絕。照 `timetable.resolve(..., key=key)`，存檔、`_deliver_big_events`。
- `Game.admin_clear_lock(event_id: str) -> list[str]`：只有第一季；拿掉 `locks[event_id]` 與 `lock_losers[event_id]`；沒有鎖定就說沒有。
- `Game.admin_cancel_battle() -> list[str]`：沒有進行中的戰鬥就說沒有；否則 `_shelve_unfinished_battle()`（參戰者補「不算勝負」），加一則天下大事傳聞「{決戰名}臨時取消，這一仗沒有打成。」。時刻表決戰取消後不會自己再開（`showdowns_opened` 留著），要收尾用定結果。
- `admin_battles`：分版本的決戰（宛城）在 `version_from` 那件結算之前不列（PM 2026-10-05）。

## 與總計畫不同的地方（回報 PM 時一起講）

1. 跳到下一件在決戰集結或開打時拒絕（總計畫沒寫）：一路跳過正在打的決戰，下一場會排隊、前線起點也會變，試玩時看不懂。
2. 取消決戰後那件不會自己再開，要收尾用「定結果」（`showdowns_opened` 留著，不然下一個曆時就自動又開一次）。
3. `admin_choices` 另外回 `results`、`locks` 給救場的下拉選單用。
4. 跳到下一件取整到下一個曆時交界（季的事只在交界跑；排定時間不在交界上時，停在排定時間會什麼都沒發生）。
