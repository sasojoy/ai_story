# 賽季：新手福利從加入日起算、公告停機時鐘暫停 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 兩件賽季生命週期的事：①新手福利（前 3 天氣血回復加倍、新立門戶福緣）從每個角色自己加入這一季的那一刻起算；②管理者（或主機端腳本）可以讓賽季時鐘暫停——停機維護那段時間不算進賽季、決戰不推、玩家不能行動、假人不出手；繼續之後季末往後延，排好的決戰照原本約好的現實時間開（原本的時間落在暫停裡的，繼續那一刻就開集結），打到一半的決戰剩下的時間不變。

**Architecture:**
- 加入時間是 `PlayerState.joined_at`（世界秒）：新角色與換季重來的角色先是 `None`，第一次 `sync`（補算完賽季之後）或 `advance` 才蓋；舊存檔讀成 `0.0`（從季初算，跟現在一樣）。`roster.since_join` 把「加入以來」換成季曆秒，`newbie`／`fortune_due`／`fortune_overdue` 照它算——只在 `rules.season_one` 成立時，beta 那一季照舊從季初、用世界天。
- 暫停是 `SharedWorldState.paused_at`（存在 `world` 表那一列的 JSON，不改資料表）。兩個關口：補算看 `catch_up_season`（暫停中不推、對時點不動），決戰看 `Game._battle_status(tick=True)`（暫停中只讀）。玩家的同步、`options()` 的 tick、Infra 排程計畫的 `Game.world_tick` 都只走這兩個關口，所以誰先合進 main 都不用改別人。繼續（`resume_clock`）把對時點往後挪「跳過的長度」（第一季照整個曆時往下取整，曆時的交界在現實時間上才不動）、進行中的決戰期限往後挪停的長度，排好還沒開的決戰往前挪同樣的長度（現實時間不變，企劃者 2026-10-06 定 B3）；挪過頭的（原本的時間落在暫停裡）記進排隊，`Game.admin_resume_clock`／主機端腳本緊接著呼叫 `start_pending_battle` 開集結（B11）。
- 擋動作分兩層：引擎的 `options()` 暫停中只給一顆灰的（`choose()` 自己就按不下去，假人、整季機器人也一樣）；伺服器在拿到行動鎖、同步之後擋不走選單的動作（`act` 與鎖外三段的 A 段）。管理者動作暫停中只按得到「繼續」。

**Tech Stack:** Python 3、pydantic、FastAPI（既有）、SQLite（既有）、pytest；原生 JavaScript（`web/app.js`，沒有建置步驟）。

- `tianxia/` 不 import 任何網頁框架；**引擎不讀電腦時鐘**：暫停、繼續的現實時間由 `server.py`（`time.time()`）或主機端腳本的 `main()` 傳進來（`admin_pause_clock(now)`、`pause_clock(now)`）；測試一律給固定的數字。
- **資料庫是唯一的真實來源**：暫停記在 `world` 表那一列（`SharedWorldState.paused_at`），伺服器重開、假人程式、主機端腳本看的都是同一個欄位；不改資料表、不升 `SCHEMA_VERSION`。
- **新欄位都有預設值**，舊存檔、舊資料庫直接讀得進來：`PlayerState.joined_at` 預設 `0.0`（新角色才明寫 `None`），`SharedWorldState.paused_at` 預設 `None`。
- **第一季開關**：加入時間的讀法（Task 1）只在 `rules.season_one(content, world)` 成立時改；開關關著、或這一季沒蓋「開」的章，新手福利照舊從季初算（`test_with_the_switch_off_the_perks_still_follow_the_season_clock`）。暫停不看開關（B8，已定），但沒人按就什麼都不變：Task 3 的管理者測試就是在開關關著的測試內容上跑的。
- **補算時間只算一次、只往前**：暫停中 `catch_up_season` 連對時點都不碰；繼續時對時點往後挪跳過的長度，不是設成「現在」（主機端腳本沒先補算就暫停時，暫停前那一小段照算）。跳過的長度第一季照整個曆時往下取整（B12），所以對時點永遠不會超過現在、季鐘繼續之後馬上就走。
- **排好的決戰照原本的現實時間開**（B3）：繼續時排好、還沒開的決戰往前挪「跳過的長度 × time_scale」個世界秒，季末與一般的大事不挪；不越過原本排在它前面、還沒結算的一般大事（B13）；原本的時間落在暫停裡的記進排隊，繼續的那一下就開（B11）。這兩件事都在 `resume_clock` 那一次 `mutate` 裡做（`world.keep_showdowns_on_time` 只改傳進來的季），開集結是呼叫端緊接著的 `start_pending_battle`。
- **`mutate` 不能巢狀**：`pause_clock`／`resume_clock` 各自是一次 `mutate`，決戰期限在同一個 `mutate` 裡改（`shift_deadlines` 只改傳進來的物件，不碰存取介面）。
- **伺服器假人跟真人看不出差別**：暫停對每個角色一樣；假人程式暫停中整輪跳過，主控台照舊只印數字。
- **擋動作在鎖裡**：伺服器在拿到行動鎖、同步之後才看 `paused_at()`，丟 `GameError` 時整筆交易撤回；鎖外三段（對話、大場面、開爐、隨口應對）在 A 段就擋，模型一次都不叫。
- 畫面文字只用繁體中文；行動名稱照 CLAUDE.md（遊歷、交友）。不碰 `content/`（這份沒有新內容）、不碰 `saves/`、`.local/`。

def _pause_step(world, content, now: float, pause: tuple[float, float], frozen: list[float], log: dict) -> None:
    """到了就暫停（一季只停一次）、停滿就繼續（跟管理者按「繼續」一樣：原本的時間落在暫停裡的決戰這一刻開集結）；
    繼續的那一刻（還沒有人同步之前）記下停的這一段季走了多少——應該是 0。"""
    start, end = START + pause[0] * 3600, START + (pause[0] + pause[1]) * 3600
    if not frozen and start <= now < end and world.pause_clock(now):
        frozen.append(world.get_season().time)
        log["at_day"] = frozen[0] / 86400
    elif frozen and now >= end and world.paused_at() is not None:
        world.resume_clock(content, now)
        log["season_moved"] = world.get_season().time - frozen[0]
