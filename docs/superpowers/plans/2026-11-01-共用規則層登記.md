# 共用規則層登記 實作計畫（全部拆包第 15 批：只登記、不搬程式）

> **給執行的人：** 照 superpowers:executing-plans 一個 Task 一個 commit 做，不開子代理；每做完一個 Task 推一次 `dev/core-shared-1`（`git push origin HEAD:dev/core-shared-1`）。

**目標：** 開第二份名單「共用規則層」（`tianxia/core/registry.SHARED`）把總表第 15 列的那幾十個規則模組登記進來，`services.py` 補上五區量好的共用服務；包 import 共用規則層不再算過渡（不必註「過渡：待搬」）；邊界測試補上第 11 批沒守到的那一條「共用規則層只 import 核心本體與同一層」；`test_for` 改共用規則層的模組照手冊 4.3 的一種挑。**行為一個字不變**：`tianxia/` 裡只動名單、說明字與 import 那一行行尾的註，不搬程式、不改任何一行會執行的程式。

**架構：** 三層 import 的方向（總表第六節第 5 條）：核心本體（`MODULES` 十五個＋`tianxia/core/`）可以 import 共用規則層；共用規則層可以 import 核心本體與同一層；包可以 import 兩層；兩層都不准 import 包。現行程式裡有些候選 import 了「之後會成包」的舊模組（擂台、懸賞、鐵匠鋪、伏筆……），照派工的兩個選項，這一批一律**先不收**（`SHARED_LATER`，寫明卡在哪、哪一批之後收）；只有兩個例外收了、記成過渡（1.3）。import 了「排定收進核心本體或共用規則層」的舊模組（`figures`、`world`、`atlas` 的路線……）的照收，那幾條記進邊界測試的 `SHARED_PENDING`（寫哪一批收）。

**依據：** 手冊 `docs/superpowers/specs/2026-10-30-開發模式-design.md` 第三節、第十五節（含第 11 批的 PM 認定：接縫掛鉤、`SHARED` 的格式是模組名 → 一句理由）；總表 `docs/superpowers/plans/2026-10-31-全部拆包-總表.md` 第 3.3 節甲表第 15 列、第六節第 4、5 條、附錄甲、附錄丙；批次表 `2026-10-31-主動搬六包-批次.md` 第二節逐條、第一節「10/31 晚起改成並行」；第 11 批計畫 `2026-11-01-核心收接縫.md`（格式照它）。分支 `dev/core-shared-1`，從 `origin/feature/core-shared`（`a242343b`＝develop）開。埠 8195、`shared1.localhost`（這一批沒動 `web/`、路由，開發這一側不開實機）；暫存 scratchpad `shared1/`。

1. **登記的模組真的不 import 包**：`SHARED` 裡每一個，最外層、函式裡（不含 `TYPE_CHECKING`）的 import 只碰核心本體、`tianxia/core/`、同一層，或 `SHARED_PENDING` 寫明的那幾條；`SHARED_PENDING` 的對象沒有一個是現在的包或別名（第 8 批 `generals` 成包那一下這條會紅，強迫那一批先處理）。

### 1.3 碰到「之後會成包」的模組：怎麼處理

派工的兩個選項是「先改成查詢服務」或「先不收」。這幾個模組讀的都是**還沒成包**的舊模組（擂台、懸賞、伏筆、有所感……還在 `tianxia/*.py`），現在沒有包可以回答查詢；查詢服務在這一層的寫法（`ctx.<名>` 是 `Game` 上的方法，規則模組拿不到 `ctx`）要那一包成包時才有對象。所以：

- **先不收 8 個**（`SHARED_LATER`，邊界測試守「還卡著」）：`fusion`（有所感，第 24 批）、`skillview`（自創第 44、修練第 23、玉璽第 27、鐵匠鋪第 41 批）、`shopview`（擂台第 12、懸賞第 45、鐵匠鋪第 41 批）、`events`、`narration`、`rumor_view`（伏筆與機緣，軍情第 34 批）、`tiers`、`leaderboard`（擂台的名次與稱號，第 12 批；總表第 12 列寫那一批「要決定留在核心當查詢服務」）。它們不是誰的底：先不收沒有連帶（拿掉之後剩下的候選沒有一個 import 它們）。包 import 它們的那幾行照舊註「過渡：待搬」（探索包 `events` 3 行、酒肆包 `shopview` 1 行）。
- **收了、記成過渡 2 條**（`SHARED_PENDING` 的「之後成包」那一種；理由交 PM，第五節）：
