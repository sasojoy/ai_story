# 路上：改道、路上小事、路上見聞 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the road worth being on: players can turn back or reroute from the middle of a road (A), do four once-per-leg road tasks while walking or hurrying (B), and sometimes see a short written road sight on arrival (C).

**Architecture:** All rules stay in `tianxia/`. The road position is computed, never stored: `atlas.road_spot()` returns the two stops the player is between and how far along (from `Journey`'s arrival times plus two new `Journey` fields that describe a rerouted, partial first leg). `atlas.way_to()` is the single "how do I get there from where I am" function: at a stop it is the existing shortest route, on the road it compares turning back with going on. Travel, 折返 (the new `road:back[:<mode>]` option), the map buttons and the map drawing all use it. Road tasks are `road:<task>` options, remembered per leg on `PlayerState.leg_actions`. Road sights are content (`content/road_sights.json`, model `RoadSight`), rolled in `Game._arrivals` after each stop. The web page only adds shortcuts (page-side tab switches) and lets the 走法 toggle drive 折返.

**Tech Stack:** Python 3, pydantic v2, FastAPI (`server.py`), vanilla JS (`web/app.js`), SQLite world store, pytest.

**Spec:** `docs/superpowers/specs/2026-10-03-路上-design.md` (authority; A = §三, B = §四, C = §五) and, for C's content, `docs/superpowers/specs/2026-10-03-第一季陣營內容-路上見聞.md` §二 (the 30 sights).

def _partway(game, share=1 / 3):
    """從小鎮步行往湖邊（夾具 3 分鐘），把時間推到走了 share 成的那一刻；回傳這一趟。"""

@dataclass(frozen=True)
class RoadSpot:
    """路上的位置（路上設計第二節）：在 behind 與 ahead 這兩站之間的那條路上，正往 ahead 走。只用這三樣表示，
    不另外存座標。平常 behind 就是 player.location（最後抵達的那一站，設計裡的 P）、ahead 是下一站（N）；
    掉頭之後 behind 是剛才要去的那一站（人正在離開它）。"""

    behind: str  # 身後那一站：正在離開的那一頭
    ahead: str  # 前面那一站：正要走到的那一頭
    done: float  # 從 behind 往 ahead 走了幾成，0～1
    minutes: float  # behind—ahead 這條路整條的路程（步行分鐘）


def road_spot(state: GameState, content: Content) -> RoadSpot | None:
    """在路上的位置；人在某一站（沒在路上）時是 None。走了幾成＝這一段已經走掉的時間 ÷ 這一段的時間；
    改道出發的第一段只走那條路剩下的部分（Journey.origin、share）。"""
    j = state.player.journey
    if j is None or j.reached >= len(j.path):
        return None
    ahead = j.path[j.reached]
    first = j.reached == 0 and j.origin is not None
    behind = j.origin if first else state.player.location
    share = j.share if first else 0.0
    minutes = leg_minutes(content, behind, ahead)
    span = travel_seconds(minutes * (1 - share), j.mode)  # 這一段這一趟要走幾秒
    left = j.arrive_at[j.reached] - state.world.time
    walked = 1.0 if span <= 0 else min(1.0, max(0.0, 1 - left / span))
    return RoadSpot(behind, ahead, share + (1 - share) * walked, minutes)


def way_to(state: GameState, content: Content, loc_id: str) -> Route | None:
    """從現在的位置到 loc_id 路程最短的走法；走不到時是 None。人在某一站時就是 routes 的那一條（所在地本身是 None）。
    在路上時（路上設計 3.1）比兩種走法、取路程短的（一樣近時繼續往前）：繼續走完這一段到前面那一站再接著走，
    或掉頭先回身後那一站再接著走。第一段是半段路、路的種類照原本那一條；身後那一站本身也到得了（就是折返）。"""
    spot = road_spot(state, content)
    if spot is None:
        route = routes(state, content).get(loc_id)
        return route if route is not None and route.path else None
    known = known_locations(state, content)
    best: Route | None = None
    for end, other, part in ((spot.ahead, spot.behind, 1 - spot.done), (spot.behind, spot.ahead, spot.done)):
        onward = shortest_routes(state, content, known, start=end).get(loc_id)
        if onward is None:
            continue
        way = Route((end, *onward.path), (spot.minutes * part, *onward.legs), origin=other, share=1 - part)
        if best is None or round(way.minutes, 6) < round(best.minutes, 6):
            best = way
    return best

    def _road(self, arg: str) -> list[str]:
        """路上的選項（路上設計第三、四節）。road:back[:<走法>] 是折返：回身後那一站，跟大地圖改道走同一條路（見 _depart）。

        if what == "back":
            return self._depart(self._back_way(), mode or "walk")
        self.state.player.leg_actions.add(what)
        tasks = {"think": self._road_think, "ask": self._road_ask, "survey": self._road_survey, "gather": self._road_gather}
        return tasks[what]()

    def _road_ends(self) -> tuple[str, str]:
        """這段路的兩頭：身後那一站、前面那一站。"""

        heard = [

            if r.region in regions and r.faction in (None, p.faction) and r.character in (None, p.name)

        s, c = self.state, self.content
        views = atlas.views(s, c)
        found: list[str] = []
        for end in self._road_ends():
            for loc_id in (end, *(str(dest) for dest in c.locations[end].connections)):
                if views[loc_id] in ("outline", "dot") and loc_id not in found:

        return [f"你留意沿路的地形，摸清了{'、'.join(c.locations[loc_id].name for loc_id in found)}的位置。"]

## Decisions the spec didn't settle

1. **Sight rewards are large in aggregate (needs a ruling).** The spec's numbers are implemented as given: 30%, rewards up to 心得 5 / 銀兩 10. A walking-heavy test bot reaches about 500 stops a season, and sights roughly double its season 心得 and materials (Task 6). For humans, honest walking also earns from road tasks: each leg (about 3 minutes on the real map) gives 心得 +3 plus 0.4 of a material plus about 0.4 心得 from sights, at no stamina cost. Station play is stamina-limited: regen is 1 point per 3 minutes, so one 10-stamina 歷練 (心得 12–20) about every 30 minutes. Walking back and forth between two stops therefore out-earns staying put, against the spec's §四 intent that 「一直趕路」 should not be the best play. Every number is a `Config` default (`road_think_xinde`, `road_gather_chance`, `road_sight_chance`), so a ruling is a one-line `content/config.json` change once Infra's FB-013 edit there lands.
2. **`leg_actions` lives on `PlayerState`, not on `Journey` as the spec says.** On `Journey`, 折返 at f ≈ 0 makes an infinite free loop: depart, do all four, 折返 (≈0 time, walking costs no stamina), arrive back, depart again with a new `Journey`. The rule here: reaching a stop other than `player.location` clears the set; returning to the stop just left does not. That gives exactly one set of tasks per real leg walked, however the player turns around. Side effect: after a turn-back, the next leg starts with those tasks still greyed until a new stop is reached.
3. **折返 goes to the stop behind the player** (the end they are walking away from). Normally that is the spec's P (`player.location`). After a turn-back it is the stop they had been heading to, so pressing 折返 again turns around again instead of doing nothing.
4. **Two `Journey` fields, `origin` and `share`,** describe a rerouted partial first leg. They are not coordinates, so §二's "不另外存座標" holds. The position is still computed from arrival times.
5. **On the road no stop is "current"** (`atlas.location_view`). P shows as a visible stop, 「（你）」 and 「（所在地）」 disappear from it, and the 你 marker carries the identity. The routes layer and the route line count from the road position, and the minimap centres on the marker, so they agree with the travel buttons.
6. **Ties between going on and turning back go on.**
7. **The disabled 「（在路上，… 抵達…）」 info row stays** as the first option. The toggle sits between it and 折返.
8. **Option ids:** a new `road:` kind. `road:back[:hurry|dash]` mirrors `move:<id>[:<mode>]`, so `choose()`'s "the id must be on the current menu" rule validates the mode as it does for 前往. The tasks are `road:think|ask|survey|gather`. `bot.pick` and `bot_policy.take_turn` drop every `road:` id. This lands in Task 1, because 折返 is always enabled on the road.
9. **Labels:** tasks use 「邊走邊想（心得 +3）」, 「沿途打聽（聽一則這一帶的傳聞）」, 「留意地形（摸清附近的地點）」, 「路邊採集（有機會撿到素材）」, and when done 「邊走邊想（這段路已經想過了）」 and so on. They carry no 體力 part because they are free. The 折返 journal entry is titled 「前往 X」 like any trip, so its arrival merges into the same entry. The departure line says 改道 instead of 動身, and stays hidden like the normal one.
10. **沿途打聽** skips other factions' 軍情 and other characters' personal clues. The rumor board doesn't enforce visibility layers yet, but a road task shouldn't leak them. Only rumors with a `region` qualify. World-layer rumors without a location have none, so they are never heard on the road.
11. **留意地形** marks every unlocked place with view `outline` or `dot` among both ends and their direct neighbours, the ends included.
12. **路邊採集's attribute rule:** collect the attributes of every material either end lists (any tier), then pick a tier-1 material with one of those attributes. If neither end lists any, pick any tier-1 material.
13. **Tunables are `Config` defaults; `content/config.json` is not edited** (Infra is changing it). The defaults are `road_think_xinde=3`, `road_rumor_pool=5`, `road_gather_chance=0.4`, `road_sight_chance=0.3`, `road_sight_recent=5`.
14. **The test fixture turns sights off** (`road_sight_chance: 0`, and with chance 0 no random number is even drawn), so every existing fixture test keeps its random sequence. Sight tests set the chance themselves.
15. **Sight text joins the arrival's journal entry** (merged into the trip's entry, dated at the arrival). When an offline catch-up reaches several stops at once, their sights share the one entry dated at the last arrival in that batch.
16. **`road_sights.json` is required**, like `materials.json`, and the coverage check always runs. On a map without regions it checks each road kind alone. Rewards must be positive, and a sight's material counts as a material source for the "every material is obtainable" check.
17. **Verified on fb567bf (origin/main), as the controller asked.** Against cc9561a's descendant 94f77c2 the plan applied cleanly. Moving to fb567bf (PRs #3–#5) touched four anchors, all now written against fb567bf:
    - `bot_policy.take_turn`'s filter, which now also drops `FREE_TEXT_OPTION`;
    - the `app.js` options map, which now has the quick-reply answer form;
    - the engine's `from .models import …` line, which now starts with `FREE_TEXT_MAX`;
    - the end of `tests/test_server.py`, where the new 隨口應對 tests follow the 走法 tests.

    The final check: the plan text was applied mechanically to a fresh fb567bf worktree, task by task, with the suite run after each task, and the result is identical to the hand-built tree.

## Risks

- **Concurrent edits.** Infra's FB-013 work changes `tianxia/engine.py::_explore` and `content/config.json`. The `engine.py` anchors here sit elsewhere (the import line, `_everyday_options`, `_depart`, `_arrivals` and others), but an edit to the `from .models import …` line or nearby would make an anchor miss. Re-read and reapply the same change. The test counts shift by whatever Infra adds.
- **Balance** (Decisions, item 1): sights and road tasks together can make walking the best 心得 farm. Tuning is a config change, but someone has to decide.
- **Chaotic simulations.** Any new random draw on arrival reshuffles every seeded season, so endings and days in `sim_server_bots` and `fun_run` change with no real rhythm change. The isolation check in Task 6 is the reliable signal.
- **Front end untested by pytest.** `web/app.js` and `web/style.css` changes are checked only by `node --check` and the controller's browser pass (Task 3 Step 7), including the 375 px phone width.
- **Floors on tiny trips.** `travel_stamina` charges at least 1 for 趕路 and 疾行, and `whole_minutes` shows at least 「約 1 分鐘」. So 折返 right after setting out reads 「步行約 1 分鐘」 and costs 1 point when hurried, though it is nearly instant. This is inherited behaviour, left as is.
- **Content edits to the map** (moved coordinates or road kinds) while someone is mid-road change `leg_minutes`. The walked fraction is clamped to 0–1, so the marker and reroutes stay sane, just approximate for that one trip.
- **OpenCC fallback.** If OpenCC fails to load, the Traditional check only catches the characters in `zh.FALLBACK`. The 30 sights pass under OpenCC; the simplified-text test uses fallback characters on purpose.
