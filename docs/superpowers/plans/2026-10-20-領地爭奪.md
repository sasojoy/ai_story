# 領地爭奪（第 38 項改版）開發計畫

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 第一季的地圖分成黃巾、官軍兩種陣營領地與中立領地；兩軍每天下令或投票挑一兩塊、晚上打縮小版的決戰（攻城戰）搶地；佔領決定三條戰線大勢值的基準，其他來源照舊推偏移；玉璽碎片只從中立地探索撿到；每天一篇〈天下形勢〉。

**Architecture:** 新的純規則模組 `tianxia/conquest.py`（區塊、相連、控制方、基準＋偏移、加成、進度）接在 `territory.py` 之下：開關開著時 `territory.update` 不再拔河，控制方只由攻城戰、時刻表指定、管理者改；`world.trends[戰線]` 照舊存「此刻的值」（＝夾過的基準＋偏移），所以所有讀線的地方不用改。第二批加 `conquest_day.py`（每天 22:00 的鐘、下令、投票、主將挑、時程表）與 `siege.py`（攻城戰＝決戰引擎的縮小版），攻城戰另存一串（world 表的 JSON 記流水號、battles 表一場一列，資料庫結構不動），所以能跟時刻表決戰、別的攻城戰同時打。第三批碎片改成「開季藏一片、探索撿到」（`seal.py`），〈天下形勢〉照舊計畫的三段式（`xingshi.py`）。

**Tech Stack:** Python 3（pydantic 模型、SQLite），FastAPI（`server.py`），原生 JS（`web/app.js`），pytest＋webharness。

**Spec:** `docs/superpowers/specs/2026-10-20-領地爭奪-design.md`（企劃者核准版）。〈天下形勢〉的三段式沿用 `docs/superpowers/plans/2026-10-18-AI判斷勢力版圖.md` 的 2.1、2.4、2.5 與 Task 3～5。

### 2.2 大勢值（4.7）

- `ConquestState.start`：開季第一次算時抄下每塊的種類（之後內容改了，這一季不跟著動）。
- 一方在一條線上的「佔得」＝這條線上它控制、而開季不是它的區塊權重和（中立 `neutral_weight` 1、陣營 `faction_weight` 2；大本營與 `fixed` 不算）。這樣開季兩邊都是 0、基準 50（4.7「開季基準在 50」）。
- 基準 `base(line)＝50＋share×(佔得_黃巾－佔得_官軍)÷分母`；`share` 35【預設，PM】；分母照 `weigh_by`：`"total"`（設計：那條線所有可奪區塊的權重和）或 `"neutral"`（只算中立的權重和）【預設 `"total"`，見「要 PM 決定的」第 5 條】。
- 偏移 `ConquestState.offset[line]` 開季 0。值＝`clamp(round(base＋offset), 0, 100)`，存進 `w.trends[line]`（所有讀線的地方不用改）。
- 推線（`change_trend` 推三條戰線）：`new = clamp(value＋delta)`，`offset = new − base`（重錨：推進牆的部分丟掉，跟現在一樣），回實際推動量。易手只重算基準、偏移不動，值重新夾。

### 2.3 進度（3.7、4.4）

- `ConquestState.progress[loc]`：0～100、照戰線的方向（100 往黃巾、0 往官軍），沒寫是 50。
- 第一批：任何可奪的區塊都記；第二批起只有「今天公告、還沒打」的目標推得動（`conquest.progress_open`），打完或作廢歸 50。
- 推一下＝`max(1, Σ|train_trend|)`×（攻 1、守 `Config.sortie.hold_share`）×`progress_scale`【預設 2.0】÷√n（n＝那一邊 `active_window_days` 內推過的人，`push.buffered`／`push.active_count`，同推線的人數緩衝；`active_pushers` 照記）。沒有每人上限：出陣一天 5 次本身就是上限。事件在那一塊了結也推 `event_progress`【預設 1.0】一次。
- 貢獻照推線那一條：`push.contribution(名目量…)` 記進那一週（不然出陣不推線之後沒人升得到第 4 階）。
- 開打起點：進度偏 50 每 10 點偏 `start_shift_per_10`【預設 2】、最多 `start_shift_cap`【預設 10】（4.4），換成戰局方向（`factions[0]` 是官軍，往黃巾偏就是戰局往下）。
- 玩家看到的是一句話（「淯水河畔一帶，我軍漸佔上風」，待 joy 潤），不寫數字（同戰況變化的規矩）。

### 2.4 每天的鐘（第二批，4.3）

- `day_key(real)＝floor((real＋時區×3600－settle_hour×3600)÷86400)`，`settle_hour` 22【預設】、時區照 `pill_day_utc_offset_hours`。下令、投票都是替「下一個 key」下的。
- 結算在 `Game.sync`（擂台換日附近）照 `pill_now()` 觸發：key 比 `settled_key` 大才做，第一次只記 key（開季當天沒有令可結）。
- 一天每邊幾塊：`中立區塊數 ÷ 季長 ≥ two_per_day_ratio`（0.5）就 2，否則 1（4.2）。v1 是 12 塊：週末、21 天都是 2。
- 開打時段 12:00～21:00 的整點與半點（`slot_first`／`slot_last`／`slot_step_minutes`）；時刻表決戰前 `showdown_gap_before` 30 分到後 `showdown_gap_after` 45 分的時段拿掉（見「要 PM 決定的」第 6 條）。
- 結算時：每一邊照「有第 4 階的命令→票數最多的那一組→主將照規則挑」定（順序見 Task 8），兩邊合成時程表（同一塊同一刻併成一場，同一塊不同刻照時間排），每場換成世界秒；集結在開打前 `muster_seconds`（範本寫 1800）開。

### 2.5 攻城戰（第二批，4.4）

- 範本：`content/battles.json` 每個有區塊的大區一筆 `siege_<大區>`（`factions` [guan, huang]、一幕、`rounds_per_act` 5、`decisive_margin` 40、`muster_seconds` 1800、`round_seconds` 180、`free_text_gamble` 照決戰、`outcomes` 一筆保底），字待 joy 潤。

3. `siege.slots`：兩軍各站自己那一格，散人只能投效兩軍之一（沒有守的那一格）。
4. 回合照決戰一模一樣（兩軍正面打，偏離中線 40 當場收場）；`siege.verdict` 戰局剛好 50 是相持（`STALEMATE_LINE`「兩軍相持不下，某地照舊沒人佔」），否則推過中線的那一軍拿下。QA 量到的「相持」就是兩邊人一樣多、戰局停在 50。
5. 不同時段兩邊都挑同一塊：`siege.open_waiting` 開集結那一刻重看誰佔著（Review Focus 3），後打的照打新主人或原本的守將——這一條不動。

**新規則（【企劃者】三條＋【開發】定的做法，字待 joy 潤、數字【預設】）**：
- **誰算三方混戰**（`battle_instance.melee`）：攻城、開集結那一刻沒人佔、攻方是兩軍、那裡有守將（`guard_squad` 找得到隊伍；開季中立的每一塊都有，找不到時退回上面第 4 條的正面打）。守將站第三格 `battle_instance.GUARD`（`"guard"`，`SiegeInfo.guard_side` 記它；`side_names` 寫「守軍」），不是任何一軍；範本照舊只有官軍、黃巾兩格。
- **守將兩邊都打**（照單方攻中立地時守將的打法）：守將每回合照「兩軍上一回合合起來出最多的那一招」喊令（`call_orders`，六成照讀、其餘隨口），他的招算進兩軍各自的「對面」（剋制係數照兩軍以外所有人這一回合出招的比例算）；他出強攻時集火打兩軍顯眼的人。守將（與助守的人）**不推戰線**。
- **兩軍互打＝戰線只算兩軍之間**：三招、剋制、推力、自己扣血、集火、點名照決戰原本的規矩，只在官軍與黃巾之間算出戰局（強攻照舊打得到對面：推戰線、集火對面顯眼的人、點名打傷對面的人）。**偏離中線不當場收場**（三方混戰只有守將倒下或回合打完才收）。
- **打守將**（照單方攻中立地時守將池子的扣法）：兩軍每一個出強攻的人（含隨行同伴）打守將 `focus_per_attacker`，點名守將的放手一搏成了打掉池子的 `hit_base`＋風險×`hit_per_risk`（最多 `hit_max`），一回合最多 `round_cap`；助守的人出固守替他擋（`guard_per`／盾陣 `guard_role`，最多 `guard_cap`，擋下的平分給他們）。**一軍打守將的力道再乘「這一回合開打時戰線往自己偏多少」**：自己那一頭的戰局 ÷ 50（中線 ×1，壓到底 ×2，被壓到底 ×0）——這就是「打守將還是打對面」的答案：每一招都照決戰跟對面交鋒，強攻另外打守將；把對面壓下去，下一回合自己打守將就多幾成、對面就少幾成（兩軍人數一樣時兩軍合起來打守將的總量不變，只是換誰打）。
- **守將的池子**（`ConquestRules.melee_pool_per_head`【預設】30）：集結結束那一刻照兩軍到場的人數算（至少算 2 人）。一個人五回合都強攻、戰線在中線，打得掉 15×5＝75；所以兩軍平均四成的回合出強攻（或放手一搏點名守將）守將撐不過五回合，一回合最多打掉四分之一、最快第 4 回合倒。原本的 1500（龍頭主將的池子）照十來個人的服量過是打不倒的，交 PM 看要不要另定。
- **最後一刀**：守將的池子在哪一回合歸零，那一回合**打守將打得多的那一軍**拿下（兩軍都打到、超過剩下的照比例分）；一樣多看這一回合開打時戰線偏向哪一軍；戰線也剛好在中線，照自己的亂數（`最後一刀|戰役|流水號|回合`）擲。那個人＝那一軍這一回合打守將打得最多的參戰者（隨行同伴打的算主人的；一樣多照強攻份量、名號），記 `slew`（戰功）與 `Commander.felled_by`（收場補名望 `slay_fame`，同擊退龍頭）。守將倒下那一回合當場收場。大勝／險勝照拿下那一軍最後的戰線偏多少（≥15 大勝）。
- **回合打完守將沒倒**：守住，這塊地照舊中立（`MELEE_HELD_LINE`）；贏的一方記守軍（`outcome_side` 是 `GUARD`，險勝），助守的人拿得勝的軍餉。
- **助守**：散人、不是兩軍的人照舊可以臨時投效兩軍之一、或助守【守軍】（站 `GUARD` 那一格）。助守的人用官軍那一組招的字（範本只寫了兩軍的招）；他們的份量不推戰線（按鈕不寫分數、不接「主將令」，守將的將令那一行不寫給他們看），固守替守將擋、強攻集火兩軍顯眼的人、放手一搏可以點名兩軍的人；沒點名的放手一搏成了替守將補回同樣的量（`hit_base`＋風險×`hit_per_risk`，補不過上限）。助守不帶隨行同伴（挑同伴那一步跳過；同伴只在兩軍那兩格上陣）。戰局條旁的「本場戰功」只列兩軍；論功的天下大事、戰報的「你站在守軍」、排名照 `side_names` 有守軍。
- **寫出是誰補上最後一刀**：回合裡一句 `BLOW_LINE`；收場的勝負的關鍵 `BLOW_REASON`（「第 N 回合，某軍的某某補上了最後一刀」）進戰報與江湖紀錄；天下大事 `BLOW_RUMOR`（具名，天下大事一律寫名號）接著「落入」那一句；戰報、紀錄標題 `MELEE_TAKEN_TITLE`「某軍補上最後一刀，拿下某地」，守住是「守軍守住某地」。
- **集結結束只有一軍到場＝轉回單方攻中立地**（裁決 23，PM 2026-10-21）：另一軍一個人都沒來算棄權，到場的那一軍照單方攻中立地打（守將照舊、戰線過了門檻就拿下，不用把守將打倒，`siege.lone_army`）；兩軍都沒人到照裁決 19 作罷，兩軍都有人到照上面的三方混戰。
- **不動的**：開關關著、單方攻中立地、攻陣營區塊、不同時段兩邊都挑同一塊，一個字都不變（三方混戰的每一處都先問 `melee`；`tests/test_conquest_siege.py` 等舊檔照跑）。假人照現在的規則出招（`bot_policy._battle_score` 讀 `option_of`，助守的人對應到官軍那一組招）。

### 6.2 FB-530 的修法（2026-10-20，QA 第一輪之後）

偏移就是「其他來源累積的量」，夾值只在算出要顯示的值那一刻做（`value`／`reweigh` 照舊 `clamp(基準＋偏移)`）。`apply_push` 不再從夾過的值重錨：未夾的 `基準＋偏移` 加上 delta；推過牆的那一截丟掉——往 100 推時新的未夾值最多 max(原本的未夾值, 100)，往 0 推時最少 min(原本的未夾值, 0)。所以基準已經在牆外時，往牆那一邊推偏移不動（推的全丟掉），往回推照實記進偏移（值可能還夾在 100，易手之後才看得出來）；回傳的實際推動量照舊是顯示的值前後差。順帶：基準有小數時推 1 不再因為四捨五入讓偏移多走或少走半格。決戰收場這類直接寫 `world.trends` 的照舊在 `_sync` 照上一次的基準重錨（那是明寫一個值）。
