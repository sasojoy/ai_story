## 三、橋的規則（`scan`、`render`、`post`、`advance`、`log_line`、`main`；簽名照計畫）

- `state`＝`{"new": [單號…], "reply": 最大 id, "flag": 最大 id, "file": 最大 id}`；檔不在＝全空（第一次開會把舊單全貼：要先 `--once --dry-run` 記成貼過，寫進操作文件）。寫回用暫存檔＋`os.replace`，**每貼成功一則就存**（中途掛了不重貼）。
- `scan` 順序：`NEW`（單號小的先；`id not in new` 且 `now - created >= grace` 或已有圖；帶那張單快照裡全部的圖）→ `REPLY`（replies.id 序）→ `HUMAN`（flags.id 序）→ `FILE`（files.id 序，只對 `new` 裡〔含這一輪剛 NEW 的不算：那幾張跟 NEW 一起上，水位直接走過〕的單）。
- REPLY／HUMAN 的單還沒貼 NEW（還在 60 秒裡）：那一種的水位**停在它前面**，這一輪後面同種的都等（最多等 60 秒），不越過。
- `render(event, ticket_row, mention_ids=())`：計畫的 `render(event, ticket_row)` 拿不到 ID，加一個有預設值的關鍵字參數（見 decided）。頭一行 `#12・類別名・名號・版本・送單時間（本機時間 YYYY-MM-DD HH:MM）`；NEW 接全文、REPLY 接「玩家再回」＋那一則、HUMAN 接「玩家要找真人」＋`<@ID>` 兩個、FILE 接「補一張截圖」；整則超過 1,900 字截掉補「…」（Discord 上限 2,000）。
- `post`：`files[i]` 的 multipart＋`payload_json`＝`{"content", "allowed_mentions"}`（一般 `{"parse": []}`、HUMAN `{"parse": [], "users": ids}`）；`timeout=20`。回 `ok`（2xx）、`retry`（逾時、連線錯、429、5xx）、`dead`（其他 4xx：400、401、403、404 照計畫，413 等也算，見 decided）。**例外的字不印**（`requests` 的例外字串帶 webhook 網址＝金鑰）；警告只印狀態碼。
- 一輪：碰到 `retry` 這一輪就停（後面的不越過，保住先後）；`dead` 印警告、`advance`、照寫 log。連續失敗輪數到 10 的倍數印一行警告到 stderr、不停。沒有 `discord_webhook` 或 `--dry-run`：不叫 `post_fn`、照寫 log、照前進。
- `--log` 每則一行 `NEW 12`／`REPLY 12`／`HUMAN 12`／`FILE 12`（utf-8、附加、flush）；`ALIVE <本機時間>` 每 300 秒印 stdout。`--once` 跑一輪結束（旁檔不在＝空的一輪、結束碼 0）。金鑰檔 `--config` 讀 `discord_webhook`、`mention`，壞了當沒有（印一句）。

## 四、CLI（`main(argv, session=None) -> int`；子命令照計畫）

- `argparse(allow_abbrev=False)`；**鎖定模式**（`TIANXIA_SUPPORT_LOCKED=1`）先掃原始 argv：`--config`、`--url`、`--inbox`（含 `--x=…`）出現就印一句、回 2、什麼都不打；路徑改讀 `TIANXIA_SUPPORT_CONFIG／URL／INBOX`，沒設照預設（`ROOT/.local/support.json`、金鑰檔的 `server_url` 再 `http://127.0.0.1:7861`、`ROOT/.local/support-inbox`）。argparse 自己的 `SystemExit` 轉成回傳碼。
- 每次請求帶 `Authorization: Bearer <bot_token>`、只用 `session.request(method, url, headers=, json=)`。金鑰檔沒 token → 印 token 那一句、2、不打。回應：2xx 成功；400 印 `error` 原句、1；404 `detail == "Not Found"` → token 那一句、2；404 帶別的句（「找不到這張單。」）原句、1；其他碼與連不上 → 一句、2。
- `queue`：先 `POST /api/support/sweep`（`json={}`；失敗照上面處理），再 `GET /api/support/queue`；一行 `#單號 標籤 類別名 名號 更新時間 摘要（30 字、換行換空白）`，標籤照 `admin_flag` → `請管理者`、`human` → `等真人`、`status == "answered"` → `等玩家`、其餘 `待客服官`；最後一行四種標籤各幾張。**不印 `login`**（queue 回應裡有）。
- `ticket <n>`：單頭、全文、每一則（判斷順序 `internal` → 內部註記、`system` → 系統、`auto` → 自動回覆、`staff` → 客服、其餘玩家）、帳號卡（名號、建帳號日、綁了哪幾種〔只印種類名，不印 `shown`〕、餘額、帳本；`gone` 印一句）；**不印 `login`**；每張圖 `GET /api/support/file/<n>/<seq>` 存 `<inbox>/<n>/<seq>.<kind>`、印絕對路徑。
- `answer <n> [--close] [--human <ID>]`：stdin（`sys.stdin.buffer` 解 utf-8）→ `POST answer {id, body, then: close|wait, relay_from?}`；`--human` 只收數字（不然 2）。`note <n>`：stdin → `then=admin`。stdin 空或全空白印 `EMPTY` 那一句、1、不送。`close <n>` → `POST close {id}`。
- stdout 的 utf-8 只在 `__main__` 裡 `reconfigure`（測試用 capsys）。永遠不印 token、`bot` 字樣、`login`。
