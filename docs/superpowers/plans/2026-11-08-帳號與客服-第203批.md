## 包與檔（`tianxia/features/identity/`，第 201 批開的包）

- `codes.py`（新，純規則，不讀時鐘、不讀環境）：`ip_buckets(ip)`（IPv4 原樣；IPv6 回 /64 與 /48 兩格）、`pool_of(purpose, bound)`（login＝已綁的登入與找回、bind＝第 204 批、anon＝沒綁的新號碼）、`buckets_for(...)`（60 秒一號、每日兩格〔共用格 5、信任瀏覽器格 5〕、來源一小時 10、全服池的時與天）、`new_code()`（`secrets.randbelow`，6 碼補零）、`code_hmac(key, challenge_id, code)`、`send(...)`、`verify(...)`；所有回玩家的字常數在這一檔最上面。
- `senders.py`（新）：`SmsSender`、`MailSender`、`TurnstileVerifier` 三個 Protocol；`FakeSms`、`FakeMail`（`outbox` 記 `(to, text)`）、`FakeTurnstile`（token `"ok"` 才過）；`NoSender`（丟 `SendFailed`，正式機在服務商接上之前用這個）；`CloudflareTurnstile`（`urllib` POST siteverify，逾時 5 秒，驗 `success`、`hostname`、`action`；測試不打它）；`pick(content)` 照 `Config.identity.fake_services` 回一組三個。秘密（Turnstile secret）從 `.local/identity.json` 的 `turnstile_secret` 讀，路徑用 `identity_base.KEY_FILE`。
- `store.py`（改）：`challenges` 多 `channel`、`subject_hmac`、`display` 三欄（第 201 批的旁檔只有測試建過；開檔時 `PRAGMA table_info` 缺欄就 `ALTER TABLE ADD COLUMN`）；新表 `trusted_devices(dev_hash, subject_hmac, at, PK 兩欄)`、`pending(token_hash PK, provider, subject_hmac, display, expires)`；新方法 `check_all_and_record(buckets, now)`（一筆 `BEGIN IMMEDIATE`：每一格都沒滿才全部記、回 `None`，有一格滿了一筆都不記、回那一格的名字）、`put_challenge`（同 `subject_hmac`＋`purpose` 的舊單先刪＝新碼作廢舊碼）、`challenge(id)`、`bump_tries(id, cap)`（到 cap 就刪）、`drop_challenge`、`trust_device`、`is_trusted`、`put_pending`。
- `routes.py`（只加自己兩條路由）：`POST /api/identity/code/send`、`POST /api/identity/code/verify`，現在時間 `time.time()` 在這裡讀、傳進 `codes`。
- `__init__.py`：`Feature` 不加格（沒有選項、沒有 status：`phone_missing` 是第 205 批）；只改模組說明多兩檔一句。
- `README.md`：多「驗證碼登入」一節（路由、旁檔多的表、cookie、開關、退版）。

## 路由

| 路由 | gate | 登入 | 做什麼 |
|---|---|---|---|
| `POST /api/identity/code/send` `{channel: "phone"/"email", to, turnstile}` | 第一行 `identity_base.on`，再 `channel in ways`，否則 404 | 不用 | 正規化（壞的回 `BAD_PHONE`/`BAD_EMAIL`）→ Turnstile（失敗回 `NEED_HUMAN`，不碰計數）→ 查有沒有綁（決定池）→ `check_all_and_record`（滿了：回 `SENT`、不寄、舊單不動）→ 產碼、寄（`SendFailed` 回 `CANNOT_SEND`，計數不退）→ `put_challenge`、設 `tx_code`。成功與滿了都回 `{"message": SENT, "notice": NOTICE, "privacy": privacy_url}` 同一份位元組 |
| `POST /api/identity/code/verify` `{code}` | 同上（channel 取自 challenge） | 不用 | 沒 cookie、過期、錯碼回 `BAD_CODE`（錯碼 `tries+1`，到 5 刪單）；對了刪單、記 `verified_at`、`trust_device`；有帳號 → `shell._start_session`、從回應的 set-cookie 取 token 記 `session_auth(method=channel)`、回 `shell._entry(key)`；查無帳號 → `put_pending`、設 `tx_pending`、回 `{"stage": "create", "pending": true}` |
