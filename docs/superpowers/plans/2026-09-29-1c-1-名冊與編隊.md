# 《天下大勢》1c-1 名冊與編隊 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 門下從「一支三人出戰隊」變成「名冊＋多支隊伍」：16 名原創同伴分天、地、玄、黃四品，每人有自己的統御；隊伍數與每隊的統御上限依主線幕數開放；新人經收徒、交遊與奇遇結識、招降、新立門戶福緣入門；門下頁改成隊伍切換、每欄的「換人」選單與名冊。派遣（1c-2）與招賢（1c-3）不在這一步。

**Architecture:** 內容模型多了同伴的統御（`command`）、取得管道（`sources`）、收徒地點（`recruit_at`）與天品特性（`trait`），事件效果的「結識」（`Effect.recruit`）、條件的「還沒入門」（`Condition.members_none`）、福緣事件（`Event.fortune`）與敵方隊伍的招降（`Squad.surrender`），載入時照品階規則交叉檢查。狀態把 `PlayerState.team` 換成 `teams: list[Team]`（第一支是本隊、你固定是隊長；舊存檔自動轉換），名冊就是原本的 `members`；隊伍數與統御上限看本季到過的最遠一幕（`WorldState.act_reached`）。新模組 `tianxia/roster.py` 管名冊、編隊、統御、入門、收徒、招降、福緣與門下頁「名冊・隊伍」的文字；`team.py` 仍只管戰鬥單位、武學與心得（多了「誰在第幾隊」的查詢與特性上陣）。`engine.Game` 接上收徒選項、招降、福緣與換人；`app.py` 的門下頁加隊伍切換、換人選單與名冊。

**Tech Stack:** Python 3.14、Pydantic 2、Gradio 6.24.0（已 pin）、pytest。

**Spec:** `docs/superpowers/specs/2026-09-29-門下名冊派遣招賢-design.md`——本計畫只做 §零 表格的「1c-1 名冊與編隊」：§一、§二（派遣才需要的部分除外）、§三、§六.1 的「名冊・隊伍」、§七 與 §九 對應的部分、§十 對應的測試。上位文件：`docs/superpowers/specs/2026-09-29-第一階段-人物武學與戰鬥-design.md`、`docs/superpowers/specs/2026-09-29-勢力層與武學系統-draft.md` §6。

## Global Constraints

- 所有玩家看得到的文字一律使用**繁體中文**；人物、武學名稱原創，不用金庸、古龍等作品或知名歷史人物的專有名詞。這次新增的名字：同伴杜三斤、阿棠、方小舟、白小滿、羅石頭、程素衣、駱行雲、阮青弦、陸沉舟、祝小蟬、石磬、賀橫江、晏歸鴻、守墓人；武學碎石拳、素衣劍、趟子腿、斷弦、破陣槍、驚蟬石、晨鐘、分水刺、歸鴻劍、歸藏掌、驚鴻、枯守；測試夾具的小六、書生、琴師、俠女、頭目、隱士、飛針、浪濤劍、天外劍、靜心訣。

## 計畫層級的裁定（設計文件沒寫死的細節）

1. **狀態的形狀**：`PlayerState.team: list[str]` 換成 `teams: list[Team]`，`Team(BaseModel)` 這次只有 `members: list[str]`（第一位是隊長）。1c-2 的每隊體力與派遣狀態直接加在 `Team` 上（例如 `stamina`、`dispatch`），不用另開平行的陣列；舊存檔讀進來時新欄位走預設值。存檔裡一律放「設定裡最多的隊伍數」支（現在是 4 支），開放與否即時算；`roster.normalize` 在讀檔時補齊、清掉不在門下或重複的人、把還沒開放的隊伍清空，而且不動 `Team` 上的其他欄位。舊存檔的 `team` 由 `PlayerState` 的 `model_validator(mode="before")` 轉成本隊，名冊就是原本的 `members`，不需要備份。
2. **你本人固定是本隊的第一位（隊長）**：現在沒有任何介面能換隊長（門下頁照隊伍順序畫欄、`check_actor` 同分時本來就讓你先），所以直接定死：`set_member` 拒絕動本隊第一位，也拒絕把你放進別隊。本隊第一欄的「換人」選單鎖住，只寫「你本人（固定是本隊的隊長）」（各欄才對得齊）。派遣隊的第一位就是隊長；空出一位時後面的人往前補，空位選人時補在最後。
3. **隊伍數與統御上限看「本季到過的最遠一幕」**：新增 `WorldState.act_reached`，`world.update_storyline` 推進幕數時跟著更新。原因：主線改寫（寶藏線取代寇亂線）會把 `act` 歸零，照 `act` 算會把已開放的隊伍關上、上限從 18 掉回 15。寶藏線的第四幕（act=3）比照 config 最後一格（第三幕的 4 隊、20）。舊存檔的 `act_reached` 取 `max(act_reached, act)`。
4. **名冊與候補**：名冊的順序是你本人、天、地、玄、黃，同品階依入門先後（`members` 的插入順序，存讀檔保留）。新人一律先列候補，不會自動補進空位。
5. **統御只擋「換進去之後超過上限」**：空出位置永遠可以；被換下的人回到候補；從別隊移過來的人會離開原隊。拒絕時回傳「（統御 19／15，陸沉舟換不進第二隊。）」，什麼都不改、不寫江湖紀錄。還沒開放的隊伍回傳「（第三隊第二幕開放。）」。1c-1 沒有派遣，「別隊待命的人」就是別隊的所有人。
6. **這次不做的隊伍規則**：「換隊不能用來刷體力」（設計文件 §2.2）與「派遣中的隊伍不能換人、派遣中的人的武學不能移走」要等 1c-2 隊伍有自己的體力與派遣狀態才有意義，留給 1c-2；`Team` 已經留好位置。資訊列這次也不寫體力。
7. **武學配置**：同一門武學同時只能配給一個人（`team.set_loadout` 原本就會從別人身上移走，跨隊照樣）；「某人的本命不能再配給隊上其他人」改成看**目標那個人那一隊**（`team.teammates`），候補只看自己。門下頁的「配置到」本來就不讓本命進自選欄（`is_innate`），介面行為不變。
8. **只有本隊出手**：`team.team_keys(state, index=0)` 預設就是本隊；戰鬥、勝算、檢定、戰報陣容、右欄狀態的「隊伍」都只看本隊，經驗也只給本隊（`team.add_exp` 改走 `team_keys`，候補與別隊不長經驗）。
9. **天品特性**：內容上是一門 `kind: 心法`、每個效果都不寫 `top`（效果固定）的武學，載入時檢查；每名天品都要有，其他品階與敵人不能有。`team.build_unit` 在本命之後以第 1 成把它加進戰鬥單位，沒有新的戰鬥規則；不在武學庫、不能升級或散功。人物卡用白話寫出效果（`skillview.trait_line`）。
10. **品階規則放在 `content.py` 的常數**（`TIER_COMMAND`、`TIER_INNATE`、`TIER_S`、`TIER_TOP`、`SOURCE_TIERS`）：它們是內容檢查，不是遊戲數字。另外把「取得管道要真的帶得來」寫成檢查：事件帶來的人要寫那條管道（福緣事件→福緣、奇遇事件→奇遇、其他事件→交遊），`surrender` 的人要有「招降」；反過來，寫了交遊、奇遇、福緣、招降的人一定要有事件或敵方隊伍帶得來（這樣「每人至少一條免費管道」才真的走得到）。管道限品階：收徒 黃玄、交遊 玄地、福緣 地、奇遇 地天、招降 地天；「開局」要和 `config.start_companions` 一致；福緣事件的 `actions` 要是空的、每個選項都要結識一個人。「至少一名福緣地品」要等真實內容有了 16 名同伴才加（Task 4）。
11. **本命品質**：`Skill.quality` 只影響武學詳情的「〔下品〕」標籤，不影響任何數字（`tianxia/` 裡只有 `skillview.detail` 讀它）。韓鐵「開碑手」、小墨「亂針」本來就是下品，符合玄品，不用改；測試夾具韓鐵的「驚濤掌」原本沒寫 quality（預設中品），補上 `"quality": "下"`，數字不變。
12. **結識事件**：`Effect.recruit`（同伴 id）＋`Condition.members_none`；載入時要求事件的條件列出它結識的人。萬一還是結識到已入門的人（例如兩個事件結識同一人），照 `config.duplicate_xinde` 改給心得（黃 10、玄 20、地 50、天 100，暫定・另談；1c-3 的付費心得上限不算這筆）。
13. **收徒**：選項放在「交遊」之後、移動之前。四種樣子：可以收「收徒（體力 5・銀兩 40）」、沒人可收「此地已無可收之徒」、今天滿了「收徒（今天已收了 2 次）」、錢不夠「收徒（銀兩不足，要 40 兩）」（依這個順序判斷）；體力不夠時照一般選項灰掉。抽法：先在「這裡還有人可收」的品階之間照 `apprentice_weights`（75:25）抽品階，再在同品階裡平均抽一位——所以揚州城這類城鎮收得到四名黃品與羅石頭，棲霞劍派多一位只在那裡收得到的程素衣。每天的次數用 `apprentice_day`／`apprentice_count` 記（遊戲日）。花費寫進紀錄「銀兩 -40」，體力照其他行動不寫。
14. **招降**：在 `Game._battle_rewards` 的最後擲（升級訊息之後），歷練與劇情戰都走這裡；投效的敘事寫進戰鬥紀錄的 notes，所以戰鬥卡片看得到：「水寨頭目敗退，【賀橫江】願意投效！」。1c-2 的派遣隊打贏時也會走同一個函式（`roster.surrender`）。
15. **招降的對象**：不收龍頭人物（翻江龍、鬼手劉三一直由世界模擬扮演，收進門下劇情會自相矛盾；設計文件 §3.6 的例子只是舉例）。改成水寨頭目 → 地品「賀橫江」（預設 25%；太湖水寨可以一直歷練）與藏龍洞守墓人 → 天品「守墓人」（50%：寶藏線裡這一仗每季只打得贏一次，打贏時寶藏已被取走，他也不必再守）。「名字相同或相近」：守墓人同名；水寨頭目在敵方是職稱，同伴用本名賀橫江，投效訊息與人物說明都寫明他是水寨頭目。翻江龍隊伍裡的「水寨頭目」是另一個人，照舊出現。
16. **福緣**：福緣事件是 `fortune: true`、`actions: []` 的事件——不會被隨機抽到，也不會讓沒有交遊事件的地點多出「交遊」。第 2 天起第一次交遊時，從還能觸發（那位地品還沒入門）的福緣事件裡隨機挑一個先跳出來；第 7 天結束（`world.time ≥ 7 天`）還沒發生時，在時間流逝中直接送上門：取內容順序第一個還能觸發的福緣事件的第一個選項，另寫一則「結識【陸沉舟】」標「地品・福緣」。所有福緣地品都已入門時（1c-3 招賢之後才可能）就記為已發生、什麼都不給。每季一次（`PlayerState.fortune`）。舊存檔沒有這個欄位（False）：已經過了第 7 天的舊存檔，下一次時間流逝就會收到福緣。
17. **江湖紀錄**：入門發生在一次行動裡時，那一則的標題照舊（「收徒・揚州城」「鏢局快腿・收他入門」「歷練・太湖水寨」），結果標記還空著就標「玄品・入門」（打仗或檢定已經有標記時保留原標記），入門那句「【駱行雲】入門（玄品・快・統御 3），從第 1 級練起，先列候補。」寫在敘事裡。只有福緣自己送上門時另寫一則「結識【某某】」。
18. **入門等級**：各隊成員（含你，不含候補）的最低等級，至少 1；新人經驗 0、內力全滿、本命第 1 成、兩格自選空著。
19. **門下頁**：這次不放空的「招賢」分頁（1c-3 再加）。隊伍切換用 `gr.Radio`，值是第幾隊（整數）；建立時沒有選項，所以**不能先給值**——撰寫計畫時在 7862 埠實測，`value=0` 會讓第一次打開門下就被 Gradio 擋下（「Value: 0 … is not in the list of choices: []」），因此一開始是 `None`，處理函式把 `None` 與不認得的值都當本隊。還沒開放的隊伍整排不顯示、資訊列寫「**第三隊**　第二幕開放」；開放的隊伍三欄都畫，空位只有「換人」選單。換人選單的值是人物 key，「（空）」的值是空字串。名冊用 `gr.Radio`，點一個人在右邊顯示他的人物卡（這張卡多一行本命，黃品寫「本命　無」；隊伍欄的人物卡不寫本命，因為下面就是本命按鈕）。資訊列：本隊「跟著你行動」、其他隊「待命」。
20. **`library_handler` 改名 `view_handler`**：武學庫選武學、切換隊伍、在名冊點人共用這一個處理函式（都只重畫門下頁、不存檔）；自選欄的選取只在還是顯示中那一隊的人時保留。換人照一般動作同步時間、存檔、重畫（`make_swap_handler`）。
21. **模擬機器人**：遇到有 `recruit` 的選項一定選、能收徒一定收、每一步之後把本隊換成統御上限內「四項屬性加總」最強的兩人；其他照舊隨機。`play_season` 多一個 `observe` 參數，模擬器用它記第 1、3、7 天結束時的名冊人數。
22. **內容與數值**：16 名同伴、各自的統御與數字見 Task 4 的表。同品階裡統御不同（地 4／5／5／6、玄 3／3／3／4／4／4、黃 1／2／2／3），統御低的比較好塞進隊伍。兩名天品都是統御 7：本隊要到第三幕（20）才塞得下兩名天品（5＋7＋7＝19），合乎設計文件 §1.3。撰寫計畫時量過（Task 4 Step 7）：同一格換人比較，第 5 級、武學第 3 成對藏龍洞守墓人，玄 0%、地 55～68%、天 95～98%；就算帶著天品，第 10 級的你＋晏歸鴻＋阿棠打翻江龍也只有 8%。模擬 30 季（Task 4 Step 9）：名冊人數（含你）第 1 天 5.7、第 3 天 8.6、第 7 天 10.0、季末 11.6（9～14 人），季末平均天 0.3、地 1.6、玄 5.0、黃 3.7。

- [ ] **Step 5: 新增 `tianxia/roster.py`**

```python
"""名冊與編隊：誰在門下、各隊有誰、每隊的統御與上限、隊伍依主線幕數開放。

名冊就是 PlayerState.members（你本人加上這一季入門的所有同伴）；隊伍是 PlayerState.teams，第一支是本隊，
一定有你、而且你固定是隊長。沒排進任何一隊的人是候補。1c-1 只有本隊會出手（歷練、探索、交遊、劇情戰、檢定），
第二隊起的派遣隊要到 1c-2 才會出門。
"""
from __future__ import annotations

from . import team
from .models import COMPANION_TIERS, Content
from .state import PLAYER, TEAM_SIZE, GameState, Team

NUMERALS = "零一二三四五六七八九十"


# ── 隊伍數與統御上限 ─────────────────────────────────────


def stage(state: GameState, content: Content) -> int:
    """隊伍數與統御上限看本季到過的最遠一幕（主線改寫會把幕數歸零，已開放的隊伍不會因此關上）。"""
    return min(state.world.act_reached, len(content.config.team_counts) - 1)


def team_count(state: GameState, content: Content) -> int:
    """目前開放幾隊（含本隊）。"""
    return content.config.team_counts[stage(state, content)]


def command_cap(state: GameState, content: Content) -> int:
    """每隊的總統御上限。"""
    return content.config.command_caps[stage(state, content)]


def team_name(index: int) -> str:
    """本隊、第二隊、第三隊……"""
    return "本隊" if index == 0 else f"第{NUMERALS[index + 1]}隊"


def opens_at(content: Content, index: int) -> str:
    """還沒開放的隊伍什麼時候開放，例如「第二幕開放」；設定裡永遠不會開放時寫「未開放」。"""
    act = next((a for a, n in enumerate(content.config.team_counts) if n > index), None)
    return "未開放" if act is None else f"第{NUMERALS[act + 1]}幕開放"


def command_of(content: Content, key: str) -> int:
    """一個人的統御：你本人是 config.player_command，同伴寫在人物資料上。"""
    return content.config.player_command if key == PLAYER else content.characters[key].command or 0


def team_command(state: GameState, content: Content, index: int) -> int:
    """第 index 隊目前的總統御。"""
    return sum(command_of(content, key) for key in team.team_keys(state, index))


# ── 名冊 ──────────────────────────────────────────────


def roster(state: GameState, content: Content) -> list[str]:
    """名冊：你本人在最前，其餘依品階（天地玄黃）排，同品階依入門先後。"""
    order = {tier: i for i, tier in enumerate(COMPANION_TIERS)}
    others = [key for key in state.player.members if key != PLAYER]
    return [PLAYER] + sorted(others, key=lambda key: order[content.characters[key].tier])


def bench(state: GameState, content: Content) -> list[str]:
    """候補：在名冊裡、但不在任何一隊的人，順序同 roster。"""
    return [key for key in roster(state, content) if team.team_of(state, key) is None]


def normalize(state: GameState, content: Content) -> None:
    """讀檔或換了內容之後整理隊伍：補齊到設定裡最多的隊伍數；丟掉已不在門下、重複出現或待在還沒開放的隊伍裡的人
    （他們回到候補）；每隊最多 TEAM_SIZE 人；你本人固定是本隊的隊長。Team 上的其他欄位原封不動。"""
    p = state.player
    size = max(content.config.team_counts)
    teams = p.teams[:size] + [Team() for _ in range(size - len(p.teams))]
    opened = team_count(state, content)
    seen = {PLAYER}
    for i, t in enumerate(teams):
        keep: list[str] = []
        room = TEAM_SIZE - 1 if i == 0 else TEAM_SIZE
        for key in t.members if i < opened else []:
            if key in p.members and key not in seen and len(keep) < room:
                keep.append(key)
                seen.add(key)
        t.members = [PLAYER] + keep if i == 0 else keep
    p.teams = teams


# ── 換人 ──────────────────────────────────────────────


def set_member(state: GameState, content: Content, index: int, slot: int, key: str | None) -> list[str]:
    """門下頁的「換人」：把第 index 隊第 slot 位（從 0 起算）換成 key。key 為 None 時空出這一位，後面的人往前補；
    slot 超過目前人數時補在最後。key 原本在別隊時從那一隊移過來，被換下的人回到候補。
    換不成時回傳「（原因。）」、什麼都不改；沒有變化時回傳空清單。"""
    p = state.player
    name = team_name(index)
    if not 0 <= index < len(p.teams) or not 0 <= slot < TEAM_SIZE:
        return ["（沒有這個位置。）"]
    if index >= team_count(state, content):
        return [f"（{name}{opens_at(content, index)}。）"]
    if index == 0 and slot == 0:
        return ["（你本人固定是本隊的隊長。）"]
    if key == PLAYER:
        return ["（你本人只能待在本隊。）"]
    if key is not None and key not in p.members:
        return ["（名冊裡沒有這個人。）"]
    members = team.team_keys(state, index)
    old = members[slot] if slot < len(members) else None
    if key == old:
        return []
    if key is not None and key in members:
        return [f"（{team.member_name(state, content, key)}已經在{name}。）"]
    new = list(members)
    if key is None:
        new.remove(old)
    elif old is None:
        new.append(key)
    else:
        new[slot] = key
    total, cap = sum(command_of(content, k) for k in new), command_cap(state, content)
    if key is not None and total > cap:
        return [f"（統御 {total}／{cap}，{team.member_name(state, content, key)}換不進{name}。）"]
    source = team.team_of(state, key) if key is not None else None
    if source is not None:
        p.teams[source].members.remove(key)
    p.teams[index].members = new
    usage = f"（{name}統御 {total}／{cap}）"
    if key is None:
        return [f"{team.member_name(state, content, old)}移到候補{usage}"]
    came = f"從{team_name(source)}" if source is not None else ""
    moved = f"{team.member_name(state, content, key)}{came}編入{name}"
    if old is not None:
        moved += f"，{team.member_name(state, content, old)}移到候補"
    return [moved + usage]
```

def join_level(state: GameState) -> int:
    """新人的等級：目前各隊成員中最低的等級（候補不算），至少 1。"""
    p = state.player

def recruit(state: GameState, content: Content, char_id: str) -> list[str]:
    """char_id 入門：從 join_level 起算、先列候補。已經在門下時照 config.duplicate_xinde 改給心得
    （劇情事件萬一給了已入門的人時；不算進 1c-3 的付費心得上限）。回傳敘事與數值變化。"""

    return f"{content.characters[char_id].tier}品・入門"


# ── 收徒 ──────────────────────────────────────────────


def apprentice_candidates(state: GameState, content: Content) -> list[str]:
    """在目前所在地收得到、還沒入門的人：有「收徒」管道，寫了 recruit_at 的只在那些地點。"""
    p, weights = state.player, content.config.apprentice_weights
    return [
        cid for cid, ch in content.characters.items()
        if "收徒" in ch.sources and ch.tier in weights and cid not in p.members
        and (not ch.recruit_at or p.location in ch.recruit_at)
    ]


def apprenticed_today(state: GameState) -> int:
    p = state.player
    return p.apprentice_count if p.apprentice_day == _day(state) else 0


def apprentice_block(state: GameState, content: Content) -> str | None:
    """「收徒」選項的狀態：這裡不是城鎮或門派時為 None（不顯示）；收得了時是空字串（體力由 engine 照一般行動判斷）；
    收不了時是按鈕上要寫的原因。"""
    cfg = content.config
    if not set(content.locations[state.player.location].tags) & set(cfg.apprentice_tags):
        return None
    if not apprentice_candidates(state, content):
        return "此地已無可收之徒"
    if apprenticed_today(state) >= cfg.apprentice_per_day:
        return f"收徒（今天已收了 {cfg.apprentice_per_day} 次）"
    if state.player.stats.get("silver", 0) < cfg.apprentice_silver:
        return f"收徒（銀兩不足，要 {cfg.apprentice_silver} 兩）"
    return ""


def apprentice(state: GameState, content: Content, rng: random.Random) -> list[str]:
    """收徒：花銀兩與體力，從這裡收得到的人裡先依 config.apprentice_weights 抽品階（只在還有人的品階之間）、
    再在同品階裡平均抽一位。呼叫前 engine 已確認 apprentice_block 是空字串、體力也夠。"""
    cfg, p = content.config, state.player
    pool = apprentice_candidates(state, content)
    tiers = [tier for tier in cfg.apprentice_weights if any(content.characters[k].tier == tier for k in pool)]
    tier = rng.choices(tiers, weights=[cfg.apprentice_weights[t] for t in tiers])[0]
    pick = rng.choice([k for k in pool if content.characters[k].tier == tier])
    p.stamina -= cfg.apprentice_stamina
    p.stats["silver"] -= cfg.apprentice_silver
    p.apprentice_count = apprenticed_today(state) + 1
    p.apprentice_day = _day(state)
    return [f"銀兩 -{cfg.apprentice_silver}"] + recruit(state, content, pick)


# ── 招降 ──────────────────────────────────────────────


def surrender(state: GameState, content: Content, squad: Squad, rng: random.Random) -> list[str]:
    """打贏有 surrender 的敵方隊伍後擲一次招降；沒有招降或那人已經入門時不擲（不動亂數）。"""
    offer = squad.surrender
    if offer is None or offer.character in state.player.members:
        return []
    chance = content.config.surrender_chance if offer.chance is None else offer.chance
    if rng.random() >= chance:
        return []
    name = content.characters[offer.character].name
    return [f"{squad.name}敗退，【{name}】願意投效！"] + recruit(state, content, offer.character)


# ── 新立門戶福緣 ─────────────────────────────────────────


def fortune_due(state: GameState, content: Content) -> bool:
    """福緣還沒發生，而且已經是第 fortune_day_min 天（含）以後：這時交遊必定先觸發福緣事件。"""
    return not state.player.fortune and _day(state) >= content.config.fortune_day_min


def fortune_overdue(state: GameState, content: Content) -> bool:
    """第 fortune_day_max 天已經結束，福緣還沒發生：直接送上門。"""
    return not state.player.fortune and state.world.time >= content.config.fortune_day_max * DAY

```python
"""亂數機器人：玩完一整季，把心得花在武學上。用於整季測試與平衡模擬。

大多數時候隨機選一個可用的選項；只有三件事照規矩來：遇到結識的選項一定接受、能收徒就收徒、
每一步之後把本隊換成統御上限內最強的組合（見 arrange_team）。
"""
from __future__ import annotations

import random
from collections.abc import Callable
from itertools import combinations

from . import roster, team
from .engine import Game, Option
from .models import Content
from .state import PLAYER

HALF_HOUR = 1800


def spend_xinde(game: Game) -> None:
    """貪心花心得：只要付得起，就把目前最便宜的一門升一成（同價時取排在前面的）。"""
    state, content = game.state, game.content
    while True:
        costs = []
        for _, target in game.upgrade_options():
            level = team.target_level(state, content, target)
            if level is not None and level < team.MAX_SKILL_LEVEL:
                costs.append((team.upgrade_cost(content, level), target))
        if not costs:
            return
        cost, target = min(costs, key=lambda c: c[0])
        if state.player.stats.get("xinde", 0) < cost:
            return
        game.upgrade(target)


def pick(game: Game, options: list[Option], rng: random.Random) -> str:
    """結識的選項一定接受、能收徒就收徒；其餘隨機挑一個。"""
    s = game.state
    if s.pending_event:
        choices = game.content.events[s.pending_event].choices
        for option in options:
            if option.id.startswith("choice:") and choices[int(option.id.partition(":")[2])].effect.recruit:
                return option.id
    if any(option.id == "act:apprentice" for option in options):
        return "act:apprentice"
    return rng.choice(options).id


def arrange_team(game: Game) -> None:
    """把本隊你以外的兩格換成統御上限內最強的兩人（強弱看目前四項屬性加總，一樣強時取名冊裡排前面的）。"""
    s, c = game.state, game.content
    room = game.command_cap() - roster.command_of(c, PLAYER)
    others = [key for key in roster.roster(s, c) if key != PLAYER]
    power = {key: sum(team.member_stats(s, c, key).values()) for key in others}
    pairs = [pair for pair in combinations(others, 2) if sum(roster.command_of(c, k) for k in pair) <= room]
    if not pairs:
        return
    best = max(pairs, key=lambda pair: sum(power[k] for k in pair))
    if set(best) == set(game.team_keys()[1:]):
        return
    game.set_member(0, 2, None)
    game.set_member(0, 1, None)
    for key in best:
        game.set_member(0, 2, key)


def play_season(
    content: Content, seed: int, max_steps: int = 20000, observe: Callable[[Game], None] | None = None
) -> Game:
    """玩完一季；observe 不是 None 時，每一步之後都呼叫一次（模擬器用來記錄第幾天有多少人）。"""
    game = Game.new(content, f"機器人{seed}", rng=random.Random(seed))
    rng = random.Random(seed)
    for step in range(max_steps):
        if game.state.world.ended:
            break
        options = [o for o in game.options(odds=False) if o.enabled]
        if options:
            game.choose(pick(game, options, rng))
            spend_xinde(game)
            arrange_team(game)
        if not options or step % 4 == 0:
            game.advance(HALF_HOUR)
        if observe is not None:
            observe(game)
    return game
```
