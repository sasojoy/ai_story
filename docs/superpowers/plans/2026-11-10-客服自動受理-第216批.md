## 路由（都在包裡，第一行 `_gate_off`，關著 404 先於登入與解 JSON）

- `_staff(shell, request, *, allow_bot=True)`：`Authorization` 以 `Bearer ` 開頭 → token 路：`support_bot_token()` None、`hmac.compare_digest(t.encode("latin-1"), tok.encode("utf-8"))` 假、`allow_bot` 假、`bot_account_id` None、`by_id` None → `HTTPException(404)`（同一句）；對了回 `by_id(bot_id)`，不看 cookie、不看 `staff_session_ok`，設 `request.state.support_desk = True`。沒有 Bearer 照舊 cookie 路、`support_desk = False`。
- `_lookup`：`_staff(..., allow_bot=False)`。`_view_file`：有 Bearer 就走 `_staff`（token 看得到圖、錯 token 404），沒有照舊。
- `POST /api/support/human {id}`：`_json` → 登入（401）→ `add_human`；別人的、不存在 404 `NOT_FOUND`，結了 400 `CLOSED_ALREADY`；回 `_player_ticket`。伺服器不要求單上已有自動回覆（照計畫 store 的條件；畫面才看）。
- `POST /api/support/sweep {}`：`_json` → `_staff`（客服 cookie 或 token；玩家 404）→ 旁檔不在回 `{"closed": []}`，否則 `store.sweep(now, days*DAY_SECONDS, AUTO_CLOSED.format(days=…))` 回 `{"closed": [...]}`；不推播。
- `_answer`：`support_desk` 為真才收 `body["relay_from"]`（轉 `str`、去空白，空當沒有），cookie 身分帶了忽略；推播照舊。
- 節流：沒有新的（伺服器既有的 1,000 字、單數、狀態就是上限，計畫「不做」）。
