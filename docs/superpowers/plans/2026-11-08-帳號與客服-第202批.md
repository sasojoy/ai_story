## 包裡的檔（`tianxia/features/identity/`）

- `oauth.py`（新，純規則＋可換的 HTTP）：兩家的設定表（authorize、token 網址、`iss` 可接受值：LINE `https://access.line.me`；Google `https://accounts.google.com`、`accounts.google.com`；scope 只 `openid`）；`secrets(provider)` 讀 `identity_base.KEY_FILE` 裡的 `{"line": {"client_id","client_secret"}, "google": {...}}`；`ready(content, provider)`＝在 `ways`＋金鑰兩欄都有＋`redirect_base` 不空；`authorize_url(...)`（state、nonce、PKCE S256）；`exchange(provider, code, verifier, redirect_uri)` 經模組層 `HTTP = requests.post`（測試換成假的，逾時 10 秒）；`claims(id_token)` 只 base64url 解中段；`check(claims, provider, client_id, nonce, now)` 驗 `iss`、`aud`、`exp > now`、`nonce`、`sub` 非空且 ≤255 字，回 `sub` 或 None。不驗簽章：`id_token` 是我們直接向對方 token 端點經 TLS 拿的（OIDC Core 3.1.3.7 第 6 項），寫進模組說明。時間一律參數傳入。
- `store.py`：加兩張表（`CREATE TABLE IF NOT EXISTS`，舊旁檔照開）：`oauth_tickets`（`state_hash` PK、`provider`、`purpose`、`browser_hash`、`nonce`、`verifier`、`expires`、`created`）、`pending`（`token_hash` PK、`provider`、`subject`、`expires`、`created`）。函式 `put_ticket`、`take_ticket(state_hash, now)`（讀完就刪，過期當沒有，順手清過期列）、`put_pending`、`get_pending(token_hash, now)`、`drop_pending`。限制計數沿用 `count_and_record`。
- `routes.py`：見「路由」。`gate_info` 拿掉 `support_mail`，`ways` 的 line、google 只列 `oauth.ready` 的（email、phone 照舊列設定的，按了照舊「尚未開放」）。
- `__init__.py`、`README.md`：模組說明與 README 補這批（`oauth.py`、四條路由、兩張旁表、cookie、退版、另外要跑的）。
- `tests/`：見「測試」。

## 資料

- 主資料庫第 9 版不動。開帳號寫 `accounts` 一列＋`logins` 一列（`provider` `line`／`google`，`subject` 原樣不過 `normalize`，`display` 「LINE」「Google」），跟角色同一筆交易。
- 旁檔 `<db>-identity.sqlite` 多 `oauth_tickets`、`pending`；開帳號成功寫 `bindings_meta`（`subject_hmac`＝`identity_base.subject_hmac(key, provider, sub)`、`verified_at`＝now）。

## 路由（都在包的 `routes.py`；不拿行動鎖、模型不叫）

1. `POST /api/identity/start` `{provider, purpose}`：第一行 gate（關著 404）；provider 不 `ready` 或 purpose 不是 `login` 404；帶有效 `tx_session` 回 400「你已經登入了，要換帳號請先登出」（設計「先問要不要換」的保守版：快速登入只在登入頁有）；`count_and_record("oauth:<ip>", 3600, start_per_hour, now)` 超過回 400 一句；寫票、發 `tx_oauth`，回 `{"url": authorize_url}`（不用 302：fetch 跟不了外站轉址）。不用登入。
2. `GET /auth/{provider}/callback?code&state[&error]`：第一行 gate（關著 404）；provider 不認得 404。`error` → 302 `/?auth=cancel`；票拿不到、過期、provider 或 `tx_oauth` 對不上 → 302 `/?auth=fail`（票照樣作廢）；換 token、`check` 不過 → `fail`。`login_key` 查到 → `shell._start_session` 後 302 `/?auth=ok`；查不到 → 寫 `pending`、發 `tx_pending`、302 `/?auth=new&via=<provider>`。一律刪 `tx_oauth`。不用登入。
3. `POST /api/identity/character` `{name, gender}`：**先看 cookie**（`tx_pending` 與 `tx_session` 都沒帶 401「請先登入。」，同第 211 批「先 401 再 gate」的認定，不進 `NO_LOGIN_ROUTES`）→ gate（關著 404）→ `pending` 拿不到 401 同一句 → 這個身分已有帳號（連按兩次）就開 session 回 `shell._entry` → `shell._register_allowed(shell.client_ip(request), now)` 不過丟 `GameError(shell.TOO_MANY_REGISTERS)` → `with shell.open_database().transaction():` `create_without_password` ＋ `shell.create_character(key, name, gender)`（巢狀併進同一筆；名號錯就整筆退，帳號不留）→ `shell._registered`、`record_verified`、`drop_pending`、刪 `tx_pending`、`shell._start_session`，回 `shell._entry(key)`。
4. `GET /api/identity/gate`：照舊，少 `support_mail`。
