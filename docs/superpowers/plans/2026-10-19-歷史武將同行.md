# 歷史武將同行 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 十五位不是大勢人物的歷史武將照陣營招進名下（全服唯一、一人三位、情誼放慢），大決戰挑一位上陣站在戰場上，打完回江湖。

**Architecture:** 一個 `Config.companions` 開關（正式開、測試內容關，關著一個字都不變）管招募開放、名下三位、放走、決戰助陣、決戰後回江湖、叛投帶不走；情誼放慢另一個欄位 `Config.affinity_gain_scale`（1＝不放慢）。上陣的同伴是 `BattleParticipant.escort`（照 `Commander` 的打法），跟 `active_battle` 一起存，不改資料庫結構。收場時 `escorts.after_battle` 全服放掉 owner、記 `CompanionProgress.parted_from`，原主人自己的 Game 同步時把情誼減半。

**Tech Stack:** Python 3.14、pydantic、pytest；原生 JS（`web/app.js`）。`C:/Ray/專案/天下大勢/.venv/Scripts/python.exe`。

**Spec:** `docs/superpowers/specs/2026-10-18-歷史武將同行-design.md`（第九節 PM 裁決優先）

## Global Constraints

- 開關：`Config.companions.enabled` 正式開（`content/config.json`）、測試內容關；關著時招募、隊伍、決戰、叛投一個字都不變（第八節）。
- 情誼放慢：`Config.affinity_gain_scale` 正式 0.7、`content/profiles/weekend.json` 0.85、測試內容 1；只乘加的，每筆四捨五入，原本加 1 以上的至少加 1（9.4）。
- 十六位大勢人物（`figures.json` 寫了 `character` 的）不能招；其餘十五位 `recruitable: true`；張燕改 `side: "huang"`（9.2）。
- 名下最多 `max_owned` 3 位，照 owner 算、名號比對不分大小寫（`characters.name_key`）。
- 份量＝`battle_instance.strength(他的威力)` × 0.5，不吃職位、坐騎、部下；敗走推 2；池子、集火、點名、固守護、一回合上限照人物（`GeneralTuning`）。
- 情誼減半無條件捨去；收兵、取消的那一場不算派過（第六節）。
- 不改資料庫結構（第 5 版）；新字標「待 joy 潤」；假人與整季機器人不招、不另外設計；任何畫面不透露誰是假人。
- 測試只跑 `scripts/test_for.py --base origin/develop`（tianxia-flow）。

## Review Focus

1. 兩個分頁同時招第四位：上限要在 `try_recruit` 的同一筆寫入裡判，不能只靠選單（Task 1 補測試）。
2. 決戰打到一半主人放走（或叛投放掉）他、別人招走：收場不能把新主人的清掉（Task 6 補測試）。
3. 主人這一回合離開大區（away）：他的同伴這一回合不出手、也挨不到打（Task 4 補測試）。
4. 放手一搏寫的名字同時對得上參戰者與同伴：參戰者優先，再來人物、最後同伴（Task 4 補測試）。
5. 季終收兵、管理者取消的那一場：同伴照舊是主人的、情誼不動（Task 6 補測試）。
