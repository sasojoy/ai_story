  1. **只改工具、測試、文件的波，網頁比對紅了不必重跑**：PM 用 `git diff --stat <閘門基準> <閘門 head>` 看**整個** diff（不是只看 `web/`），兩邊餵給伺服器與瀏覽器的檔一個位元組都一樣、兩邊又是同一份工具在走，紅的就是走查自己對自己的雜訊——寫進紀錄、把樣子（哪一景、哪個視窗、幾個像素、哪幾個樣式）交給下一個工具批，照樣落地。
  2. **「把雜訊壓下來、沒根除」的工具改動可以收**，條件三個都要有：判法沒放鬆（門檻、白名單、雜訊類都沒動）；有一個「計算樣式不變、像素真的變」的正對照照樣紅；檔頭照實寫剩下的機率與樣子。剩下的列進交接與下一個工具批，不當成修好了。
  3. **工具批的回報要有 selftest 改前改後各一次的表**（每一列）；`pkg-css` 這種不在 selftest 表裡的突變另外各跑一次。沒有的話審查記 should、下一批補。
  4. **收尾在跑的時候 PM 不往 develop 推東西**（文件也先留在本地），落地時一起推：合併與閘門的基準是派工時寫死的那一筆。
