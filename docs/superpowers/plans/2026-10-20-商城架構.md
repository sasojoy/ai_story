# 商城架構 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 元寶錢包、帳本、joy 寫的商品表、購買發貨、月卡、封測 5000 元寶與管理者工具；第一批不動畫面，第二批照企劃者挑的對比圖做商城那一層，第三批收尾。

**Architecture:** 錢包不另存餘額：餘額＝帳本 `mall_ledger` 的加總，每一筆帶不重複的編號（`ref UNIQUE`），重送不會算兩次。帳本、購買紀錄、月卡（`mall_entitlements`）三張新表是資料庫第 6 版；錢包的主人是**角色名號的 casefold**（＝`characters.key`＝真人的 `accounts.character_key`，見 1.2）。規則在 `tianxia/mall.py`（純規則，資料庫走 `tianxia/wallet.py`），引擎只接幾個薄的入口；購買在伺服器的行動鎖（一筆交易）裡做，扣元寶、寫購買紀錄、發貨同一筆，出錯整筆撤回。

**Tech Stack:** Python 3.14、pydantic、SQLite、FastAPI、pytest；`C:/Ray/專案/天下大勢/.venv/Scripts/python.exe`。

**Spec:** `docs/superpowers/specs/2026-10-20-商城架構-design.md`（企劃者 2026-10-20 核准；【企劃者】不改）

## 一、對現行程式（develop 050ce871）

### 1.1 帳號與登入
- 線上版**就是用帳號密碼登入**：`server.py` 只有 `/api/register`、`/api/login`（`tianxia/accounts.py`），`docs/superpowers/feedback/beta-主機端操作.md` 也寫「有網址的人都能進來註冊」。`CLAUDE.md` 原則「封測的線上版不開、只留在開發與測試環境」與 `accounts.py` 開頭那句是舊的，跟程式對不上（回報 PM，這一批不改那兩處）。
- 帳號：`accounts`（`id`、`character`、`character_key UNIQUE`、`created`）＋`logins`（`provider='password'`、`subject`＝小寫帳號）。登入狀態：`server.SESSIONS` 記在記憶體，cookie → **小寫帳號**（不是 `accounts.id`）。一個帳號一個角色：`bind_character` 綁過就不能換（`HAS_CHARACTER`）。
- **假人沒有帳號**：`bot_runner` 只建角色（`characters` 表，`is_bot`），從不碰 `accounts`。設計 4.2／4.8「假人帳號也照樣發 5000」照字面做不到。
- `scripts/monitor.py` 拿 `SELECT COUNT(*) FROM accounts` 當帳號數：替假人補帳號列會把它灌水。

### 1.2 所以錢包掛在哪【開發，要 PM 確認】
- 錢包的主人用**角色名號的 casefold**（`characters.name_key`），不用 `accounts.id`。理由：(1) 真人的帳號與角色一對一、綁了不換，這個鍵就是 `accounts.character_key`；(2) 假人沒有帳號也有錢包，照樣發 5000，管理者查帳時真人假人長得一樣（看不出誰是假人）；(3) 不必替假人造帳號列（monitor 灌水、`character_key UNIQUE` 撞名）。買東西本來就要有角色（回體丹進角色、月卡照角色算）。
- 換季角色重來，`characters` 那一列（同一個鍵）留著，錢包跟著跨季；讀不懂的存檔被 `backup` 重開時名號不變，錢包也還在。
- 代價：之後真的要「一個帳號多個角色」時錢包要搬（設計寫一個帳號一個角色）。

### 1.3 回體丹
- `PlayerState.stamina_pills`（手上幾顆）、`pill_day`／`pills_today`（今天服幾顆）。上限只從 `Game.pill_cap()` 出：新手期 `newbie_pills_per_day`（正式 5）、其餘 `stamina_pills_per_day`（正式 2；測試內容 0＝不限）。`pills_left_today`、`PILL_DAY_FULL`、狀態列 `pills.today` 都讀 `pill_cap()`，月卡加在這一個地方就全跟著變。
- 「一天」：`Game._pill_day()`＝`(pill_now() + 偏移×3600) // 86400`，`pill_now()`＝`sync` 給的 `now`＋`advance` 推過的現實秒；台灣 00:00 換日。`docs/guide/行動與地盤.md` 還寫「一天最多 5 顆」（舊的，現在平常 2、新手 5），回報、不在這一批改。
- 拿到回體丹的那條路就是 `p.stamina_pills += n` 加一則江湖紀錄（簽到、懸賞、新手福利都這樣）。
- 不限（`stamina_pills_per_day` 0）時月卡不加：不限就是不限。

### 1.4 資料庫遷移規矩
- `database.py`：`SCHEMA_V1`～`SCHEMA_V5_TABLES`，`SCHEMA` 接起來、`MIGRATIONS[n]` 是 n→n+1、`SCHEMA_VERSION` 5；`_ensure_schema` 在拿到寫入權的同一筆交易裡一版一版跑、最後寫 `user_version`，中途出錯整筆撤回。第 6 版照這個加 `SCHEMA_V6_TABLES`、`MIGRATIONS[5]`、`SCHEMA_VERSION = 6`（PM 已把第 6 版排給商城）。

### 1.5 其他
- 管理者動作照慣例是 `Game.admin_*`、登記進 `server.ADMIN_ACTIONS`（`/api/do/<op>`）；`_admin_refusal` 要季在跑，商城的帳跟季無關，另寫檢查（是管理者、商城開著）。
- 「時刻只有一個寫法」講的是遊戲時間（季曆）；購買紀錄是現實時間，另寫成台灣時間「10/25 21:40」（`mall.real_text`）。
- 店面這個字已經被鐵匠鋪、馬市、懸賞榜用掉（`shopview`、`shop_lines.json`、`Config.shop_screens`、`PlayerState.shop_*`），開關與模組叫 `mall`（`Config.mall`、`tianxia/mall.py`、`content/mall.json`）。

## 二、要 PM 決定的

1. **錢包的主人**：照 1.2 用角色名號（假人也有錢包、也發 5000）。不同意的話另一條是只掛真人的 `accounts.id`，假人沒有錢包（這一版看不出來，開外觀時要再補）。
2. **退一筆購買**：照設計 4.7 退全額元寶；回體丹收回手上還有的（最多當初那幾顆、用掉的不追），月卡把那一張加的天數扣回去（扣到今天以前就是到期）；一筆只能退一次。
3. **哪些時候能買**：籌備中、休季、序章裡都能買（帳跟著角色、不看季）；只有管理者暫停賽季時鐘（維護）時擋（同其他動作）。
4. **一次買一件**：這一版沒有數量鈕，一筆購買一件；限購數的是沒退的購買筆數。
5. **管理者區的畫面**：第一批只有引擎與 API（`/api/do/mall_*`、`/api/admin/mall`）跟主機端腳本，設定頁的那一組表單放第二批（不必等對比圖）。
6. **購買紀錄寫現實時間**（台灣時間「10/25 21:40」），不走季曆的寫法。
7. 佔位的商品（joy 換）：回體丹五顆 100 元寶（每天限 5 次）、回體丹三十顆 500、月卡三十天 600（一個帳號限 3 次）。七天的季裡三十天的月卡跨到正式開服也不會留（整份資料庫換新）。

## Global Constraints

- 開關 `Config.mall.enabled`：模型預設關、測試內容（`tests/fixtures/content/config.json`）明寫 `"mall": {"enabled": false}`、正式內容開、`week7` 開；關著時不發元寶、不讀不寫三張新表（月卡不加上限）、`/api/mall*` 與 `/api/do/mall_*` 都 404，其餘一個字都不變。
- 封測發放 `Config.mall.beta_grant`：預設 0，`content/profiles/week7.json` 寫 5000【預設】；設定覆寫檔是淺合併，`week7` 要整個 `mall` 一起寫（`{"enabled": true, "beta_grant": 5000}`）。
- 每個錢包只發一次：編號 `grant:beta:<主人>`；之後再開新的一季、再登入都不再發。
- 月卡：每天回體丹上限 +`Config.mall.card_pill_bonus`（1）【預設】；平常 2→3、新手期 5→6。天數照回體丹的台灣日：買的那一天算第一天，`N` 天卡到 `start+N`（不含）；還沒到期再買從到期日往後接。
- 允許的效果第一版只有 `pills`（回體丹 N 顆，消耗品）與 `card_days`（月卡 N 天）；外觀、通行證的種類留著，允許表裡沒有它們的效果，所以這一版寫不出外觀與通行證商品。
- 帳的原因只有 `grant`（封測發放）、`buy`（購買）、`refund`（退款）、`reissue`（補發）、`revoke`（扣回）、`topup`（儲值，留給之後的金流）。
- 餘額不能是負的；管理者的每一筆寫進帳（誰、何時、為什麼），原因那一句必填。
- 引擎不讀電腦時鐘（時間由伺服器傳進 `Game.sync`）；購買在行動鎖裡；任何畫面與回話不透露誰是假人。
- 新寫給玩家看的字標「待 joy 潤」，數字標【預設】；規則寫進 `docs/guide/商城.md`，`CLAUDE.md` 區塊表補一列。
- 測試只跑 `scripts/test_for.py --base origin/feature/shop` 與新寫的測試檔；改到 `tests/fixtures/` 只跑改到的與直接相關的（tianxia-flow）。
