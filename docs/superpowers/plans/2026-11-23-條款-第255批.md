## 二、做法（不動殼、不包 fetch、不輪詢）

照 PM 建議：多看一個 `#toast`。不換訊號的理由：`api()` 的 403 沒有別的對外痕跡（不 render、不改 S），吐司是唯一包裡看得到的。
1. 純函式 `termsShouldReask({ text, inGame, layerOpen, now, last })` → bool：`text` 含「條款」、`inGame`、`!layerOpen`、`now - last >= TERMS_REASK_GAP_MS`（5000）。
   常數 `TERMS_REASK_GAP_MS` 與 `termsReaskAt`（上一次因吐司重問的時刻，初值 0）放在 `termsAsked` 旁邊。
2. `termsOnToast()`：讀 `document.getElementById("toast").textContent`、`inGame` 照 `termsWatch` 同一個寫法（`typeof S !== "undefined" && S.stage === "game"`）、
   `layerOpen = !!document.querySelector(".terms-layer")`、`Date.now()`；要重問就 `termsReaskAt = now; termsAsked = false; termsCheck();`。
   `termsCheck` 本身不改（成功就照回來的畫；回「不必同意」`need` 空 → `termsShow` 只 `termsClose()`，什麼都不畫；斷線照舊放 `termsAsked`）。
   斷線時 `termsReaskAt` 不歸零：5 秒之內的下一句不再打，之後的照常——派工「一次擋下只重問一次」，保守不加分支。
3. 觀察那一段（`if (typeof MutationObserver ...)` 裡面）多一個 observer 看 `#toast`：`{ childList: true, characterData: true, subtree: true }`，
   一樣用 `queueMicrotask` 合併（另一個旗標 `termsToastQueued`），沒有 `#toast` 就不看。原本看 `#app` 那一支一個字不動。
4. 按同意 → `termsShow(data)` 收層 → 被擋的鈕殼已還原（api 丟錯），再按一次伺服器放行。不用另外做事。

吐司跳的那一刻同意層可能剛被 `#app` 那一支畫出來（同一個 microtask 之後）：`layerOpen` 擋掉、不重問。不在遊戲裡（登入頁 REGISTER_NEED 也含「條款」）`inGame` 擋掉。
