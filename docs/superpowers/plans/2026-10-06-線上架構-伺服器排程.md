# 線上架構：伺服器自己的排程 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 伺服器每隔幾秒自己推一次全服的事，沒有人在線時也照樣跑：世界時間、時刻表、時間到了開決戰、決戰的集結與回合逾時、季末收季與季終收兵。

**Architecture:**
- 引擎多一個「只有世界、沒有玩家」的 `Game`（`Game.for_world`），以及它的一下 `Game.world_tick(now)`。這一下做的事，跟玩家 `sync` 加上 `options()` 裡屬於全服的那一半一樣：
  - 補算共用賽季到 `now`；
  - 推一次決戰。
- `server.py` 開一條背景執行緒，每 `Config.world_tick_seconds` 秒拿一次行動鎖，叫這一下。用的是跟玩家請求同一把鎖，以及同一套鎖內模型額度與斷路器。
- 預設是關的（0 秒）：不開執行緒，行為跟現在一模一樣。

**Tech Stack:** Python 3、FastAPI／uvicorn（既有），`threading`，pytest。

**Spec:** `docs/superpowers/specs/2026-10-02-線上架構-design.md`：
- 第四節「世界時間與排程」：每 10 秒推進世界時間、決戰的集結與回合逾時；依時刻表的大事與三場決戰；季末；
- 第十一節「沒有排程，世界、決戰逾時、季末都等有人點擊」。

**這份照現在的架構寫**（PM 2026-10-06 同意）：資料庫是唯一的真實來源，一個動作＝一筆交易，用 `action_lock` 排隊。設計第二節的「記憶體主迴圈」不在這份。假人照舊是另一支程式（`run_bots.py`），設計第四節「每 20 秒假人輪流行動」也不在這份。

計畫依據 main `4e84e55`。

**排程與風險**：排在備份之後、LLM 佇列之前（企劃者 2026-10-06：全部做完再一起測）。
- 開關預設關（`world_tick_seconds = 0`），所以合進 main 不會改變任何行為；

## Global Constraints

- **引擎不讀電腦時鐘**（CLAUDE.md）：
  - `Game.world_tick(now)` 的 `now` 由呼叫端傳入；
  - 只有 `server.py` 的排程迴圈讀 `time.time()`。
- **`mutate`、`mutate_season`、`mutate_battle` 不能巢狀**：`world_tick` 只呼叫既有的、本來就在 mutate 外面的函式（`catch_up_season`、`_battle_status`）。
- **排程的每一下都包在 `world.action_lock()` 裡**：
  - 跟玩家請求同一把鎖，同時只有一個在跑；
  - 不在鎖裡等任何鎖外的東西；
  - 鎖內的模型呼叫照 `in_lock_model_timeout`（15 秒）與全服斷路器（`server._model_paused`、`server._pause_model`），跟玩家請求同一套。
- **開關預設關**：`Config.world_tick_seconds: float = 0`，0 是不開執行緒；要開由設定檔或 `content/profiles/*.json` 設成正數（設計預設 10）。
- **補算時間只算一次**：共用賽季的時鐘看 `season_last_real`（`catch_up_season`），排程與玩家的同步誰先誰後都只推一次。
- **既有規則一字不改**：
  - 大事公告照 FB-038 由每個人同步時補；
  - 決戰結果照 W13／FB-027 補送；
  - 季終收兵照 FB-035；
  - 沒開成的決戰照 T8 用前線起點判。
- **假人不受影響**：`run_bots.py` 照舊。排程不讓任何假人行動，也不顯示、不記錄任何跟假人有關的東西。
- 測試一律用暫存資料庫（`tests/conftest.py` 的 `isolated_database`），不碰 `saves/`、`.local/`、`C:\Ray\tianxia-play\`。

## Review Focus

1. **排程與玩家同步交錯**：同一段現實時間，共用賽季只能推一次。Task 1 加測試：排程推過之後玩家同步，賽季時間不變。
2. **排程那一下出錯**：例外要印出來、交易撤回、鎖放掉，下一輪照跑，執行緒不能就此死掉。Task 3 加測試：第一下丟例外，第二下照常執行。
3. **季已經結束、決戰還在打、沒有人在線**：排程那一下要照 FB-035 收兵，參戰者下次上線補到那一則。Task 1 加測試。

```python
    @classmethod
    def for_world(
        cls, content: Content, world: WorldStateStore, rng: random.Random | None = None,
    ) -> Game:
        """沒有玩家的 Game：給伺服器的排程推全服的事用（線上架構設計第四節，見 world_tick）。state 是共用賽季的空殼
        （world._season_vehicle：名號空白、不存檔），所以收場補送戰報、季終收兵那些「補給自己」的步驟對它都是空的。"""
        return cls(content, _season_vehicle(content, world.get_season()), rng, world)

    def world_tick(self, now: float) -> list[str]:
        """伺服器排程的一下：全服的事推到 now。跟玩家 sync 加上 options() 裡全服的那一半一樣，所以有沒有人在線都一致：
        1. 補算共用賽季（catch_up_season：大勢、季的事、時刻表、時間到了開決戰、季末收季）；
        2. 推一次決戰（_battle_status：集結與回合逾時、機器人補位、結算、收場套結果、季終收兵、開等著的決戰）。
        兩邊都是「追到 now 為止」，排程與玩家的請求誰先誰後都只推一次。不存角色、不寫任何人的江湖紀錄：
        大事公告與決戰戰報照舊在每個人同步時補（FB-038、W13）。回傳的訊息只給排程印紀錄用。"""
        self.now = now
        self._reconcile_season()
        msgs = list(self.world.catch_up_season(self.content, now, self.rng))
        self.state.world = self.world.get_season()
        self._battle_status(tick=True)
        return msgs
```

```python
@contextlib.contextmanager
def _model_guard(game: Game):
    """已經拿到行動鎖之後：這一次拿鎖的鎖內模型額度重新開始；全服斷路器開著時一開始就用完；這一次拿鎖裡有鎖內的模型
    呼叫失敗，就打開斷路器（見 MODEL_BREAKER_SECONDS）。玩家請求（_locked）與排程（world_step）共用這一套。"""
    game.reset_model_budget()
    paused = _model_paused()
    if paused:
        game._model_budget.gave_up = True  # 斷路器開著：額度一開始就用完（直接碰 Game 的私有欄位，PM 同意只在這裡這樣做）
    try:
        yield
    finally:
        if not paused and game._model_budget.gave_up:  # 這一次拿鎖裡鎖內的模型呼叫失敗了（私有欄位，同上）
            _pause_model()


@contextlib.contextmanager
def _locked(game: Game):
    """（保留原本 _locked 的 docstring，只把最後一句改成「鎖內的模型額度與斷路器見 _model_guard」。）"""
    with game.world.action_lock(), _model_guard(game):
        _reload(game)
        game.set_move_mode(MOVE_MODE.get())
        yield
```

```python
SCHEDULER_STOP = threading.Event()  # 讓排程執行緒停下來（測試用；伺服器關掉時執行緒是 daemon，跟著結束）


def run_scheduler(interval: float, stop: threading.Event, step=None, clock=time.time) -> None:
    """排程迴圈：每 interval 秒叫一次 step(clock())（預設是 world_step），直到 stop 被設起來。
    一下出錯就印出來，下一輪照跑：排程不能因為一次例外就停掉，不然世界又變成等人點擊才動。"""
    step = step or world_step
    while not stop.wait(interval):
        try:
            step(clock())
        except Exception as e:  # noqa: BLE001  任何錯都不能讓排程死掉
            print(f"排程這一下出錯：{e!r}", flush=True)
            traceback.print_exc()


def scheduler_line(interval: float) -> str:
    if interval <= 0:
        return "排程：關（世界時間等有人連線才推）"
    return f"排程：每 {interval:g} 秒推一次全服的事（世界時間、時刻表、決戰逾時、季末）"


def start_scheduler(interval: float) -> threading.Thread | None:
    """開關打開（interval > 0）時開排程執行緒（daemon：伺服器關掉時跟著結束）；關著回 None。"""
    if interval <= 0:
        return None
    thread = threading.Thread(target=run_scheduler, args=(interval, SCHEDULER_STOP), daemon=True, name="world-scheduler")
    thread.start()
    return thread
```
