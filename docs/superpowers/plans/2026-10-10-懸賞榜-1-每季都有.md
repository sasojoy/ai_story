# 懸賞榜（第一批：每季都有＋FB-121）實作計畫

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 懸賞榜、通緝、遊俠名號、截殺從第一季開關底下搬出來，只看劇本有沒有陣營，每一季都有；第一季規則關著的季（14 天、預設設定）每週初掛一批單（只掛這一週、不疊單、期限錨在週初）；截殺多一個主機的緊急開關（關著時通緝一起收），打贏的貢獻只在第一季記；截殺與通緝的新手期從各自加入的那一刻算；FB-121 的閉關（連鐵匠鋪）、張數只算看得到的、期限與名額、被搶先或過期補一句、同一地點不重複、通緝輸入框下限一起修好。

**Architecture:** 規則幾乎全寫在 `tianxia/bounties.py`（開關 `active`、看得到的 `visible`、期限 `due_text`／`due_line`、週初掛單的 `tick` 與 `issue` 的兩道擋、`deliver_lapses`），新手期寫在 `tianxia/roster.py` 的新函式 `raid_newbie`（不動管新手福利的 `since_join`／`newbie`），名號只改 `ranger.active`；`tianxia/world.py` 在 `advance_world_state` 每一步、`settle_season_start` 開季那一刻替規則關著的季叫 `bounties.tick`；計數器是新欄位 `WorldState.bounty_week`（不借 `hooked_week`）。`engine.py` 只動最少的幾處（截殺三個函式的開關與貢獻、閒著的選單的張數、`_bounty_options` 改列 `visible`、`_idle` 擋懸賞榜與鐵匠鋪、`sync` 補一句）。**資料庫不升版**（`bounty_week` 在 `seasons.data` 的 JSON 裡，有預設值）。

**Tech Stack:** Python 3.12、pydantic、SQLite（不動結構）、pytest（`-n auto`）、原生 JavaScript 網頁（`web/app.js`、node 假瀏覽器測試）。

**Spec:** `docs/superpowers/specs/2026-10-10-懸賞榜每季都有-design.md`（企劃者 2026-10-10 審過；14.1 四件已定、14.2 照預設）第十三節「第一批」：2.2（開關、`Config.bounties.enabled`、`Config.raid.enabled` 與它連帶收起通緝、截殺貢獻只在第一季記）、2.3 第 1～6 點、2.4（上線說明）、第三節（`bounty_week`、`bounties.tick`、`issue` 的兩道擋與錨在週初的期限、`due_text`、`settle_season_start` 的分支）、6.2 與 14.1 丁（新手期從 `joined_at` 算、`post_problem` 補新手期）、第七節 FB-121（第 2～6 件）、第八節（推送指紋分類）、10.1 那幾支測試的改寫與 10.2 第一批的新測試、11.1 第 1 點（`measure_sanren.py --profile none`）。

**跟第二批的關係**：第二批是「求藝、求兵」（設計第四節、第九節、11.1 第 2～3 點、11.2），這份不做。本計畫留給第二批接的介面見「交接」最後一段。
