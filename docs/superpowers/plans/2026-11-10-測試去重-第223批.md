## 五、順序與坑
1. 一個檔改完就跑那一檔（`-p no:xdist`），整批改完 `measure.ps1 after` 對表，再跑 `scripts/test_for.py`（改的都是測試檔，會連 slow 跑那幾個檔）。
2. CRLF：Write 出 LF，寫完轉回 CRLF，提交前 `git ls-files --eol` 看 `i/lf`。
3. module fixture 不能用 function 範圍的 `real`／`on`／`content`；別讓 module fixture 開資料庫（只 validate，不 `Game.new`）。MIL-04、FIG-05 照舊用 function fixture。
4. 主 validate 不截 20 筆（`content.py` 最後一行 `raise ContentError("內容檔有誤：\n" + "\n".join(errors))`，`errors[:20]` 是前面評級那一支），每組照舊不超過 8 個。
5. 檔名全 repo 不能重複；不開新檔（共用小檔不做：兩檔夾具不同）。
