# 伺服器假人學會合成、修練、學藝 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 伺服器假人（`run_bots.py`）也會玩武學：
- 學藝：在教武學的地方學一門自己沒有的屬性。
- 合成：武學＋意境、武學＋武學、意境＋意境。
- 修練：衝下一品。
- 改練更強的、庫滿了熔最弱的、練成絕學就定名。

首創配方跟真人一樣請模型取名（企劃者 2026-10-05），所以從名字看不出首創者是假人。

**Architecture:**
- **怎麼做事**：假人每一輪照舊只走 `Game` 的公開行動。新的 `bot_policy.tend_arts` 在主要行動之前做這些武學的事，挑合成的方式跟整季機器人（`bot.py`）共用同一段 `bot.pick_forge`。
- **首創取名走三段式**：
  - A（鎖內）：`Game.forge_request(..., named_outside=True)` 開單。假人的 `Game` 沒有 client，也照樣開單。
  - B（鎖外）：`bot_runner` 請模型取名（`naming.generate`）。
  - C（鎖內）：重讀角色、交給 `Game.forge(proposed=...)` 整個重驗再登記。
- **一次一件**：B 段在假人程式的迴圈裡做，同時只有一件；兩件之間至少隔 `bot_naming_gap_seconds`。輪不到的假人這一輪不開首創的爐，查得到配方的照開。
- **鎖內不叫模型**：假人的 `Game.client` 照舊是 `None`，鎖內一個模型都不叫。只有 B 段用假人程式自己的 client。

**Tech Stack:** Python 3、pydantic（`tianxia/`）、pytest；`run_bots.py`、`scripts/sim_server_bots.py`。

**Spec:**
- `docs/superpowers/specs/2026-10-02-伺服器假人-design.md`：假人跟真人完全一樣、看不出來；第三節「假人不接 LLM」底下已經加上首創取名的例外。
- `docs/superpowers/specs/2026-10-05-武學與成長-design.md`：第十二節（三種合成、合到舊的）、修練、附錄 B 學藝。
- PM 10/5、10/6 的決定（見 Global Constraints）。

**開工條件：**
- 照 main `3dc2370` 起的程式（武學計畫的合成、修練、熔煉、學藝、功法庫都已經在 main）。
- **跟 LLM 佇列計畫（`plans/2026-10-06-線上架構-LLM佇列.md`）互不相依，先後都可以**。佇列在伺服器程式的記憶體裡，`run_bots.py` 是另一支程式用不到它。這份照 PM 10/5 的暫時做法：一次最多一件，有一件在等時跳過首次融合。
  - 等佇列放進資料庫、或假人移進伺服器程式之後，B 段換成 `model_call(..., bot=True)`，排在真人後面、受 `llm_queue_bot_cap` 限制。那是之後的事，不在這份。

**執行方式：** 子代理逐步做（superpowers:subagent-driven-development）。每個 Task 由一個新的子代理實作，另一個子代理審過才做下一個。最後整條分支再審一次。

## Global Constraints

- **看不出是假人**（伺服器假人設計）：
  - 只走 `Game` 的公開行動（`forge`、`cultivate`、`switch_art`、`melt_art`、`melt_insight`、`name_mastered`、`choose("learn:…")`、`practice`）。
  - 江湖紀錄、江湖史、首創名字都跟真人一樣。
  - 主控台與 log 只印數字。
- **首創配方叫模型取名**（企劃者 2026-10-05）：
  - 沒人合過、要長新的：請模型取名。
  - 合到舊的、候選兩個以上：請模型挑一個。
  - 都走三段式，A、C 在 `action_lock` 裡。`bot_runner` 每次拿鎖都 `reset_model_budget()`（同 `server._locked`）。
  - 模型叫不動、太慢：照真人的退路走字表，跟真人在模型掛掉時一樣。
- **假人取名的節制**（PM 10/5 暫時做法）：
  - 同時最多一件（假人程式的迴圈一個一個來，B 段在迴圈裡做完才換下一個假人）。
  - 兩件之間至少隔 `bot_naming_gap_seconds`（120）。
  - 一件最多 `bot_naming_budget_seconds`（30）。
  - 輪不到的假人這一輪不開「要取名的爐」，改天再來；查得到配方、不必叫模型的照開。
  - `bot_naming` 關掉、或假人程式沒有 client：一律不開要取名的爐。
- **鎖內不叫模型**：假人的 `Game.client` 照舊是 `None`。開爐的 C 段一定給 `proposed`，不必取名時是 `(None, "")`。
- **定名**：練成絕學、輪到假人定名時，沿用現在的名字（真人也可以這樣，見 `cultivation.name_mastered`），不叫模型。
- **學藝**：
  - 這裡教、學得了（`library.learn_problem` 是 None）、自己同一種（內功／武學）還沒有這個屬性，才學一門。
  - 付完學費還要剩 `LEARN_SILVER_RESERVE` 兩（療傷用），免費的不看。
  - 庫裡至少留 `LEARN_ROOM` 格給合成。
  - 走選單上的「學〇〇」（`Game.choose`）。
- **頻率**（都是【預設】，整季模擬量完再定）：
  - 合成：`FORGE_CHANCE`（每輪 0.25）；武學＋武學的份額 `SERVER_BLEND_SHARE`（0.15，低於整季機器人的 0.3：持有 30 門就有 435 對，每一對都是首創，都要叫模型）。
  - 修練：`CULTIVATE_CHANCE`（0.2）；體力照整季機器人的保留量。
- **整季機器人（`bot.py`）的行為一個字都不變**：拆出來的 `pick_forge` 擲亂數的順序跟原本一樣，既有的 `tests/test_bot.py` 全過。
- 測試：`.venv/Scripts/python.exe -m pytest -q`。commit 照專案慣例（明列路徑）；push 照 PM 的規矩。

## Review Focus

1. **B 段不握鎖**：假人請模型取名時，真人與伺服器拿得到行動鎖。→ Task 3 `test_a_bot_names_its_first_recipe_outside_the_lock`。
2. **一次一件、有間隔**：同一輪兩個假人都想開首創的爐，只有一個叫模型，另一個這一輪不開；隔夠了才輪到下一個。→ Task 3 `test_only_one_bot_names_per_gap`。
3. **C 段重驗**：取名回來時配方已被別人登記、或假人的東西變了，不重複扣、不留錯的名字。→ Task 3 `test_a_recipe_claimed_while_the_bot_waited_is_not_charged_twice`。

```python
class ForgePlan(NamedTuple):
    """挑好的一爐（還沒開）：武學＋意境是 (武學, (意境,), None)、武學＋武學是 (第一門, (), 第二門)、意境＋意境是 (None, (甲, 乙), None)。"""

    art_id: str | None
    insight_ids: tuple[str, ...]
    other_art: str | None


def pick_forge(
    game: Game, rng: random.Random, merge_share: float = MERGE_SHARE, blend_share: float = BLEND_SHARE,
) -> ForgePlan | None:
    """挑一爐（整季機器人與伺服器假人共用）：體力低於 FORGE_RESERVE、或什麼都合不了就是 None。只挑、不開爐，什麼都不改。
    亂數的擲法跟原本寫在 forge_and_cultivate 裡的一模一樣（見那邊的說明），整季機器人的結果不變。"""
    state, content, world = game.state, game.content, game.world
    p = state.player
    arts = library.owned_arts(state)
    can_fuse, can_blend = bool(p.insights and arts), len(arts) >= 2
    if not (can_fuse or can_blend) or p.stamina < FORGE_RESERVE:
        return None
    if len(p.insights) >= 2 and rng.random() < merge_share:
        for _ in range(FORGE_TRIES):
            a, b = rng.choice(p.insights), rng.choice(p.insights)
            if fusion.merge_problem(state, content, world, a, b) is None:
                return ForgePlan(None, (a, b), None)
        return None
    if can_blend and (not can_fuse or rng.random() < blend_share):
        for _ in range(FORGE_TRIES):
            a, b = rng.sample(arts, 2)
            if fusion.blend_problem(state, content, world, a, b) is None:
                return ForgePlan(a, (), b)
        return None
    for _ in range(FORGE_TRIES):
        art_id, insight_id = rng.choice(arts), rng.choice(p.insights)
        if fusion.fuse_problem(state, content, world, art_id, insight_id) is None:
            return ForgePlan(art_id, (insight_id,), None)
    return None
```

def tend_arts(game: Game, rng: random.Random, slot: NamingSlot | None = None) -> list[str]:
    """假人的武學（修練頁與煉製頁上的事），每一輪主要行動之前做；只走 Game 的公開行動，跟真人按按鈕一樣：
    1. 練成絕學、輪到自己定名：沿用現在的名字（不叫模型）；
    2. 這裡教、自己同一種還沒有這個屬性的，學一門（見 _learn_here）；
    3. 庫滿了熔最弱的一門；
    4. 有東西可合、體力有餘時，FORGE_CHANCE 的機會合一爐（挑法同整季機器人，武學＋武學的份額低一點；
       首創的要叫模型，見 _forge）；
    5. 功法庫裡有更強的就改練；
    6. 體力有餘、有東西可修時，CULTIVATE_CHANCE 的機會修練一次（衝絕學、手上有破境丹就服）。
    亂數只在真的有事可做時才擲：什麼武學都沒有的假人，擲亂數的順序跟以前一樣。"""
    state, content, world = game.state, game.content, game.world
    p = state.player
    msgs: list[str] = []
    if p.naming is not None:
        art = team.resolve_art(p.naming, content, world)
        if art is not None:
            msgs += game.name_mastered(art.name)
    msgs += _learn_here(game)
    if library.full(state, content):
        bot.melt_the_weakest(game)
    arts = library.owned_arts(state)
    forgeable = bool(p.insights and arts) or len(arts) >= 2
    if forgeable and p.stamina >= bot.FORGE_RESERVE and rng.random() < FORGE_CHANCE:
        plan = bot.pick_forge(game, rng, blend_share=SERVER_BLEND_SHARE)
        if plan is not None:
            msgs += _forge(game, plan, slot)
            if slot is not None and slot.job is not None:
                return msgs  # 這一爐在等名字：改練與修練等開完爐再說
    bot.switch_to_the_strongest(game)
    if p.stamina >= bot.CULTIVATE_RESERVE:

        if ready and rng.random() < CULTIVATE_CHANCE:
            msgs += game.cultivate(ready[0], use_legend=bot.takes_the_pill(game, ready[0]))
    return msgs


def _learn_here(game: Game) -> list[str]:
    """學藝（武學與成長設計附錄 B）：這裡教、學得了、自己同一種（內功／武學）還沒有這個屬性的，學一門。
    付完學費要留 LEARN_SILVER_RESERVE 兩（免費的不看），庫裡至少留 LEARN_ROOM 格給合成。走選單上的「學〇〇」。"""
    state, content, world = game.state, game.content, game.world
    if library.cap_of(state, content) - library.held_count(state) < LEARN_ROOM:
        return []
    enabled = {o.id for o in game.options(odds=False, tick=False) if o.enabled}
    have = {
        (art.kind, art.attribute)
        for art in (team.player_art(state, content, world, a) for a in library.owned_arts(state)) if art is not None
    }
    silver = state.player.stats.get("silver", 0)
    for skill, problem in library.lessons_here(state, content):
        fee = skill.learn.silver if skill.learn is not None else 0
        if problem is not None or f"learn:{skill.id}" not in enabled or (skill.kind, skill.attribute) in have:
            continue
        if fee and silver - fee < LEARN_SILVER_RESERVE:
            continue
        return game.choose(f"learn:{skill.id}")
    return []


def _forge(game: Game, plan: bot.ForgePlan, slot: NamingSlot | None) -> list[str]:
    """開一爐。要模型取名（或挑）的：輪得到就開單交給假人程式（B、C 段在 bot_runner），輪不到這一爐不開——
    用字表的名字搶下首創，名字的樣子看得出是假人（企劃者 2026-10-05）。不必叫模型的（配方有了、只有一個候選）照開，
    給 NO_NAME，鎖內一定不叫模型。"""
    insight_ids = list(plan.insight_ids)
    request = game.forge_request(plan.art_id, insight_ids, other_art=plan.other_art, named_outside=True)
    if request is None:
        return game.forge(plan.art_id, insight_ids, proposed=NO_NAME, other_art=plan.other_art)
    if slot is not None and slot.open and slot.job is None:
        slot.job = ForgeJob(plan.art_id, plan.insight_ids, plan.other_art, request)
    elif slot is not None:
        slot.skipped += 1
    return []

`scripts/sim_server_bots.py`：

```python
FORGE_KINDS = {"fuse": "武學＋意境", "blend": "武學＋武學", "merge": "意境＋意境"}


class ForgeTally:
    """一季的合成量測（PM 10/6：首創組合數、合到舊的比例、模型呼叫數；持有 30 門有 435 對，武學＋武學要控頻率）。"""

    def __init__(self) -> None:
        self.forged: Counter = Counter()  # 開了的爐，照種類
        self.new = 0  # 首創（登記了新的武學或意境）
        self.landed = 0  # 合到舊的（連到已經有的那一門）
        self.named = 0  # 請模型取新名字
        self.picked = 0  # 請模型從候選挑一個
        self.skipped = 0  # 想開首創的爐、輪不到取名而作罷

    def report(self, libraries: list[int]) -> dict:
        most = max(libraries, default=0)
        return {
            "開爐": dict(self.forged), "首創": self.new, "合到舊的": self.landed,
            "合到舊的比例": round(self.landed / (self.new + self.landed), 2) if self.new + self.landed else 0.0,
            "取名呼叫": self.named, "挑選呼叫": self.picked, "輪不到取名": self.skipped,
            "庫存最多": most, "最多可配對": most * (most - 1) // 2,
        }
```

`run_season(content, workdir, seed, tick, real_model=False)`：

- 建一個 `tally = ForgeTally()`。
- 用 `mock.patch.object` 包住下面幾樣，原本的照樣執行，只多記數：
  - `SqliteWorldStore.claim_recipe`、`claim_insight_recipe`：回傳的第二個值是 True（這一次登記成）時 `tally.new += 1`。
  - `SqliteWorldStore.link_recipe`、`link_insight_recipe`：同上，`tally.landed += 1`。
  - `Game.forge`：照引數記種類（`other_art` 有是武學＋武學、`art_id` 有是武學＋意境、都沒有是意境＋意境）。
- `real_model` 是 False 時，`naming.generate` 換成假的：
  - 有 `choices` 時 `tally.picked += 1`、回 `(choices[0], "")`；
  - 沒有時 `tally.named += 1`、回 `(naming.fallback_name(content, f"模擬|{request.key}", request.name_kind, salt=tally.named), "")`。
- `BotRunner(..., client=object() if not real_model else OllamaClient.from_config(content.config))`。
- 每一輪 `runner.tick()` 的回報，`tally.skipped += report.naming_skipped`。
- 結果的 dict 加 `"forge": tally.report([library.held_count(s) for s in bots])`。

`main()` 加 `parser.add_argument("--real-model", action="store_true", help="假人取名真的叫模型（慢；預設用假的、只數次數）")`，傳給 `run_season`。

（`claim_insight_recipe`、`link_insight_recipe` 照 `world_state.py` 實際的名字；包的時候用 `autospec=True` 或手寫 wrapper，讓 `self` 傳得進去。）

## 計畫裡的決定（設計與 PM 沒寫死、這份替實作選的）

| 題目 | 這份的做法 | 理由 |
|---|---|---|
| B 段在哪裡跑 | 假人程式的迴圈裡，做完才換下一個假人 | 「一次一件」自然成立，不用多開執行緒；假人慢幾秒沒有人在等 |
| 輪不到取名時 | 這一爐不開，查得到配方的照開 | PM 10/5「有一件在等時跳過首次融合」；用字表名字搶首創就看得出是假人 |
| 等名字的那一輪 | 不做主要行動 | 不然體力可能花掉，C 段開不成、模型白叫 |
| 絕學定名 | 沿用現在的名字，不叫模型 | 真人也可以沿用；首創取名已經是模型取的，沿用看不出差別，也少一次模型呼叫 |
| 學藝的條件 | 同一種沒有這個屬性、留學費與庫存空間 | 學藝的價值是多一個合成的屬性；同屬性的下品學了沒用，還佔位置 |
| 鎖內的模型 | 假人的 `Game.client` 照舊是 None | 假人在鎖裡等模型 15 秒，真人就跟著等；只有鎖外的 B 段用模型 |
| 頻率的數字 | 全部【預設】，量完再定 | PM：「做完用整季模擬量……再定數字」 |

## 不在這份

- 假人取名排進 LLM 佇列（真人優先、`llm_queue_bot_cap`）：要等佇列放進資料庫，或假人移進伺服器程式。
- 假人往教武學的地方走（專程去學藝）：這一版只在走到了才學。
- 假人做機緣、伏筆、隨口應對、跟大勢人物對話：照舊不做。
