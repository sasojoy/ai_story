## 五、driver 要改的
1. **等版面穩定才取**：換寬度、捲回頂端後，每 100 ms 讀一次簽章（`scrollHeight`、`scrollWidth`、`.shell` 的 rect、所有 class 的雜湊），連續 4 次一樣才取樣式與 DOM，上限 3 秒；到上限記 `unstable:true`（比對時不准歸雜訊）。取代現在固定的 `sleep(420/220/450)`（B：fit 類別約 450 ms 才準）。
2. **樣式走整個 body＋偽元素**：現有 `STYLESIG` 已走全部元素；加 `::before`、`::after`（`content` 不是 `none` 才算）。逐元素存屬性文字，同一鏡內用雜湊去重、gzip 一鏡一檔（估一輪 100 MB，跑完刪）。比對才印得出**哪個屬性**差，`layout-used` 那類要靠它。`.shell` 專用的 dump 拿掉。
3. **視窗加 640、641、900**：斷點量到 `min-width:641px` 7 處、`900px` 2 處。walk 裡這三個只取樣式、不拍照（一鏡多約 1 秒），`light` 鏡不取；這三個寬度的像素由語料重播出。
4. **語料重播**（`replay.py --corpus <dom 夾> --a-web <夾> --b-web <夾> --out <夾> [--no-freeze] [--styles-only]`）：dom 快照的 body 去掉 script，配候選 `web/index.html` 的 `<head>`，本機靜態服務 `/static/*`（用候選的 `web/`），不跑 JS、不碰遊戲伺服器。六個視窗取樣式與像素。先照正規化的 DOM 去重。總表換算 210 個快照約 2.7 分，第二段量實數。快照要多存 `<html>` 屬性。語料是 walk 的產物，**不進 git**（`--keep` 或 `walk` 留著給 CSS 批用）。
5. **動畫另開一輪不凍結**：用語料重播 `--no-freeze --styles-only`，不凍結、`prefers-reduced-motion: no-preference`，只比 `animation-*`、`transition-*`；`@keyframes` 看 `cssrules.json`。要的是凍結時看不到的宣告，不比影格。
6. **亂數從源頭定**：FREEZE 把 `crypto.getRandomValues` 也種子化（`web/admin.js:217` 臨時密碼、`web/mall.js:719` 訂單編號，現在沒定）；`click()`、`clickKey()` 前重設 `Math.random` 的種子（`web/app.js:2344` 洗牌；`web/outing.js:498、718` 的 canvas 每影格都在吃亂數，才是 `mt_shuffle` 差的原因）。
7. **揮發元素**：每個視窗、每一屏記 `.huaben-link`、分享列的 rect，像素差全落在裡面才算那一類。
8. **畫布**：遮罩改成預設開 `canvas:not(.mv-ground){visibility:hidden}`（B r2 開了 canvas 的差全消失）；`.mv-ground`（輿圖底，`web/map.js:116`）先不遮，base 對 base 不穩才遮、寫理由。另記每個畫布非空白當資訊，不比。
