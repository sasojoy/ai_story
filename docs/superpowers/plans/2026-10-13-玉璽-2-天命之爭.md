**Goal:** 做玉璽碎片設計第十八節「玉璽二：天命之爭」。七片在這一輪都現世過（PM 己：有主的、隱沒的都算），換季時新的一季蓋上**天命之季**的章：這一季**不提前收季**；時刻表上標了 `seal` 的三場決戰（長社、宛城、廣宗）開集結時**必定璽動、每場一片**（PM 丙），不擲 7%、拿掉新主保護與全服一季兩次的上限，每片每季照舊最多一次；**不擲現世**；隱沒的碎片在標了 `seal` 的前兩場收場時各**喚回**一片（勝方戰功前三名抽，排在挑戰者之後），**喚回不算現世**（PM 辛）。第 12 週週一 20:00（季曆）在冀州開**天命之爭**：碎片握在哪一軍（開集結那一刻的投靠名冊），戰局起點就往哪一軍偏，每片 3 點、最多 12 點；手上有碎片的人到場份量 ×1.2；天命之爭本身不璽動、不打單挑。勝方**得天命**：這一季的結局改寫成第一季設計 13.1 的持璽結局——官軍得天命是「漢室重光」、黃巾得天命是「黃天當立」（豪強照 PM 戊不能得天命，「群雄得璽」見「要 PM 定的」第 2 條）；這一刻手上有碎片的人以「合璽之人」留名；勝方參戰者名望 +10、軍餉加倍。保底收場、沒開成、管理者取消都是「天命未定」，結局照三方態勢。天命之季之後的那一次換季，七片全部**散去**、回到未現世，第二輪從頭來。另外：管理者「蓋天命之季」（下一季／這一季），量表（天命之季多久來一次、天命之爭結果分布）。

**Architecture:**
- **規則都加在 `tianxia/seal.py`**（玉璽一的模組）：天命之爭是哪一件（`mandate_event`、`mandate_battle`、`is_mandate_battle`）、該不該蓋章與蓋章（`mandate_due`、`stamp_mandate`）、散去（`scatter`）、天命之季的璽動（`roll_stir(..., mandate=True)`）、喚回（`recall_events`、`roll_recall`）、起點（`mandate_lean`、`lean_shift`、`lean_text`）、保底的判斷抽成 `deserted`、字句。import 方向不變（`seal` 不 import `timetable`、`world`、`rules`、`engine`）：要算時刻的地方由呼叫端照 `timetable.default_time` 算好傳進來。
- **時刻表的天命之爭是「選擇加入」**（「要 PM 定的」第 1 條；跟設計 8.3 的過濾法不同）：`content/timetable.json` 照舊一份，標 `mandate_only` 的那一件載入時分到 `Content.mandate_timetable`，`Content.timetable` 照舊是那 12 件。`timetable.events(season, content)` 在蓋了章的季（`WorldState.mandate`）才把它排進來（同一週排在季末之前），`timetable.find(content, id)` 照 id 兩份都找、不看章（只給已經開出來的那一場收場、補結算、軍令修正用；會「開」或「定」大事的入口 `_claim_showdown`、`Game._timetable_event` 走 `events`）。要看得到天命之爭的十幾處（開集結、收場、補結算、時刻表的到期與排序、暫停後挪時間、管理者的開戰／排時間／定結果、本週大事、季末結算卡、碎片卡）改走它們；其餘照舊讀 `content.timetable` 的地方（howto、opportunities、季末大事……）自然看不到——漏改的地方最壞是天命之季少顯示一列，不會在一般季冒出來。
- **接點**：`sqlite_world.next_season` 照舊判隱沒（剛結束的不是天命之季）或在單挑記完之後散去（是），再在新的一季判 `mandate_due` 蓋章（直接改 `state`，不巢狀 mutate）；`seal.on_muster` 認天命之爭（起點偏移、`BattleInstance.seal_lean`）與天命之季（必定璽動、不擲現世）；`Game._seal_settle` 多兩支——天命之爭交給新的 `Game._mandate_settle`（記 `WorldState.mandate_result`、合璽之人、江湖史），天命之季前兩場多喚回；`Game._settle_showdown` 在天命之爭保底收場時把時間軸記成跳過；`world.settle_waiting_showdowns` 沒開成的天命之爭也記跳過；`world.evaluate_ending` 先看 `mandate_result`、`season_endings` 排除天命結局；`world.end_season` 沒定下來的記「天命未定」；`world.decisive_ending` 與 `rules.stance_rule_note` 讀新的 `rules.decisive_week`；`Game._showdown_pay` 照天命之爭加倍、加名望；`Game._battle_choose`／`_enlist`／`_backfill_battle_scores` 加入時份量 ×1.2（`Game._mandate_weight`）；`Game._deliver_seal_results` 補喚回、散去、合璽之人。
- **資料**（不升版，維持第 5 版）：`WorldState.mandate`、`mandate_result`；`SealRegistry.mandate_season`、`mandate_pending`；`SealEvent.round`、`holders`，kind 多 `recall`、`scatter`、`mandate`；`BattleInstance.seal_lean`；內容 `TimetableEvent.mandate_only`、`mandate_endings`、`weekday`、`hour`，`Ending.mandate`，`Content.mandate_timetable`；`Config.seal.mandate: MandateTuning`。
- **畫面**：不加新卡片。天下大事與江湖史寫蓋章、集結、喚回、天命、散去；狀態列「下一件」與時刻表照 `timetable.events` 排進天命之爭；持有者的碎片卡在天命之季換一句、日期多天命之爭；決戰畫面多一句碎片在哪一軍；見聞→江湖史七格照這一輪（第二輪起標題寫「第 N 輪」）；管理者「玉璽」一組多兩顆鈕。

**Tech Stack:** Python 3.12、pydantic、SQLite（不動結構，維持第 5 版）、pytest（`-n auto`）、原生 JavaScript（`web/app.js`、node 假瀏覽器測試）。

1. **天命之爭怎麼放進時刻表**（跟設計 8.3 不同）。
   - 建議（甲）：照「Architecture」第二條——同一個 `content/timetable.json`，標 `mandate_only` 的那一件載入時分到 `Content.mandate_timetable`；`timetable.events(season, content)` 在蓋了章的季才排進來，要看得到它的地方（約 14 處，Task 2 列全）改走 `events`／`find`；其餘地方不必改。守門測試反過來寫：`content.mandate_timetable` 只准 `timetable.py`、`seal.py`、`content.py`、`models.py` 讀。

   - 乙：照設計 8.3（`content.timetable` 13 件、過濾函式、守門測試不准直接讀 `content.timetable`、改兩支舊測試）。
2. **「群雄得璽」要不要做**（第一季設計 13.1 的第三種持璽結局；PM 戊當時說「等天命之爭那一批再看」）。

3. **軍餉加倍與名望 +10 給誰**。
   - 建議（甲）：只給得天命那一方的參戰者（8.3「勝方參戰者名望 +10、軍餉加倍」照字面讀）。加倍的是銀兩與經驗（`round(...) × pay_scale`，正好兩倍）；貢獻不加倍（貢獻是陣營的帳，不是軍餉）。

def mandate_lean(world: WorldStateStore, content: Content, definition: BattleDef) -> dict[str, int]:
    """天命之爭開集結那一刻：能站的每一方各握幾片（持有者照這一季的投靠名冊，不讀存檔；散人、隱沒的不算）。第三方也數（畫面與
    之後的「群雄得璽」用；起點只看兩軍，lean_shift）。"""
    sides = battle_instance.sides(definition)
    out: dict[str, int] = {}
    for shard in world.seal_state().registry.shards.values():
        if shard.state == "held" and shard.holder and shard.id in content.seal:
            side = world.faction_of(shard.holder)
            if side in sides:
                out[side] = out.get(side, 0) + 1
    return out


def lean_shift(lean: dict[str, int], definition: BattleDef, cfg: SealTuning) -> int:
    """起點往握碎片的那一軍偏（8.3；PM 戊）：（第一軍 − 第二軍）× start_shift，夾在 ±start_shift_cap；第一軍（官軍）是正向
    （同 BattleDef.factions[0] 的約定）；豪強不推。"""
    first, second = definition.factions[0].id, definition.factions[1].id
    raw = (lean.get(first, 0) - lean.get(second, 0)) * cfg.mandate.start_shift
    return max(-cfg.mandate.start_shift_cap, min(cfg.mandate.start_shift_cap, raw))


def lean_text(lean: dict[str, int], definition: BattleDef) -> str:
    """「官軍握著2片、黃巾軍握著1片」（只寫兩軍，照 BattleDef 的名字）；都沒有寫 LEAN_NONE。"""
    parts = [LEAN_PART.format(side=f.name, n=lean[f.id]) for f in definition.factions if lean.get(f.id)]
    return "、".join(parts) or LEAN_NONE

def mandate_mc(emerge_rate: float, trials: int = 4000, seed: int = 0) -> dict:
    """天命之季多久來一次（玉璽二）：每季最多現世一片、機率 emerge_rate，數到七片都現世過要幾季（下一季就是天命之季）。
    只用 random.Random(seed)：同樣的參數結果一樣。回 rate、mean、p10、p50、p90（季）與 cycle（一輪＝湊齊＋天命之季一季）。"""
    rng = random.Random(seed)
    counts = []
    for _ in range(trials):
        seasons = got = 0
        while got < 7:
            seasons += 1
            got += rng.random() < emerge_rate
        counts.append(seasons)
    counts.sort()
    mean = round(sum(counts) / len(counts), 1)

    def pick(q: float) -> int:
        return counts[min(len(counts) - 1, int(q * len(counts)))]

    return {"rate": emerge_rate, "mean": mean, "p10": pick(0.1), "p50": pick(0.5), "p90": pick(0.9), "cycle": round(mean + 1, 1)}
