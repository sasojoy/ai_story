## 三、第一條：殼的 js 照 hunk 挑

**範圍**：只有 `web/app.js`、`web/main.js`（新常數 `SHELL_HUNK_JS`）。`shell.js`、`state.js`、`fit.js`、`arena_*` 照舊走原挑法，`WEB_SCRIPTS` 不動。

**位置**：`pick` 裡 `if f.startswith("web/"):` 那一支（第 1277 行）開頭；原本那幾行就是「原挑法」，收成一個區域函式共用。

**規則**（照順序）：
1. 沒有 hunk（給了檔名、跟 base 沒差）→ 原挑法。
2. hunk 每一行照新舊兩份各自的位置找 span（重用 `_split`，span 函式見下）。落在 span 外、又不是空行或註解（`//`、`/*`、`*` 開頭）→ 原挑法。`_split` 的 `_meaningful` 只認 `#`，不改它的簽名：拿到 `None` 那一組自己再濾一次。
3. 任一個名字寫到它的測試檔超過 `SHELL_NAME_CAP = 20` → 原挑法。
4. 其他：寫到這些名字的測試檔＋`test_shell_web.py`（載入檢查、每個按鈕一個主人）＋`test_server_bots.py`（FB-673 掃 `web/` 不准出現的字；原挑法本來就有，14 條 0.2 秒，總表沒寫，保守留著）＋`result.smoke = True`。不加 `test_server.py`（它的煙霧那幾條 `-m smoke` 會跑）。
5. 只改註解、落不到任何名字 → 只有第 4 條固定那幾個。
6. 寫到名字的檔裡，用 webharness 又**整檔 slow** 的（現在 4 個：`test_epiphany_name_web`、`test_errands_web`、`test_seal_acts_web`、`test_sortie_report`）放進 `result.runs_js`，連 slow 一起跑。不然挑到了也不跑（10/31 審查抓過同一件事，見 feature_web 那一支的註解）。部分 slow 的不放。

每一條都寫 `result.why`：退回的寫原因（落在哪一行以外、哪個名字幾檔）；沒有測試寫到的名字列出來，寫「靠 03:30」。

**span 函式 `shell_spans(src)`**（照縮排，兩支檔頂層都縮排兩格；換行先統一成 `\n`，`hunks()` 讀的已經是）：
- 頂層宣告：`^  (async )?function 名字(`、`^  (const|let) 名字 =`，span 名字就是它。
- 結尾：往下找，碰到 `^  [}\])]` 結束在那一行，碰到別的 `^  \S` 或 `^\S` 結束在上一行。**不准只找收尾那一行**：行尾有註解的 `const X = 1; // …` 與沒有收尾行的 `const A = cond\n    ? x\n    : y;` 都會把後面的名字吞掉，歸屬往挑少的方向錯。我第一版量就踩到（吞掉一百個名字），上面的數字是修過重量的。
- 事件處理：`^  (document|window)\.addEventListener\("` 開始的那一段**自己不算 span**，裡面 `^        case "x"`（縮排八格）才算，span 名字 `case:x`；一行多個 `case "a": case "b":` 都算，連續只有標籤的行併成一個，名字記 `case:a|b`（現在兩種都沒有，留著是怕之後有）。結尾：下一個同縮排 `case` 的前一行，或第一個縮排小於八格的非空行的前一行。handler 前段與沒有 case 的 handler（`submit`、`keydown`……）落在 span 外 → 原挑法，這是對的方向。
- `const` 與函式裡的 `switch`（第 1653 行那個在函式裡）照函式名，不拆。
- 認不出來一律落在 span 外 → 原挑法。縮排整個變了就是全部退回，不會挑少。

**寫到名字 `_name_writers(name)`**（`functools.lru_cache`）：`all_tests()` 扣 `TEXT_BLIND`，看 `web_text(t)`（含 kit，webharness、server_kit 不算），regex `(?<![\w$-])名字(?![\w$-])`。連字號要擋：`report-list` 不算寫到 `report`。case 的標籤用同一支，`admin`、`tab`、`news` 這種常見字超過 20 就退回，方向是對的。上面的數字就是用這個量的。`_index()` 認不得連字號，不用它。

**新常數**：`SHELL_HUNK_JS`、`SHELL_NAME_CAP = 20`、`SHELL_LOAD_TESTS = ("test_shell_web.py", "test_server_bots.py")`。

## 四、第二條：共用層的內容驗證帶 test_content

**位置**：`pick` 的共用規則層那一支（第 1223～1227 行），原本的挑法不動，加一段。

**什麼算內容驗證**：模組最外層的 def，名字符合 `_?(check|validate)_`，**參數有 `need`**。`need` 要留著：`ranks.check_summons`、`events.check_note`、`jianfa_numbers._check_100` 都不是內容驗證。現在 15 個模組 17 個函式：`battlelog`、`conquest`、`figures`、`forge_secrets`（3 個）、`orders`、`plans`、`push`、`relations`、`secret_recipes`、`siege`、`signature`、`terrain`、`territory`、`timetable`、`traits`。全部都在 `SHARED_MODULES`。

**怎麼判斷**：
- 拿 hunk：`hunks_of` 有就用，沒有就 `hunks(f, base)`。
- 沒有 hunk → 照整個檔算：模組裡有內容驗證就加（同 engine「跟 base 沒有差異，照整個檔算」）。
- 有 hunk → `_split(..., lambda s: [x[:3] for x in _core_spans(s)])` 取名字，每個名字 `_callers_up(seed, users)`（`users` 取自 `_core_refs`）碰得到內容驗證就加。這樣改它用到的小函式與常數也算；`None` 那一組（import、模組層句子）不算。
- 加的是 `test_content.py`（`named` 裡有才加），`why` 寫改到哪個名字、經哪個驗證。

**15 個模組的說明各拿掉一句**（只動那一句，別的字不動）：
- 這 14 個：`）：改它要另外跑 tests/core/test_content.py。` → `）。`。行號：`battlelog:6`、`conquest:17`、`forge_secrets:14`、`orders:21`、`plans:24`、`push:4`、`relations:8`、`secret_recipes:18`、`siege:24`、`signature:6`、`terrain:11`、`territory:11`、`timetable:11`、`traits:13`。
- `figures:24`（派工單的 14 個沒算到它，第 100 批才搬進來；同一條規則挑得到，不拿掉就成了假話）：`；改了另外跑 tests/core/test_content.py，test_for 改這一份帶不到）。` → `）。`。
- **不動** 9 個包的 `__init__.py`（`bounties`、`bout`、`companions`、`faction`、`gear`、`military`、`seal`、`sense`、`story`）：包的 `checks.py` 走「那一包的 tests／＋核心契約」，那句話還是對的。寫進 leftovers，要不要也帶由 PM 定。
