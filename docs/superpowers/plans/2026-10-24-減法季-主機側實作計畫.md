# 減法季・主機側實作計畫（批 2、3b、3c、4、6、7b：規則引擎那一半）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 照雲端側 2026-10-24 的〈減法季 切工方案〉（Joy 定「反過來」：雲端拿畫面與主機那一半，我們拿規則引擎那一半），把整合設計裡規則的六批做出來：探索一顆與三道閘與屬性五段（批 2）、出陣約戰（3b）、三陣營四勝利（3c）、隨口應對分岔與痕跡與貢獻（4）、人物心意與託付（6）、列傳為終點的引擎與商品（7b）。每一批一個工作樹、一個 PR 到 `feature/jianfa`，引擎用測試驗完就能交；畫面由雲端側照我們給的欄位表畫。

**Architecture:** 規則全掛在 `Config.jianfa` 的子開關後面（批 0 定欄位名，兩邊用同一個）、開季蓋章；關著一個字都不變。新規則各自一個純規則模組（`explore_one.py`、`growth.py`、`sortie_duel.py`、`wins.py`、`outcomes.py`、`stances.py`、`errands.py`、`zhuan_end.py`【暫名】），`engine.py` 只接線；狀態放 `PlayerState`／`WorldState` 的 JSON 欄位，資料庫結構版本盡量不動（只有列傳商品的 entitlements 種類用現成的表）。模型只做三件事：歸類到清單裡的一個 id、評一個機率、寫字；數字全在引擎，模型回的數字再夾一次。

**Tech Stack:** Python 3（pydantic 模型、SQLite）、FastAPI（`server.py`，只動資料欄位不動畫面）、pytest（`scripts/test_for.py --base origin/feature/jianfa`）。

**Spec:** `docs/superpowers/specs/2026-10-24-減法季-整合設計.md`（企劃者 2026-10-24 四輪定案版；第三、四、五、九、十二、十五章）。分工：雲端側的〈減法季 切工方案〉（企劃者 2026-10-24 轉來的 PDF；重點抄在第一節）。內容初版：`content/events_outcomes.json`（分岔 30 則）、`scripts/check_outcomes.py`。

## Global Constraints

- **開關**：規則改動全掛 `Config.jianfa`（`JianfaRules`，批 0 定；子開關名照整合設計第十二章：`explore_one`、`drill_gates`、`stat_milestones`、`sortie_duel`、`four_wins`、`free_text_outcomes`、`marks_visible`、`stances`、`errands`、`zhuan_end`；批 0 的欄位名跟這裡不一樣時照批 0），開季蓋章 `WorldState.jianfa_on`（整包蓋，不分子開關），`season21`、`week7` 全開、`weekend` 全關；正在跑的季不變。判斷一律走 `jianfa.on(content, world, "<子開關>")`，不要只看設定。**關著一個字都不變**：每一批交貨前拿雲端側批 0 之後的 `feature/jianfa` 當 base，三種季的畫面對照（`tianxia-qa/引擎驗收.md` 第 7 節的做法）逐位元組比。
- **交界**（切工方案「交界與約定」）：我們不動 `web/`、`server_push.py`、`zh.py`；`server.py` 與 `models.py` 兩邊都會改，每批開工先 `git merge --no-ff origin/feature/jianfa`、交貨前再合一次；`engine.py` 雲端側不動。畫面要的資料我們放進 `main_view`／各 API 的回傳（第一節的欄位表），雲端側照表畫；表改了先改這一份再改程式。
- **數字一律寫進 `Config`**（欄位註解標【預設】與出處章節）；玩家看得到的字標「待 joy 潤」；不改 joy 寫好的事件文字（分岔的後果另放 `events_outcomes.json`，批 4 併進 `free_text.outcomes`）。
- **假人看不出來**：假人可以挑後果、挑心意、應約戰、封招、配點，不可以寫字；畫面與戰報一律「某某應戰」，不寫假人、不寫「沒有人防守」；假人應戰的時間在窗內隨機。
- **擲骰用自己的亂數**（`random.Random("用途|名號|流水號")`），不碰 `Game.rng`；約戰結算、假人應戰的時間都是。
- **引擎不讀電腦時鐘**：約戰的窗、冷卻、一天幾次一律用 `Game.now`／`_pill_day`（台灣 00:00 換日）。
- **資料庫**：狀態放 `PlayerState`／`WorldState` 的 JSON；要加表時才升版本（第七批的商品用現成的 `mall_entitlements`、`purchases`，不升）。舊存檔讀得進來：新欄位都有預設值，關著的季 JSON 一個鍵都不多（照 `Game._battle_marks` 的教訓：有值才放）。
- **測試**：`scripts/test_for.py --base origin/feature/jianfa`（先 `git fetch origin +refs/heads/feature/jianfa:refs/remotes/origin/feature/jianfa`），`TIANXIA_DB` 設到 repo 外；新測試超過一秒標 `@pytest.mark.slow`；不改 `tests/conftest.py`，共用的建法放 `tests/jianfa_kit.py`（`jianfa_game(profile="season21", **on)`、`plain_game()`）。用正式內容測舊規則的測試在 helper 裡把 `jianfa` 關掉。
- **規則改了寫進 `docs/guide/`** 那一塊（行動與地盤、戰鬥、武學與成長、核心與存檔、大勢人物與賽季、散人與玩家互動、商城、模型與假人），不寫回 `CLAUDE.md`。
- 每個 Task 一個 commit；一批一個 PR 到 `feature/jianfa`（雲端推不了 `develop`、`main`，合 PR 請 Joy 或主機側按）。

## Review Focus

1. **約戰到時沒人結算**：窗到了伺服器排程收；排程壞了下一個同步的人替它收；兩個程式（`server.py`、`run_bots.py`）輪流同步不重複結算、不倒退（`sortie_duel.settle_due` 只往前走，照 `arena.roll_day` 的教訓）。
2. **兩個真人同時應戰**：行動鎖裡先按的那一位是守方，第二位回「已有人應戰」、次數不扣。
3. **季末只看贏的那一軍的帳**：豪強兩本帳、傾向隨時換、換了帳不清；贏的那一本不到門檻才看輸的那一本；輸的那一軍也有三、四階；兩本都不到沒有。20 人與 2,000 人同一條規則（名次比例）。
4. **分岔歸類的安全**：模型回的 `outcome` 不在清單就一律 `leave`；`chance` 夾在那一種後果自己的範圍；公開的只有後果與痕跡，永遠不公開句子（傳聞、江湖史、戰報、行狀都不寫玩家寫的字）。
5. **45 級之後的經驗來源**：只有打出來的（任何一場仗）才算；事件、感悟、託付、素材拍的經驗 45 之後換心得；升級的每一個地方都走同一個入口。
6. **關著一個字都不變**：三種季的畫面對照、存檔 JSON 鍵數不多。
