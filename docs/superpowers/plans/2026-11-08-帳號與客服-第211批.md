## 三、資料
旁檔 `<db>-support.sqlite`：
- `tickets`(id INTEGER PK, account_id INT, account_created REAL, login TEXT, character TEXT, version TEXT, category TEXT, body TEXT, status TEXT〔open 處理中／answered 已回覆／closed 已結〕, admin_flag INT, created REAL, updated REAL)；索引 (account_id, status)、(account_id, created)。
- `replies`(id INTEGER PK, ticket_id INT, by_account_id INT, staff INT, internal INT, body TEXT, created REAL, seen INT, journaled INT)。
- `login`、`character`、`version` 是設計 6.1「伺服器填」的快照（計畫的欄位表沒寫，補上）。存檔欄位：無。

## 四、路由（`routes.py`；每條第一行 `_gate(request)`：先 `shell._account(request)`〔沒登入 401〕再看開關〔關著 404〕）
| 方法 路徑 | 誰 | 做什麼 |
|---|---|---|
| POST `/api/support/ticket` {category, body} | 玩家 | 白名單、1,000 字、3 張沒結、24 小時 5 張；帳號、名號、時間、版本（`shell.patch_notes()` 第一筆的日期）伺服器填 |
| GET `/api/support/mine` | 玩家 | 自己的單與看得到的回覆（不含 internal）；讀了就把 seen 記上 |
| POST `/api/support/reply` {id, body} | 玩家 | 單號＋帳號＋account_created 都對才行，否則 404 同一句；沒結的才回；狀態回 open |
| GET `/api/support/queue` | 客服 | 沒回的、等玩家、今天新單三數與清單 |
| GET `/api/support/ticket/{id}` | 客服 | 一張單＋全部回覆＋帳號卡（單上已有的） |
| POST `/api/support/answer` {id, body, then: wait\|close\|admin} | 客服 | 回覆並等玩家／回覆並結單／請管理者處理（internal 註記＋admin_flag）；非 internal 的回覆推播一則 |
| POST `/api/support/close` {id} | 客服 | 結單 |
- `_staff(shell, request)`：帳號鍵→(id, 登入名)比名單，不是回 404（跟不存在同一句，不透露有這條路）。
- 推播：`shell.WEB_PUSH` 是 None 跳過；`"support" in push.store.kinds_off(key)` 跳過；`send(key, shell.NOTICE_TITLE, notices.SUPPORT_TEXT, tag="support", now=now)`。
- 節流只有送單的兩個上限（設計沒寫回單上限，不加）。`NO_LOGIN_ROUTES` 不加：沒登入一律 401（開著關著一樣）。
