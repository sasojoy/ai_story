# 《天下大勢》1c-3 招賢 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 門下頁多一個「招賢」分頁：用元寶（測試用的付費貨幣，設定分頁有「測試：領取 1000 元寶」）單抽或十連，機率公開、同品階平均分配，連續 40 抽必得天品、十連至少一名地品以上；新人照入門規則入門，重複的人換成心得，受付費心得護欄限制（每季上限、過半減半、滿了改給銀兩）。元寶與保底計數跨季保留。模擬器多一個付費機器人，量付費與免費的本隊交手勝率，以及免費機器人一季拿到多少心得。派遣（1c-2）不在這一步，也不依賴它。

**Architecture:** 新模組 `tianxia/gacha.py` 管卡池、價格、抽法（品階、十連保底、天品保底）、重複換算與付費心得護欄、江湖紀錄的標記與摘要，以及招賢分頁的文字與結果卡 HTML；新人入門沿用 `roster.recruit`。狀態在 `PlayerState` 加上元寶、保底計數、本季招賢心得與最近一次的結果（`Pull`），`Game.new_season` 把元寶與保底計數帶到下一季。`engine.Game` 多了 `pull(count)`、`grant_yuanbao()` 與招賢分頁的文字轉接；`app.py` 的門下頁分成「名冊・隊伍」「招賢」兩個分頁，設定分頁多一顆測試按鈕。所有數字在 `content/config.json`，其中「暫定・另談」的名稱列在 `provisional`。

**Tech Stack:** Python 3.14、Pydantic 2、Gradio 6.24.0（已 pin）、pytest。

**Spec:** `docs/superpowers/specs/2026-09-29-門下名冊派遣招賢-design.md`——本計畫只做 §零 表格的「1c-3 招賢」：§五、§六.1 的「招賢」分頁、§七 與 §八 裡招賢的部分、§九 的付費機器人與付費／免費勝率、免費機器人一季的心得，以及 §十 的招賢測試。1c-1（名冊與編隊）已完成；1c-2（派遣）還沒做，企劃者選擇先做招賢，本計畫不依賴派遣。

## 計畫層級的裁定（設計文件沒寫死的細節）

1. **新模組 `tianxia/gacha.py`，不塞進 `roster.py`**：`roster.py` 已經三百多行，管名冊、編隊、入門、收徒、招降、福緣與「名冊・隊伍」的文字；招賢有自己的設定、狀態計數、保底與護欄規則、江湖紀錄的標記與整個分頁的文字，是一個完整的單位。它只借用 `roster.recruit` 讓新人照 1c-1 的入門規則入門（入門等級、先列候補、入門那句話）。
2. **「暫定・另談」寫在 config 裡**：JSON 不能寫註解，`Config` 多一個 `provisional: list[str]`，真實內容列出 `duplicate_xinde`、`gacha_single`、`gacha_ten`、`gacha_xinde_cap`、`gacha_xinde_half`、`gacha_silver`；載入時只檢查名稱是 `Config` 的欄位，不影響任何數字。機率、保底抽數、十連保證的品階是設計文件的「預設」，不列進去。
3. **狀態的形狀**：`PlayerState` 加 `yuanbao`（元寶）、`gacha_pity`（連續幾抽沒出天品）、`gacha_xinde`（本季招賢換到的心得）、`gacha_last: list[Pull]`（最近一次的結果，`Pull(character, new, xinde, silver)`）。結果放在存檔裡而不是介面的 `gr.State`：計時器重畫、重新整理頁面、讀檔之後結果卡都還在，也不必把一個新的 State 接進門下頁的每個處理函式。`Game.new_season` 帶過去的只有元寶與保底計數（和 `last_real`、`tutorial_step` 一樣）；本季招賢心得、結果卡、名冊都照舊清空。內容裡已刪掉的人物從 `gacha_last` 移除（`_drop_stale_references`）。
4. **機率與卡池**：`gacha_rates` 是百分比，載入時要求寫齊天地玄黃、不是負的、加起來 100；機率大於 0 的品階卡池裡一定要有人（人物的 `sources` 有「招賢」），天品的機率一定要大於 0（保底要有天品可給）。先擲品階、再在同品階裡平均抽一位。卡池的順序依品階、同品階依內容順序；真實內容是天 1、地 3、玄 4、黃 4 共 12 人，頁面上每人標出單人機率（例如地品每人 4%、玄品每人 8.75%），已入門的人註明「（已入門）」。
5. **十連保底怎麼保**：只看十連的第十抽——前九抽都沒有 `gacha_ten_floor`（地品）以上時，第十抽只在地品以上的品階之間照機率的比例抽（天 3：地 12，也就是天 20%、地 80%）；前九抽已經有了，第十抽照常。這和「第十抽照常抽、低於地品就在地、天之間重抽」的分布完全相同，只是少擲一次亂數。
6. **天品保底**：`gacha_pity` 記連續幾抽沒出天品；這一抽如果是連續第 40 抽（`gacha_pity + 1 ≥ 40`）就直接是天品、不擲品階。任何天品（保底給的、運氣抽到的、十連保底抽到的）都把計數歸零；十連保底給的地品照樣加一。兩種保底各自計算：保底在十連中途給了天品，十連的「至少一名地品以上」也就滿足了，第十抽照常抽。頁面寫「再 N 抽必得天品」，N＝40 − 計數（至少 1）。
7. **亂數**：每一抽用 `Game.rng` 擲一次品階（保底時不擲）、再用一次挑人。抽不成（元寶不足、賽季已落幕、不是 1 或 10 抽）時什麼都不動、不用亂數、不寫江湖紀錄，只回傳原因。
8. **同一次十連抽到同一位新人兩次**：一抽一抽依序處理，第一次入門，第二次就算重複、換成心得。
9. **付費心得護欄的算法**：看這一個重複之前的本季招賢心得——不到 `gacha_xinde_half`（150）照表給（黃 10、玄 20、地 50、天 100）；到了 150（含）之後給一半（無條件捨去）；最多補到 `gacha_xinde_cap`（300）為止，補不滿一整份的餘額不另外換銀兩；已經滿 300 的重複改給 `gacha_silver`（黃 10、玄 20、地 50、天 100）的銀兩。所以跨過 150 的那一個重複照給整份（例如 140 時抽到重複天品 → 240）。只有招賢換到的心得算進 `gacha_xinde`；1c-1 劇情事件結識到已入門的人換到的心得不算（`roster.recruit` 不動它）。設計文件的第 3 層「境界上限」等 1b 的境界系統再接，這次不做；第 4 層「只在當季有效」本來就成立（心得與 `gacha_xinde` 隨新賽季清空）。
10. **賽季落幕後不能抽**：名冊馬上就要清空，抽了等於白花元寶；按鈕寫「單抽（賽季已落幕）」且按不下去。閉關中、事件進行中照樣可以抽（招賢不花體力、不動時間，和其他門下操作一樣）。
11. **江湖紀錄**：一次單抽或十連寫一則，標題「招賢・單抽」「招賢・十連」；結果標記點名一位「得地品【陸沉舟】」——品階最高的那一位，同品階時新入門優先，再來是先抽到的；敘事一抽一句（新人是 1c-1 的入門那句「【陸沉舟】入門（地品・剛・統御 5），從第 1 級練起，先列候補。」，重複是「【阿棠】（黃品）重複 → 心得 +10」，減半、補到上限、改給銀兩時句尾註明原因）；數值變化是「元寶 -1000」「心得 +70」「銀兩 +20」（同標籤加總）。測試按鈕寫一則「測試：領取元寶」，只有「元寶 +1000」。
12. **門下頁**：上方兩個分頁，1c-1 做好的一切原封不動放進「名冊・隊伍」。「招賢」分頁左邊是一行「元寶 1000　｜　再 40 抽必得天品　｜　本季招賢心得 0／300」、一行測試元寶的說明、「單抽」「十連」兩顆按鈕（元寶不足時按不下去並寫「十連（元寶不足，要 1000）」）、抽完的摘要「十連：新入門 7 人，重複 3 人（心得 +50）。」、「最近一次的結果」一排結果卡；右邊是公開的機率、保底、重複換算與卡池。結果卡用一個 `gr.HTML` 排（彈性換行，手機寬度也不會橫向捲動），品階只用左邊的色條區分。動作結果的顯示位置從「換人或不是」兩處改成三處（`render_menxia(..., note=...)`：`skill`／`swap`／`gacha`），寫一處就清掉另外兩處，規則和 1c-1 相同。右欄的狀態不顯示元寶（元寶只用在招賢分頁，數字在分頁上與江湖紀錄裡）。
13. **付費機器人**：`play_season(..., yuanbao=N)` 開季先把元寶加進去，能十連就十連、零頭單抽（`bot.spend_yuanbao`），接著花掉換來的心得、把本隊排成統御上限內最強的組合，其餘和免費機器人完全一樣（1c-1 的最後裁定：收徒只在名冊塞不滿已開放的隊伍、而且付得起下一次時收；結識一律接受；本隊看四項屬性加總）。`play_season` 在第一步之前多呼叫一次 `observe`（開季的樣子，付費機器人已經抽完、排好），既有的名冊人數統計不受影響（後面的觀察會蓋過去）。
14. **模擬怎麼量**：（一）「整季拿到的心得」＝季末餘額＋花在精進上的心得（機器人從不散功，內容裡也沒有扣心得的事件，所以這就是總收入；不必在狀態裡另外記）。（二）交手：同一個種子各跑一季免費與付費，取三個時間點的狀態深拷貝——開季＝付費機器人抽完、排好、還沒走第一步；第二幕、第三幕＝那一季第一次到達（看 `act_reached`，主線改寫不會讓它倒退）；那一季沒到就用季末的樣子，並印出有幾季是這樣。兩邊的本隊內力全滿打 40 場，一半付費方列在前面、一半免費方列在前面（同速時列在前面的先出手），平手不算勝。設計文件的目標（≤70%／≤60%／≤55%）只印在旁邊對照，**測試不檢查**：經濟數字還沒談定。
15. **模擬器舊註解**：`CHECKPOINTS` 的註解原本寫「設計草稿的目標：……季末 10～12 人」，改成說明機器人的收徒策略（名冊塞滿已開放的隊伍就不再收：第一幕 6、第二幕 9、第三幕 12 人），所以印出的人數反映的是策略，不是規則的上限。
16. **量到的數字**（撰寫計畫時，30 季，Task 4 Step 7）：免費機器人整季拿到的心得平均 200（最少 84、最多 308）——付費心得上限 300 比免費機器人一整季的平均總收入還高。付費方勝率（開季／第二幕／第三幕）：1000 元寶 90%／70%／67%（第三幕有 1 季至少一邊沒到，用季末）；3000 元寶 99%／80%／64%；10000 元寶 100%／91%／76%（目標 70%／60%／55%）。付費機器人的本季招賢心得平均：1000 元寶 55、3000 元寶 254、10000 元寶 300。這些數字留給「招賢的經濟數字另談」時參考。

之後減半、補到 gacha_xinde_cap 為止，之後改給銀兩（gacha_silver）。境界上限（設計文件 1c §5.6 第 3 層）
等 1b 的境界系統再接。價格、重複換算與護欄的數字都是暫定・另談，全在 config。
亂數只在真的抽的時候用（Game.rng），看頁面、按不下去都不動亂數。
"""
from __future__ import annotations

import random

from . import roster
from .models import COMPANION_TIERS, Content
from .state import GameState, Pull

SINGLE, TEN = 1, 10  # 單抽、十連
TOP = COMPANION_TIERS[0]  # 保底必得的品階（天品）


def pool(content: Content) -> dict[str, list[str]]:
    """卡池：品階 → 人物 id（依內容順序）；只列有人的品階，依天地玄黃排。"""
    found = {
        tier: [cid for cid, ch in content.characters.items() if ch.tier == tier and "招賢" in ch.sources]
        for tier in COMPANION_TIERS
    }
    return {tier: ids for tier, ids in found.items() if ids}


def label(count: int) -> str:
    return "單抽" if count == SINGLE else "十連"


def cost(content: Content, count: int) -> int:
    return content.config.gacha_single if count == SINGLE else content.config.gacha_ten


def block(state: GameState, content: Content, count: int) -> str:
    """抽不成的原因（「元寶不足，要 1000」「賽季已落幕」）；抽得成時是空字串。"""
    if count not in (SINGLE, TEN):
        return "沒有這種抽法"
    if state.world.ended:
        return "賽季已落幕"
    price = cost(content, count)
    if state.player.yuanbao < price:
        return f"元寶不足，要 {price}"
    return ""


def floor_tiers(content: Content) -> list[str]:
    """十連保證的品階：config.gacha_ten_floor 與比它高的（預設是天、地）。"""
    return list(COMPANION_TIERS[: COMPANION_TIERS.index(content.config.gacha_ten_floor) + 1])


def roll_tier(state: GameState, content: Content, rng: random.Random, floor: bool = False) -> str:
    """這一抽的品階。保底到了（這是連續第 gacha_pity 抽沒出天品）就是天品，不用亂數；
    floor（十連的最後一抽，前九抽都沒有地品以上）時只在 floor_tiers 之間照機率的比例抽（預設天 3：地 12）；
    其餘照 config.gacha_rates。"""
    cfg = content.config
    if state.player.gacha_pity + 1 >= cfg.gacha_pity:
        return TOP
    tiers = floor_tiers(content) if floor else list(COMPANION_TIERS)
    return rng.choices(tiers, weights=[cfg.gacha_rates[t] for t in tiers])[0]


def pull(state: GameState, content: Content, rng: random.Random, count: int) -> list[str]:
    """招賢 count 抽（呼叫前已確認 block 是空字串）：扣元寶，一抽一抽依序抽品階、再在同品階裡平均抽一位；
    新人入門，已入門的人換成心得或銀兩（同一次十連抽到同一位新人兩次，第二次就算重複）。
    結果依序記在 PlayerState.gacha_last。回傳江湖紀錄用的訊息：「元寶 -1000」、每一抽一句，
    以及每筆心得、銀兩（紀錄裡會加總成一項）。"""
    p = state.player
    price = cost(content, count)
    p.yuanbao -= price
    msgs = [f"元寶 -{price}"]
    pulls: list[Pull] = []
    drawable, floor = pool(content), floor_tiers(content)
    for i in range(count):
        short = count == TEN and i == TEN - 1 and all(content.characters[x.character].tier not in floor for x in pulls)
        tier = roll_tier(state, content, rng, floor=short)
        cid = rng.choice(drawable[tier])
        p.gacha_pity = 0 if tier == TOP else p.gacha_pity + 1
        if cid in p.members:
            result, lines = _duplicate(state, content, cid)
        else:
            result, lines = Pull(character=cid, new=True), roster.recruit(state, content, cid)
        pulls.append(result)
        msgs += lines
    p.gacha_last = pulls
    return msgs


def _duplicate(state: GameState, content: Content, cid: str) -> tuple[Pull, list[str]]:
    """抽到已入門的人：照 config.duplicate_xinde 換成心得，受付費心得護欄限制——本季招賢心得到了 gacha_xinde_half
    之後減半、最多補到 gacha_xinde_cap；已經滿了就改給 gacha_silver 的銀兩。"""
    cfg, p = content.config, state.player
    ch = content.characters[cid]
    head = f"【{ch.name}】（{ch.tier}品）重複"
    got = p.gacha_xinde
    if got >= cfg.gacha_xinde_cap:
        silver = cfg.gacha_silver[ch.tier]
        p.stats["silver"] = p.stats.get("silver", 0) + silver
        note = f"（本季招賢心得已滿 {cfg.gacha_xinde_cap}）"
        return Pull(character=cid, new=False, silver=silver), [f"{head} → 銀兩 +{silver}{note}", f"銀兩 +{silver}"]
    amount, note = cfg.duplicate_xinde[ch.tier], ""
    if got >= cfg.gacha_xinde_half:
        amount, note = amount // 2, f"（本季招賢心得已達 {cfg.gacha_xinde_half}，減半）"
    if amount > cfg.gacha_xinde_cap - got:
        amount, note = cfg.gacha_xinde_cap - got, f"（補到本季上限 {cfg.gacha_xinde_cap}）"
    p.gacha_xinde += amount
    p.stats["xinde"] = p.stats.get("xinde", 0) + amount
    return Pull(character=cid, new=False, xinde=amount), [f"{head} → 心得 +{amount}{note}", f"心得 +{amount}"]
```

# ── 江湖紀錄與摘要 ─────────────────────────────────────────


def tag(content: Content, pulls: list[Pull]) -> str:
    """江湖紀錄的結果標記，點名品階最高的那一位（同品階時新入門優先，再來是先抽到的），例如「得地品【陸沉舟】」。"""
    order = {tier: i for i, tier in enumerate(COMPANION_TIERS)}
    best = min(pulls, key=lambda x: (order[content.characters[x.character].tier], not x.new))
    ch = content.characters[best.character]
    return f"得{ch.tier}品【{ch.name}】"


def summary(pulls: list[Pull], count: int) -> str:
    """抽完顯示在招賢分頁的一句話，例如「十連：新入門 2 人，重複 8 人（心得 +70）。」"""
    new = sum(x.new for x in pulls)
    parts = [f"新入門 {new} 人"] if new else []
    if len(pulls) > new:
        totals = (("心得", sum(x.xinde for x in pulls)), ("銀兩", sum(x.silver for x in pulls)))
        gains = "、".join(f"{name} +{amount}" for name, amount in totals if amount)
        parts.append(f"重複 {len(pulls) - new} 人" + (f"（{gains}）" if gains else ""))
    return f"{label(count)}：{'，'.join(parts)}。"
```

```python
"""平衡模擬：讓亂數機器人玩完整季，統計結局、大勢發展、名冊的成長與整季拿到的心得；
給了元寶時另跑一組付費機器人（開季先把元寶花在招賢），量兩邊本隊交手的勝率。

用法：.venv/Scripts/python.exe scripts/simulate.py 30          （免費機器人 30 季）
      .venv/Scripts/python.exe scripts/simulate.py 30 3000     （再加上開季先花 3000 元寶招賢的付費機器人）
"""
import random
import sys
from collections import Counter
from pathlib import Path

ROOT = Path(__file__).resolve().parent.parent
sys.path.insert(0, str(ROOT))

from tianxia import team  # noqa: E402
from tianxia.battle import run_battle  # noqa: E402
from tianxia.bot import play_season  # noqa: E402
from tianxia.content import load_content  # noqa: E402
from tianxia.models import COMPANION_TIERS  # noqa: E402
from tianxia.rules import DAY, current_day  # noqa: E402
from tianxia.state import PLAYER  # noqa: E402

# 看第幾天結束時的名冊人數。設計草稿的新手目標是第 1 天 3 人、第 3 天 6 人、季末 10～12 人；但機器人只在名冊（含你）
# 還塞不滿已開放的隊伍（第一幕 6 人、第二幕 9 人、第三幕 12 人）、而且付完還付得起下一次時才收徒，結識、福緣、招降
# 則一律接受，所以這裡的人數反映的是這套策略，不是遊戲規則的上限。
CHECKPOINTS = (1, 3, 7)
# 付費方與免費方本隊交手的時間點（看 act_reached）：開季＝招賢之後、第一步之前；第二幕、第三幕＝那一季第一次到達時。
# 那一季沒到就用季末的樣子。後面是設計文件 1c §九的目標：付費方勝率不超過這個數。
DUEL_POINTS = {0: ("開季", 0.70), 1: ("第二幕", 0.60), 2: ("第三幕", 0.55)}
DUEL_RUNS = 40  # 每一對交手幾場（內力全滿）：一半付費方列在前面、一半免費方列在前面（同速時列在前面的先出手）


def xinde_earned(game) -> int:
    """這一季拿到的心得（不是餘額）：餘額加上花在精進上的。機器人從不散功、內容裡也沒有扣心得的事件，
    所以這就是整季的總收入（歷練、劇情、新手引導、重複結識，付費機器人另有招賢）。"""
    p, c = game.state.player, game.content
    levels = list(p.skills.values()) + [m.innate_level for key, m in p.members.items() if key != PLAYER]
    return p.stats.get("xinde", 0) + sum(team.upgrade_cost(c, n) for level in levels for n in range(1, level))


def play(content, runs: int, yuanbao: int = 0) -> dict:
    """runs 季，回傳統計；snaps[i][幕] 是第 i 季在那個時間點的狀態（深拷貝），reached[i] 是第 i 季真的到過的幕。"""
    stats = {
        "endings": Counter(), "thresholds": Counter(), "storylines": Counter(), "days": [], "events": [],
        "sizes": {day: [] for day in CHECKPOINTS}, "final_sizes": [], "final_tiers": Counter(),
        "xinde": [], "gacha_xinde": [], "snaps": [], "reached": [],
    }
    for seed in range(runs):
        seen: dict[int, int] = {}
        snaps: dict[int, object] = {}

        def observe(game, seen=seen, snaps=snaps) -> None:
            today = current_day(game.state)
            for day in CHECKPOINTS:
                if today <= day:
                    seen[day] = len(game.state.player.members)
            for act in DUEL_POINTS:
                if act not in snaps and game.state.world.act_reached >= act:
                    snaps[act] = game.state.model_copy(deep=True)

        game = play_season(content, seed, observe=observe, yuanbao=yuanbao)
        world, p = game.state.world, game.state.player
        stats["endings"][world.ending_title] += 1
        stats["thresholds"].update(world.fired_thresholds)
        stats["storylines"][world.storyline] += 1
        stats["days"].append(world.time / DAY)
        stats["events"].append(len(p.seen_events))
        for day in CHECKPOINTS:
            stats["sizes"][day].append(seen.get(day, len(p.members)))
        stats["final_sizes"].append(len(p.members))
        stats["final_tiers"].update(content.characters[key].tier for key in p.members if key != PLAYER)
        stats["xinde"].append(xinde_earned(game))
        stats["gacha_xinde"].append(p.gacha_xinde)
        stats["reached"].append(set(snaps))
        for act in DUEL_POINTS:
            snaps.setdefault(act, game.state.model_copy(deep=True))
        stats["snaps"].append(snaps)
    return stats


def duel(paid, free, content, seed: int) -> tuple[int, int]:
    """付費方與免費方的本隊（內力全滿）打 DUEL_RUNS 場，回傳（付費方勝場, 平手場）。"""
    rules, rng = team.battle_rules(content), random.Random(seed)
    wins = draws = 0
    for i in range(DUEL_RUNS):
        for state in (paid, free):
            for member in state.player.members.values():
                member.neili = None
        ours, theirs = team.team_units(paid, content), team.team_units(free, content)
        if i % 2 == 0:
            outcome = run_battle(ours, theirs, rng, rules).outcome
        else:
            outcome = {"win": "lose", "lose": "win", "draw": "draw"}[run_battle(theirs, ours, rng, rules).outcome]
        wins += outcome == "win"
        draws += outcome == "draw"
    return wins, draws


def report(title: str, stats: dict, runs: int) -> None:
    print(title)
    print("結局：", dict(stats["endings"]))
    print("門檻觸發次數：", dict(stats["thresholds"]))
    print("最終主線：", dict(stats["storylines"]))
    print(f"平均季長 {sum(stats['days']) / runs:.1f} 天；平均遇到 {sum(stats['events']) / runs:.1f} 種事件")
    sizes, final = stats["sizes"], stats["final_sizes"]
    counts = "　".join(f"第{day}天 {sum(sizes[day]) / runs:.1f}" for day in CHECKPOINTS)
    print(f"名冊人數（含你本人，平均）：{counts}　季末 {sum(final) / runs:.1f}（最少 {min(final)}、最多 {max(final)}）")
    tiers = stats["final_tiers"]
    print("季末品階（每季平均幾人）：" + "　".join(f"{tier} {tiers[tier] / runs:.1f}" for tier in COMPANION_TIERS))
    xinde = stats["xinde"]
    gacha = f"，其中招賢 {sum(stats['gacha_xinde']) / runs:.0f}" if any(stats["gacha_xinde"]) else ""
    print(f"整季拿到的心得（不是餘額）：平均 {sum(xinde) / runs:.0f}{gacha}（最少 {min(xinde)}、最多 {max(xinde)}）")


def main(runs: int, yuanbao: int) -> None:
    content = load_content(ROOT / "content")
    free = play(content, runs)
    report(f"模擬 {runs} 季（免費機器人）", free, runs)
    if not yuanbao:
        return
    paid = play(content, runs, yuanbao)
    print()
    report(f"付費機器人：開季先花 {yuanbao} 元寶招賢", paid, runs)
    print()
    print(f"付費方本隊對免費方本隊（同一個種子的兩季，每一對 {DUEL_RUNS} 場，內力全滿）：")
    for act, (name, target) in DUEL_POINTS.items():
        wins = draws = 0
        for seed in range(runs):
            w, d = duel(paid["snaps"][seed][act], free["snaps"][seed][act], content, seed)
            wins, draws = wins + w, draws + d
        total = runs * DUEL_RUNS
        missing = sum(act not in paid["reached"][seed] or act not in free["reached"][seed] for seed in range(runs))
        note = f"；{missing} 季至少一邊沒到，用季末" if missing else ""
        print(f"  {name}：付費方勝 {wins / total:.0%}、平 {draws / total:.0%}（目標 ≤ {target:.0%}{note}）")


if __name__ == "__main__":
    main(int(sys.argv[1]) if len(sys.argv) > 1 else 20, int(sys.argv[2]) if len(sys.argv) > 2 else 0)
```
