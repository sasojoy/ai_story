# T5 晉升（第 1、2 階）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 投靠的人有頭銜（官軍・鄉勇／黃巾軍・信眾／地方豪強・鄉里子弟）；本季為陣營累積的貢獻到 300，收到召見（「皇甫嵩召你到長社營中」）；走到那裡演完第 2 階的晉升奇遇（三個選項都晉升，差在情誼與小獎勵），頭銜升為屯長／小帥／宗族頭人，帶回兩名部下，部下算進遊歷與挑戰的威力；升第 2 階的人每天彙整成一則陣營軍情。另外收兩件 T4 的尾巴：挑戰本人照求見的同一套條件擋掉還沒到任的人物，`figures.defeat` 的兩句換成 S1 審過的版本。全部掛在第一季開關後面。

**Architecture:** 新模組 `tianxia/ranks.py`（頭銜、召見、晉升、部下、每日彙整）。內容在新檔 `content/promotions.json`、`content/followers.json`、`content/events/promotion.json`，`content/skills.json` 加六門部下的武學。召見在每次行動之後檢查（`Game.choose`、`Game.sync` 的最後），所以不管貢獻從哪裡來（推大勢、挑戰打贏、伏筆、護糧）都接得到——T4 交接備註第 1 條要的就是這個。晉升奇遇由引擎直接端出（`act:summons`，或在召見的地點探索、交友），不走隨機抽選。部下是 `PlayerState.followers` 裡的模板 id，打仗時照模板建成威力貢獻者，接在 `team.team_participants` 後面。

**Tech Stack:** Python 3.14、pydantic、FastAPI、原生 JavaScript、pytest。

## Global Constraints

- 開關：一律 `rules.season_one(content, world)`。開關關著（或沒蓋章的 beta 季）時：沒有頭銜（狀態列照舊「門派・陣營」或「散人」）、不發召見、沒有 `act:summons`、探索交友照舊、部下不存在、挑戰選項照 T4（beta 本來就沒有挑戰）。
- 部下不能對話、不能散功、不進同伴名冊（它們不是 `characters.json` 的人物），只算威力；不扣氣血、不吃經驗（這一版的簡化）。
- 召見沒有期限；召見之後貢獻照樣累積；同一階只發一次（`PlayerState.summons` 有值就不再發）。
- 出面的人：召見地點此刻在場（`figures.present_at`）的主版人物優先，不在就換接手的人（演接手版）；兩個都不在，仍演接手版（內容只寫了兩版）。發召見那一刻寫出的名字照當下，到了現場照當下再挑一次（晉升文件第一節「召見發出後人物才不在的，召見自動改由接手的人發」）。
- 豪強的 `nearest_base`：發召見時照路網，挑離玩家所在最近的豪強投靠點（`atlas.shortest_routes`）。
- 每日彙整：升第 2 階的人記在 `WorldState.promoted_today`，過了那個曆日由季的事（`world.season_hour`）發一則陣營軍情「昨日升為屯長的有：甲、乙。」；收季時把還沒發的一起發掉。傳聞只能新增不能改（`sqlite_world` 的傳聞是只寫入一次），所以不能在當下發了再改。
- 情誼增減走新的 `Effect.affinity`（人物 id → 增減，夾在 0～100，訊息「皇甫嵩情誼 +10」）。
- 文字：選項、反應、召見、場景、結尾照內容表 2.2、2.3 原文（S1 審過）；事件放在 `content/events/promotion.json`，事件文字之後若 joy 要潤飾，走她的 PR。
- 每個任務做完全套都要過；畫面的東西 375×812 看過。

4. **部下讓勝算變好但不吃傷**：遊歷打完氣血只扣本人與同伴，部下不在 `take_encounter_toll` 的名單裡；勝算的估計照樣算部下（Task 4 `test_followers_add_power_and_take_no_toll`）。
5. **換季**：新的一季頭銜、召見、部下都重來（新角色），引導照 T6 的規則（Task 2 `test_new_season_resets_rank_summons_and_followers`）。

## 與總計畫不同的地方（回報 PM 時一起講）

1. **不加 `Condition.rank_min／rank_max／summoned_rank`**：晉升奇遇由引擎直接端出（`act:summons`、或在召見地點探索交友），不走事件抽選，用不到這三個條件。
2. **`Config.followers_by_rank` 不加**：部下照選項的 `effect.followers` 給（內容表 2.3 每個選項都寫了兩個模板）。
3. **召見文字與結尾放在 `promotions.json`**（`summons_text`、`summons_handoff`、`closing`），事件檔只放場景與選項。
4. **每日彙整延到隔天發**（傳聞只能新增不能改），收季時把剩下的發掉。
5. **`Effect.affinity` 是新欄位**（以前事件不能改情誼）。
6. **出面人物兩個都不在時仍演接手版**（內容只有兩版）。
