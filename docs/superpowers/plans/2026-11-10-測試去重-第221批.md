## 一、換成 `real_content()`（`from conftest import real_content`；engine 那條 `classic_rules(real_content())`）

`real_content(profile)` 每次給一份 pickle 複本，改它不會漏出去；所以「載入後改欄位再 `validate`」「同一條載兩份」都照換（兩次各叫一次）。
沒被換的判準：那條或它的 fixture patch 了載入路徑（`content`／`load_content`／`validate`／`_locate`／設定覆寫檔／`ADMINS_FILE`），或抄一份資料夾改檔再載。下面清單裡的 patch 全是事後換 `server.CONTENT`、`server.PROFILE`、`uvicorn.run`、`sim.MAX_REAL_DAYS`、`tempfile.tempdir`、`sys.stdout`，不碰載入，照換。
換完那一檔若 `load_content`／`CONTENT_DIR`／`ROOT`／`Path` 沒人用了就拿掉那個 import／常數；還有人用就留著。

## 二、`tests/server/test_set_password.py`（S1）

`scripts/set_password.py:22` 是模組層 `from tianxia.content import ... load_content`，第 48 行叫模組層的名字（只有 `--character` 或有 identity 金鑰才讀），
所以 `monkeypatch.setattr(set_password, "load_content", ...)` 打得到（`_identity_on` 與 158 行已經這樣用）。
做法：檔裡加一個 autouse fixture（`request`, `monkeypatch`, `content`），`request.node.name` 是 `test_a_character_it_creates_gets_the_same_profile_as_the_server` 就不套，
其餘 `monkeypatch.setattr(set_password, "load_content", lambda *a, **k: content)`。已經自己 patch 的兩條（`_identity_on`、158）後 patch 蓋前 patch，不用動。
坑：腳本照 `serving_profile()`（沒設是 season21）印 `profile_line(content, "season21")`、`identity_base.on(content)` 判 12 字：除了 profile 那條沒有一條斷言設定那一行；
跑一次確認 11 條全綠，紅了就那一條不套、寫進回報。autouse 跟測試自己要的 `content` 是同一份（同一個 function 範圍的 fixture），腳本另建的角色名字不同，不互相干擾。
