大的那一條（:77-112，留 `@pytest.mark.slow`、留 20000 筆×1000 字、測試名不改、docstring 可補一句新判準）：
- 拿掉 20 秒 `deadline`。writer 只看 `stop`；另留保險期限 `time.monotonic() + 120`（註明只防測試自己卡死，不是判準）。
- writer 整段包 `try/except Exception as e: errors.append(e)`，`finally` 關連線；每次 commit 後 `commits += 1`（用一格 list 或小物件）並 `set()` 一個 `Event` 讓主執行緒等得到「又 commit 了」。
- 主執行緒：先等第一筆 commit（Event wait，逾時 10 秒），取代 `time.sleep(0.2)`。
- backup 呼叫用 try/except 收例外（存起來，不在 try 裡斷）。backup 回來的那一刻記 `n = commits`、`alive = thread.is_alive()`，清掉 Event，再等「commits > n」（輪詢 Event，總逾時 10 秒），記 `kept_writing`；然後 `stop.set()`、`join()`。
- 斷言順序（訊息照派工單）：
  1. `not errors` — 「寫入的那一邊被鎖死」＋例外內容。
  2. 備份沒丟例外 — 「備份被擋」＋例外內容。
  3. `alive and kept_writing` — 訊息也以「備份被擋」開頭：「備份是等寫入停了才做完的」。**不比備份期間 commit 幾次**。
  4. `integrity_check`（verify 已做）、`verify(out)["characters"] == 2`、備份檔 chronicle 筆數 ≥ 20000＋插入前的筆數（插入前先數一次 live 庫的 chronicle，不假設是 0）。
- 結構護欄（主力）：monkeypatch `backup_db.sqlite3` 換成一個 `types.ModuleType` 殼——`__getattr__` 全轉給真的 `sqlite3`（`Error`、`DatabaseError` 等照用），只蓋 `connect`：照原參數加 `factory=_Guarded` 呼叫真的 `sqlite3.connect`。`_Guarded(sqlite3.Connection)` 的 `backup(self, target, *, pages=-1, **kw)`：`pages > 0` 時**當場** `raise AssertionError("護欄：備份改回分步複製（pages=…）…")`，否則 `super().backup(target, pages=pages, **kw)`；另記一筆呼叫次數，斷言最後 ==1（確定護欄真的有攔到那一下）。
  - 為什麼當場丟：`backup_db.backup` 只接 `sqlite3.Error`／`OSError`，AssertionError 會直接穿出來，回歸時測試幾毫秒就紅，不必等 120 秒。主執行緒的 except 收例外時要讓 AssertionError 照樣往外丟（或另外判斷）——護欄紅要紅在護欄那一句，不是被吞成「備份被擋」。
  - 只 patch `backup_db.sqlite3` 這個名字（monkeypatch.setattr(backup_db, "sqlite3", shim)），不動全域 `sqlite3`：writer 執行緒用的是測試檔自己的 `sqlite3`，不受影響。`restore_db` 不受影響。
- 小的那一條（:52-74）：writer 同樣包 try/except 收 `errors`（finally 關連線）；`join` 之後**先**斷 `not errors`（「寫入的那一邊被鎖死」），再照舊斷 verify。其餘不動、不加護欄。
