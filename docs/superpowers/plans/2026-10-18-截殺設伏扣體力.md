# 截殺、設伏讓輸的人扣體力：開發計劃

- 日期：2026-10-18
- 狀態：企劃者 10/18 要求直接寫開發計劃；【PM】【預設】【待企劃者】標記同正式季整合
- 來源：企劃者 10/17 清單第 33 條「截殺 設伏 是不是要扣到玩家體力才會有感」
- 分支：從 `develop` 開 `feature/raid-stamina`（獨立的一份，不接在正式季哪一批後面）

## 零、一句話

截殺、設伏分出勝負時，輸的那一方另扣一筆體力（【預設】截殺 15、設伏 20），被截的人下線也照扣；確認句、戰報、江湖紀錄寫出扣了多少。

## 一、現在的程式

- 截殺：`Game.raid`（`tianxia/engine.py:8013`）先 `raid_refusal`，發起的人 `me.stamina -= cfg.stamina`（8024），記冷卻（8025-8026），擲策馬脫身（8028-8030，跑掉了走 `_raid_fled` 8061，不打、誰都不失），打一場，`winner._raid_spoils(loser, …)`（8044）。平手 `spoils` 是 None。
- `_raid_spoils`（8091）：輸的扣銀兩、扣氣血（`team._apply_toll`，8103），回 `RaidSpoils`（`engine.py:204`：winner、lost、taken、hp、contrib、goods、evil）。
- `_raid_record`（8109 起）：輸的那一邊 `record.changes.append(f"氣血 -{spoils.hp}")`（8140-8141）；`msgs` 由 `battlelog.gains_list(record)` 組（8150），發起的人前面插 `體力 -{cfg.stamina}`（8151-8152）。戰報與江湖紀錄共用這一份。
- 截殺鈕的確認句：`tianxia/raid.py:25`「真的要對{name}下手？輸了要丟銀兩、掉氣血。」
- 設伏：`Game._ambush_check`（`engine.py:8330`）→ `_ambush_fight`（8364）。路過的人是 self（在自己的 sync／travel 裡），伏兵 `owner` 是 `_load_kin` 讀的別人的存檔（8357），最後 `_save_kin(owner)`（8398）。`_ambush_spoils`（8401）同截殺扣銀兩、素材、氣血（8429）；`_ambush_record`（8434 起）輸的那一邊寫 `氣血 -N`。
- 設定：`Raid`（`tianxia/models.py:1711`，`stamina` 10、`hp_loss` 0.08…）；`AmbushRules`（`models.py:2327`，`stamina` 80、`hp_loss` 0.1…）。正式內容 `content/config.json:109` 只寫了 `"ambush": {"enabled": false}`，沒寫 `raid`；測試內容 `tests/fixtures/content/config.json:22` 同樣只有 ambush。
- 體力回復是增量算的：`sync` 照 `now - state.last_real` 叫 `_advance_player_local`（`engine.py:806-812`），那裡 `p.stamina = min(stamina_max, p.stamina + regen)`（965-972；新手期倍數、承露 `treasures.amount(…, "stamina_regen")`）。
- `_kin`（`engine.py:10259`）明寫「不補算他的時間」：別人的那一份 `stamina` 是他上次同步時的值。

## 二、設計決定

### 2.1 扣多少、扣誰
- 輸的一方另扣體力：截殺 `Raid.loser_stamina`【預設】15、設伏 `AmbushRules.loser_stamina`【預設】20。【PM】
- 「輸的一方」照現在的 `winner/loser` 判：截殺發起的人輸了也扣（他已經先付了 10，再扣 15）；伏兵輸了也扣（他設伏付過 80，再扣 20）。【PM】
- 平手、策馬脫身不扣。贏的一方不扣。【PM】
- 不扣到 0 以下：實扣 `min(設定值, 他此刻的體力)` 取整；實扣 0 時不寫那一行。【PM】
- 新手期、城鎮、冷卻、護身、截殺的緊急開關都照舊（輸贏之前就擋掉了，不必另寫）。
- 依據【PM】：截殺發起 10、遊歷 6；扣 15 約兩三下遊歷、現實 45 分鐘的回復（3 分鐘 1 點）。設伏一下 80、劫一場搶 40 兩，輸的扣 20 比截殺重一截，跟它本身就比截殺大一號對齊。護身 1 小時之內不會再被截，一小時最多被扣一次 15，回得比扣得快（一小時回 20）。

### 2.2 下線的人「照扣」怎麼算【PM】
- 只扣存檔裡的值不夠：他上次同步時是 240，下線久了本來就會回滿 250，扣成 225 再回也是回滿，等於沒扣。
- 做法：先算「他此刻該有多少」＝ `min(上限, 存的 + 從 last_real 到 now 的回復)`，從這個數扣，再把存的值寫成「扣完的數 − 那段回復」。他下次同步照舊加回那段回復，看到的正好是扣完的數，之後照常回。存的值可能暫時是負的，只有他自己同步之前存在資料庫裡；回復公式本來就是加完再夾上限，不必改。
- 回復怎麼算抽成一個函式，`_advance_player_local` 與這裡共用，不寫第二份（新手期倍數、承露都照算）。
- 在線、正在自己請求裡的人（設伏路過的 self 在 sync 裡）`last_real == now`，回復是 0，同一條公式就對。

### 2.3 玩家看得到什麼（字都待 joy 潤）
- 截殺鈕的確認句：開著時寫「真的要對{name}下手？輸了要丟銀兩、掉氣血，還要耗 {n} 體力。」（`n` 照 `loser_stamina`；0 時照舊那一句）。
- 設伏鈕沒有確認句，不加。設伏的說明（`ambush.py` 檔頭與 `SET_LABEL` 旁有說明句的地方）若有寫輸了賠什麼，補「體力」兩個字；沒有就不加。【PM】
- 戰報「得失」與江湖紀錄：輸的那一邊在 `氣血 -N` 後面多一格 `體力 -N`（`record.changes`，`gains_list` 自然帶進紀錄）。發起的人輸了，紀錄裡會有兩行體力（前面付的 `體力 -10` 與輸了的 `體力 -15`）：付的那一行改寫成「出手 體力 -10」以免看起來重複【PM】。
- 被截的人下線：照舊在他下次同步時讀到那一則「遭X截殺」，裡面就有 `體力 -15`；體力條直接是扣完的數。

### 2.4 開關
- `loser_stamina` 預設 0（`models.py` 的預設＝關，關著一個字都不變）；正式內容 `content/config.json` 寫 `"raid": {"loser_stamina": 15}`、`"ambush"` 加 `"loser_stamina": 20`。測試內容不寫＝0＝關，`tests/fixtures/` 不動（不必跑整套）。
- 設伏整個在正式內容關著（`ambush.enabled` false），所以正式內容上線時實際只有截殺會扣；設伏那一半等設伏打開才看得到。

### 2.5 跟其他系統的接縫
- 整合設計 7.5 寫「截殺照舊【定】」（企劃者 10/16，21 天季不改截殺）；這一份是企劃者 10/17 清單第 33 條另外提的，只加輸家扣體力，不改 7.5 列的任何一樣（勝負、新手期、冷卻、護身、銀兩氣血），交審時點明是 10/17 的新要求。
- `_advance_player_local` 也被「日常氣血見底」（feature/formal-season 第 3 批之後）改：它在回完血之後接 `_grave_check`。抽 `_stamina_regen` 只動體力那幾行，不動氣血那一段，後合的那一邊解衝突。
- 正式季第 1 批把「今天」統一成現實一天、截殺照舊（21 天季設計 1.3、第十一章），這一份不碰換日、不碰冷卻，不衝突。
- 假人：跟真人同一條規則、同一句話；`bot_policy` 的截殺判斷不改（只在「穩勝」「有把握」才動手，原本就照輸了的代價定的，見 `bot_policy.py:53`）。
- 截殺新手期保護（`roster.raid_newbie`）在打之前擋，新手期體力 3 倍回復跟這裡無關。
- 回體丹一天上限不動。

### 2.6 不做
- 不扣到 0 以下、不讓體力 0 的人因此被擋在某些動作外（本來就是體力規則）。
- 不改截殺、設伏的勝負、銀兩、氣血、冷卻、護身。
- 策馬脫身、平手不扣。
- 不寫量表、不先跑模擬（企劃者 10/14）。

## 三、開發計劃

### Task 1　設定欄位
- `tianxia/models.py`：`Raid` 加 `loser_stamina: int = Field(default=0, ge=0)`，`AmbushRules` 同樣加；docstring 各補一行「輸的一方另扣幾點體力（企劃者 10/17 清單第 33 條；正式 15／20【預設】，0＝關）」。
- `content/config.json`：補 `"raid": {"loser_stamina": 15}`（目前沒有 raid 這一鍵，新增）、`"ambush": {"enabled": false, "loser_stamina": 20}`。
- 測試：讀正式內容 `content.config.raid.loser_stamina == 15`、`ambush.loser_stamina == 20`；測試內容兩個都是 0。放進新檔 `tests/test_raid_stamina.py`。
- 跑：`scripts/test_for.py --base origin/feature/raid-stamina`（會挑到內容的測試與真實內容；照它挑的跑，不另加）。

### Task 2　體力回復抽一個函式＋扣體力的函式
- `tianxia/engine.py`：
  - 從 `_advance_player_local` 抽出 `_stamina_regen(self, seconds) -> float`（新手期倍數、承露都在裡面），`_advance_player_local` 改叫它，數字一個不變。
  - 新增 `_drain_stamina(self, loser: Game, n: int) -> int`（或寫成 loser 自己的方法）：`r = loser._stamina_regen(max(0, now - loser.state.last_real) * time_scale)`（`last_real` 是 None 時 r＝0）；`have = min(上限, p.stamina + r)`；`took = min(n, int(have))`；`p.stamina = have - took - r`；回 `took`。`now` 用 `self.now`（`_kin` 已經接上）。不讀時鐘。
- 測試（`tests/test_raid_stamina.py`）：
  - 在線的人（last_real == now）扣 15，體力少 15；只剩 6 時扣 6、不到負數。
  - 下線一段時間、本來會回滿的人：扣完之後讓他 sync，體力是「上限 − 15」不是上限。
  - 下線但不會回滿的人：sync 之後＝存的＋回復−15。
  - `_advance_player_local` 抽函式前後同樣輸入體力一樣（照舊的回復測試能過就算）。
- 跑：`pytest tests/test_raid_stamina.py`，加上 `scripts/test_for.py --base origin/feature/raid-stamina` 挑到的。

### Task 3　截殺接上
- `RaidSpoils` 加 `stamina: int = 0`（輸的人實扣幾點）。
- `_raid_spoils`：扣完氣血之後 `took = self._drain_stamina(loser, cfg.loser_stamina)` 放進 spoils。
- `_raid_record`：輸的那一邊在 `氣血 -N` 後面 `record.changes.append(f"體力 -{spoils.stamina}")`（> 0 才寫）；發起的人前面那一行在 `loser_stamina > 0` 時改寫成「出手 體力 -10」（新常數 `RAID_PAID`，待 joy 潤；0 時照舊「體力 -10」，一個字都不變）。
- `tianxia/raid.py::buttons`：`loser_stamina > 0` 時確認句換成帶體力的那一句（常數放 raid.py，待 joy 潤）。
- `_raid_fled` 不動。
- 測試（照 `tests/test_raid.py` 的 `pair` 寫法，monkeypatch 把 `loser_stamina` 設 15、固定結果）：
  - 守方輸：守方體力 −15，戰報「得失」與他的「遭X截殺」紀錄有 `體力 -15`；發起的人只付 10。
  - 攻方輸：攻方共少 25，紀錄裡「出手 體力 -10」與 `體力 -15` 各一行。
  - 平手、策馬脫身：誰都不另扣。
  - 守方下線（存檔裡的體力是舊的、`last_real` 在一小時前）：打完他 sync，體力照 2.2 的算法。
  - 開關 0：體力、確認句、紀錄跟現在一字不差（拿 `test_raid.py` 現有的幾條在 0 下照跑就算）。
  - 假人當守方：紀錄字句跟真人一樣（照 `test_no_word_reveals_a_bot` 的寫法）。
- 跑：`pytest tests/test_raid.py tests/test_raid_stamina.py`。

### Task 4　設伏接上
- `_ambush_spoils`：扣完氣血之後 `took = self._drain_stamina(loser, cfg.loser_stamina)` 放進 spoils（loser 是路過的 self 或伏兵 owner 都一樣；owner 的存檔照舊由 `_ambush_fight` 最後 `_save_kin` 寫回）。
- `_ambush_record`：輸的那一邊 `體力 -N` 同截殺。
- `ambush.py` 檔頭與給玩家看的說明若寫了輸了賠什麼，補體力（字待 joy 潤）；`OWNER_LOST`／`PASSER_LOST` 那幾句不改。
- 測試（`tests/test_stamina_plays.py` 的 `real, world` 寫法，`ambush.enabled` 與 `loser_stamina` 用 monkeypatch 打開）：

  - `loser_stamina` 0：跟現在一字不差。
- 跑：`pytest tests/test_stamina_plays.py tests/test_stamina_plays_off.py tests/test_raid_stamina.py`。

## 四、等企劃者

1. 【待企劃者】截殺扣 15、設伏扣 20，你要的「有感」是這個量級（約 45 分鐘、1 小時的回復），還是要重到「被截一次這一陣子做不了什麼」（例如 50）？量級差到三倍以上時，2.2 下線照扣的算法不變，但要另加「一天最多被扣多少」的上限，不然護身 1 小時一過就能再扣，不在線的人回來可能一下少一大截。
