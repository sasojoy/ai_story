## 三、畫面（`web/support.js`）

1. **上限讀法**：`SUPPORT_FILES_MAX`、`SUPPORT_FILE_BYTES` 兩個常數換成函式（例 `supportFilesMax()`、`supportFileBytes()`），讀 `S.supportMine` 的 `files_max`／`file_bytes_max`；另兩個 `supportOpenMax()`、`supportDailyMax()`。缺鍵或不是數字（舊回應、`supportLoad` 失敗給的 `{tickets:[]}`）退回 3、3000000、3、5。**坑：`files_max` 0 是合法值，不能寫 `v || 3`**，要判「是有限數字」。
2. **MB 寫法**：跟 `routes._mb` 的 `%g` 一樣：`String(Number((n / 1e6).toPrecision(6)))`（3000000→「3」、1000000→「1」、2500000→「2.5」）。小於 100 位元組時 `%g` 會寫成指數、JS 不會，這種設定不實際，不追。
3. **組字**：`SUPPORT_FILE_NOTE`「最多 N 張、每張 M MB 以內（PNG、JPEG、WebP）」、`SUPPORT_FILE_BIG`「圖太大了：一張最多 M MB。」、`SUPPORT_FILE_FULL`「一張單最多附 N 張圖。」、`SUPPORT_NOTE`（15 行）與清單底下那句（178 行）「同時最多 A 張沒結的單，一天最多送 B 張。」都改成函式組；**預設值組出來跟現在逐字一樣**。旁註 `// 待 joy 潤` 留著（字的骨架沒變，不算新字）。
4. **0 張**：`supportPickHtml()` 在 `supportFilesMax() === 0` 回 `""`（按鈕、說明列、空位格整塊不畫）。送單（`supportForm` 的 `support-new-form`，現在 336–347 行）：上限 0 時不走逐張上傳那一段（picks 當空的；`S.supportPicks` 照舊清掉）。補圖那一格（`supportAddHtml`，107 行）只換讀法，0 時照舊不出現。
5. **客服桌面讀不到**（`supportDeskReload` 288–297、`supportDeskHtml` 270–282、`renderSupportDesk` 283–287、`support-desk-refresh` 306）：
   - catch：**只在 `S.supportDesk` 還是空的時候**（queue 本身失敗）設 `S.supportDeskFailed = true`，不再填全 0 的物件；queue 成功、只有點開的那張單讀失敗的，照現在留著清單（保守，不改這一條）。
   - `supportDeskHtml`：旗標真時，標題（`.ad-head`，不動）下面只畫一行 `<p class="muted">讀不到客服單，請按重新整理；剛用驗證碼登入的話，請改用帳號密碼重新登入。</p>`，不畫四個磚與清單。
   - `renderSupportDesk`：旗標真時**不自動重讀**（不然 render→reload→fail→render 會無限打）。
   - 「重新整理」：清旗標、`S.supportDesk = null`、重畫 → 重讀；讀到了照常畫。
   - `api()` 自己跳的 toast 在殼裡，不管。
