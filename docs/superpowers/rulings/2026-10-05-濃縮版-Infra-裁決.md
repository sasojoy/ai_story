# 第一季濃縮版：Infra 做的裁決（T0～T8、FB-033～040）

計畫：`docs/superpowers/plans/2026-10-04-第一季濃縮版.md`。2026-10-05 起遊戲程式交給專職開發。

這份是 Infra 在實作中自己定、或 PM 與企劃者定了交給 Infra 的事。只收專職開發接手 T9～T11 時用得到的，每一條寫做法、理由，以及錯了要改什麼。計畫 T8 節後面的「交接備註」寫的是坑與介面，跟這份互補。

## 共通

- **新規則一律掛在季的章後面**：判斷用 `rules.season_one(content, world)`，等於 `calendar.season_one_on`，也就是開關開著、而且這一季開季時蓋了「開」的章。
  - 理由：做到一半的 main 也會換上試玩伺服器；開關打開時還在跑的 beta 季，不能半套新規則（PM 10/4）。
- **沒蓋章的舊季一律算 14 天**（`models.DEFAULT_SEASON_DAYS`，FB-037，PM 定）。週末設定只管有蓋章的季。
  - 理由：換版順序做錯時，正在跑的舊季也不會被 2.5 天的季長收掉。
- **兩個 session 都要用的介面**（PM 10/4）：先進 main 的定義它，後到的在 main 上補完，不另寫一份。
  - 例子：`trend_accum`（T3 定義，T1 用）、`SeasonOneOff`（T8 定義，T4 補 events）、`donations` 與 `grain_of`／`take_grain`（T7a 先放最小版，T6 補完）。
- **戰況讀法只有一份**：`timetable._front_value`，它裡面呼叫 T1 的 `rules.trend_value`；劇本沒有那條線時回 50。伏筆也呼叫它，不另寫一份。
- **front 欄位寫戰線 id**（`MapRegion.front` 的值），不寫大區 id。載入時檢查時刻表、人物效果、`@commander`、伏筆（地圖擴充的 T1 審查提的）。
  - 理由：寫成 youzhou 時，讀戰況會靜靜拿到固定的 50。
  - 錯了要改：改成在讀值前做大區→戰線的換算。

## 換季重來（T0、FB-034、FB-035）

- **好感度帶一成**（`Config.affinity_carry_ratio`，無條件捨去）；其餘 `PlayerState` 欄位跟著新角色重來。要跨季保留的，才加進 `_reset_player_for_new_season` 的清單。
- **新手引導**：做完或略過的照舊不再出現；沒做完的從起始步重來（FB-034）。
  - 理由：新角色沒有武學，接著上一季的下一步「出城遊歷」會必敗。
- **季終時還沒打完的決戰收兵、不算勝負**（FB-035）。做法是先在 battles 表標成 ended＋`unfinished`，再拿掉，參戰者同步時補一則江湖紀錄。
  - 這件事發生在三處：自然收季（`_battle_status`）、管理者收季、管理者開下一季。開下一季也要做，因為自然收季後若沒人同步，`next_season` 會直接清掉決戰，參戰者就收不到那一則。
- **武學榜跳過別季的角色**（`leaderboard`）。

## 季曆與時刻表（T2、T2b、FB-038、FB-040）

- **成功率的修正按等比例調整**（企劃者「先等比例調整」）：
  - m ≥ 0：p + m(1−p)/0.5；m < 0：p + m·p/0.5；
  - 基準先夾在 0.1～0.9；`event_mods` 合計夾在 ±0.20，`event_bonus` 不夾；結果再夾在 0～1。
- **豪強不做決戰裡的「趁亂」**；一方陣營沒人參戰也照常結算（企劃者「一方陣營沒人就算了」）。
- **鎖定時的公告怎麼組**（T2b，照 S1 cce433f）：具名的一段＋這一檔的結果句（含 `note` 與人物的後話）＋搶輸的一筆＋豪強的一筆。
  - 搶輸的一筆排在 note 之後，因為長社黃巾大勝的「波才北上」屬於結果句。
- **大事公告不跟著推進的人走**（FB-038，PM 定：比照 FB-035）。每個角色同步時補自己還沒看過的（`events_seen`）。
  - 一次補到好幾件時，合成一則「江湖大事」。
  - 這一季中途才建立的角色，也補到這一季已經發生的大事。
  - 錯了要改：建角時把已經發生的標成看過。
- **開季那一刻就結算第 1 週**（FB-040）：`season_hour` 拆成「每曆時的事」與 `season_events`，開季那一下只跑 `season_events`。
  - 理由：每曆時的 tick（T1 的割據、T4 的人物）不能在開季那一刻多跑一次。
- **開季的結算只掛在管理者的開季與開下一季**。`auto_open_first_season` 只有測試內容用。

## 推力與貢獻（T3）

- **開關關著時**就是原本的 `change_trend`，一個字都不變。
- **人數緩衝**：n 是自己陣營一個曆日內推過大勢的人，不論推的方向，含自己、含假人。散人的 n 當 1，不記貢獻，也不進活躍名單。
- **每曆日上限**算緩衝之後的量；超過的部分不推大勢，貢獻記兩成。貢獻照不打折的推力算。
- **`trend_accum` 帶正負號、往零取整**：不足一點的推力全服共用，滿一點才推；兩邊陣營推的會互相抵銷。
- **不會動的推動不記貢獻**：推力是 0，或往下推一條還沒浮現的線，都不記，避免拿來刷貢獻。
- **只有玩家自己造成的推動走 `push_trend`**：時刻表、決戰、管理者、`sim_tick` 不走；引導獎勵（`guide.py`）也不走，因為那裡沒有 Game。

## 伏筆（T7a、T7b、T7c）

- **拆兩刀**：T7a 做引擎，用 fixture 的鏈測；T7b 轉真實的 11 條。計畫 T7 節有拆法表。
- **開關**：`foreshadow.active` 是唯一的判斷，條件是開關開著、季蓋了章、而且至少有一條鏈。
  - 開關關著時，伏筆事件一律不出現。要被藏起來，事件得是某條鏈的片段來源，或會給伏筆物品、計數。新加的伏筆事件要符合這兩種之一。
- **`Condition` 多了 `factions`、`night`、`week_min`、`week_max`**。
  - 理由：內容表 4.5 有「只對某陣營」「夜裡」「第 4～6 週」的事件。
  - `night`、`week_*` 只在事件、選項、福緣的條件上有效；門檻與引導不給 content，讀不到。
- **片段事件給哪一則**：照玩家做得了的鏈挑。同一則事件（例如老船夫）可以分別給官軍、黃巾各自的那一片。
- **對話片段的人物可以寫 `stand_in`**：主角色退場、重創或下獄時，改由他出面（盧植→董卓、皇甫嵩→朱儁）。不靠 T4 的 `commander`。
- **名望不夠求見不到的人，對話片段改從同一大區的行動偷聽**（T7c，企劃者 10/5）。
  - 文字前面加「聽說{人物}說過：」；偷聽到與當面問到算同一片。
  - 求見的判斷只有一份：`rules.can_meet`。
  - 注意：名望低的人片段池變大，單一行動片段被抽到的機率會稍微變低，試玩時要看。
- **做完伏筆記貢獻 `Config.foreshadow_contrib = 50`**，相當於五點推力。伏筆文件只寫「記貢獻」，沒有數字。
- **官銀**：黃巾在冀州、潁川汝南打贏官軍隊伍時，30% 得一個（內容表 4.0）。只有自己還做得了、而且讀官銀的鏈存在時才擲；沒有鏈讀時，江湖紀錄、戰報、背包都不會出現官銀。
- **匿名的鎖定者**：公告與江湖史寫「某位少俠」（`Lock.shown`、`WorldState.third_party_shown`），時間軸照記真名，留給 13.3 的稱號（PM 同意）。
- **最後一步的需求**：整條鏈的需求和這一趟的需求合起來算、一起交。答錯沒收糧草時，手上不夠就有多少收多少。
- **答錯的 `lose_items` 收走手上全部**；答對只交換算後的量。
- **新野那一步的時間窗**（`during_muster`）：先算成「排定的決戰時間到大事結算」。
- **事件文字的占位**：13 則事件先用內容表 4.5 的情境欄當文字，tags 標「待joy寫」，等 joy 換。
- **S1 審過的句子**（內容表 4.6）：兩頭賣糧完成時，接在後完成那一趟自己的句子後面；宛城官軍的標籤是「請纓」。
- **伏筆物品的畫面**：放在煉製頁，只列名字和數量；計數與「還差什麼」不做（範圍凍結）。

## 三場大戲（T8）

- **「第一季不觸發」清單**：`Scenario.season_one_off`，分五種，各自是那一種內容的 id。
  - thresholds：黃巾聲勢 50／60／80／10；
  - storylines：`huangjin_line`；
  - battles：`huangjin_showdown`；
  - events：T4 補 `kou_boss`；
  - milestones：擊敗波才、平定黃巾、打贏或輸掉黃巾決戰。
  - 讀法：`rules.season_one_off(content, world, kind)`。格式是跟地圖擴充說好的；milestones 是後加的，因為「主線與目標」不該列出做不到的目標（PM）。
  - **玉璽計畫再加兩種**（2026-10-06，地圖擴充；寫這份裁決時還沒實作）：
    - world_events：第一季不觸發的 beta 世界事件，世界事件的迴圈、管理者的觸發與選單都跳過，例如董卓搶碎片 `dongzhuo_takes_shard`（`plans/2026-10-06-玉璽碎片-1-…`，Task 2）；
    - unlocks：第一季拿掉的地點解鎖條件，例如南華觀不必等 `xi_open`（`atlas.is_unlocked` 看它；`plans/2026-10-06-玉璽碎片-2-…`，Task 2）。
  - 加種類照同一套：`SeasonOneOff` 加欄位（預設空的）、`rules.OffKind` 加名字、`content.validate` 照種類各自檢查 id、用到的地方照 `rules.season_one_off` 跳過。
- **「主線與目標」**：關掉的主線不顯示。全部都關掉時整塊不畫，由本週大事卡與倒數撐著。「可能的結局」還是 beta 的，留給 T9。
- **沒開成的決戰照前線起點判**（Review Focus 1、2）：
  - 情況一：同一次推進已經走到決戰之後的下一件大事。這時先把決戰判掉，再結算那件大事（`settle_waiting_showdowns(before=event)`）。理由是補算得那麼長，表示整段時間連假人都不在線；伺服器一直開著的話，也會因為沒人參戰而得到同一個結果。
  - 情況二：走到季末。收季前判掉。
  - 已經在打、季末時還沒打完的，照 FB-035 收兵，不算勝負。
  - 錯了要改：玩家會錯過一場本來可以晚一點加入的決戰。
  - 很少碰到的情況：決戰因為另一場還在打，開不成又拖過整段間隔，也照這條判掉。
- **戰局剛好 50 又有鎖定時**：先照「平手算守方贏」定出戰場上的贏家，再看鎖定（計畫的文字：戰場上也贏是大勝，否則險勝）。
