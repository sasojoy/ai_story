# T4 大勢人物、聲威、敗走與接手：裁決、擱置事項與交接備註

總計畫：`docs/superpowers/plans/2026-10-04-第一季濃縮版.md` 的 T4。展開計畫：`docs/superpowers/plans/2026-10-04-T4-大勢人物.md`（7 個任務）。內容權威：`docs/superpowers/specs/2026-10-04-第一季陣營內容-濃縮版內容表.md` 第一節（企劃者已審）。

## 做了什麼

- **14 位大勢人物**（`content/figures.json`，照內容表 1.1）與每人一支代表本人的隊伍 `figure_<id>`（照 1.4；`fanjianglong` 原樣留給 beta）。
- **開季時種人物**：開關開著、這一季開季蓋了「開」的章時，在 `stamp_season` 把聲威、狀態、戰線、所在照人物表種進 `WorldState.figures`。T4 之前就蓋章的季沒有種過，讀的時候照人物表的起始值（不寫回存檔）。
- **人物每曆時推戰線**（`figures.tick`，在 `season_hour` 裡、割據之後、大事之前）：照 `actions_per_day` 累積、滿 1 推 `push` 點；戰線偏向對方 15 以上時推得兩倍勤；官軍三將與孫堅第 2 週才出兵。開季那一刻不推。
- **虛擬玩家在第一季讓位**：`sim_tick` 不讓它們出手，門檻照舊每小時檢查。輿圖的「常出沒」與龍頭人物詳情改標大勢人物（推哪條戰線、聲威）。
- **時刻表的人物結局**（`figures.apply`）：退場、重創、重挫、聲威大減、受挫、下獄、到任；聲威歸零時退場（天命人物重創）；空出的戰線照接位鏈交接，另發一則天下大事傳聞。
- **挑戰本人**（`act:challenge:<人物 id>`）：在人物所在、敵對陣營的成員才有（豪強兩邊都能挑戰，散人沒有）。打贏時：
  - 他敗走，聲威 −5（照陣營人數緩衝）；
  - 你跟他的情誼 −5；
  - 2 個**現實**小時內他不見你：求見、交友、挑戰都按不下去，寫「剛吃了敗仗，閉門不見」；
  - 記貢獻 50。
  輸了照遊歷賠銀兩、扣氣血。體力照遊歷（10）。
- **假人**勝算「穩勝」「有把握」時會挑戰（分數 1.5：比探索高、比推戰線的遊歷低）。
- **`kou_boss` 在第一季抽不到**：`scenario.json` 的 `season_one_off.events`。
- **全部掛在開關後面**（`rules.season_one`）。開關關著、或這一季沒蓋章時，beta 的規則、存檔、畫面一個字都不變。

## 裁決

1. **beta 的內容一個字都不改**（PM 2026-10-04）：總計畫 T4 寫的「`sim_players` 清空、`kou.json` 改寫或刪掉、`fanjianglong` 改名 `figure_bocai`、拿掉 `bocai_defeated`、改寫 `huangjin_line`」**由這個做法取代**——beta 的東西全部留著，只在開關開著時關掉。理由是「開關關著＝beta 一模一樣」這條規矩優先。
2. **`kou_boss` 用 `scenario.json` 的清單關，不碰事件檔**（PM 2026-10-04）：joy 正在改事件檔。清單的格式跟 Infra 的 T8 共用（`season_one_off`，五種：thresholds／storylines／battles／events／milestones），T8 先進 main、定義模型與檢查；T4 只補事件抽選跳過，清單加 `"kou_boss"`。
3. **`beat_bocai` 照樣留在 `season_one_off.milestones`**：挑戰本人打贏不寫 `bocai_defeated`，所以第一季「擊敗波才」照樣做不到。
4. **主線顯示不歸 T4**（PM）：江湖頁「主線與目標」在第一季怎麼顯示，由 T8 處理。
5. **介面跟總計畫不同的地方**（Infra 同意）：
   - `figures.holds(state, change)` → `holds(state, content, change)`（沒種過的人物要讀人物表；唯一的呼叫端 `timetable.resolve` 一起改）；
   - `figures.tick(...)` 回傳 `None`（背景推動不出訊息）；
   - `figures.apply` 一律回傳 `[]`：接手另發一則傳聞，不接在時刻表公告後面（公告原文已經寫了結果，接上去會重複，也會打壞逐字比對公告的測試）；
   - `Config.figure_difficulty_at_100／at_0` → `figure_difficulty_floor = 0.5`（內容表 1.4 每人難度不同，一組整數表達不了）；新增 `figure_defeat_affinity = 5`。
6. **計畫先定的 20 個細節**照展開計畫「總計畫與內容表沒定、這份計畫先定的」那一節，例如：主將是人物表排最前面那位；接位的人也接下前任的所在；下獄不走接位鏈；已經退場的人不再被時刻表改。
7. **新寫的句子，用語歸 S1**：「X連吃敗仗，聲威掃地，退出了這一季的戰事。」（天命人物是「元氣大傷」）、「Y接手Z的戰事。」要改直接改 `figures.defeat`／`_hand_over`。
8. **割據平衡**：企劃者 10/4 定「這部分先不動」。

## 給 PM、企劃者與 T11 的

- **割據照樣一路漲到頂**（T1 已記）。人物推戰線之後，戰線多半停在亂局裡，割據漲得更穩。
- **14 支人物隊伍沒有寫 `drops`**：素材走依難度的預設表（難度 ≥100 靈品必掉、天品 25%）。其中五位屬「實」「虛」，預設表找不到同屬性就在四種天品裡隨機給。連帶的影響：載入時的「每種素材都有來源」檢查會把它們算成所有靈品、天品的來源，beta 那一季若哪天拿掉某個素材唯一的來源，這個檢查抓不到。要精確就得給這五支寫 `drops`，那要內容表給數字。
- **獎勵**照舊波才隊伍（心得 80、經驗 80）；南華觀看守者是 100／80。要不要分開由企劃者決定。
- **人物空了的戰線不會自己回到中段**：一方的接位鏈走到底，那條戰線只剩另一方在推。總計畫第五節寫「人不在時戰線會慢慢回到中段」，這裡讀成「玩家不在時，兩方人物互推加上落後加倍，會讓戰線停在中段」。若企劃者要的是「沒有人物時自己往 50 走」，那是 T11 的平衡項目。
- **好玩度量表**的「對手 N/…」分母多算了 14 支 beta 打不到的人物隊伍。

## 擱置（小問題，都不擋合併）

- 測試還沒蓋到的地方：
  - 落後加倍剛好在 35／65 那一點；
  - 輿圖「第 N 週起」沒有後綴的情形；
  - 接位鏈跳過已退場的人、接位鏈有環時的保護；
  - 假人只在「凶險」時測了不挑戰，其他三種勝算詞沒逐一測。
- 時刻表測試夾具沒有人物表的 id（不是那 14 位）遇上聲威歸零時，「重創」會被改寫成「退場」；兩者都算出局，行為沒差，只有文件說法不一致。
- 貢獻帳的寫法現在有三處（遊歷推大勢、挑戰打贏、伏筆），活躍時窗的算式也重複兩處。
- 輿圖的人物動態不看戰線浮現了沒（三條戰線現在都是公開的，不會洩漏）。
- 同一個曆時裡，同一條戰線的幾位人物照人物表順序推；先推的會影響後推的看到的戰況（決定性的）。
- `has_events_here` 不看 `season_one_off.events`；`kou_boss` 只在探索出現，現在不會出問題，將來清單裡若放交友事件要一起改。
- 正在跟某位人物對話時他剛好下獄或退場，對話照舊進行到玩家告辭為止（計畫原本就延後）。

### T5、T6 要接的介面（都在 main 的 `tianxia/figures.py` 與 `engine.py`）

- **讀人物**（都不檢查第一季的開關，呼叫端要自己用 `rules.season_one(content, world)` 擋）：
  - `figures.state_of(state, content, fid) -> FigureState`：種過的照存檔；沒種過的照人物表起始值，不寫回存檔；
  - `figures.is_out(state, fid)`：退場或重創（下獄不算）；
  - `figures.commander(state, content, front, faction) -> 人物 id | None`：那條戰線那一方當下的主將，人物表的順序就是位階；沒有時回 None，呼叫端換泛稱（內容表第三節：官軍「營中」、黃巾「渠帥」）；
  - `figures.name_of(content, fid)`：人物的名號（T6 計畫裡寫的 `figure_name` 用這個）；
  - `figures.present_at(state, content, loc_id)`：此刻站在這裡、在場的人物 id；
  - `figures.difficulty(state, content, fid)`、`figures.squad_of(...)`：挑戰本人的難度跟著聲威內插；
  - `Game.challenge_odds(fid) -> str`：勝算詞，假人與按鈕用。
- **改人物**：
  - `figures.apply(state, content, fid, FigureChange(...)) -> []`：時刻表結局的七種用詞，或只給 `prestige=-15`。聲威歸零時自己處理退場或重創、接手、天下大事傳聞；**回傳一律是空的**，要給玩家看的句子呼叫端自己寫。
  - `figures.defeat(state, content, fid, amount) -> list[str]`：挑戰打贏扣聲威。不足一點的累積在 `trend_accum["prestige:<人物 id>"]`，歸零時同樣退場與接手；回傳給打贏的人看的句子。「打擊大勢人物」達成時扣 15，用哪一個都可以：`apply` 不回句子，`defeat` 回句子。
- **T6 的呼叫點**：`engine.Game._rout`（挑戰打贏）最後有一段註解，寫好了 `orders.credit(... kind="challenge", location=..., front=figures.state_of(...).front, figure=fid)` 的呼叫方式，取消註解接上即可。
- **假人**：`bot_policy.CHALLENGE_SCORE = 1.5`、`CHALLENGE_ODDS = ("穩勝", "有把握")`。「打擊」軍令讓假人專程去找人是 T6 的事：人物的所在用 `figures.state_of(...).location`。

### 總計畫裡沒寫的坑

1. **挑戰打贏的貢獻不經過 `push_trend`**：`Game._rout` 直接寫 `p.contrib`／`contrib_weeks`（50 點）。T5 的 `check_summons` 總計畫寫成「由 `Game.push_trend` 在貢獻變動後呼叫」，**挑戰打贏之後也要呼叫**，不然靠打人物累積到 300 的人收不到召見。
2. **貢獻帳已經有三處各寫一份**（`push_trend`、`_rout`、伏筆），活躍時窗的算式也有兩份。T6 的 `orders.credit` 護糧送到要記貢獻時，先抽一個共用的小函式，不要再複製第四份。
3. **開關**：一律用 `rules.season_one(content, world)`，也就是開關開著**而且**這一季開季時蓋了「開」的章。只看 `Config.season_one` 會在 beta 那一季誤開。第一季要關掉的 beta 內容，放進 `scenario.json` 的 `season_one_off`（五種，讀的入口是 `rules.season_one_off(content, world, kind)`）。
4. **`trend_accum` 的鍵有前綴**：戰線 id（T3）、`"geju"`、`"fig:<人物 id>"`（人物推動）、`"prestige:<人物 id>"`（挑戰扣聲威）。新的累積要取新的前綴。
5. **長時間快轉的測試，戰線會自己動**：人物每曆時都在推，潁川會被拉向官軍（T7b 的端到端伏筆測試快轉五週後要把潁川放回 50）。第一季的測試若要固定戰況，快轉之後自己設回去。
6. **黃巾聲勢的舊門檻在第一季已經關掉**（T8）。要拿「門檻還在每小時檢查」當證據的測試，用 `yuxi_50`。
7. **割據會漲到 100**（企劃者：先不動）。任何以割據為條件的軍令在第一季後半都是滿的；豪強 85 就是決定性勝利。
8. **伺服器假人目前從不挑戰**：只挑「穩勝」「有把握」，而人物隊伍難度 100～160，假人很少打得贏。總審查跑了多季，挑戰全部來自隨機的機器人。T6 的打擊軍令若要假人真的去打，門檻或分數要另外調。
9. **戰況的平衡點**：總審查的三個種子裡，冀州季末都在 76 左右，跟玩家做什麼無關。潁川 36～37、南陽 32～35。給 T11 參考。
10. **人物 id 必須等於他的對話人物 id**：伏筆用對話人物 id 讀 `WorldState.figures`。`check_figures` 會擋。
11. **內容表沒給的數字照舊波才隊伍**（心得 80、經驗 80、不寫 drops），見上面「給 PM」。
12. **事件文字歸 joy**：第一季要關掉的 beta 事件用 `season_one_off.events`，不在事件檔加鍵。
13. **這台機器**：裸的 `python` 是 Windows Store 空殼，一律用 `.venv/Scripts/python.exe`；commit 用 Git Bash heredoc（PowerShell 會加 BOM）；任何會開世界的臨時腳本先設 `TIANXIA_DB` 到暫存檔，不然會開到 worktree 的 `saves/tianxia.db`。
